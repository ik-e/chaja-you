## 이번 브랜치에서 수정한 것

- `pyproject.toml`: `[tool.uv] package = false` 명시, MVP `pytest` 탐색 대상 한정. **기존 런타임/dev dependencies와 uv.lock은 미변경**.
- `prototype/lesson-registration/tests/test_fixture_environment.py`: 합성 fixture 기본 안전 속성 및 값 smoke test(2건).
- `.github/workflows/mvp-environment-check.yml`: uv 버전 0.10.0 고정, `uv lock --check` → `uv sync --locked --group dev` → `uv pip check` → pytest/ruff 실행 설정. GitHub Actions **실행 결과는 아직 없음**.
- `.gitignore`: pytest/ruff cache와 프로토타입 런타임 임시 파일 제외.
- `ENVIRONMENT.md`: 실행 절차 및 기술 스택 미선정 경계 기록.

## 실제 실행에 필요한 재현 명령 (프로젝트 루트)

```bash
uv --version
uv python pin --help
uv lock --check
uv sync --locked --group dev
uv pip check --python .venv/bin/python
uv run --locked pytest prototype/lesson-registration/tests -q
uv run --locked ruff check prototype/lesson-registration/tests
python tools/project_docs.py --check
```

Windows PowerShell에서는 `uv pip check --python .venv/Scripts/python.exe`로 Python 경로를 바꾼다. `uv python pin --help`는 옵션 조회이며 핀 변경을 수행하지 않는다.

## 열린 사항

1. **실제 설치·CI 패스 여부** — PR 생성 또는 개발자 머신에서 실행하여 증거 확보. 현재는 성공이라고 보고하지 않는다.
2. **의존성 필요성** — 기존 `pydantic-settings`, `python-dotenv`, `requests` 등은 루트 선언만으로 MVP 필수라고 단정할 수 없다. 어떤 코드에서 실제로 필요한지 R05 기술 선택 후 최소화/그룹 분리를 검토한다.
3. **UI 기술 선택** — Python 백엔드만 uv로 관리하고, Node/React가 선정되면 별도 `package.json`/잠금 파일을 추가한다. 지금은 불필요한 프레임워크를 설치하지 않는다.
4. **정본 반영** — 이 검사는 제안 브랜치 전용이며, `main`의 의존성 정책이나 Phase Intent를 변경하지 않았다.

## 결론

현재 기존 설정에서 **즉시 드러나는 메타데이터/루트 의존성 불일치는 발견되지 않았다**. 그러나 설치·실행/외부 취약점까지 통과한 것은 아니다. CI의 잠금·설치·의존성·smoke/lint 실행 결과를 확인한 뒤 완료로 승격한다.
