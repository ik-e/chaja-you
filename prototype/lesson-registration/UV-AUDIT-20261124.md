# 기존 uv 설정 감사와 축소 · 2026-11-24

**상태:** 정적 확인/브랜치 의존성 축소 반영. 실제 `uv lock --check` / `uv sync` / CI 실행은 R05/TASK-041 미완료.

## 삭제 판단

| 직접 의존성 | 기존 설정 | 사용처 조사 | 이번 결정 |
| --- | --- | --- | --- |
| pydantic | runtime | 현재 저장소에서 조사한 Python 도구 12개에 직접 import 없음 | 제거, 모델 계약 채택 때 재검토 |

| python-dotenv | runtime | 동일 | 제거 |
| requests | runtime | 동일 | 제거 |

**주의:** 사용처 검사는 조사한 기존 스크립트/문서 및 새 테스트에 대한 정적 탐색이다. 향후 브랜치의 미병합 구현 의존성까지 절대적으로 불필요하다는 뜻은 아니다.

## lock 변경

- `pyproject.toml`의 런타임 `dependencies=[]`, 개발 `pytest>=9.2.0`·`ruff>=0.17.4`.
- `uv.lock` 루트가 dev 의존성만 참조하게 하고, 불필요한 이전 런타임 패키지와 해당 전이 의존성 12개를 제거.
- 남은 항목: `chaja-you`, `colorama`, `iniconfig`, `packaging`, `pluggy`, `pygments`, `pytest`, `ruff` (총 8개).
- `uv.lock`은 내용을 정적으로 최소화했다. **uv 리졸버의 실제 일치 확인은 미실행**이므로 TASK-041이 `uv lock --check`로 검증하고 필요 시 공식 `uv lock`으로 다시 생성·커밋한다.

- 기존 문서 CI는 표준 라이브러리 기반 `python tools/project_docs.py --check`를 사용한다. 삭제 의존성에 대한 직접 import는 조사 범위에서 찾지 못했다.
- 새 `.github/workflows/mvp-environment-check.yml`: Python 3.12, uv 0.10.0, lock→sync→dependency check→pytest→ruff. 실제 CI 실행 전이다.

## 남은 검증 및 안전

1. R05: 실제 uv install/lock/pytest/ruff 및 기존 문서 검사 로그 제출, 깨질 경우 원인 기록.
