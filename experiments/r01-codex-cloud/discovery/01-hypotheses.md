# 01 — 타겟·문제 가설의 출발점

- 기준일: 2026-11-16 (KST)
- 범위: R01 개인 탐색 자료. 공식 팀 결정이나 확정된 고객 세그먼트가 아니다.
- 근거 등급: 직접 확인은 공개 원문/제품 문서에서 확인한 내용, 게시자 보고는 사용자의 자기 보고, 해석은 가능한 설명, 미확인은 인터뷰·반복 사용 관측이 필요한 항목이다.
- 자료 범위: R01의 2026-11-13 R4 기술 정리, 2026-11-14 경쟁 조사, 실험 HANDOFF/B0 및 2026-11-16 공개 이슈·제품 문서.

## 먼저 고정한 기존 맥락

R01의 상위 가치 제안은 새 지능을 만드는 것이 아니라 기존 LLM과 도구·기억·인터페이스를 연결하여 사용자가 여러 업무에서 반복하는 불필요한 설명·감독·검토·판단 비용을 줄이는 것이다. 특정 도메인, 워크플로, 멀티에이전트 구조는 확정되지 않았다.

R01 R4는 프로젝트 변경·TASK 검토를 값싼 후보 실험으로, 반복 문서 리뷰를 반대 비교 사례로 제안했지만 사용자 문제와 제품 가치는 검증 전이라고 명시한다. HANDOFF도 이전 승인 범위의 재사용, 조건 변경 뒤 필요한 결정만 재검토, 승인·검증 부담을 가설로 둔다. B0는 모의 Status API 과제만 통과했고 실제 사용자 고통·경쟁 가치·시장 수요는 검증되지 않았다.

## 타겟 후보

| 후보 | 탐색상 정의 | 현재 증거 | 아직 확인되지 않은 것 |

| B — 숙련 개인 개발자 후보 | 혼자 반복적인 AI 개발·리서치 작업을 수행하고 직접 도구 승인과 결과 검토를 맡는 사람 | Codex CLI와 로컬 MCP를 매일 쓴다는 공개 사용자 댓글이 있고 반복 승인 증상을 보고함 | 직무/숙련도, 전체 업무 중 빈도, 다른 도구에서도 같은 비용이 있는지 |

## 반증해야 할 경쟁 설명

1. 문제는 일반적인 사용자 비용이 아니라 특정 OpenSpec 버전/설정 또는 한 저장소 구조에만 해당할 수 있다.
2. 잘 작성된 AGENTS.md·프로젝트 지침, OpenSpec Store/workset, 로컬 변경 분할만으로 충분히 해결될 수 있다.
3. 거짓양성은 게이트 설계만의 문제가 아니며, 제보자는 위험 허용 수준이나 설정을 다르게 선택했을 수 있다.
4. 도구 승인/토큰 사용 비용이 모델·호스트의 버전별 일시 문제일 수 있다.
5. 공개 GitHub 이슈는 실패를 겪은 사람이 글을 쓸 선택 편향이 있다. 사건이 실제라고 해서 전체 사용자에게 반복된다는 뜻은 아니다.

## 현재 결론

U1~U4 중 반복성·피해 강도·시장 규모가 입증된 가설은 아직 없다. 후속 검증 대상으로 다중 저장소 작업 상태 정확성과 반복 MCP 승인 부담을 우선 남긴다. 기억 부족, 멀티에이전트 부족, 오케스트레이터 필요를 사용자 문제로 선언하지 않는다.
