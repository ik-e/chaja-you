## 경계와 담당자 협의

I2는 `PreparationPort.prepare(request)` 동기 함수다. 입력은 `source`, `profile`, `answers`이며 출력은 `ready`, `values`, `facts`, `issues`, `provenance`다. 결과가 준비 완료일 때 R03은 프로필 값 스키마를 다시 확인한다. 원문 Source는 보존하고 R03이 정규화한 ResolvedAnswer를 받아 현재 등록 준비에 반영한다.

- R03에는 사용자 답변과 원본 사실이 충돌할 때 어떤 `field`와 `conflict` 이슈를 반환해야 `FACT_CONFLICT`로 연결되는지, 모델 중단과 안전 오류의 전달 형태 및 제한 시간을 예제와 함께 확인한다.
- R01의 PR #44 D05는 동기 포트 유지, DB 트랜잭션 밖의 제한된 호출, 늦은 결과 무시를 제안한다. PR은 아직 열려 있다. timeout·revision 및 모델 취소 방식은 확정되지 않았다.
- R03의 독립 서버는 `MODEL_UNAVAILABLE`과 일반 예외를 준비 차단 이슈로 저장하며 스키마가 잘못된 응답은 `RUNTIME_ERROR`로 판정한다. 특정 예외와 응답 지연의 실제 연결은 R02·R03이 공동 시험한다.
- R04·R05와 모의 프로필의 필수 항목과 오류 표시를 맞춘다. 크몽 3단계는 현재 모의 프로필에 한정한다. 단일 모드는 R02 화면에서 가능한 것으로 확인했지만 이 mock 프로필에 없는 상태이며 임의로 빈 패키지를 채우지 않는다. 숨고 mock은 서비스 설정이며 견적·결제를 다루지 않는다.

## 구현 순서

1. 고정 스키마와 Profile 필드를 공통 `SchemaCatalog`로 검증한다. 유효하지 않은 입력이나 허용되지 않은 profile에는 안전한 오류를 반환한다.
2. 모델 호출 인터페이스를 담당 영역에 두고 합성 원문에서 사실 후보·근거 locator·질문을 받는다. 원문에 없는 가격, 단위, VAT, 제공 범위는 자동 확정하지 않는다. provider 선택·접근 환경·비용·의존성은 확인 후 기록한다.
3. 사실과 출처를 검증하고 승인 값과 선택한 프로필 필드를 대조한다. 누락과 출처 불명, 서로 다른 가격·단위·VAT는 issue로 남기며 blocking issue가 있으면 `ready=false`다. 계산·변환은 근거와 단위가 명확하고 프로필 규칙에 맞을 때만 후보로 낸다.
4. 정규화된 사용자 답변을 적용한 뒤 재검사한다. 원본 사실과의 충돌을 숨기거나 임의로 한쪽을 선택하지 않는다. 사실 수정과 현재 요청에만 적용되는 선택을 CS-02에 맞춰 구별한다.
5. 합성 후보로 정상·누락·충돌·잘못된 모델 응답·모델 불가·timeout·늦은 결과·사용자 재답변을 시험한다. 실제 모델 시험은 승인된 환경과 합성 자료에서 별도 수행한다.
6. 공통 계약, R03 연결 및 AT-01·T5-08·T6-02 제품 시험은 동일한 후보·계약·입력에서 별도로 관측한다. 준비 모듈의 단독 통과와 전체 제품 통과를 구별한다.

## 공동 기준 적용 및 준비 흐름 보완 · 2026-11-25

- PR #44가 병합된 main `16e9d95107ef8ffac8c58e3b8fd30643044e7658`을 병합했다. D05 협의는 필요하지만 기준 적용 자체를 추가 승인 대기하지 않는다. 이전 절의 'PR 열림', '모든 후보 재확인', '크몽 전체 차단'은 당시 이력이다.
- 원문에 정확히 존재하고 값과 인용이 일치하는 자유 텍스트 네 항목(title, description, process, preparation)만 direct 사실·provenance와 함께 준비 값에 넣는다. 실제 문맥과 항목의 의미가 맞는지는 최종 검토와 실제 모델 평가가 필요하다. 원문 불일치, 문맥이 추가된 인용, 선택지·복합 데이터는 자동 확정하지 않는다. 최종 승인 단계는 그대로다.
- 사용자가 명시적으로 VAT 포함 계약 필드를 채운 정상 3개 패키지는 더 이상 무조건 재확인하지 않는다. 가격·시간 등 추출된 원문 후보가 입력과 다르면 충돌 차단한다. 인용에 VAT 별도/불포함/제외가 명시돼 있어도 VAT 포함 입력과 충돌 처리한다. 원문만 있는 가격은 패키지나 VAT 포함 값으로 자동 생성하지 않는다. 모델이 원문이나 VAT 표현을 인용하지 못한 경우의 탐지 성능은 미검증이며 실제 모델 평가가 필요하다.
- R03의 실제 Coordinator와 합성 I2를 연결해 원문 제목의 준비, 원문과 상충하는 수정의 `FACT_CONFLICT` 및 기존 revision 보존, 모델 실패 저장을 확인했다. 부모 패키지 답변 뒤 중첩 수정 시 다른 패키지 정보 보존 문제는 재현 상태이며 `unsupported`와 `ready=false`로 멈춘다. R03과 D05 처리 방식을 협의해야 한다.
- R01 방향은 OpenAI API 후보 모델을 같은 합성 입력·품질 기준으로 비교하고 비용을 평가하는 것이다. R01이 실험 접근·예산을 준비 중이므로 실제 호출과 모델 선택은 아직 하지 않았다. OpenAI 응답·거절 시험은 가짜 HTTP다. 동기 호출 제한시간·늦은 revision 폐기는 R03과 실제 연결 검증 전이다.

## D05 R03 협의 제안 · 2026-11-25

- 목표: H5 부분 수정에도 삭제 의도가 없는 패키지와 기존 facts/provenance를 보존하고 원본 충돌·오류 시 기존 revision을 잃지 않는다. 제안이며 R03 합의·실제 결합 전이다.
- 권장: 기존 I2 계약을 유지하고 R03이 기존 `/packages` 부모 답변과 새 leaf 답변을 함께 I2에 전달한다. R02는 복사한 부모에 leaf만 적용하고 전체 결과를 반환한다. `/packages`가 없는 leaf는 추측하지 않고 `unsupported` blocking으로 반환한다. R03은 지원 불가한 부분 수정 또는 패키지 누락을 기존 revision/preparation/answers를 유지하며 거부하는 방식을 검토한다. 변경이 어렵다면 H5에서 기존 부모를 정확히 보존한 전체 `/packages` 답변으로 정규화하는 대안을 비교한다.
- 사례 A: 부모 패키지 3개가 있고 `/packages/0/amount_vat_included_krw`만 수정하면 나머지 2개와 수정하지 않은 필드, facts/provenance가 그대로인지 검증한다. 사례 B: 원문과 수정 금액이 충돌하면 해당 leaf `conflict`·blocking을 반환하고 R03은 `FACT_CONFLICT`로 매핑해 이전 revision을 유지한다. 부모가 없는 leaf도 조용히 일부만 저장하지 않는다.
- timeout/동시성 권장: 30초는 현재 추출기의 시험 설정으로만 제안하고 운영값은 측정 후 정한다. R02는 timeout을 `MODEL_UNAVAILABLE`로 안전하게 전달한다. R03은 호출 시작 revision을 기준으로 종료 후 CAS해 오래된 결과를 버린다. H4 신규 요청의 model_unavailable 이슈 저장과 H5 실패 시 이전 preparation/answers 보존을 어떻게 함께 표현할지는 R03과 실제 응답·저장 예제로 확정한다. timeout이 원격 모델 작업 자체를 취소한다고 가정하지 않는다.
- 완료 기준: 두 담당 구현을 실제로 연결한 정상 수정, 충돌, 부모 부재, timeout, 다른 revision의 선행 저장, 늦은 결과 미반영 시험과 커밋·재현 명령을 함께 기록한다. 현행 mock-only·공통 스키마를 바꾸지 않으며, 변경이 불가피할 때만 R01에 근거와 영향을 전달한다.

## R01 리뷰 반영 및 자기 성찰 후보 · 2026-11-25

- 지원하지 않는 모델 필드가 있으면 임의 내용을 출력하지 않고 `unsupported`로 차단하되, 정상 후보의 사실·근거는 보존한다. 원문 숫자가 같은 것만으로 금액·분·회·일을 동일시하지 않도록 숫자 바로 옆 단위를 요구한다. 단위가 없거나 다르면 원문 후보를 확정하지 않고 차단한다. 라벨 문맥과 VAT 별도/가격 대안에 대한 합성 반례를 보강했으며 모든 자연어 표현을 포괄한다고 주장하지 않는다.
- `BoundedReflectionExtractor`는 명시 주입되는 **미채택 실험 후보**다. 근거가 있는 후보의 지원 불가 필드만 교정기에 한 번 제안하고, 원래 후보의 값·인용을 추가·삭제·변경하는 수정은 받아들이지 않는다. 원본 누락·충돌은 보정하지 않으며 결과는 기존 PREP 검증을 다시 통과해야 한다. 실제 모델/API나 앱에는 자동 연결하지 않는다.
- 가짜 추출기·교정기 A/B에서 유효 근거 보존, 형식 교정 1회 제한, 값·인용 변경 거절, 원본 가격 충돌 보존, 모델 timeout 차단을 시험했다. 이는 합성 코드 시험이며 실제 모델 자기 성찰 A/B 결과나 DLV-06 완료가 아니다.
- 최신 main `089b8a4` 적용 후 `uv run --locked --all-groups --python 3.12 python dev.py test r02-preparation`에서 55개 및 bootstrap replay 통과, `dev.py check-changes r02-preparation --base 089b8a4` 통과. 실제 모델 재시험은 R01에 제안한 비용·사례 검토 전 실행하지 않았다.
