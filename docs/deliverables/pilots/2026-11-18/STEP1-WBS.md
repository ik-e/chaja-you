## 2. 일정 관리 규칙

1. **이전 구현 계획과 현재 두 트랙을 혼합하지 않는다.** 원래 일정은 역사적 기록이며 현재 Phase Intent가 우선한다.
2. W01/W04/W06의 과거 완료는 당시 작업만 뜻하며 실사용 검증·제출 접수나 새 제품 선정을 뜻하지 않는다.
3. 일정 표의 계획/실적/근거·대기 사유를 분리한다. 예상일 변경은 담당/사유/후속 영향과 함께 기록한다.
4. Step2 문서 작성, 열람 테스트, 대시보드 링크 등록, 제출완료 전환, 실제 접수를 별도 완료 상태로 둔다.
5. 이 시연본의 계획은 다른 팀원의 정본 TASK나 담당·마감에 영향을 주지 않는다. R05의 기술 검토 협조는 필요시 별도 소통한다.
6. 신규 제품 선정 후 설계→구현→시험→결과서·리허설과 실제 가용 시간까지 포함해 다시 WBS를 수립한다.

**제출 예외:** 강사 피드백의 WBS 화면 캡처/별도 제출 방식은 원본 양식 확인이 필요합니다. 현재 임의 방식으로 공식 완료 처리하지 않습니다.
