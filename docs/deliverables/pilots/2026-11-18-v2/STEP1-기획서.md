### 1.3 이전 찾아you 예시의 사용자 문제 (L26-2 현재 반영)

- **사용자 가설:** Android 앱 후보를 조건별로 빠르게 비교해야 하는 개인 사용자.
- **대표 상황:** PomoToki와 Focus To-Do에 대해 오프라인 타이머(필수)·무계정 사용(선호)을 확인한다.
- **현재 대안:** 일반 검색, 앱 공식 안내, 범용 LLM으로 정리, 직접 기기 시험. 이미 상당 부분 문제를 해결할 수 있다.
- **대안 이후 잔여 문제 가설:** 출처·앱 버전·기기 환경에 따라 확인 수준이 다를 때 조건별 충족/미충족/미확인을 근거와 시점까지 재구성하기 어렵다.
- **검증 결핍:** 실제 사용자 인터뷰, 대안 대비 동일 조건 비교, 비용/시간/판정 정확도 실측 없음. 위 내용은 해결되지 않은 사용자 Pain의 **입증이 아니라 조사 가설**이다.

### 1.4 제안 범위와 검증 방법 (L26-2·3 현재 반영)

| 이전 안의 사례 | 사용자 요청·중간 조건 | 확인 수준 | 11/21 이후 처리 |

| APP-A | 지정 앱 두 개의 필수·선호 조건별 비교; 불필요한 발굴 생략 | 문서·합성 구조 검토 | 새 주제에서 재사용 여부 결정 |
| APP-C | 중간 판정에 따른 후보 조사 추가/생략/보류 | 합성 분기 테스트. 현실의 두 후보 모두 미충족 시나리오는 미확인 | 도메인 전용 조건 자동 승계 금지 |

**재사용 후보:** request→task→attempt→source→evidence→verdict→report 관계, 실패·미확인·부분 결과 구분, 권한·키·호출 예산. **도메인 고유:** 앱 이름·조건·출처·테스트 문항·후속 분기. 구조 재사용도 실제 다른 주제에서 검증하기 전까지는 가설입니다.

### 1.5 기대 효과와 판단 기준

가장 강한 기존 대안(일반 검색/범용 AI/수작업 중 대표 과제에 적합한 한 가지)과 제안 흐름을 **동일 요청·자료·제약**으로 비교하는 작은 실험을 준비합니다. 조건별 판단 정확성, 근거 연결, 미확인 표시, 작업 수, 완료 시간과 사용 부담을 측정할 예정입니다. 아직 사용자가 실제로 시간을 절약했다거나 더 높은 성능을 얻었다는 결과는 **없습니다**.

### 1.6 주제 선정 이후 필요한 보완 (지금 완료 처리 금지)

선정한 제품의 정상·실패 사용자 흐름, 에이전트 역할·인계, 복구/검증, 기술 공급자 및 UI/배포 결정, 새로운 실측 기준은 그때 재검토합니다. 이는 산출물 L26의 '선정 후' 항목이며 현재 기능 확정을 요구하는 근거로 사용하지 않습니다.
