# V4 경량 AI 설계·실행 체계 — 변경 및 평가

> **상태: 2026-11-19 R01 검토용 · 실제 사용자/제품 가치 미검증.**
> 이전 [V3 상세 모델](../../planning-design-info-model.json)은 보존하고 운영 진입점만 경량화합니다. [V4 플레이북](../../AI-DESIGN-PLAYBOOK.md)을 먼저 읽고 필요한 세부사항에만 접근합니다.

## 1. 바꾼 이유

기존 17단계·28개 유형·202개 필드가 실제 매 작업의 절차가 되면 작업 준비·설명·교정 비용이 오히려 증가할 수 있습니다. 따라서 V4는 **한 사용자 흐름의 작은 결과를 실제 시험해 근거로 만드는 운영층**입니다. 정보 사전·대형 도식은 필요할 때만 펼칩니다.

- **유지:** 상위 Intent·Phase·중요 결정권자, 논리 선행관계, 용어·도메인/계약 정본, GitHub와 ADR·TASK·Run/Eval·제출물 프로젝션.
- **변경:** 7개 최소 정보(기존 자료의 참조로 충족 가능), S/M/H 설계 깊이, 대표 수직 슬라이스, AI의 직접 실행·검증·실패 수정 루프.
- **추가하지 않음:** 새 승인 회의, 전면 JSON 마이그레이션, 모든 TASK의 202개 필드 입력, 자동 Issue 배정, 무허가 데이터 수집, 미승인 제품 구현.

## 2. 예시 데이터와 검사 대상

[AI-SLICE-EXAMPLE.json](AI-SLICE-EXAMPLE.json)은 미선정 CAND-016에서 관측 정보의 'unknown' 분류를 보존하는 **비채택 예시**입니다. 예시는 사용자→요구→공통 상태 계약→컴포넌트→테스트와 권한·범위 경계를 참조합니다.

정본 모델·시범 정보·컴포넌트·공통 계약을 재사용하는 [Python 검사 코드](../../../../tools/check_ai_design_playbook.py)와 [GitHub Actions 워크플로](../../../../.github/workflows/ai-design-playbook-check.yml)를 추가했습니다.

검증 의도:
- 상위 요구/검증 ID, 컴포넌트/논리 실행 단위/인터페이스 ID가 실제 존재하는지 검사.
- 중복 저장된 상태·오류가 공통 계약과 일치하는지 확인.
- 제품 미채택·구현/시험 미실행 상태를 거짓으로 승격하지 못하도록 검사.
- 의도적 오류 5종(허위 실행 완료, 요구 ID 누락, 컴포넌트 누락, 미승인 채택, 도메인 계약 오류)을 탐지.

**테스트 상태:** 이 문서 작성 시 별도 Python 실행과 CI 최종 결과는 확인 전. CI 통과가 관측되면 해당 실행 URL/결과를 별도 기록하고, 테스트하지 않은 실제 사용성·생산성을 통과로 표시하지 않습니다.

## 3. 인간 개입 감소 검증은 별도 실험

기존 TASK 중 같은 수준의 작은 작업을 B0(기존 방식)과 B1(V4 정보 계약+실행 루프)로 비교할 것을 권장합니다. 사람의 **필수 승인**과 **반복 설명·교정**을 따로 기록하고, 수용 시험/실패·수정·실제 소요시간과 함께 봅니다.

AI가 더 많은 코드/문서를 생산했다는 사실은 성과가 아닙니다. 사용자 가치·품질·감독 부담의 변화에 대한 실제 근거가 있을 때만 평가합니다. 이 비교는 아직 `not_run`입니다.

## 4. 채택 권고

**V4를 기본 읽기/작업 선택 규칙의 제안으로 검토하고**, 실제 현장 적용에 앞서 팀의 유효한 Phase·TASK에서 시범 적용합니다. 기존 기록·승인 절차의 중복 강제 없이, 해당 작업에서 필요한 설계 정보만 선택하는 것이 성공 기준입니다.
