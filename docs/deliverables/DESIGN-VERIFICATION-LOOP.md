# 설계 정제·합성·변경 검증 루프

2026-11-24 · R01 요청에 따른 공통 설계 체계 보완. 기존 L0~L7 및 IT-00~27, 권한·Phase·TASK 기준 유지. 레슨 등록 V0.7에서 발견한 실제 결함(상위 재개 정책 누락, 호출/의존 불일치, 계승 입력 타입 누락, MVP 수용 기준 연결 누락)을 도입 근거로 삼는다. 검증 자체의 효용 일반화는 아직 실험 대상이다.

## 운영 규칙

설계 단계의 완료 조건을 "정보가 작성됨"에서 "현재 단계에서 확인할 수 있는 속성이 실제로 확인됨"으로 바꾼다. 초안과 병렬 조사는 막지 않는다. 기준선 확정 또는 의존하는 다음 작업으로 전달하기 전에 영향을 받는 작은 슬라이스만 검사한다.

1. 상위 목적·요구·제약과 이번 변경 범위를 참조한다.
2. 구체화하면서 상위 의무가 보존되어야 하는 속성(정제), 관련 계약을 결합할 때 성립해야 하는 속성(합성)을 선정한다.
3. 실제 정본을 읽어 코드로 판정할 수 있는 규칙을 실행한다. 의미적 판단은 별도 AI 리뷰, 현실 적합성은 실험으로 분리한다.
4. 실패는 가장 작은 범위에서 수정하고 다시 실행한다. 상위/동일/하위 정보의 영향 후보를 검토한다. 기존 DAG의 선행관계에 피드백 간선을 강제로 삽입하지 않는다.
5. 결과를 현재 원본 blob, 규칙 정의, 엔진/adapter 버전에 결합한다. 영향을 받은 근거는 재실행하고 무관한 근거는 유지한다.
6. 통과·실패·미실행·미확인을 구분하고 현재 단계의 전달 가능 여부를 판단한다. 정본/권한/제품 채택 상태를 자동 변경하지 않는다.

| 수준 | 실제로 실행할 수 있는 설계 검증 예 | 별도 검토/실험 |
|---|---|---|
| L0–L1 | 참조 출처·명시 제약 충돌 | 문제 실재·대안 잔여 손실 |
| L2 | 요구별 수용 조건/필수 의무 연결 | 요구 충분성·가치 가설 |
| L3 | 명시 불변식/권한 경계 반례 | 업무 의미·현실 제약 |
| L4 | 책임/호출/의존 그래프 및 순환 | 구조 대안·실현성 |
| L5 | 상위 가드 보존, 타입·상태·API/UI 교차 계약 | 형식화되지 않은 의미, 실제 동시성 |
| L6 | 필수 수용 조건/통합 시험 연결, 변경 근거 최신성 | 전체 슬라이스 의미 리뷰 |
| L7 | 전달 대상·버전·검증 결과 연결 | 실제 구현/제품/제출 결과 |

표는 규칙 후보이지 전 단계 일괄 강제 검사 목록이 아니다. S/M/H 및 현재 위험을 기준으로 선택한다. 필요한 규칙을 선택하지 않은 문제는 자동 판정으로 발견할 수 없다. 실제 시험 실행 전에는 제품 근거를 만들지 않는다.

## 실행 방법

`node tools/run_design_stage_verification.mjs --self-test`

`node tools/run_design_stage_verification.mjs <repository-relative-manifest.json>`

Manifest: sources는 정본 경로, rules는 id/revision/kind/method/stage/required/question/source_refs/policy_refs/checker, adapter는 도메인별 정본 해석 함수. 엔진은 공통 guard-presence, call/dependency graph, type-name resolution, selected coverage를 제공한다. adapter는 독립적인 판단 기준(상위 정책에서 도출한 의무)을 정본 검사 대상으로 연결한다. 의무 자체를 하위 설계에서 복사하면 누락 탐지가 무력화될 수 있다. 모든 판정에 영향을 주는 파일과 정책을 source_refs에 포함해야 한다. 외부 의존 코드가 추가되면 adapter fingerprint 범위를 확장해야 한다.

결과는 pass/fail/not_run/unknown. 단계 게이트는 blocked/review_required/declared_checks_pass. 마지막 상태는 선택한 필수 결정론적 규칙에 한정되며 단계 승인이나 의미적 완전성·제품 동작을 뜻하지 않는다. 리뷰/실험 근거는 별도 기록과 권한자 판단으로 연결하며 이 엔진은 이를 자동 통과시키지 않는다. 증거는 신뢰된 실행 경로에서 생성해야 하며 이 엔진은 임의의 위조 결과에 대한 서명 검증기가 아니다.

## 검증 및 종료

공통 엔진 합성 self-test 19/19. 레슨 등록의 V0.7→V0.8 역사적 재생에서 선택한 4개 규칙은 수정 전 4 fail, 수정 후 4 pass. 기존 결과를 변경된 원본에 적용하면 review_required. 알려진 결함을 대상으로 한 사후 재생이며 신규 프로젝트의 결함 탐지율, 작업 시간 감소, 사용자 개입 감소를 입증하지 않는다. 실사용 비교에서는 미리 규칙을 선정하고 신규 슬라이스의 결함 발견 시점, 재작업, 사람 개입, 실행 비용을 관측한다.

현재 단계에서 해결할 수 있는 충돌을 해소하고 선택한 필수 검사와 독립 리뷰가 충족되며 잔여 위험이 후속 확인과 연결되면 종료한다. 해결 가능한 국소 수정은 AI가 수행하되 범위/목표/권한/중대한 공통 계약·일정 변경은 기존 결정권자에게 올린다. 별도 승인 회의나 새 TASK를 자동 생성하지 않는다.
