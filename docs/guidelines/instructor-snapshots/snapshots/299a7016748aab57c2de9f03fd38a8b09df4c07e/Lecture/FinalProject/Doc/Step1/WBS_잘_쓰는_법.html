WHAT IS WBS

WBS는 해야 할 일 전체의 지도입니다

W

Work

프로젝트가 만들어 내야 할 결과물과 그에 필요한 일

B

Breakdown

관리할 수 있는 크기가 될 때까지 쪼갠다

S

위에서 아래로 이어지는 계층 구조로 정리한다

WHY WBS

WBS가 있으면 달라지는 네 가지

WBS VS OTHERS

할 일 목록, 간트 차트와 무엇이 다른가

도구답하는 질문한계
할 일 목록지금 뭘 해야 하지?전체 범위와 구조가 안 보인다

RULE #1

100% 규칙 — 빠짐없이, 겹침없이

하위 항목을 모두 더하면 정확히 상위 항목 전체가 되어야 합니다.

  • 빠진 일이 있으면 → 계획에 없는 일이 나중에 터진다
  • 겹치는 일이 있으면 → 두 사람이 같은 일을 하거나 아무도 안 한다
  • 범위 밖의 일이 있으면 → 그 일은 WBS에서 지운다

2.2 DB 스키마

RULE #2

위는 결과물(명사), 아래는 작업(동사)

상위 레벨 = 결과물

끝났을 때 손에 쥐는 것

인증 기능
API 설계 문서
배포 환경

최하위 레벨 = 작업

그 결과물을 만들기 위해 하는 일

엔드포인트 목록 작성
Dockerfile 작성
