## 1. 목적·범위 및 로직

PREP의 verify→correct→verify 후보가 근거 있는 후보 오류를 탐지·보정하고 정보 자체가 부족할 때 질문으로 종료하는지 검증. 단순 timeout 재시도/외부 실행 복구는 자기 성찰 성과에 포함하지 않는다. 보정 최대 1회는 후보이며 R02 확인 후 고정.

## 2. 환경·조건·합격 기준

A는 자기 성찰 보정 비활성(결정적 검사·사용자 보호 유지), B는 활성. 동일 실제 모델·입력·프롬프트·설정·검증 규칙을 비교한다. 근거 없는 가격/시간/VAT/권리/승인 생성 0건, 실패한 schema/업무 검증값을 ready로 반환 0건, 모든 실행의 상한·종료 사유 기록. 정답·지표·상한과 fixture SHA, code/model/config는 실행 전 고정. 구체 품질 수치 기준·timeout·모델 선택은 R02/R01 확인 필요. T5-08 실제 모델·AT-01·T6-02와 연계하되 전체 제품 gate 통과로 간주하지 않는다.

## 4. 추적 증빙

TC/run ID, commit, 모델/config, 입력 fixture SHA, 노드, 검사 code·근거 ID, 수정 요약, 보정 횟수, 최종 verdict, token/time/cost 및 로그 링크를 기록. 비공개 추론 원문/자격증명/민감정보 금지. [초기 모델 비교 기록(PR52)](https://github.com/ik-e/chaja-you/pull/52)은 자기 성찰 A/B 시험이 아니므로 본 결과서의 실행으로 계산하지 않는다.

## 7. 실행 추적 샘플

실제 로그 없음. 실행 후 SC-02의 A/B 노드 순서, State 변화, 오류와 보정, 최종 결과를 동일 TC/run ID로 연결한다. 합성 기대 흐름을 실제 실행 추적으로 대체하지 않는다.

## 8. 결과 요약

실제 모델 초기 합성 비교 각 5사례(3/5·4/5, 양 모델 가격 충돌 오류)는 담당자 보고이며 모델 선정·전체 비용 미확정. 자기 성찰 A/B 및 보정 시험 0건, 통과율·비용 산정 불가. 공통 CI/R03 mock 회귀를 자기 성찰 시험으로 합산하지 않는다. R02 PLAN·실제 loop/모델·실행 명령 및 근거 확보 후 작성. 12/4 결과서의 실측/재현 증빙 및 공식 제출 상태는 별도 확인한다.
