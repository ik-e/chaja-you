## 1. 핵심 제품 방향

**찾아you는 사용자가 처음부터 목적을 완벽하게 설명하지 못해도 의도에 대한 불확실성을 관리하며 필요한 질문을 통해 목표를 함께 구체화하고, 그 목적에 필요한 정보를 조사·검증·구축한 뒤, 변화하는 조건에 맞춰 판단 근거와 후속 작업을 갱신하는 시스템을 지향한다.**

단순 검색 속도나 멀티에이전트 사용 자체보다, **의도 정렬 → 필요한 정보 식별 → 근거 기반 판단 상태 구축 → 변경 영향·증분 재검토**를 사용자 가치의 중심에 둔다.

이는 프론티어 모델이 본질적으로 수행할 수 없는 기능을 주장하는 것이 아니다. 기존 ChatGPT·Deep Research·Work 및 다른 도구를 잘 사용하는 방식과 같은 과제에서 비교해 추가 가치를 입증해야 하는 가설이다.

## 2. 타겟 사용자

### 2.1 우선 검증 타겟

**제한된 일정·인력·예산 안에서 기술 프로젝트의 설계와 기술 선택을 책임지는 소규모 AI·소프트웨어 개발팀 리더.**

대표 상황:
- 사용할 프레임워크·오케스트레이터·아키텍처를 결정해야 한다.
- 무엇을 직접 구현하고 기존 도구를 재사용할지 판단해야 한다.
- 중요한 미확인 사항과 최소 검증 실험을 찾아야 한다.
- 프로젝트 인원·일정·요구사항이 바뀐 뒤 기존 결정을 재검토해야 한다.
- AI 조사 결과를 기술 결정, 설계 문서, 실제 작업으로 연결해야 한다.

### 2.2 타겟 경계

개인 개발자·일반 기획자·전문 리서치 조직은 인접 집단이다. 동일한 문제의 강도와 해결 방식을 공유한다고 가정하지 않는다.

**근거 수준:** R01의 직접 경험을 문제 발견의 출발점으로 사용한다. 다른 개발팀 리더의 이용 행동, 문제 빈도·강도, 반복 사용 의사는 관찰 전이다.

위 표 전체는 **현재 사용자 가치 가설**이며, 다른 사용자에게 실증되었다는 의미가 아니다.

## 4. 문제 정의

> 복잡한 기술 프로젝트의 기획·설계를 책임지는 사용자는 자신의 목표와 제약, 필요한 정보 및 판단 기준을 처음부터 완전하게 표현하기 어렵고, 제한된 자원 안에서 AI와 검색 도구를 활용하면서도 의도를 반복적으로 교정하고 조사·검증을 설계하며, 근거와 결정을 연결하고 변화에 따라 재검토하는 작업을 직접 관리해야 할 수 있다.

**해결하려는 문제:** 사용자가 모든 요청을 정교하게 작성하거나 조사를 직접 지휘하지 않아도, 현재 이해한 의도와 그 불확실성을 바탕으로 결정에 필요한 정보를 확보·구축하고 조건 변화 시 필요한 판단만 재검토하도록 돕는 것.

시스템은 사용자의 의도를 '읽어낸다'거나 최종 결정을 자동으로 확정한다고 주장하지 않는다. 중요한 추론은 사용자가 확인·수정할 수 있어야 한다.

## 5. 기존 대안과 차별화 가설

| 대안 | 이미 해결할 수 있는 부분 | 동일 과제로 검증할 차이 |
| --- | --- | --- |
| 일반 검색·공식 기술 문서 | 기술 사실·예제·사양 제공 | 사용자가 조사 질문과 판단 구조를 직접 조합하는 부담 |
| ChatGPT 등 프론티어 모델 | 질문, 비교, 계획, 피드백 반영, 문서 작성 | 의도 가설·판단 근거·결정 변경의 추적이 추가로 도움이 되는가 |
| Deep Research·ChatGPT Work 등 조사·작업형 AI | 다단계 조사, 출처 보고서, 연결된 자료 기반 작업 | 전용 결정 상태와 변경 영향 관리가 실제 성과를 개선하는가 |
| GitHub·Notion·결정 기록 문서 | 작업·문서·결정 이력 보존 | 리서치 주장·근거·재검토 조건을 연결하는 수고를 줄일 수 있는가 |

기존 도구의 기능이 부족하다고 **선언하지 않는다**. 잘 작성한 프롬프트, 실제 이용 가능한 도구·연결 자료를 포함한 강한 기준선과 비교한다.

**차별화 가설:** 개별 답변이나 보고서를 넘어, 사용자와 확인한 의도·추론된 가정·결정·근거·변경 의존성을 지속 상태로 관리하면 같은 목표를 수행할 때 판단 누락·재작업·사용자 교정 부담을 줄일 수 있다.

## 6. 핵심 피처

### F0. 상호작용적 의도 도출과 정렬

명시된 목표·제약, AI가 추론한 의도, 확인되지 않은 중요한 가정, 사용자가 승인한 기준을 구분한다. **현재 결정을 바꿀 수 있는 불확실성**을 우선 질문한다.

질문을 남발하지 않으며, 위험이 작고 되돌릴 수 있는 부분은 가정과 한계를 표시한 채 진행할 수 있다. 새 피드백으로 의도 가설이 바뀌면 조사 계획과 판단 상태에 영향을 연결한다.

- 대응: P0, P1, P3
- 검증: 모호한 요청에서 중요한 조건 발견률, 불필요한 질문 수, 사용자의 정정·교정 횟수
- 한계: 의도 추론은 AI 정렬의 전체 문제가 아니며, 사실성·권한·안전·상충 가치 문제를 대체하지 않는다.

### F1. 목적·의사결정 중심 조사 설계

목표와 승인된 제약을 바탕으로 결정 항목, 비교 기준, 검증할 가정, 필요한 정보, 우선 조사 질문을 구성한다.

- 대응: P1, P3
- 출력: 결정 질문, 필수/선호 기준, 미확인 정보, 조사 우선순위

### F2. 근거가 연결된 판단 상태 구축

대상·조건·주장·근거·출처·확인 시점·검증 상태·현재 판단과 재검토 조건을 연결한다. 결정할 수 있는 것, 결정할 수 없는 것, 다음 확인 작업을 구분해 보여준다.

- 대응: P2, P5
- 출력: 대안 비교, 근거 추적, 미확인·충돌·실패, 잠정 선택과 사용자 확인 사항
- 원칙: AI가 추론한 의도를 사람의 확정된 의도로 자동 승격하지 않는다.

### F3. 변경 영향과 선택적 재조사

새로운 조건·피드백·근거가 발생하면 관련 결정과 가정을 찾아 기존 자료의 유효성·갱신 필요성을 구분한다. 다시 조사해야 할 항목과 후속 작업 수정 후보를 제시한다.

- 대응: P0, P4, P5
- 출력: 변경 전·후 조건, 영향받은 결정, 유지 가능한 근거, 추가 검증, 설계·TASK 수정 후보
- 원칙: 외부 문서·작업의 실제 변경은 권한과 사용자 승인 범위 안에서 수행한다.

### F4. 동적 조사 작업과 자원 제어 — 기술 가설

도메인과 중간 결과에 따라 조사 작업을 선택·추가·생략·보류하며 시간·호출·비용과 종료 이유를 기록한다. 초기에는 정보 가치를 정확히 최적화한다고 주장하지 않는다.

- 대응: P1, P3
- 검증: 고정 흐름과 같은 품질·근거 조건에서 누락, 실제 자원 사용, 불필요한 작업을 비교

**우선순위:** F0~F3는 제품 가치 가설. F4는 그 가치를 지원해야 하는 기술 가설이며, 모두 완성하는 것을 첫 MVP 필수 조건으로 삼지 않는다.

## 7. 대표 시나리오

### A. 의도가 불완전한 최초 요청

사용자: "5명이 8주 동안 만드는 리서치 AI에 적합한 오케스트레이터를 결정하고 싶어."

1. 시스템은 사용자가 명시한 목표·제약과 AI가 **추론**한 기준을 분리한다.
2. 예를 들어 재시작·복구, 학습 비용, 팀 숙련도 중 결정을 바꿀 수 있는 누락 조건을 필요에 따라 확인한다.
3. 순수 Python·LangGraph 등의 대안을 어떤 기준으로 비교할지 사용자와 맞춘다.
4. 공식 문서·작은 재현 실험에서 필요한 근거를 확보하고 미확인을 남긴다.
5. 잠정 판단, 근거, 후속 실험, 결정 재검토 조건을 출력한다.

### B. 의도·제약이 나중에 변경되는 후속 요청

사용자: "처음 설명하지 않았는데 우리 팀은 LangGraph 경험이 없고, 인원도 3명으로 줄었어."

1. 새 정보를 사용자가 명시한 제약으로 기록한다.
2. 기존 의도 가설·비교 기준·결정 중 영향을 받는 항목을 식별한다.
3. 유효한 기존 자료는 보존하고 결정에 중요한 불확실성만 추가로 확인한다.
4. 기존 판단의 유지·변경·보류 이유와 후속 작업의 영향을 제시한다.

이 시나리오의 성공 조건은 '처음부터 숨은 의도를 맞히는 것'이 아니라 **새로운 사용자 의도를 정확히 반영하고 이전 가정을 수정하는 것**이다.

## 8. 첫 MVP 및 기존 앱 PoC와의 관계

**첫 제품 가치 검증 후보:** 한 개의 소규모 개발팀 기술 선택 과제 + 한 번의 중요한 제약·의도 변경.

Must 후보:
1. 모호한 기술 선택 요청에서 명시/추론/미확인 의도를 구분하고 중요한 질문만 한다.
2. 결정 기준·필요 정보·검증 질문을 구조화한다.
3. 허용된 출처의 근거를 결정·미확인 사항에 연결해 판단 상태를 만든다.
4. 제약 한 가지를 변경하여 영향받은 결정과 재확인 항목을 식별한다.
5. 사용자의 최종 판단에 필요한 차이·다음 실험을 제시한다.

**이번 최소 가치 검증에서 완성하지 않을 것:** 자유로운 에이전트 팀 생성, 다중 도메인 범용 엔진, 복잡한 비용 최적화, 대규모 장기 기억·RAG, 전체 저장소 자동 변경, 독립적인 최종 결정 자동화.

기존 APP-A·C는 조건·근거·분기 기술 검증 사례로서 유지한다. 실제 제품의 첫 도메인·Must 범위를 **이 문서만으로 변경하지 않는다**. 두 시나리오의 사용자 가치·기술적 구현 비용을 TASK-015에서 비교한 후 별도 R01 결정을 요구한다.

## 10. 위험·경계

- **의도 추론의 과신:** AI가 추정한 목표와 사용자가 확인한 목표를 명확히 구분한다.
- **질문 과잉:** 매 단계 확인받지 않고 결정 영향이 큰 미확인 사항을 우선 확인한다.
- **기존 AI와 중복:** 기존 도구가 이미 충분하면 전용 구현의 가치가 약할 수 있음을 인정한다.
- **가치 가설의 편향:** R01 개인 경험은 유효한 출발점이지만 일반 사용자 수요의 증거가 아니다.
- **판단 책임:** 기술 선택의 자동 정답이나 성공을 보장하지 않고 사용자가 최종 승인한다.
- **자료 접근·이용:** 공개 열람과 자동 수집·저장·재사용 권한을 구분하고 무단 크롤링에 의존하지 않는다.
- **범위 확대:** 의도 도출·상태 유지·재조사를 전부 범용 구현으로 고정하지 않고 최소 실험에서 확인한다.
