## 0. 핵심 결론

**추가 프레임워크 구현보다 이미 제공되는 실행 도구를 재사용하는 것이 합리적이다.** 상위 에이전트가 하위 작업을 동적으로 위임·통합하는 구조, 체크포인트와 인간 개입, 실행 추적, 최대 실행 횟수 등은 이미 공식 문서에 설명되어 있다 [C01~C04].

반면 **기존 지능·도구·기억을 연결했을 때 사용자가 실제로 덜 개입해도 되는지**는 공개 문서만으로 입증되지 않는다. 오히려 여러 에이전트의 정보 손실, 비용 증가, 무효화된 기억의 재사용 같은 실패 가능성이 보고되어 있다 [C05~C09].

따라서 R4.0의 상위 `P=(X,Y,E,C)` 및 입출력 분해는 **문제 기술을 위한 프로젝트 설계 방식**으로 보존하되 이를 새로운 이론적 결과로 주장하지 않는다 [C10]. 그 구조를 해결하는 실제 소프트웨어는 **기존 LLM/SDK/도구를 활용하는 최소 실행 조합**부터 비교한다.

## 1. 조사 목표, 완료·추가 조사·중지 조건

이번 조사에서는 다음 **G1**을 적용했다.

- **목표:** R4 기술·제품 가설에 대응하는 1차 근거를 모으고, 이미 존재하는 기능·남은 실패 유형·실험에서 판별할 문제를 분리한 재사용 가능한 문서를 남긴다.
- **완료:** 중요한 사실 주장 8개 이상이 출처와 연결되고, 미검증 주장 및 한계가 명시되며, 기획자가 다음 작업을 선택할 수 있는 비교 실험을 제안하고, GitHub 기록을 재확인한다.
- **추가 탐색:** 결정에 영향을 미치는 주요 주장에 1차 근거가 없거나 서로 모순되거나, 공식 문서의 의미가 구현 판단에 결정적이면서 불명확할 때.
- **중지:** 위 완료 조건을 만족했거나, 접근·권한 한계로 확인할 수 없거나, 남은 쟁점이 실험 없이 자료만 더 읽어도 해결되지 않을 때.
- **사용자에게 되돌림:** 상위 목적·공식 도메인·MVP Must·승인 범위 변경처럼 사람 권위가 필요한 선택만.

**결정:** 이번 조사는 핵심 주장에 대해 공식 문서·학회/연구기관 자료를 확보했으므로 무제한 웹 탐색은 여기서 종료한다. 사용자 가치·실제 브라우저 멀티에이전트 동작은 **추가 문헌 조사보다 실행 실험이 필요한 미검증 사항**으로 남긴다.

### 출처·연구 수치의 해석 제한

- **Anthropic의 '15배 토큰'**은 Anthropic이 보고한 자사 시스템 분석의 수치이지 모든 멀티에이전트 실행의 보편적 상수가 아니다.
- **HiddenBench의 30.1% vs 80.7%**는 논문에서 지정한 분산 정보 실험/비교 조건에 대한 결과이지 찾아you 또는 Gemini–Claude 시스템의 예상 정확도가 아니다.
- **METR의 초기 19% 느려짐**은 2025년 특정 숙련 오픈소스 개발자·업무의 실험 결과다. METR은 2026년 후속 실험의 선택 편향으로 현재 효과 규모를 확정하기 어렵다고 밝혔다.
- 기술 문서가 기능을 제공한다는 것과 **이 저장소/이 브라우저에서 통합 실행했다**는 것은 명확히 구분한다.

## 3. 선행 기술과 찾아you의 책임 경계

**기존 기술을 사용:** LLM 호출·도구 실행·agent-as-tool/handoff·실행 트레이스·체크포인트·중단/재개·기본 메모리 저장.

**최소로 조립할 책임:** 상위 문제의 X/Y/E/C와 하위 입출력 연결을 도메인 사례에 맞게 표현, 사용자 목적에 대한 하위 결과 적합성 판단, 적용 범위가 있는 승인 판단의 연결, 새 의도/예외가 들어왔을 때 재구성, 사용자에게 필요한 정보만 제시.

**제품 가치의 독립 가설:** 사용자 스스로 ChatGPT+지침/기억을 관리할 때보다, 그 상태 조립의 부담을 실제로 줄이는가?

첫 실험에서 범용 Problem DAG 엔진, 범용 메모리 그래프, 독자 브라우저 자동화 플랫폼을 동시에 만들 필요는 없다. 웹 탭 사용은 **가능한 실행 경로 하나**이지 문제 정의의 필수 요소가 아니다.

## 4. 확인된 실패 위험과 시험해야 할 반례

1. **정보 손실:** Gemini에 제공한 중간 정보가 Claude 검토 입력으로 제대로 넘어가는가? 중요한 공통 전제만 전달하고 반대 근거를 누락하지 않는가? [C06]
2. **오래된 판단:** 사용자가 이전 기준을 철회·변경하면 다음 작업에서 과거 상태를 사용하지 않는가? [C07]
3. **협업 비용:** 에이전트 수/토큰/대기시간 증가가 사용자 검토 부담 감소를 압도하지 않는가? [C05, C09]
4. **과잉 자동화:** 어떤 입력에서는 단일 GPT/규칙 기반으로 충분한데도 멀티탭 대화를 강행하지 않는가? [C01, C05]
5. **브라우저 접속:** CDP로 실제 Edge 세션에 붙는지, 각 서비스 메시지를 허용된 방식으로 보낼 수 있는지, 응답 수집이 안정적인지 확인해야 한다. 이 조사는 **접속 실험이 아니다**. [C08]
6. **사람의 결정권:** 중요한 범위 변경, 권한 필요한 외부 쓰기, 사전 승인되지 않은 판단 승격은 시스템이 독단적으로 결정하지 않는다.

## 5. 최소 비교 실험 (제안·미실행)

| 비교 조건 | 방식 | 주로 비교할 것 |
| --- | --- | --- |
| **B1 강한 단일 AI** | 같은 정보와 잘 관리된 프로젝트 지침/기억을 가진 단일 GPT | 기본 결과 품질·인간 개입·시간 |
| **B2 단순 병렬 AI** | Gemini와 Claude에 독립 작업 위임 후 사용자가/단순 프로그램이 취합 | 모델 다양성과 병렬 효과 |
| **D0 상위 에이전트 협업** | 문제 분해→서로 다른 하위 작업→상대 결과 전달→교차 검토→재계획→통합 | 추가 조정 기능의 실질적 가치 |

**실제 기록:** 각 `Task`에 X/Y/E/C, `Dispatch`에 전송 여부, `Response`에 실제 결과, `Handoff`에 어떤 출력이 다음 입력으로 넘어갔는지, `Review`에 근거 있는 오류/충돌, `Outcome`에 최종 결과와 사용자 비용을 연결한다.

**완료 조건:** B1/B2/D0의 모든 필수 결과가 읽기 가능하고, 실제 실행·미실행을 구분했으며, 중요한 예외·누락·사용자 개입 시간과 재작업을 비교할 수 있어야 한다.

**중지 조건:** 두 AI 중 하나 접근 불가, 승인되지 않은 메시지 전송·외부 조치 필요, 응답/근거의 보존 실패, 정해진 작업 예산 초과 등. 이 경우 `blocked`/ `not_run`을 기록하고 성능의 성공/실패로 추정하지 않는다.

## 7. 다음 조사와 실행의 우선순위

**자료 추가 조사보다 실험이 먼저 필요한 문제**

- 실제 웹 AI 탭에 메시지 전송·응답 수집·교차 검증이 작동하는가? **미실행**
- B1 대비 D0가 추가 사용자 관리 비용을 줄이는가? **미실행**
- 사용자가 철회한 판단, 도메인이 다른 판단을 오적용하지 않는가? **미실행**
- 앱 리서치/프로젝트 검토 중 실제 타겟에게 더 강한 반복 문제가 어디인가? **미확인**

**추가 조사 재개 조건:** 구현 중 공식 SDK·브라우저 API의 기능/허용 범위가 설계 판단을 바꾸는 경우, 또는 실험에서 새로운 실패 유형이 관측되는 경우. 그때 관련 1차 자료만 제한적으로 추가 조사한다.

**사용자 결정 요청 조건:** 공식 MVP·도메인·제품 목표가 달라져야 할 충분한 근거가 나온 경우. 현재 문헌 조사 결과만으로 그 변경을 요청하지 않는다.
