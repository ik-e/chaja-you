# 새 시스템 비전 범위 조사 종합 (6개 AI 자문)

- 조사일: 2026-11-11
- 상태: R01의 갱신된 시스템 비전과 8주 MVP 범위 검토용. 팀 결정·확정 설계가 아니다.
- 조사 진행: ChatGPT, Claude, Perplexity, DeepSeek, Grok 답변 완료. Gemini는 기존 시스템 비교표 일부를 반환한 뒤 계속 생성 중이며, 완결 답변은 이번 종합의 근거로 사용하지 않았다.
- 원칙: AI가 제시한 기술·연구 수치와 출처는 원문 검증이 끝나기 전 기획서의 확정 사실로 인용하지 않는다.

## 1. 검토한 비전

사용자의 목적과 도메인에 맞춰 조사 작업을 구성하고, 인터넷 공개정보를 찾아 쓸 수 있는 형태로 정리한다. 출처 특성·정책·과거 조사 경험을 기록하고, 이를 다음 조사에 활용해 판단을 개선할 수 있는지 검증한다.

검토용 MVP 가설은 다음과 같다.

- 단일 도메인과 공개 자료만 다룬다.
- 전체 웹을 수집하지 않고, 작은 출처 메타정보 카탈로그를 수작업으로 만든다.
- 도메인 온톨로지는 우선 태그·용어집 수준으로 제한한다.
- 조사 정책을 짧고 명시적인 규칙으로 둔다.
- 중앙 워크플로가 고정된 조사 역할 2개를 조정한다.
- 과거 기록은 검토 후 보관하고, 비슷한 요청에 참고 제안으로 보여준다.

## 2. 여섯 AI의 자문 과업과 상태

|---|---|---|

| Grok | 범위·일정·리스크 반대검토 | 완료. 경험 재사용 효과가 가장 검증하기 어려운 가설이라고 지적. 작은 기준선 비교와 실패 모드 기록을 권고. 성능 수치는 원문 재검증이 필요하다고 표시. |

## 3. 자문을 종합한 결론

### 3.1 “인터넷 지도”는 출처 카탈로그로 정의한다

전체 웹 크롤링, 완전한 웹 지식 그래프, 자동 신뢰도 점수화는 MVP 범위에서 제외한다. 카탈로그가 담을 정보는 “이 출처를 어떤 질문에, 어떤 방식으로, 언제 확인해 쓸 수 있는가”에 필요한 항목으로 제한한다.

**필수 후보 필드**

- `source_id`, 이름, 진입 URL
- 발행 주체와 자료 유형 (예: 공공기관·논문·기업 공식 문서·언론)
- 도메인/주제 태그, 언어
- 출처가 뒷받침하기 적합한 정보 유형
- 발행일/콘텐츠 갱신일과 메타정보 갱신일의 구분
- 최종 확인일, 확인자, 접근 방식
- 이용약관·라이선스 확인 URL과 팀의 접근 정책 상태
- 출처를 등록한 이유 또는 신뢰 근거

**후순위 후보**: 신뢰도 점수, 자동 갱신 모니터, 자동 크롤러, 임베딩 기반 출처 선택, 세분화된 관계 그래프. URL 시드 20~30개 정도로 시작하고, 실제 작성에 걸린 시간과 누락률을 보고 규모를 정한다.

출처 접근과 관련해 `robots.txt`와 이용 약관/라이선스는 서로 다른 정보로 관리한다. `robots.txt` 준수만으로 콘텐츠 이용 권한이 확보됐다고 가정하지 않는다.

### 3.2 온톨로지는 태그·용어집으로 시작한다

완전한 온톨로지 구축이나 자동 관계 추론은 이번 범위에 넣지 않는다. 도메인 용어, 동의어, 자료 유형, 비교 기준을 사람이 검토할 수 있는 작은 목록으로 관리한다. 요청 정규화와 검색어 확장에 실제 도움이 되는지 확인된 뒤 관계를 추가한다.

### 3.3 기억은 검증된 사례만, 검색 결과는 제안으로 쓴다

과거 조사물을 전부 “경험”으로 취급하면 오류나 낡은 정보가 다음 조사로 전파될 수 있다. 기록은 다음 두 층으로 구분하는 것이 유용하다.

- **조사 실행 기록:** 요청, 계획, 검색어, 출처, 주장-근거 판정, 결과, 실패·수정 사유, 날짜와 도구 버전
- **재사용 가능한 경험:** 검토를 통과한 계획·출처·실패 회피 정보. 다음 요청에 참고로 제시하고 사용자가 수락·수정·거부

첫 구현은 JSON/SQLite 등 단순 저장과 도메인·질문 유형·키워드 검색이면 충분할 수 있다. 벡터 DB나 의미 검색이 꼭 필요한지 먼저 검증한다. 사람의 평가를 받지 않은 정보, 개인식별·민감 정보, 오래된 최신 사실은 자동으로 재사용하지 않는다.

### 3.4 정책은 작고 명시적으로 유지한다

초기 정책은 출처 우선순위, 1차·2차 자료 구분, 최신성 확인, 인용 기준, 충돌·미확인 표시, 접근 제한을 다루는 짧은 규칙으로 둔다. 각 조사 기록과 정책 버전을 연결해 어떤 원칙으로 결과가 나왔는지 추적할 수 있게 한다.

### 3.5 아키텍처는 통제 가능한 최소 흐름으로 제한한다

`요청 정규화 → 2~4개 하위 질문 계획 → 사용자 승인 → 고정 역할 2개의 조사 → 주장-출처 연결 및 검증 → 결과 제시 → 검토된 경험 저장`

역할은 우선 `검색·출처 수집`과 `근거 확인·통합`으로 고정한다. 호출 수, 재시도, 단계 수, 실행 시간을 제한하고, 제한 도달 시 미완료·미검증으로 끝낸다. 수치형 제한은 PoC 결과와 팀 예산에 따라 정한다.

## 4. 경험 재사용 가설을 검증하는 최소 실험

이번 자문에서 가장 중요한 합의는 **경험이 쌓이면 더 나아진다는 점은 아직 증명되지 않았다는 것**이다. 카탈로그와 기억을 만들었다는 사실만으로 효율 향상을 주장하지 않는다.

### 비교 조건 제안

- **A — 기본 검색:** 도메인 카탈로그와 과거 기록 없이 공개 웹 검색
- **B — 카탈로그:** 동일 검색 기능에 수작업 출처 메타정보를 제공
- **C — 카탈로그+경험:** B에 검토를 통과한 과거 조사 기록을 참고 제안으로 추가

시간이 부족하면 우선 B와 C를 비교해 기억 재사용 효과를 보고, 카탈로그의 별도 효과가 불분명할 때 A/B 비교를 추가한다. C에서는 기록을 사용자가 수락·거부할 수 있게 한다.

### 과제와 측정

같은 도메인에서 반복 가능한 공개 조사 과제 10~15개를 준비하고, 각 과제에 필요한 핵심 사실 체크리스트와 출처를 사전에 만든다. 조건별로 검색 예산과 모델을 같게 하고, 가능한 한 결과 평가자는 조건을 모르게 한다.

- **품질:** 체크리스트 핵심 정보 포함률, 핵심 주장과 근거의 부합 여부, 출처 최신성·유형 다양성, 미확인/충돌의 정확한 표시
- **효율:** 검색·열람 횟수, 첫 적절한 출처를 찾기까지의 시간, 총 조사 시간, 토큰/비용
- **기억의 부작용:** 무관한 기억 주입, 낡은 근거 재사용, 편향·오류 전파
- **카탈로그 비용:** 출처 선정·기록·갱신에 들어간 사람 시간

성공 임계치는 실험 전 팀이 정한다. 결과가 좋아지지 않거나 평가가 어려우면 기억 기능을 “참고 기록 검색”으로 한정하고 개선 효과를 주장하지 않는다. 작은 표본은 구현 방향을 보는 데만 쓰며 통계적 일반화로 표현하지 않는다.

## 5. 기획서에 반영할 문제·목표 초안

**문제정의 초안**

> 복잡한 온라인 조사는 여러 출처를 탐색하고 조건에 맞는 정보를 비교·정리한 뒤 중요한 사실을 원출처에서 다시 확인하는 과정이 반복된다. 생성형 AI가 탐색과 종합을 돕더라도 도메인 맥락에 맞는 출처를 찾고 주장과 근거를 확인하며 이전 조사에서 얻은 유용한 지식을 재사용하는 문제는 남는다. 본 프로젝트는 한 도메인에서 출처 메타정보와 검토된 조사 기록을 활용해 반복 조사에서 필요한 정보에 더 효율적이고 근거 있게 도달할 수 있는지 검증한다.

이 문장은 기획서 초안용 가설이며, 실제 사용자 인터뷰·비교 실험 이전에 “문제가 확인됐다”, “효율을 개선한다”라고 확정하지 않는다.

## 6. 위험과 범위 결정

| 위험/가정 | 초기 대응 |
|---|---|
| 도메인이 정해지지 않아 카탈로그가 추상적임 | 1차 자료가 공개되어 있고 반복 질문·정답 점검이 가능한 한 도메인을 먼저 선정 |
| 카탈로그 시드가 편향되거나 불완전함 | 누락 출처를 기록하고, 카탈로그 밖 일반 검색 경로를 유지 |
| 메타정보가 낡음 | 콘텐츠 발행/갱신일과 메타정보 수정일을 분리하고 확인일 기록 |
| 기억의 오류·낡은 지식 전파 | 검토 통과 기록만 재사용 후보로 등록, 출처·날짜 검증, 수락은 사용자 선택 |
| RAG/온톨로지 구현이 과해짐 | 키워드/태그 검색과 용어집부터 시작, 벡터 DB·학습은 실험으로 필요성이 확인될 때 검토 |
| 역할·워크플로 복잡도 증가 | 역할 2개 고정, 상한·종료 조건 명시, 단일 검색 흐름으로 축소 가능한 대안 유지 |
| “개선” 주장 검증 실패 | 경험 유무 비교 기준선을 먼저 만들고 긍정/부정 결과 모두 산출물로 기록 |

Claude는 인터넷 지도 메타정보 자체가 검색 횟수나 근거 품질을 개선한다고 직접 보여주는 연구를 찾지 못했다고 보고했다. 따라서 **카탈로그의 효용과 경험 재사용 효과는 공개 자료로 이미 입증된 성능이 아니라 이번 팀이 실험으로 확인해야 할 핵심 가설**이다. AI 답변이 제시한 정확도·비용·벤치마크 수치는 원문 검증 전 인용하지 않는다.
