# 2026-11-26 R02 일일 계획 · TASK-055

오늘은 강사가 레슨 모집 정보를 등록하고 관리할 때 어떤 행동을 해야 하고 어디에서 막히는지 정리한다. R02는 전체 사용자 스토리와 7개 플랫폼을 독립적으로 조사한다. R01은 R02·R04·R05의 결과를 비교해 서비스 범위를 결정하고 DB를 설계한다.

## 오늘 할 일

- [ ] **기획안 V1.2를 검토하고 의견을 공유한다.** 강사의 등록 경험에 비춰 타깃·고통·원인이 맞는지, 각 기능이 어떤 수고를 덜어 주는지 확인한다. 빠진 행동, 불필요한 기능, 기술·정책 제약은 해당 피처와 함께 적는다.
- [ ] **전체 피처를 사용자 행동으로 풀어 쓴다(A1).** F01~F29를 모두 검토하고 E01~E05는 조건부로 표시한다. 예를 들어 ‘강사가 반려된 모집 글의 가격을 수정한다’처럼 한 줄에 한 행동을 쓴다. 최초·재이용, 정상·오류·예외·반복 상황별로 선행 조건, 입력, 사용자가 확인하는 결과와 다음 행동을 연결한다. 내부 처리만 있는 피처에는 그 이유를 남긴다.
- [ ] **7개 플랫폼의 업무와 데이터를 비교한다(A2).** 크몽·탈잉·숨고·프람피·뮬·힙합플레이야·힙합LE 각각에서 신규·추가 등록, 조회, 수정, 갱신, 상태 확인, 오류·반려 대응을 검토한다. 업무별 지원 여부와 근거, 관리 대상과 소유자, 입력·반환·공개 필드, 가격·시간 단위, 인증·수정 조건, 결과를 확인할 방법을 기록한다.
- [ ] **스토리와 플랫폼 근거를 교차 확인한다(A3·A4).** 조사에서 발견한 행동·오류는 해당 스토리에 연결하고, 스토리에 필요한 값이 실제로 제공되는지도 확인한다. 직접 관찰·공식 문서·기존 조사·추론을 구분하고 출처 위치와 확인일을 적는다. 허용된 공개 자료로 확인할 수 없는 로그인 이후 절차는 미확인 사유와 재확인 방법을 남긴다.
- [ ] **R02 조사 결과를 인계한다(A5).** 지정 JSON에 결과를 채우고 전체 F/E 및 7개 플랫폼의 누락과 참조 ID를 점검한다. TASK-055 결과에 산출물 경로·커밋·점검 결과와 남은 질문을 기록한다. 서비스에 포함할지 판단이 필요한 행동은 근거와 함께 R01에게 전달한다. [R02 결과 양식과 공통 작업 계약](https://github.com/ik-e/chaja-you/tree/bf35475/docs/artifacts/planning/lesson-registration-20261126)
