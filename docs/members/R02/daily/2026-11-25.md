## 개발 계획 초안

1. **계약과 사례 매핑** — `PrepareInput`에서 원본·프로필·사용자 답변이 어떻게 전달되는지 확인하고 `Preparation`의 사실, 근거, 필드 값, 이슈와 준비 상태를 대조한다. 원문과 사용자 답변의 출처를 추적하고 원본 변경과 플랫폼별 선택을 구분한다.
2. **AI 후보 생성 경계** — 합성 입력으로 실제 모델이 사실 후보·근거·확인 질문을 반환하는 흐름을 설계한다. 모델·접속 방법·의존성·비용·timeout의 실제 값은 환경 확인 후 정한다. 모델이 없는 값을 만들어 내면 검증에서 차단한다.
3. **결정적 검증** — 가격 액수·통화/단위·회당 시간·횟수·기간·VAT를 각각 검토한다. 빠진 값은 질문하고 서로 다른 값은 충돌로 남긴다. 크몽과 숨고의 모의 프로필에 맞지 않는 값을 구분해 표시한다.
4. **실패와 재검사** — 준비에 필요한 정보가 없거나 충돌하면 `ready=false`가 유지되는지 확인한다. 모델 불가·형식 오류·timeout을 구분하고 늦게 도착한 결과가 새로운 사용자 답변을 덮어쓰지 않는 기준을 R03과 협의한다. 사용자 수정 후 관련 값을 다시 검증한다.
5. **독립 시험과 인계** — 담당 테스트 명령으로 정상·실패·미확인을 기록한다. 실제 모델을 이용한 합성 데이터 시험과 AT-01·T5-08·T6-02 제품 수용 시험은 각각 별도의 근거로 남긴다. 실행 방법·fixture·관측 결과·커밋을 기록해 12월 4일 인계 가능성을 확인한다.

세부 순서와 공수는 담당 PLAN 및 팀 조율 후 보완한다. 12월 4일은 인계 목표 후보이고, 12월 8일 mock MVP와 1월 4일 최종 목표의 세부 일정은 확정 전이다.
