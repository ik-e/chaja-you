## 핵심 판단

R03 최신안은 ECRM의 페이지 데이터 문구와 실제 화면에서의 표시 경로·인증 전 접근성 미확인을 구분하도록 이미 정정했다. 두나님의 시간 만료·재인증·재입력은 해당 이용 경로의 사후 자기보고 1건으로 유지한다. **접수 전에 자료를 준비하면 인증 후 입력 시간을 줄여 재인증·재입력을 줄일 수 있는지**는 별도 검증 가설이며, 실제 제한 시간·다른 저장/복원 경로·발생 빈도·개선 효과는 미확인이다.

## 보완 제안

1. **문제와 효과 분리:** 1페이지의 시간 만료·재입력은 두나님의 이용 경로 1건이며 일반 빈도는 미확인이라고 가까이 표시한다. 접수 전 준비가 인증 후 입력·첨부 시간과 재인증을 줄인다는 내용은 가설로 둔다.
2. **안내 탐색과 접수 항목 분리:** 비로그인 시작 화면에서 실제 안내를 찾는 경로·클릭·소요 시간·미발견 범위를 기록하고, 허용된 인증 후 화면과 비교한다. 실제 화면 일부의 신분증 첨부 안내가 인증 후에만 보인다고 단정하지 않는다.
3. **작업 시간 구간 분리:** 자료 찾기, 사전 정리, 인증 후 직접 입력·첨부, 검토·정정과 재인증·재입력을 각각 기록한다. 제안 MVP는 자료 자동 수집·ECRM 자동 입력/세션 대행을 포함하지 않는다.
4. **기존 대안과 반증:** 같은 가상 사건·정보·정정 과제로 공개 안내, 체크리스트, 충분히 지시한 LLM, 시제품을 비교한다. 사용자 사실 누락·왜곡·미확인 보존을 먼저 평가하고 이후 전체 시간·작업 횟수와 차이를 본다. 시제품이 기존 방식과 같거나 더 많은 수고가 들면 축소·보류한다.
5. **실제 여부 구분:** 현재 안내/체크리스트 A/B는 AI 작성 모의 예시이고 LLM 결과는 기존 가상 사례 재사용이다. 실제 사용자 비교나 서비스 우위 결과가 아니다. 가상 준비 품질과 실제 세션 만료·복원·개선 효과를 별도 검증한다.
6. **개인정보 경계:** R03 시제품에서 신분증 업로드를 받지 않는 범위와 실제 ECRM 접수 화면의 신분증 안내를 혼동하지 않는다. 허위 신고 제출, 타인 인증정보 수집, 무단 자동 접근 없이 검증한다.
