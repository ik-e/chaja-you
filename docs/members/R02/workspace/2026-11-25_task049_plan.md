# R02 작업 계획 · 등록 정보 준비와 AI 검증

2026-11-25 · TASK-049 초기 계획 · 후속 진행은 일지와 담당 PLAN 참조. 실제 구현·예상 공수는 확인 전

강사의 기존 레슨 정보를 AI가 근거와 함께 구조화하고, 크몽·숨고 모의 등록에 필요한 값의 누락과 충돌을 찾아 질문하도록 준비한다. R01이 채택한 공통 계약을 기준으로 계획하며, 12월 4일 인계는 후보 목표다.

## 디스코드에서 확인한 변화

- 11월 24일 팀은 크몽·탈잉·숨고의 입력 항목과 원격 브라우저를 조사했다. R05는 가상 계정과 모의 사이트에서 원격 로그인 후 같은 세션의 입력·첨부·저장 시험을 보고했다. 실제 플랫폼 로그인과 자동 제출은 검증하지 않았다.
- 11월 25일 팀장은 R02에 **등록 정보 준비·AI 구조화 및 검증**을 배정하고, 담당별 계획·구현 가능성·공수를 먼저 확인해 달라고 안내했다. 프로젝트 정본에서도 TASK-049로 확인된다.
- R05의 입력 문서에서 크몽 단일 패키지는 미확인이었으나 R02가 제공한 화면에서는 STANDARD만 선택할 수 있었다. 실제 프로필 반영 방식은 공통 계약과 모의 테스트 범위에서 확인하며 임의로 패키지를 추가하지 않는다.
- 모의 환경만 사용한다. 플랫폼 실제 로그인·등록, 실제 계정과 민감정보 사용은 별도 승인 전 범위에 포함되지 않는다.

## 진행 순서

1. **작업 계약을 읽는다.** TASK-049와 담당자 의도, 제품 작업 공간과 공통 계약 CS-01·CS-02, 데이터 스키마·두 플랫폼 프로필을 확인한다. 기존 R02 사용자 조사에서 가격·시간·횟수·추가 비용이 왜 중요한지 사례를 가져온다.
2. **담당 브랜치와 독립 환경을 확인한다.** 지정된 `r02/product-preparation`의 현재 상태와 `product/lesson-registration/` 실행 환경을 확인하고, 담당 경로 및 테스트 명령이 작동하는지 점검한다. 초기 환경 시험과 기능 완성을 별도로 기록한다.
3. **담당 PLAN.md를 작성한다.** `tests/modules/preparation/PLAN.md`에 입력과 출력, 실제 모델 접근 조건, 후보 사실의 근거 연결, 누락·충돌 질문, 오류 처리, 구현 순서와 검증 방법을 적는다. 예상 공수와 필요한 모델·실행 환경은 확인 후 제안한다.
4. **합성 예제로 확인 기준을 마련한다.** 원문에 가격이나 VAT 정보가 없으면 미확인으로 남기는 예, 서로 다른 가격이 있으면 충돌을 보존하는 예, 회당 시간·횟수·기간의 단위 차이, 크몽과 숨고의 서로 다른 필수 항목을 준비한다. 사용자 사례의 실제 금액과 사진은 시험 데이터로 복사하지 않는다.
5. **준비 모듈을 구현하고 시험한다.** `PrepareInput → Preparation` 경계에서 사실 후보·원문 근거·질문을 만들고 두 모의 프로필 기준으로 검사한다. 실제 모델 시험은 승인된 환경과 합성 자료를 사용하며 모델 접근이 불가하면 미확인으로 기록한다.
6. **인계 자료를 정리한다.** 정상·오류·미확인 사례의 입력·기대·관측·커밋과 재현 명령을 남긴다. AT-01, T5-08, T6-02는 제품 시험에서 따로 판정한다. 12월 4일 인계 가능 여부는 실제 공수와 팀 일정 확인 후 판단한다.

## 작업 위치와 확인할 사항

- 브랜치 `r02/product-preparation`
- 코드 `product/lesson-registration/src/lesson_registration/preparation/`
- 합성 자료 `product/lesson-registration/fixtures/source/`
- 계획과 시험 `product/lesson-registration/tests/modules/preparation/`
- 독립 시험은 `product/lesson-registration/`에서 `uv run --locked --python 3.12 python dev.py test r02-preparation`
- 공통 계약이나 다른 담당자의 코드를 변경해야 할 때는 영향과 대안을 정리해 관련 담당자와 협의한다.
- 팀장이 요청한 확인 사항은 작업 가능 여부, 예상 공수, 실제 모델 사용에 필요한 환경과 계정·비용 조건이다. 현시점에서 확보 여부는 미확인이다.

## 근거

디스코드에서 봇이 접근 가능한 채널·스레드를 11월 24일부터 25일 조회해 메시지 26건을 확인했다. 결과 제한이나 오류는 없었다. R05의 첨부 Markdown과 PDF도 확인했으며, 비공개 보관 스레드·음성 대화는 조회 대상에서 제외된다. 봇 조회 결과에는 사용자의 읽음 위치가 없으므로 이 26건이 정확한 미읽음 전체인지 확인할 수 없다.
