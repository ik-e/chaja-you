# 중고거래 피해 상담·신고 준비 지원 제안 요약

R03 두나 · 2026-11-16 · 멘토링용 개인 제안 · 가상 사례 비교 점검 전

**온라인 중고거래 피해를 의심하는 사람이 흩어진 거래 자료와 사건 경위를 정리하고, 빠진 내용을 확인해 상담·신고를 준비하도록 돕는 서비스입니다.**

원문을 다시 찾고 같은 내용을 반복 작성·수정하는 부담을 줄이는 것이 목표입니다.

## 1. Target — 대상 사용자

온라인 중고거래에서 돈을 보냈지만 물품을 받지 못해, 처음 상담·신고를 준비하면서 거래 경위와 자료 정리에 막힌 사람입니다.

## 2. Pain — 핵심 문제 가설

**흩어진 거래 자료를 다시 찾고 사건을 반복 정리하며, 누락·잘못된 설명을 걱정해 재확인·수정하는 부담**입니다. 어려운 법률·절차 용어는 작성 중 필요한 보조 문제로 둡니다.

## 3. 기존 대안

| 대안 | 확인 범위·비교할 역할 |
|---|---|
| [ECRM](https://ecrm.police.go.kr/minwon/main) | 공식 신고·상담, 피해 내용 작성 안내. 안내를 보고 사람이 직접 쓴 준비 결과와 비교 |
| [더치트 API](https://apidocs.thecheat.co.kr/docs/api-usage/api-search-plain/)·거래 플랫폼 | 특정 API의 등록 피해사례 조회. 플랫폼 신고·안전결제 상세 범위는 추가 확인 |
| [법률구조 안내](https://immigration.go.kr/moj/177/subview.do)·범용 LLM | 무료 상담 경로, 사건 요약·질문 생성 등의 대안 |

## 4. Remaining Pain — 무엇이 남는가

기존 안내·범용 LLM을 써도 **원문과 요약을 왕복 확인하고 수정 내용을 반복 반영하는 부담이 남는가**가 검증 질문입니다. 기존 서비스의 자동 구조화 전체 제공 여부와 설계 이유는 미확인입니다. 원진술 보존·책임·자료 접근 제약을 확인된 이유로 단정하지 않습니다.

## 5. Painkiller — 구체적인 동작

**시작 → 자유 입력 → 초안 확인·보완 → 결과 검토·복사**의 네 단계입니다. 핵심 피처는 ① 사건·자료 구조화 ② 누락 확인·수정 반영 ③ 필요한 용어 설명입니다.

| 가상 입력·중간 상태 | 시스템 동작 |
|---|---|
| ‘10만 원을 보냈는데 물건이 안 와요’ | 입력 문구와 연결된 금액·미수령 경위 정리. 날짜·상품·순서는 추정하지 않음 |
| 배송 약속일이 없음 | 필요한 질문 제시. ‘기억나지 않음’은 미확인으로 남기고 진행 |
| 금액을 수정함 | 관련 요약·자료 참조·질문을 재대조하고 변경 항목 재검토 표시 |

결과는 **사용자가 검토한 사건 요약·보유 자료 목록·미확인·상담 질문**입니다. 안내는 **“ECRM 온라인 접수 이후에는 원칙적으로 경찰서에 방문해 진술 등 후속 절차를 진행합니다”**로 표시합니다. 일부 사건의 출석 예외는 ECRM·담당 수사관 안내를 따릅니다. 본인 신분증·증빙자료·임시 접수번호를 준비하도록 안내하며, 신분증은 우리 서비스에서 받지 않습니다. [ECRM 절차 안내](https://ecrm.police.go.kr/minwon/main) (확인일: 2026-11-16) 보유 여부 응답을 자료 확인으로 취급하지 않으며, ‘판매자가 배송했다고 말함’과 ‘실제로 배송됨’을 구분합니다.

**차별화 가설:** 원래 입력·자료 연결과 주장·추측·미확인·충돌 상태를 보존하고 수정 결과를 일관되게 반영해 반복 작업을 줄입니다. **동적 구성 후보:** 계획·조정이 사건 정리·공식 안내 조사·결과 대조 작업을 선택하도록 설계합니다. 정리만 요청하면 조사를 생략하고, 충돌 시 확인 작업을 추가하며, 조사 실패 시 확인된 요약을 부분 결과로 제공합니다.

## 6. 미확인 — 검증과 범위

현재는 가상·비식별 자료로 **A: 구조화 품질 / B: 자료 찾기부터 입력·검토·수정까지의 수고**를 비교합니다. 범용 LLM에도 같은 자료와 원문 연결·미확인 보존·누락 확인·수정 반영 지시를 줍니다. 사실 누락·왜곡·임의 추정, 수정 부담·총시간을 각각 평가하며 왜곡 증가를 시간 단축으로 상쇄하지 않습니다. 멀티에이전트는 구현 후보입니다. 같은 모델·자료 접근·전체 예산 상한에서 단일·고정·동적 구성을 비교하고 사실 보존·수정 반영의 정확성과 실행 효율을 기준으로 채택 여부를 판단합니다. 고정 구성에도 같은 기준의 독립 작업 병렬 실행을 허용합니다. 사용자 금액 정정 후 연결 결과 갱신·기존 대조 재확인·무관한 조사 재실행 여부를 대표 시험으로 기록합니다. 미구현 방식은 수동 모의 점검으로 표시합니다.

**가상 점검은 실제 수요·현실의 준비 부담 감소를 입증하지 않습니다.** 실제 사용자 수요 확인·비교 실험·기술 효과 검증은 미실시입니다. 공식 신고 접수·범죄 판단은 제공하지 않으며 개인정보 처리와 법률 자문·문서 작성 경계는 전문 검토가 필요합니다. 팀 앱 MVP 변경을 확정한 제안이 아닙니다.

주제 변경은 부동산의 실제 상태는 현장 확인이 중요해 온라인 정리의 해결 범위가 불확실하다는 두나의 판단에서 출발했습니다. 새 안의 효과는 검증 대상입니다.
