# 기존 모집 글이 있는데도 등록이 어려웠던 이유

2026년 11월 24일까지 · 음악 레슨 등록 지원 서비스 기획 회고

크몽에 처음 레슨을 등록할 때 내게는 이미 뮬에 올리던 모집 글과 사진이 있었다. 더 많은 사람에게 레슨을 알리고 싶어서 크몽에도 올리기로 했지만, 기존 글을 그대로 붙여 넣기에는 작성해야 할 칸이 많았다. 서비스 소개와 제공 절차, 준비사항, 가격 정보까지 나눠 적어야 했다.

가장 막막했던 부분은 회차별 커리큘럼이었다. 평소에는 레슨생의 수준과 목표를 듣고 수업을 조율했는데, 1회차부터 4회차까지 무엇을 할지 미리 나눠 설명하려니 생각보다 시간이 오래 걸렸다. 결국 임시저장해 두고, 평소 수업에서 하던 내용을 회차별로 풀어 썼다.

## 평소 하던 일을 플랫폼의 언어로 바꾸기

요금제를 설명하는 방식도 달랐다. 다른 플랫폼에서는 기본 요금만 올리고 상담할 때 긴 수업을 추가로 안내했다. 크몽에는 실제로 운영하던 수업을 패키지로 나눠 보여줬다. 주 1회, 월 4회 기준으로 회당 90분은 월 25만 원, 3시간은 40만 원, 4시간 30분은 50만 원이었다.

3시간 수업은 원하는 레슨생이 꽤 있었다. 나에게도 연속으로 수업할 수 있고, 같은 시간을 채우기 위해 레슨생 한 명을 더 구하지 않아도 된다는 장점이 있었다. 4시간 30분 수업은 한 레슨생이 원해서 운영했다. 크몽에서 여러 패키지는 선택 사항이었고, 나는 이미 있던 요금제들을 그 양식에 맞춰 설명했다.

글을 수정하고 사진 크기를 맞춰 처음 제출하기까지는 기억으로 약 1~2시간이 걸렸다. 작성이 막혀 임시저장한 적도 있고, 개인정보가 들어간 설명 때문에 반려된 적도 있었다. 안내받은 부분을 지우고 다시 제출하는 데는 약 5~10분이 들었고, 수정한 글은 승인됐다. 당시 시간을 재지는 않았다. 가입·인증 시간과 임시저장·심사 대기 기간도 정확히 기억나지 않는다.

## 문장을 만드는 시간과 실제로 등록하는 시간

나중에는 ChatGPT로 모집 글을 다듬고 크몽 항목에 맞는 문구를 작성해 봤다. 무엇을 쓸지 생각하는 시간은 줄었다. 그래도 가격과 수업 시간·횟수가 맞는지 확인하고, 각 칸에 내용을 복사하고, 사진을 붙이고, 제출하는 일은 직접 해야 했다.

AI가 제안한 내용 중에는 내가 제공하지 않는 조건도 있었다. 별도 음원 발매에 추가 비용이 없다는 내용과 일정 변경을 최소 이틀 전에 해야 한다는 조건은 실제 운영과 달라 직접 삭제했다. 나는 수업 시간 안에서 진행하는 녹음과 기본 믹싱·마스터링은 수업료에 포함하지만, 별도 음원 제작이나 발매는 범위를 보고 비용을 상담한다. 일정 변경도 서로 가능한 시간을 맞춰 조율한다.

그래서 내가 맡기고 싶은 서비스의 흐름을 정리했다. 기존 레슨 조건과 사진을 제공하고, 플랫폼별 초안을 확인한다. 가격·시간·횟수·추가 비용과 실제 제공 범위를 승인한 다음에는 화면을 계속 보지 않아도 등록과 제출이 진행되면 좋겠다. 입력할 수 없는 조건이 생기면 임의로 바꾸지 말고 내게 물어보고, 끝난 뒤에는 심사 중인지 게시됐는지와 필요한 조치를 알려주기를 바란다.

## 강사가 직접 쓰는 시간을 기준으로

11월 23일에는 최초 등록, 공고 갱신, 후기 재게시, 문의 대응을 비교했다. 뮬 최신 글 올리기는 로그인까지 한 번에 2~3분쯤 걸렸다. 후기와 영상을 추가 네 곳에 올리는 데는 약 20분이 걸렸고, 영상 업로드가 끝나는 것을 보며 다음 곳으로 넘어가야 했다. 숨고 견적과 당근 문의를 처리한 날에는 여러 건을 합쳐 약 30분을 썼던 것으로 기억한다.

동료 강사들의 이유도 달랐다. 한 명은 음악 창작에 쓸 시간을 뺏기고 싶지 않아 한 플랫폼에만 글을 올렸고, 기존 공고를 열 곳에 최종 제출까지 대신해 주면 5만 원 정도를 낼 의향이 있다고 말했다. 다른 한 명은 플랫폼의 낮은 가격 경쟁을 우려해 인스타그램으로만 홍보했다. 두 사례는 내가 전해 들은 이야기이고 실제 결제로 이어졌는지는 확인하지 못했다.

내가 가장 먼저 맡기고 싶은 일은 새 플랫폼에 최초 등록하는 작업이다. 크몽·탈잉·숨고 세 곳을 기준으로 자료 제공, 로그인과 본인인증, 초안 확인까지 내가 직접 쓰는 시간이 합쳐서 20~30분 정도면 좋겠다. 이 시간은 아직 실험으로 확인하지 않은 희망 기준이다.

## 등록을 이어서 하는 방식도 고민했다

팀이 살펴볼 기술 방식도 정리했다. 강사가 자기 PC에서 직접 로그인한 뒤 등록을 돕는 방식은 기존 로그인 상태를 활용할 수 있다. 다만 맥과 윈도우, 평소 사용하는 브라우저가 다르기 때문에 확장 프로그램을 설치하거나 다른 브라우저에 다시 로그인해야 하는 번거로움이 생길 수 있다.

서버에서 실행되는 원격 브라우저에 강사가 직접 로그인하는 방식은 별도 확장 설치를 줄일 수 있다. 반면 세 플랫폼에 다시 로그인해야 할 수 있고, 추가 인증과 로그인 세션을 어떻게 관리할지 확인해야 한다. 암호화한 비밀번호를 받아 복호화해 사용하는 방법도 비교했다. 실제 로그인할 때 비밀번호 원문을 처리해야 하므로, 강사가 직접 인증하는 흐름을 먼저 검토하기로 정리했다.

11월 24일 팀에서는 크몽·탈잉·숨고의 입력 항목을 비교하고 서버 원격 브라우저의 모의 환경을 조사했다. R05는 자체 모의 사이트에서 로그인 이후 같은 세션으로 입력·첨부·저장하는 시험 결과를 공유했다. 실제 플랫폼에서의 로그인이나 자동 제출은 확인하지 않은 상태다.

내 경험을 되짚어 보니 처음 필요한 것은 글을 빨리 만드는 것뿐만이 아니었다. 내가 실제로 제공하는 조건이 맞는지 확인하고, 여러 플랫폼의 양식에 옮겨 담고, 마지막 결과를 확인하는 데도 시간이 들었다. 앞으로는 강사가 화면 앞에서 직접 써야 하는 시간이 얼마나 줄어드는지 살펴보고 싶다.
