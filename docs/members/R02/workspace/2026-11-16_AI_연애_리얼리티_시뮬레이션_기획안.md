# AI 연애 리얼리티 시뮬레이션 기획안

> **가제: 우리의 선택**  
> 사용자 1명과 AI 참가자 11명이 6:6 가상 소개팅에 참여해, 첫인상부터 최종 선택까지 직접 대화하며 이야기를 만들어가는 서비스

- **기획 상태:** 개인 제안. 사용자 수요와 기존 서비스 대비 차별성은 검증 전
- **개발 기간:** 8주를 가정한 계획
- **프로젝트 주제 후보:** 2번 — 지능형 업무 협업 및 자율 수행 멀티에이전트
- **작성 배경:** 제타의 AI 캐릭터 대화, 「나는 SOLO」의 선택과 관계 변화, [벤치에서 발롱까지](https://kickru.com/)의 선택·기록이 누적되는 게임 경험에서 출발
- **중요 확인 사항:** 2번 가이드의 통합 비서 일정·자산 관리 및 일정 충돌 조정에 게임 내부 일정과 참가자 관리가 인정되는지는 강사·운영 매니저 확인 필요
- **멘토 검토용:** [1페이지 요약](2026-11-16_AI_연애_리얼리티_멘토_1페이지_요약.md)

## 1. 프로젝트 개요

### 서비스 한 줄 소개

제타처럼 AI 캐릭터와 자유롭게 대화하면서, 「나는 SOLO」처럼 여러 참가자의 첫인상·자기소개·데이트·최종 선택을 경험하는 6:6 연애 시뮬레이션 웹 서비스.

### 처음 보는 사람을 위한 요약

연애 예능을 보며 직접 참가자가 되어 대화하고 선택해보고 싶다는 경험에서 출발했다. 사용자는 AI 참가자 11명을 만나 첫인상 선택부터 자기소개·단체 대화·1:1 대화·최종 선택까지 한 판을 진행한다. 참가자는 앞서 나눈 대화를 참고하고 사용자의 선택은 결과 카드에 기록된다. 여러 역할이 게임 진행·대화·기억을 나누어 관리하며 응답이 실패해도 이어서 진행하도록 설계한다. 첫 목표는 한 판을 완성하는 것이고 다양한 이벤트와 이전 선택을 바꿔보는 기능은 이후 검토한다.

[벤치에서 발롱까지](https://kickru.com/)는 사용자가 축구 선수를 만들고, 훈련·출전·이적 등의 선택을 하며 선수의 커리어를 만들어가는 웹 시뮬레이션 게임이다. 시즌마다 선택과 결과가 기록으로 쌓여 한 선수의 이야기가 완성된다.

이 기획에서는 그 흐름을 참고해, 사용자의 첫인상 선택·대화·데이트·최종 선택을 기록하고 한 판의 소개팅 이야기로 보여주고자 한다. 예를 들어 처음 관심을 가진 참가자와 대화 후 최종 선택한 참가자가 어떻게 달라졌는지 결과 카드에서 돌아볼 수 있다. 이는 참고 게임의 진행 방식을 소개팅에 응용한 제안이며, 두 게임의 장르나 내부 구현이 같다는 뜻은 아니다.

### 사용자가 경험할 흐름

```text
참가자 입장과 가명 부여
        ↓
첫인상 선택
        ↓
자기소개와 정보 공개
        ↓
단체 대화
        ↓
데이트 선택과 1:1 대화
        ↓
관계 변화
        ↓
최종 선택과 결과
```

사용자가 남성 참가자로 시작하면 사용자 1명과 남성 AI 5명, 여성 AI 6명으로 구성하고, 여성 참가자로 시작하면 사용자 1명과 여성 AI 5명, 남성 AI 6명으로 구성한다. **6:6은 이 게임의 제안 규칙**이며, 실제 방송의 모든 기수에서 참가자 수와 진행 순서가 같다는 의미는 아니다.

## 2. 멘토링 피드백 반영

11월 14일 멘토링에서 멘토는 타깃의 특징만으로 페인 포인트를 확정하지 말고, 사용자가 실제로 언제 무엇을 힘들어하는지 확인한 뒤 핵심 기능으로 연결하도록 조언했다. 특히 “연애 경험이 적다”, “이성과 대화하기 어렵다”는 설명만으로 실제 고통을 충분히 설명하기 어렵다고 지적했다.

이에 따라 본 기획은 **연애 예능에 직접 참여하는 게임의 재미**를 우선 목표로 삼는다. 대화 연습과 피드백은 선택 기능으로 검토하되, 실제 대화 능력이나 자신감 개선은 검증 전 효과로 주장하지 않는다.

| 내용 | 현재 근거 수준 |
| --- | --- |
| 제안자의 연애 예능·AI 캐릭터 대화에 대한 관심 | 대화에서 확인된 개인 관심 |
| 직접 참가해 대화하고 선택하고 싶다는 생각 | 제안자의 기획 의도 |
| 주변 다른 시청자도 참여 경험을 원한다는 내용 | 제안자가 전달한 주변 의견. 인원·질문 방식·구체 발언은 미기록 |
| 더 넓은 시청자층의 이용 의향 | 미검증 가설 |
| 기존 서비스보다 재미있고 일관된 경험인지 | 미검증 가설 |
| 실제 소개팅 대화에 도움이 되는지 | 미검증 가설 |

### 참고 자료의 해석

사용자가 제공한 「나는 SOLO」 진행 방식·가명 자료에는 입장과 가명, 첫인상 선택, 자기소개, 데이트, 최종 선택 등과 다양한 예외가 정리돼 있다. 해당 자료는 2차 위키 자료로, 기수별 차이와 작성자의 해석·추정이 섞일 수 있으므로 모든 회차의 고정 규칙으로 단정하지 않는다.

방송의 현행 가명 예시로 남성 영수·영호·영식·영철·광수·상철, 여성 영숙·정숙·순자·영자·옥순·현숙이 자료에 제시돼 있으나 초기 기수와 참가자 구성에 따른 예외도 있다. 가명별 성격·직업을 실제 사람의 고정 특성이나 MBTI로 일반화하지 않는다. 게임에는 **가명을 쓰는 구조**를 참고하되, 정식 서비스의 독자 가명을 우선 제안한다. 방송의 명칭·전용 표현·이미지·실제 인물 재사용 가능 여부는 별도 확인한다.

## 3. 타깃 사용자

### 1차 타깃

**연애 예능과 캐릭터 대화를 즐기며, 여러 참가자 사이에서 직접 말하고 선택하는 이야기를 경험하고 싶은 성인.**

- 연애 예능을 보며 참가자의 선택과 관계 변화를 따라보는 사람
- 자신이 참가자라면 어떻게 대화하고 선택할지 상상해본 사람
- AI 캐릭터와 직접 이야기하는 콘텐츠를 즐기는 사람
- 여러 인물 사이에서 관계가 변화하는 시뮬레이션에 관심이 있는 사람

### 2차 타깃

- 소개팅이나 첫 만남의 대화를 가볍게 경험해보고 싶은 성인
- 같은 상황에서 다른 말과 선택을 시도해보고 싶은 사람

연령·연애 경험에 따라 필요성을 단정하지 않는다. 사용자 전반의 이용 의향은 아직 확인하지 못했다.

### 대표 사용 상황

연애 예능을 즐기는 성인 사용자가 AI 참가자들과 한 회차에 출연한다. 첫인상에서 A를 선택했지만 다른 참가자도 A에게 관심을 보인다. A의 선택에 따라 데이트 상대가 정해지고, 다른 참가자들의 선택도 다음 단체 대화와 최종 선택에 이어진다. **이는 기획 시나리오이며 구현이나 사용자 반응은 검증 전이다.**

## 4. 사용 동기와 핵심 문제 가설

**사용 동기:** 연애 예능을 보며 관찰자에 머무르지 않고 직접 참가해 대화하고 선택해보고 싶다. 제안자와 주변 시청자의 의견에서 출발했으며 주변 의견의 인원·질문 방식은 미기록이다.

**핵심 문제 가설:** 여러 AI 참가자와 연애 예능형 이야기를 진행할 때 참가자 수나 선택 결과 등 회차의 상태가 서로 어긋나면 사용자가 상황을 정정해야 하고 이야기에 몰입하기 어려울 수 있다.

제타에서 직접 진행한 한 회차에서 참가자 인원과 첫인상 선택 결과의 설명이 서로 맞지 않는 사례를 관찰했다. 다만 사용자가 실제로 정정 부담이나 몰입 저하를 얼마나 느꼈는지, 다른 회차·사용자에게 반복되는지는 확인하지 못했다. 참가자별 장기 기억과 비공개 대화의 혼동도 이번 기록만으로 확인되지 않은 별도 가설이다.

## 5. 문제 정의와 사용자 가치

> 연애 예능의 참가자가 되어 여러 인물의 관계와 선택을 경험하고 싶은 사용자가, 인물과 선택의 흐름을 놓치거나 진행 결과가 어긋나지 않으면서 자신만의 한 회차를 만들어갈 수 있을까?

### 직접 플레이에서 확인한 기존 경험

2026년 11월 16일 사용자가 제타의 연애 예능형 콘텐츠를 한 차례 직접 진행한 대화 기록을 기준으로 한다. 전체 기능이나 다른 회차를 대표하는 시험은 아니다.

| 항목 | 이번 기록에서 관찰한 내용 | 아직 확인하지 못한 내용 |
| --- | --- | --- |
| 시작과 대화 | 가명 부여, 첫인상 선택, 데이트와 상황 묘사가 이어졌다. 참가자의 감정 변화와 다른 커플 장면도 서술됐다. | 다른 콘텐츠와 설정에서의 동작 |
| 인원과 선택 | 남성 인원 안내와 등장 묘사, 첫인상 지명과 중복 지명 설명에 서로 맞지 않는 부분이 있었다. | 오류의 반복 빈도, 화면이나 별도 기록으로 정정할 수 있는지 |
| 장면 중단 | 사용자가 진행을 그만두자고 했을 때 캐릭터가 압박하는 반응을 보였다. | 별도의 장면 제어 기능 및 다른 상황에서의 동작 |
| 비공개 정보·장기 기억 | 해당 조건을 따로 시험하지 않았다. | 정보 접근 분리, 장기 기억 및 재개 품질 |

제타는 이미 다화자 대화와 유사한 연애 예능형 콘텐츠를 제공한다. 따라서 6:6, AI 캐릭터, 첫인상과 데이트 단계 자체를 새롭거나 제타에서 불가능하다고 주장하지 않는다. 범용 LLM에서도 지침을 통한 역할극이 가능하며 동일 조건의 직접 비교는 아직 수행하지 않았다. 사용자 본인의 대화 1건은 유용한 관찰이지만 다른 사용자의 경험이나 반복 발생률을 증명하지 않는다.

### 남는 문제와 차별화 가설

선택한 내용과 참가자 관계가 한 회차 안에서 연결되는 경험이 사용자에게 중요한지, 기존 대안 이후에도 정정 부담이 남는지 확인이 필요하다. **참가자·선택·관계를 명시적으로 관리하고 공개 가능한 관계도를 제공하면, 사용자가 여러 인물의 관계와 선택이 맞물리는 한 회차에 더 쉽게 참여할 수 있을 것**이라는 가설을 검증한다. 실제 재미나 기존 서비스 대비 우위는 미검증이다.

### 사용자 가치 가설

- 사용자는 캐릭터 한 명과 대화하는 것에 더해, 다른 참가자들의 선택이 자신의 이야기와 연결되는 회차를 경험한다.
- 공개 가능한 참가자·선택 기록으로 현재 상황을 확인하고, 원하지 않는 장면은 직접 중단하거나 전환한다.
- 한 판의 첫인상부터 최종 선택까지 기록을 결과로 돌아본다.

### 멘토 검토용 3~5분 요약

- **Target:** 연애 예능의 관계와 선택을 직접 경험하고 싶은 성인 시청자.
- **사용 동기:** 관찰자가 아닌 참가자로 대화하고 선택하고 싶다. 제안자와 주변 의견에서 출발했으며 수요 규모는 미확인.
- **실제 관찰 / Pain 가설:** 제타 한 회차에서 인원과 지명 결과 설명의 불일치를 관찰했다. 이것이 반복적인 정정 부담이나 몰입 저하를 일으키는지는 미검증.
- **기존 대안:** 제타의 유사 콘텐츠에서도 가명·첫인상·데이트·대화가 가능했고, 범용 LLM도 역할극에 활용할 수 있다.
- **Remaining Pain:** 여러 참가자의 선택과 관계를 계속 파악하고 일관되게 이어가기 어렵다는 가설. 반복 실험과 사용자 확인이 필요하다.
- **Problem:** 선택과 관계가 연결되는 여러 인물의 한 회차를 사용자가 이해하고 이어갈 수 있도록 만들 수 있는가?
- **Painkiller 후보:** ① 참가자별 정보·기억 구분 ② 선택·관계·진행 상태 기록과 공개 관계도 ③ 장면 제어 및 오류 후 이전 상태 복구.
- **미확인:** 사용자 수요·불편의 크기, 기존 서비스 대비 차이, 비용·구현 가능성, 과정 주제 인정 여부.

### 제출·평가를 위한 근거와 검증 보완

- **관찰:** 제공받은 제타 플레이 기록 1건(2026-11-16)에서 인원·선택 설명의 불일치와 장면 중단 시 압박성 반응을 확인했다. 당시 별도 정정 횟수·소요 시간·몰입도는 기록되지 않았다.
- **반대 근거:** 같은 기록에서 제타는 가명 부여, 첫인상 선택, 데이트와 대화 진행을 제공했다. 이미 충분히 만족스러운 경험일 수 있으며 별도 서비스가 반드시 필요한지는 미확인이다.
- **사용자의 현재 행동:** 연애 예능을 시청하거나 제타 등의 캐릭터 대화를 이용하는 상황을 대상으로 제안한다. 제안자의 1회 플레이 외 이용 빈도·반복 행동과 다른 시청자의 대안 사용 방식은 미확인이다.
- **문제 정의 가설:** 연애 예능형 AI 콘텐츠 이용자가 여러 참가자와 한 회차를 이어가려 할 때 참가자·선택 상태가 어긋나면 이를 다시 확인하거나 정정하는 부담을 겪을 수 있다. 부담의 크기와 빈도는 미확인이다.

| 해결 기능 제안 | 관찰할 지표 | 비교 기준 |
| --- | --- | --- |
| 참가자별 정보·기억 접근 분리 | 공개 전 정보·비공개 대화 노출 사례 수 | 같은 공개 범위와 질문을 가능한 한 맞춘 제타·범용 LLM |

비교와 PoC는 미실행이다. 서비스마다 설정·대화 맥락·접근 권한이 다르면 기록하며, 실행할 수 없는 오류 주입은 미실행으로 둔다. 성공 기준·반복 횟수는 실행 전 팀이 정한다. 정보 노출 시험에는 실제 개인정보가 아닌 가상 자료만 사용한다.

### 접근 조건·도입·축소 경로

- **입력·데이터:** 초기 시험은 직접 만든 가상 참가자와 대화로 수행한다. 제타 및 각 모델의 이용약관, 대화 기록 저장·공유·재사용과 API 접근 조건은 서비스별 확인 전이며 허용되지 않은 자동 수집을 전제하지 않는다.
- **개인정보:** 실명·실제 사진 없이 시작하는 방향이다. 대화 저장 범위·보존 기간·삭제 방식과 필요한 동의는 설계·확인 전이다. 실제 사용자 자료는 권한과 동의 확인 전 수집하지 않는다.
- **사용·도입:** 연애 예능형 콘텐츠에 관심 있는 성인이 한 회차를 이용하는 흐름을 제안한다. 실제 이용 빈도·지불 의향·요금·승인 주체는 미확인이다.
- **8주 축소·중단:** 6:6이 속도·비용·일관성 측면에서 어렵다면 소수 참가자와 한 단계의 선택 연결로 PoC를 축소한다. 사용자 고통이나 기존 대안 이후 잔여 문제가 확인되지 않으면 별도 서비스의 필요성과 문제 정의를 재검토한다. 축소가 과정 필수 조건에 부합하는지는 별도 확인한다.
- **제출 정합성:** 현재 팀 정본 TASK-017은 결혼 상황의 고통을 대상으로 기술되어 있어 이 연애 예능 게임 기획안과 범위가 다르다. 본 안을 TASK-017 평가 대상으로 연결할 수 있는지는 팀장 확인 전이며, 확인 없이 TASK의 목적을 바꾸지 않는다.

## 7. 핵심 기능

6:6 구성, MBTI, 첫인상과 데이트는 콘텐츠 규칙이다. 문제 해결 기능은 **참가자별 정보·기억 관리**, **선택·관계·진행 상태 관리**, **장면 제어와 오류 복구**의 세 묶음으로 검토한다. 아래 기능은 구현 계획이며 효과는 미검증이다.

### F1. 6:6 참가자와 가명 생성

사용자는 게임 닉네임, 관심사, 짧은 자기소개와 선호하는 대화 분위기를 설정한다. 첫 MVP는 실명이나 실제 사진 없이 시작할 수 있도록 제안한다.

AI 참가자 11명은 각각 독자 가명, 무작위 MBTI, 관심사, 대화 스타일, 가치관, 정보 공개 시점과 개별 기억을 가진다. **MBTI는 캐릭터 설정의 재미 요소**이며 실제 성격이나 연애 궁합을 판정하지 않는다. 같은 유형이라도 관심사와 말투는 다르게 구성할 수 있다.

### F2. 첫인상과 자기소개

- 첫인상 단계에서는 나이·직업 등 이후 공개하기로 한 정보를 비공개로 둔다.
- 사용자는 제한된 소개를 보고 관심 참가자를 선택한다.
- 자기소개 단계에서 참가자의 관심사와 공개 정보를 확인한다.
- 첫인상 선택과 이후 관심 변화를 별도로 기록한다.
- 화면뿐 아니라 AI 참가자에게도 각 단계에서 알 수 있는 정보만 전달한다.

### F3. 단체 대화와 1:1 대화

- 공통 주제로 단체 대화를 진행하고 사용자가 직접 말하거나 질문한다.
- 사용자가 선택한 참가자 한 명과 1:1 대화를 진행한다.
- 참가자는 공개된 정보와 자신이 직접 들은 대화를 바탕으로 반응한다.
- 사용자가 대화 중 소외되지 않도록 진행 역할이 발언 순서를 조정한다.

### F4. 선택과 데이트

- 데이트 상대 선택, 요청 집중, 대기, 미배정, 선택받지 못함, 본인의 미선택을 구분한다.
- MVP에서는 정해진 1:1 시간대에서 중복 요청을 확인한다.
- 상대 선택과 게임 규칙을 확인해 다른 시간·대기·미배정 중 가능한 결과를 기록한다.
- 랜덤 데이트, 특별 데이트, 다대일 데이트는 확장으로 검토한다.

### F5. 최종 선택과 결과 카드

사용자와 AI 참가자가 각자 최종 선택 또는 미선택을 한다. 상호 선택, 선택 불일치, 미선택을 구분하고 첫인상, 대화 상대, 주요 주제와 결과를 요약한다. 결과는 가상 이야기의 결말이며 사용자의 실제 성격·매력·연애 능력을 평가하지 않는다.

**나의 소개팅 기록:** 첫인상에서 고른 참가자, 실제 대화 상대, 함께 이야기한 주제, 최종 선택과 결과를 저장된 기록으로 보여준다. 처음에는 A를 선택했지만 대화를 나눈 뒤 B를 최종 선택한 흐름을 돌아볼 수 있다. 확인되지 않은 사건은 만들어내지 않는다.

### F6. 선택형 힌트와 회고

사용자가 원할 때만 다음 질문의 예시나 실제 대화에 기반한 회고를 제공한다. 사용자 발화에 없는 내용이나 실제 연애 성공 가능성을 단정하지 않는다. 대화 연습 효과는 미검증이다.

### 관계 확인과 장면 제어 — 핵심 경험 제안

- 첫 PoC에서는 참가자 명단, 현재 단계, 공개된 선택과 확정된 데이트를 간단한 목록으로 보여준다. 비공개 선택이나 다른 참가자의 속마음은 공개하지 않는다. 시각적인 관계도는 이후 확장한다.
- 다른 참가자의 선택이 사용자의 장면과 다음 단계에 영향을 주도록 한다. MVP에서는 매 순간 11명을 호출하지 않고 단계 전환에 필요한 선택과 사건만 갱신하는 방식을 시험한다. 실제 자율성과 비용은 PoC 전이다.
- 첫 PoC에서는 장면 중단을 제공하고, 중단 요청이 캐릭터 반응과 관계없이 적용되는지 확인한다. 분위기 설정과 주제 전환은 후속 기능으로 검토한다. AI 참가자도 상황에 따라 거절할 수 있다.

### 문제와 핵심 기능의 연결

| 사용자가 마주할 수 있는 상황 | 핵심 기능 | 확인할 결과 |
| --- | --- | --- |
| 참가자가 자기소개 전에 알 수 없는 직업을 언급 | F1·F2: 인물 설정과 정보 공개 시점 관리 | 공개 전 정보를 응답에 사용하지 않는지 |
| B가 A와의 비공개 대화를 아는 듯 말함 | F3: 참가자별 기억·접근 범위 구분 | B에게 비공개 대화가 전달되지 않는지 |
| 선택이 이후 대화나 최종 결과와 어긋남 | F4·F5: 선택·일정·결과 기록과 연결 | 사용자의 선택이 해당 단계와 결과에 반영되는지 |
| 사용자가 원하는 표현을 생각하기 어려움 | F6: 선택형 힌트·회고 | 사용자가 원할 때 대화 기록에 근거해 보여주는지. 연습 효과는 미검증 |

## 8. 멀티에이전트 협업 구조

| 역할 | 주요 업무 | 구현 방향 제안 |
| --- | --- | --- |
| 진행 | 현재 단계, 발언 순서, 다음 작업 관리 | AI와 명시적인 진행 규칙 |
| 참가자 | 개별 가명·관심사·대화에 따른 반응 | AI 대화, 필요한 참가자만 호출 검토 |
| 일정 | 시간대와 참가자 중복 확인 | 규칙 기반 코드 및 설명 |
| 기억·권한 | 공개 대화와 1:1 대화 구분 | 저장 구조와 접근 규칙 |
| 검증·복구 | 오류·상태 불일치 감지 및 제한된 재시도 | 검증 코드와 복구 흐름 |
| 회고 | 실제 대화 기록에 기반한 선택형 요약 | AI 요약 |

```text
상대 선택 → 진행 단계 확인 → 일정 중복 확인
→ 참가자가 접근할 수 있는 기억 전달 → 대화 생성
→ 결과 검증 → 대화와 상태 저장
```

여러 역할을 모두 독립된 모델로 실행할 필요는 없다. 각 역할의 책임, 입력과 결과 전달을 명확히 하고 구현·측정한다.

### 게임 내 일정 충돌 사례

같은 시간에 사용자와 다른 AI 참가자가 한 참가자에게 1:1 데이트를 요청하면, 일정 역할은 중복을 감지한다. 정해진 게임 규칙과 상대의 선택을 확인한 뒤 다른 시간 제안, 대기 또는 미배정 상태를 기록한다. 이 과정은 **가상 일정**이며 실제 캘린더를 읽거나 변경하지 않는다.

2번 가이드의 일정·자산 관리 및 일정 충돌 조정 목표를 게임 내 시간·참가자 관리로 대체할 수 있는지는 강사·운영 매니저의 확인이 필요하다.

## 9. 오류 처리와 Auto-Healing 계획

| 상황 | 감지와 처리 제안 |
| --- | --- |
| AI 응답 실패·시간 초과 | 제한된 재시도 후 실패 상태와 이전 단계 표시 |
| 캐릭터 이름 혼동 | 요청 대상과 응답의 참가자 ID 비교 후 재요청 또는 오류 표시 |
| 비공개 대화 전달 | 접근 범위 검증, 전달 차단 및 기록 |
| 데이트 중복 배정 | 동일 시간·참가자 비교 후 대안 또는 미배정 기록 |
| 저장 실패 | 이전 상태 보존 및 재시도 |

같은 작업의 재시도는 기존 작업과 실행 시도를 구분해 기록하고 중복 반영을 방지한다. 실제 시험 후 오류 유형·복구 성공 여부·소요 시간·이전 상태 보존 여부를 기록한다. 현재는 설계 계획이며 복구 성능은 미검증이다.

| 필수 | 참가자별 기억과 공개 범위 | 직접 나눈 대화가 이어지고 비공개 내용이 다른 참가자에게 전달되지 않도록 상태·저장 구조를 관리한다. 짧은 기록 저장부터 시험하고 RAG 필요성은 추후 판단한다. |
| 필수 | AI 진행자의 대화 조율 | 사용자가 말을 걸면 해당 참가자가 반응하도록 진행 역할과 참가자 역할의 인계를 구성한다. 단계·허용 선택은 규칙 코드로 관리한다. |
| 필수 | 공개 상태 목록과 소개팅 기록 | 참가자 명단·현재 단계·공개 선택·확정 데이트를 목록으로 확인하고 첫인상·대화·최종 선택을 결과 카드로 보여준다. 시각적 관계도는 후속이다. |
| 필수 제안 | 장면 중단 | 사용자가 원하면 캐릭터 응답에 관계없이 현재 장면을 중단한다. 분위기 설정·주제 전환은 후속이다. |
| 필수 제안 | 오류 후 이어하기 | 응답 실패 시 제한된 재시도와 이전 상태 복원을 시험하고 결과를 기록한다. |
| 확장 | 추가 이벤트 | 기본 선택과 중복 요청 처리는 MVP에서 확인하고, 랜덤·특별 데이트 등 추가 장면은 이후 검토한다. |
| 확장 | 다른 선택으로 다시 해보기 | 특정 단계의 저장 상태로 돌아가 다른 선택을 시험한다. 원래 기록과 새 진행이 섞이지 않는지 검증한다. |
| 보조 | 진행 상태와 평가 화면 | 사용자에게 현재 단계와 다음 단계를 보여주고, 개발용으로 역할 인계·실패·복구를 확인한다. |

위 기능의 효과와 구현 가능성은 검증 전이다. 에이전트 수를 늘리는 것보다 사용자에게 이어지는 이야기를 제공하는 데 필요한 역할과 규칙을 먼저 정한다.

### 필수 MVP

사용자 1명과 AI 11명 생성 → 가명 입장 → 첫인상 → 자기소개 → 단체 대화 1회 → 1:1 대화 → 최종 선택 → 결과 카드.

첫 PoC에서는 위 6:6 흐름을 작게 연결해 ① 참가자별 정보 접근 구분 ② 공개 선택·데이트·현재 단계의 목록 표시와 상태 연결 ③ 장면 중단 및 응답 실패 후 이전 상태 복구를 우선 시험한다. 다른 참가자 선택은 단계 전환에 필요한 최소 사건으로만 반영하고, 일정 충돌 한 사례도 확인한다. 시각적 관계도, 분위기 설정과 주제 전환은 후속 기능이다. 이는 목표이며 아직 구현·시험 전이다. 교육 담당자의 과제 적용 범위 확인 후 필수 수준을 확정한다.

### 선택 기능

- 선택형 대화 힌트와 실제 대화에 기반한 회고
- 분위기 설정, 주제 전환, 시각적 관계도
- 참가자끼리의 단체 대화 반응을 다양화
- 같은 설정으로 다른 선택을 해보는 다시 플레이

### 이후 확장

- 랜덤 데이트·특별 데이트권·추가 미션
- 여러 명이 함께하는 데이트와 여러 날의 진행
- 참가자끼리의 관계 변화와 다수 장면의 심화 시뮬레이션
- 음성, 캐릭터 이미지, 사용자 제작 캐릭터, 멀티플레이

## 13. 인터뷰 없이 진행할 수 있는 검증

**진행한 관찰:** 제타의 연애 예능형 콘텐츠를 한 차례 직접 플레이했다. 5절의 인원·지명 결과 불일치와 장면 중단 반응은 해당 기록의 관찰이다. 동일 조건 비교, 반복률 측정과 우리 PoC 시험은 아직 하지 않았다.


1. **개인 경험 기록:** 연애 예능을 보며 직접 참여해보고 싶었던 장면과 AI 대화 경험을 제안자의 경험으로 기록한다.
2. **기존 서비스 비교:** 기존 제타 1회 관찰을 기록하고, 같은 첫인상·정보 공개·1:1 대화 시나리오의 반복 시험을 계획한다. 실행하지 못한 기능과 품질은 미확인으로 둔다.
3. **규칙 시나리오 작성:** 첫인상 변경, 중복 데이트, 선택받지 못함, 미선택, 상호 선택·불일치의 기대 결과를 정한다.
4. **구현 후 실제 테스트:** 참가자 혼동, 비공개 정보 누출, 일정 충돌, 응답 실패와 이전 상태 보존을 검사하고 결과를 기록한다.

문서상의 모의 시나리오, 실제 LLM·시스템 실행 결과, 실제 사용자 피드백은 서로 구분한다. 재미·몰입·대화 연습 효과는 내부 기능 시험만으로 입증하지 않는다.

### 같은 시나리오로 비교하는 검증 계획 — 아래 비교 시험 미실행

**목표:** 참가 경험을 구현하는 상태 관리가 참가자 정보·선택 혼동과 사용자의 정정 부담을 줄이는지 살핀다.

1. 공통으로 사용할 가상 참가자 12명의 프로필, 공개 시점, 발화, 선택 및 기대 결과를 미리 작성한다.
2. 제타, ChatGPT, Gemini, Claude Code와 우리 PoC에서 가능한 범위의 동일 시나리오를 각각 진행한다. Claude Code는 파일·도구를 사용하는 개발자 기준선으로 별도 표시한다.
3. **시나리오 A:** 자기소개 전 비공개 직업에 대한 질문 → 공개 전 정보를 노출하는지 확인한다.
4. **시나리오 B:** A와만 나눈 1:1 대화를 B에게 질문 → 비공개 내용을 실제로 아는 듯 답하는지 확인한다.
5. **시나리오 C:** 첫인상·데이트·최종 선택 → 선택과 결과를 올바르게 연결하는지 확인한다.
6. **시나리오 D:** 게임 중단·재개와 중복 일정 또는 응답 실패 → 이전 상태 보존 및 처리 이유를 확인한다.

| 관찰값 | 기록 방법 |
| --- | --- |
| 설정·정보 혼동 | 사전에 정한 정답과 비교해 인물 혼동·공개 전 정보·비공개 내용 노출 건수 기록 |
| 진행·선택 | 각 단계 완료 여부와 선택·결과 불일치 기록 |
| 사용자 부담 | 사람이 다시 설명하거나 정정한 횟수와 작업 시간 기록 |
| 운영 부담 | 가능한 경우 응답 시간, 호출 수·비용, 실패와 복구 결과 기록 |

모델·설정·컨텍스트·도구 권한·비공개 정보가 각 시스템에 전달되는 방식이 다를 수 있으므로 사전에 기록한다. 하나의 공통 대화에 비공개 정보를 함께 제공하면 모델 자체는 그 내용을 볼 수 있어 엄격한 접근 분리를 시험한 것으로 취급하지 않는다. 동일 조건이 불가능한 제품은 조건 차이를 명시하고, 실행하지 못한 부분은 미실행으로 둔다.

초기 PoC의 잠정 통과 조건은 **정해진 테스트 사례에서 자기소개 전 정보와 다른 참가자의 비공개 대화를 노출하지 않고, 선택한 결과를 올바르게 기록하는 것**이다. 사례 수·반복 횟수·시간·비용의 정량 합격선은 팀이 평가 조건을 정한 뒤 확정한다. 한두 차례의 성공만으로 일반적 정확성이나 사용자 가치 우위를 주장하지 않는다.

인터뷰가 현재 불가능하므로 본인 경험과 위 내부 시험을 먼저 사용한다. 최종 발표 평가의 사용자 피드백·개선 사례는 이후 가능한 수집 방법을 확인하며, 내부 테스트를 사용자 피드백으로 대체했다고 기록하지 않는다.

## 15. 팀 공유용 요약

연애 예능을 보며 참가자의 대화와 선택을 직접 경험해보고 싶은 성인을 위한 6:6 AI 소개팅 게임이다. 사용자 1명과 AI 참가자 11명이 가명으로 입장해 첫인상, 자기소개, 단체 대화, 1:1 데이트와 최종 선택을 진행한다. 참가자에게는 무작위 MBTI와 별도의 관심사·대화 스타일이 부여된다.

제타 직접 플레이 1회에서는 참가자 인원과 선택 결과 설명의 불일치를 관찰했다. 이를 계기로 참가자별 정보 관리, 선택·관계 기록과 공개 관계도, 장면 제어·오류 복구를 핵심 기능 후보로 삼는다. 다른 참가자의 선택도 이어지는 한 회차 경험이 차별화될지는 반복 시험과 사용자 확인이 필요하며, 장기 기억·비공개 정보 문제와 대화 연습 효과는 미검증이다.

8주 MVP는 첫인상부터 최종 선택까지 한 판을 완성하는 것이다. 2번 주제의 일정·자산 관리 요건을 게임 내 일정으로 충족할 수 있는지는 강사·운영 매니저 확인이 필요하다.
