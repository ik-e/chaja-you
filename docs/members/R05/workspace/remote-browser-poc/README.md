# 원격 브라우저 기반 인증 및 서버 실행 검증 PoC (R05)

사용자가 프로그램을 설치하지 않고 일반 웹 브라우저로 서버의 원격 브라우저에 직접 로그인하면, 서버 프로그램이 같은 인증 세션으로 등록 업무를 이어서 할 수 있는지 검증했다.

**결론:** 모의 환경에서 필수 검증 조건 5개와 추가 검증 4개가 모두 통과했다. 같은 시험을 3회 연속 실행했고, 3회 모두 10/10 통과했다. 이후 "로그인만 하면 서버가 자동으로 이어서 등록"하는 기능(T12)과 다른 PC 접속 기능을 추가했고, 시험 11개가 모두 통과했다. 실제 플랫폼 적용에는 6절의 미확인 항목이 남아 있다.

- 설계·기술 선택 근거·제약: [DESIGN.md](DESIGN.md)
- 실행 증거: [evidence/](evidence/) — 시험 결과 `results.json`, pytest 출력, 감사 로그, 스크린샷

| 사용자별 세션 격리 | T07 | 통과 | 다른 세션 토큰으로 API 404·WebSocket 거부. 새 세션은 로그인 안 된 상태(`needs_login`) |

시험 중 발견해서 고친 문제는 두 가지다.
1. 첫 실행 때 감사 로그에 키 입력이 한 글자마다 한 줄씩 남아 비밀번호 길이가 드러났다. 키보드 이벤트를 기록하지 않도록 바꾸고, T11에 이를 확인하는 검사를 추가했다.
2. 뷰어 상태줄이 페이지 이동을 반영하지 않았다. 페이지 이동 때마다 상태를 보내도록 고치고, T02에서 확인한다.

## 3. 실행 환경 (검증한 환경)

- Linux, Python 3.13.18, Google Chrome for Testing 153.0.8010.12 (Playwright `channel="chrome"`)
- 패키지 버전은 `requirements.txt` 참고
- Docker는 사용하지 않았다. 검증 환경에서 Docker 데몬을 실행할 수 없었다.

## 4. 재현 방법

```bash
cd docs/members/R05/workspace/remote-browser-poc
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m playwright install chromium                  # 설치된 Chrome을 쓸 경우 생략 가능

# Chrome이 없고 Playwright 번들 Chromium을 쓸 때 (PowerShell: $env:CHROME_CHANNEL="")
export CHROME_CHANNEL=

# 자동 시험 (서버 3개를 자동으로 띄우고 끈다. 약 20초)
python -m pytest tests -v
```

직접 눈으로 확인하려면 다음처럼 실행한다.

```bash
# 터미널 1: 모의 사이트
uvicorn mock_site.app:app --port 8001 --no-access-log
# 터미널 2: 제어 서버
MOCK_BASE=http://127.0.0.1:8001 uvicorn control_server.app:app --port 8002 --no-access-log
```

1. 브라우저로 `http://127.0.0.1:8002` 접속 → "새 세션 만들기"
2. 원격 화면에서 가상 계정으로 로그인 (`tutor_a` / `Mock-Pass-A!2026`, 시험 전용 값)
3. "등록 작업을 서버에 맡기기" → 제목·설명·가격·이미지 입력 → 맡기기
4. 뷰어 탭을 닫았다가 같은 주소로 다시 열면, 서버 작업 결과(저장 완료 화면)가 보인다.

## 4-1. 두 PC로 시연하기 (내 PC = 서버, 팀장님 PC = 접속)

두 PC가 같은 네트워크(같은 와이파이·공유기)에 있어야 한다.

1. **내 PC**: 이 폴더에서 PowerShell을 열고 실행한다.
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\start_demo.ps1
   ```
   창에 `다른 PC(팀장님)에서 열 주소: http://192.168.x.x:8002`가 나온다. 처음 실행하면 Windows 방화벽 창이 뜨는데, "개인 네트워크" 허용을 누른다. 학원 와이파이가 공용 네트워크로 잡혀 있으면 "공용"도 허용해야 한다.
2. **팀장님 PC**: 브라우저로 그 주소를 연다. 레슨 내용과 이미지를 넣고 "세션 만들기"를 누른 뒤 "이 화면에서 열기"를 누른다.
3. 원격 화면에서 가상 계정(`tutor_a` / `Mock-Pass-A!2026`)으로 로그인만 한다.
4. 로그인되는 순간 상태줄이 "제어: 서버"로 바뀌고, 서버가 입력·이미지 첨부·저장을 이어서 한다. 브라우저를 닫아도 계속된다.
5. 같은 링크를 다시 열면 저장 완료 화면이 보인다. 끝나면 "세션 종료"를 누른다.

링크를 연 사람이 그 세션의 원격 브라우저를 조작할 수 있으므로, 링크는 믿을 수 있는 사람에게만 보낸다. 다른 네트워크(예: 집과 학원)에서 접속하려면 HTTPS 터널이 필요하며, 이 구성은 시험하지 않았다.

검증 범위: 시험 환경에서 서버를 `0.0.0.0`으로 열고 루프백이 아닌 IP(192.0.2.2)로 접속해 원격 로그인 → 자동 등록 → `mock_success`까지 확인했다. 실제 두 대의 Windows PC 사이 접속과 `start_demo.ps1` 실행은 아직 확인하지 않았다(검증 환경에 PowerShell이 없음).

## 5. 주요 API

| 메서드 | 경로 | 설명 |
| --- | --- | --- |
| POST | `/api/sessions` | 세션 생성 (세션 ID, 토큰, 뷰어 경로). 본문에 `auto_job`을 넣으면 로그인 감지 후 자동 시작 |
| GET | `/api/sessions/{id}` | 상태: 제어 주체, 현재 경로, 뷰어 수, 작업 결과 |
| POST | `/api/sessions/{id}/handoff` | 등록 내용 맡기기 → 서버 작업 시작 (이미 진행 중이면 409) |
| POST | `/api/sessions/{id}/return[?cancel=true]` | 제어권 회수 (진행 중이면 `cancel=true` 필요) |
| DELETE | `/api/sessions/{id}` | 세션 종료, 쿠키 폐기 |
| WS | `/ws/{id}` | 첫 메시지 `{"t":"auth","token":…}` 뒤 화면 프레임 수신·입력 전송 |

`/api` 요청은 모두 `X-Session-Token` 헤더가 필요하다.

## 6. 확인하지 못한 항목

| 항목 | 상태 | 이유·범위 |
| --- | --- | --- |
| Docker·noVNC 구성 | 미실행 | 검증 환경에 Docker 데몬이 없음. 설계상 대안으로만 비교 (DESIGN.md 4절) |
| 실제 크몽·숨고 로그인 | 미시험(의도적) | 작업 범위상 금지. 서버 IP 로그인, 새 기기 인증, CAPTCHA, headless 탐지는 확인 불가 |
| HTTPS·WSS, 외부 네트워크 접속 | 미시험 | 로컬(127.0.0.1)에서만 실행 |
| 동시 사용자 부하 | 미측정 | 세션 1–3개만 시험 |
| 한글 조합 입력(IME) | 부분 | 영문·숫자·기호 키 입력만 시험함. 한글은 붙여넣기로 보내는 방식만 구현했고 시험하지 않음 |
| 원격 파일 선택창 | 미지원 | 화면 중계 범위 밖. 이미지는 맡기기 API로 전달 |

## 7. 채택 의견

- **채택 가능:** "사용자가 원격 브라우저로 직접 로그인 → 서버가 같은 세션으로 작업" 구조는 기술적으로 성립한다. 이 방식이면 서버가 비밀번호를 받거나 저장할 필요가 없다는 장점도 확인했다.
- **조건:**
  1. 실제 플랫폼은 서버 IP 로그인과 자동 등록을 막을 수 있다. 운영사 허용 여부(크몽 문의 중, 탈잉 약관 조항)를 먼저 확인해야 한다.
  2. 운영 단계에서는 사용자별 컨테이너 격리와 HTTPS가 필요하다.
  3. 제출 후 결과를 확인하지 못한 경우(`unknown`)를 자동 재시도하지 않는 원칙을 유지해야 한다.
- **다음 단계 제안:**
  1. Docker 환경에서 컨테이너 1개당 세션 1개 구성으로 같은 시험을 다시 돌린다.
  2. R03 공통 모의 계약(T1–T6) 입출력에 맞춰 연결한다.
