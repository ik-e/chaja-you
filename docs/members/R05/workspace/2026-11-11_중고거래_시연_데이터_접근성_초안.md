# 중고거래 상품 비교 시연 데이터 접근성 및 시연 흐름 초안

- 담당: R05 다혁 (백엔드)
- 상태: 초안
- 조사일: 2026-11-11
- 목적: 중고거래 상품 비교를 상위 리서치 에이전트 시스템의 시연 후보로 사용할 수 있는지 검토
- 관련 문서: [백엔드 데이터 흐름 초안](2026-11-11_리서치_백엔드_데이터_흐름_초안.md), [출처 저장 방식 초안](2026-11-11_리서치_출처_저장_방식_초안.md)

## 1. 확인할 질문

1. 상품의 모델·가격·상태·판매 여부·원문 링크를 얻을 수 있는가?
2. 같은 모델의 비교 상품을 구분해 찾을 수 있는가?
3. 데이터를 자동으로 수집하고 시연에 사용하는 조건을 확인할 수 있는가?
4. 자료 일부가 부족해도 출처가 있는 비교 보고서를 만들 수 있는가?

## 2. 현재까지 확인한 내용

[중고나라 상품 상세 페이지](https://web.joongna.com/product/233810546)에서는 제목, 가격, 모델명, 배터리·외관·기능 상태에 관한 설명을 확인할 수 있다. [검색 결과](https://web.joongna.com/search/%EC%95%84%EC%9D%B4%ED%8F%B0%2013%20PRO%20256GB)와 [시세조회 화면](https://web.joongna.com/search-price/%EC%95%84%EC%9D%B4%ED%8F%B0%2013%ED%94%84%EB%A1%9C%20256%EA%B8%B0%EA%B0%80?seq=220385499)에서도 비교 후보와 가격 정보를 볼 수 있다.

따라서 **사람이 공개 화면에서 시연에 필요한 정보를 확인하는 것은 가능**하다. 다만 공개 화면 열람과 **서버에서의 자동 수집·저장 허용 여부는 별개**다. 이번 조사에서는 중고나라 상품 조회용 공식 외부 API나 자동 수집 허용 조건을 확인하지 못했다. [중고나라 이용약관 페이지](https://web.joongna.com/terms)의 관련 조건은 추가 확인이 필요하다.

공식 API 대안으로는 상품 검색과 상세 조회를 제공하는 [eBay Browse API](https://developer.ebay.com/develop/api/buy/browse_api)가 있다. 다만 접근 토큰이 필요하고, 국내 중고거래 시연에 적합한지는 별도 판단이 필요하다. 실제 API 연결은 아직 시험하지 않았다.

## 3. 한 번의 시연 흐름

1. 사용자가 비교할 상품 링크 한 개를 입력한다.
2. 시스템이 모델명·가격·상태 설명·판매 여부를 확인한다.
3. 같은 모델과 용량의 비교 상품을 찾는다.
4. 다른 모델·용량이나 구성품만 판매하는 글을 비교 대상에서 구분한다.
5. 각 자료의 원문 링크와 확인 시각을 저장한다.
6. 가격과 상태의 차이, 확인되지 않은 사항을 보고서로 정리한다.
7. 사용자가 보고서의 판단 근거를 원문에서 확인한다.

첫 시연은 **상품 한 건과 소수의 비교 후보**만 다룬다. 판매자가 적은 상태 설명은 확인된 제품 상태가 아니라 **판매 글에 기재된 내용**으로 표시한다.

## 4. 판단되는 위험

아래는 현재 자료를 바탕으로 한 **위험 판단**이며, 이미 발생한 문제라는 뜻은 아니다.

| 위험 | 시연에 미치는 영향 | 대응 방향 |
|---|---|---|
| **자동 수집·재사용 조건 미확인** | 공개 매물을 서버에서 가져오는 방식을 확정할 수 없음 | R02와 이용 조건·공식 제공 방식을 확인하고, 확인 전에는 지속 수집을 전제로 설계하지 않음 |
| **검색 결과에 다른 모델이 섞임** | 가격 비교와 결론이 잘못될 수 있음 | 모델명·용량을 따로 추출해 일치 여부를 검사. 실제 [시세조회 화면](https://web.joongna.com/search-price/%EC%95%84%EC%9D%B4%ED%8F%B0%2013%ED%94%84%EB%A1%9C%20256%EA%B8%B0%EA%B0%80?seq=220385499)에도 다른 모델이 섞여 있음 |
| **매물 상태와 가격의 변동** | 보고서를 다시 볼 때 정보가 달라질 수 있음 | 조회 시각과 당시 판매 상태를 저장하고, 현재 거래 가능 여부를 보증하지 않음 |
| **판매 글의 상태 설명을 검증하기 어려움** | AI가 판매자 설명을 사실로 단정할 수 있음 | `판매자 기재 정보`와 `시스템이 확인한 정보`를 구분 |
| **게시글에 개인정보가 포함될 가능성** | 원문 전체를 저장·공유할 때 불필요한 정보까지 보관할 수 있음 | 연락처 등은 수집·보고서 대상에서 제외하고 필요한 상품 정보만 저장 |
| **사용자 입력 URL의 안전성** | 임의 주소를 서버가 그대로 읽으면 원치 않는 내부 주소 등에 접근할 수 있음 | 시연에서 허용할 도메인과 URL 형식을 제한 |
| **페이지 접근 실패·형식 변경** | 필드 추출이 실패해 보고서를 완성하지 못할 수 있음 | 수집 실패를 상태로 남기고 `확인 필요`로 표시 |

## 5. 예상되는 막힘과 필요한 결정

| 예상 막힘 | 누구와 확인할지 | 확인할 내용 |
|---|---|---|
| 실제 매물 데이터를 어떤 방식으로 사용할지 정해지지 않음 | R01 지효, R02 상옥 | 시연 플랫폼, 데이터 접근·이용 조건, 대체 데이터 사용 여부 |
| 비교할 상품의 일치 기준이 없음 | R03 두나, R01 지효 | 모델·용량·상태 중 무엇이 같아야 비교 가능한가 |
| 사용자 입력과 보고서 화면이 정해지지 않음 | R04 원민 | 링크 입력 방식, 진행 상태, 근거와 `확인 필요` 표시 |
| 일부 자료만 얻었을 때 종료 기준이 없음 | R01 지효, R03 두나 | 비교 후보가 적거나 출처가 부족할 때 보고서를 낼 것인가 |
| 출처 저장 방식과 실제 수집 결과의 연결이 미검증 | R05 다혁 | 수집 결과에서 URL·조회 시각·근거를 안정적으로 기록할 수 있는가 |

## 6. 잠정 결론

**공개 페이지를 사람이 확인하는 수준에서는 시연 자료가 있다.** 그러나 자동 수집·저장 조건과 안정적인 수집 방법은 확인되지 않았다. 따라서 현재 결론은 **“시연 흐름 설계 가능, 실제 데이터 연동 방식 미확정”**이다.

다음 조사에서는 이용 조건과 데이터 접근 방식을 먼저 확인한다. 그것이 해결되지 않으면, 팀이 **시연용 예시 데이터임을 명확히 표시한 자료**로 에이전트의 조사 분담·근거 저장·보고서 생성 흐름을 보여줄지 결정해야 한다.
