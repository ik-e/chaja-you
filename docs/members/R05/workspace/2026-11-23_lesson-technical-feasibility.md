## 0. 요약

1. **당근 모임과 강사용 과외/레슨 등록은 앱에서만 할 수 있다.** PC로 daangn.com을 직접 열어 보니 로그인 버튼이 없고, 모임 페이지에는 보기와 "당근 앱에서 보기"만 있었다 `[관찰 · 웹]`. 앱에서는 두 메뉴가 모두 있다 `[관찰 · 앱]`. 따라서 **브라우저 기반 실행(서버 브라우저·Browser Use·범용 AI 브라우저)으로는 당근 모임·과외/레슨 등록을 할 수 없다.** 앱 자동화는 기술 난이도가 높고 당근의 매크로 제한과도 직접 부딪친다.
2. **크몽은 웹에서 상품 등록·심사 신청 메뉴가 있다** `[공식]`. 브라우저 자동화가 적용될 수 있는 쪽은 크몽이다. 다만 판매 약관이 "비정상적인 방법"의 게시글 등록을 금지하고 `[공식]`, 외부 도구 대리 등록이 여기에 해당하는지는 **운영사 판단이 필요한 미확인 사항**이다.
3. **두 곳 모두 게시·상품 등록용 공식 API나 공식 위임 기능을 찾지 못했다.** 당근에 공식 경로가 있는 쪽은 광고(광고 OpenAPI, 공식 광고 대행)와 비즈프로필(운영자 초대, PC 당근비즈니스에서 소식 작성)이고, 모임은 해당하지 않는다.
4. **"비밀번호를 안 받는다"만으로는 위험이 사라지지 않는다.** 로그인 뒤 세션(쿠키)이 남고, 범용 AI·Browser Use는 화면 캡처·페이지 내용을 외부 모델 서버로 보낸다 `[공식]`. Browser Use는 비밀번호를 모델에서 가려도 **스크린샷은 가리지 않는다** `[공식]`.
5. **범용 AI는 사진 첨부가 막힐 수 있다.** ChatGPT Work의 내장 브라우저는 파일 업로드를 자동화할 수 없다고 명시한다 `[공식]`. 크몽은 메인 이미지 1장 이상이 필수라 `[R02 재인용]`, 이 경로만으로는 심사 접수까지 끝낼 수 없다. Chrome 확장·Computer Use 경로는 별도 검증이 필요하다.

- 공개된 웹 모임 페이지(`daangn.com/kr/group/...`)에는 홈·공지·게시판 보기와 "당근 앱에서 보기", "모임 가입하기", 앱 다운로드 안내만 있다. 모임 만들기·글쓰기 버튼은 보이지 않았다 `[관찰]`. 웹에는 로그인 버튼 자체가 없다 (아래 PC 확인 참고).

- 모임은 동네생활 탭 안의 서비스로 소개된다 `[2차]` ([더밸류뉴스 2023](https://thevaluenews.co.kr/news/177423)).
- R05가 **당근 앱**에서 "모임 만들기"와 "과외/레슨 등록" 메뉴를 직접 확인했다 `[관찰 · 앱, 2026-11-23]`.

  - 메인(`/kr/`) 상단 메뉴에는 중고거래·동네업체·중고차·동네생활·모임·알바·부동산·카페 **보기 링크만** 있고, **로그인 버튼이 없다.**

  - 과외/레슨은 웹에서 "알바 (과외/레슨)" 메뉴로만 연결되고, `jobs.daangn.com`(당근알바)로 이동한다. 여기에는 로그인 버튼이 있지만, 올라온 글은 **과외 선생님을 구하는 구인 공고**다(예: "원어민 영어회화 과외 선생님 찾아요"). 앱의 **강사용 과외/레슨 등록(선생님 프로필)과는 다른 서비스**다.

**알아 둘 점:**
- 판매 약관 제9조 7호는 "본인이나 **타인의 계정**으로 실질적으로 동일한 판매 게시글 중복 등록"을 금지한다 `[공식]`. 여러 강사의 상품을 우리 서비스가 등록할 때 문구 템플릿이 거의 같으면 이 조항과 충돌할 수 있다 `[추정]` → 강사별 문구를 다르게 만들어야 한다.
- 제9조의2 ④(용역을 타인에게 도급·위임하면 상세 페이지에 명시)는 **수업 자체를 남에게 맡기는 경우**에 관한 조항이다. 등록 대행과는 별개다 `[추정]`.
- 크몽 고객센터는 매크로 프로그램 거래를 경계하는 안내를 두고 있다. 다만 이는 예약·구매 매크로의 부정 거래에 관한 것이다 `[공식]` ([매크로 안내](https://kmong.com/support/customer-center/posts/801)).

**크몽 결론:** 웹 양식이라 **기술적으로는 가장 유력한 후보**다. 정책상 "비정상적인 방법"에 외부 도구 대리 입력이 포함되는지는 약관 문구만으로 판단할 수 없다 → **운영사 확인 필요** (부록 A-2).

### 최소 비교 계획 (R03 TASK-031과 맞춤)

R03 완료 기준에 맞춰 **동일 입력·시작 상태·종료 기준·측정값**을 고정한다.

- **시작 상태:** 강사가 이미 로그인한 크몽 등록 첫 화면
- **종료 기준:** 심사 신청 직전 화면에서 모든 필수 항목 입력 + 사진 첨부 완료. **실제 심사 신청 버튼은 누르지 않는다** (운영사 허용 전)
- **측정값:** 필수 항목 정확 입력 수 / 사진 첨부 성공 여부 / 강사 직접 작업 시간 / 강사 개입 횟수 / 가격·횟수 오류 수 / 실패 시 상태가 표시되는지
- **선행 조건:** 운영사 회신(부록 A-2)에서 테스트 자체가 제한되지 않을 것. 실제 강사 계정이 아닌 테스트 계정 사용 여부는 R01 결정 필요

## 8. 기획서에 반영할 결정 조건

1. **당근 모임 처리 방식.** 당근 모임과 강사용 과외/레슨 등록은 앱에서만 할 수 있음을 확인했다. MVP의 당근 범위를 아래 중 하나로 정한다. (R01·R02 결정 필요)
   - (a) 당근용 모임명·소개·첫 글·사진 묶음을 준비하고, **게시는 강사가 앱에서 직접** 한다
   - (b) 웹에서 작성할 수 있는 **당근 비즈니스(비즈프로필 소식)**로 게시처를 바꾸는 것을 검토한다
   - (c) 앱 자동화는 운영사가 명시적으로 허용할 때만 검토한다
   - (d) 앱의 **과외/레슨 등록(선생님 프로필)**을 모임 대신 또는 모임과 함께 게시처 후보로 둔다. 레슨 모집 전용 공간이라 모임의 "취지와 무관한 홍보" 제한과 덜 부딪칠 수 있다 `[추정]`. 다만 이것도 앱 경로이고, 동일·유사 프로필의 반복 업로드 제한이 있다 `[R02 재인용]`
   - 참고: 동료 강사는 "마지막 클릭만 하는 방식"을 원하지 않는다고 했다 `[R02 재인용]`. (a)는 이 조건과 충돌하므로 지불 의향을 다시 확인해야 한다.
2. **실제 제출 여부.** 크몽이 외부 도구의 대리 입력·심사 신청을 허용한다고 답하기 전까지는 **심사 신청 직전까지만** 검증하고 실제 제출은 하지 않는다. 회신에서 제한하면 크몽 자동 제출은 MVP에서 뺀다.
3. **실행 위치와 엔진.** 크몽 자동 입력을 검증할 때는 **강사 PC 로컬 실행(B)**을 1순위로 둔다. 서버 브라우저(C)는 세션이 서버에 남고(R1) 사진도 서버로 와야 해서(R8) 위험이 더 크다. 엔진은 **사진 첨부가 되는지**를 첫 통과 조건으로 둔다. 범용 AI 내장 브라우저처럼 파일 업로드를 못 하면 크몽 완료 기준을 채울 수 없다.
