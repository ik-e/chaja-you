## 1. 개요

기획안 V1.2의 핵심 피처 34개를 구현 전 검토할 수 있는 기능 단위로 풀어 쓴다. 각 기능의 예외는 [설계보고서](2026-11-25_R04_마이AI오피스_서비스절차_사용자흐름_설계보고서.md) Ⅱ부의 공통 오류 코드(ERR-xx)와 루프(Lx)로 연결한다. '(시스템)'은 사용자 화면 행동이 아닌 내부 처리이며, 관련 스토리 칸의 괄호는 R04 시스템 이벤트 ID다.

| 범위 표기 | 의미 |
|---|---|
| MVP | 기획 11.4의 제품 MVP 제안: 동일 원본 재사용, 신규·추가 등록, 대표 기존 정보 수정, 통합 결과 확인 (최소 2개 플랫폼) |
| 확장 | 기획 11.4의 제품 확장: 공고 갱신, 사용자 요청 기반 상태 관리 확대 |
| 조건부 | 기획 5.9·11.2의 자동 모니터링 (MVP 제외) |
| 추가 후보 | 기획 피처 목록에는 없으나 서비스 운영에 필요하다고 R04가 제안하는 기능 (근거 표기, R01 결정 필요) |

## 12. 공통 처리 원칙 (기획 9.2·9.3 요약)

- 외부 업무는 플랫폼 허용, 사용자 인증·권한 확인, 대상 식별, 입력 일치, 필수 조건 충족, 사용자 승인, 실행 조건 일치, 중복 위험 없음이 모두 충족될 때만 실행한다. 하나라도 어긋나면 실행하지 않고 이유와 필요한 조치를 안내한다.
- 실패·미확인·부분 성공을 구분하고, 응답이 없다고 등록되지 않았다고 단정하지 않는다. 미확인 외부 효과가 있으면 중복 실행을 막는다.
- 외부 플랫폼의 비밀번호·인증코드는 수집·저장하지 않는다. 작업용 세션은 업무 종료 후 폐기한다.
- 현 단계는 mock-only이며 실제 외부 실행은 하지 않는다. 플랫폼 대행 허용은 미확인이다(TASK-056).

## 13. 미결정 사항 (R01 결정 요청)

1. MVP 대상 플랫폼 2개 이상의 선정과 F14·F15·F20 수정 업무의 MVP 포함 범위
2. 인증 방식(플랫폼 공식 화면 직접 인증의 제공 방법)과 재시도 상한
3. 미확인 결과의 재조회 간격·상한, 상태 갱신 요청 빈도 제한
4. 진행 중 작업이 있는 원본의 수정·삭제 처리(ERR-22)
5. 자동 모니터링 최소 주기·기간·알림 채널
