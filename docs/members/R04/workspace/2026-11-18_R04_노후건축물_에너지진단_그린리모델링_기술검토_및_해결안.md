## 1. 시스템 아키텍처 및 데이터 흐름도

## 2. 핵심 기술 난제 및 세부 엔지니어링 해결안

### [난제 1] 건축물대장 주소와 국토부 에너지 소비량 API 간의 '건물 고유 식별자' 불일치
- **문제점**:
  - 사용자는 "마포대로 123"과 같은 도로명주소를 입력하지만, 건축물대장 API는 `대지위치(지번)` 및 `관리건축물대장PK`, 에너지 소비량 API는 `대지위치`와 `시군구코드+법정동코드+번지` 형식을 요구하여 키 매핑 실패 빈발.
- **해결안 (행안부 도로명주소 API 지오코딩 + PNU 19자리 정규화)**:
  1. **PNU(필지토지코드 19자리) 자동 변환**:
     - 도로명주소를 행안부 주소 API를 통해 `[시도(2) + 시군구(3) + 읍면동(3) + 리(2) + 대지구분(1) + 본번(4) + 부번(4)]` 19자리 고유 PNU 코드로 변환.
  2. **국가건물에너지통합관리시스템 PK 결합 캐싱**:
     - PNU 코드를 기반으로 건축물대장 표제부와 월별 에너지 소비량 API를 1:1 매핑하고, 매핑 결과를 Redis에 30일간 캐시.

### [난제 2] 계절별 기후 차이에 따른 에너지 소비량 왜곡 (날씨 보정 부재)
- **문제점**:
  - 단순히 작년과 올해 가스 사용량을 비교하면, 올겨울이 유독 따뜻했을 경우 건물이 단열을 잘해서 가스를 적게 쓴 것으로 오판하는 착시 현상 발생.
- **해결안 (기후도일 HDD / CDD 기반 기상 정규화 회귀분석)**:
  1. **난방도일(HDD) 및 냉방도일(CDD) 계산**:
     - 기준 온도(난방 $18^\circ\text{C}$, 냉방 $24^\circ\text{C}$)를 바탕으로 해당 연도 해당 월의 일별 외기 기온 데이터를 적분하여 $\text{HDD} = \sum \max(0, 18 - T_{\text{avg}})$, $\text{CDD} = \sum \max(0, T_{\text{avg}} - 24)$ 산출.
  2. **단위 기후도일당 에너지 소비 원단위($\text{kWh}/\text{m}^2/\text{HDD}$)** 산출:
     - 날씨 영향을 제거한 순수 건물의 열성능(Thermal Performance) 원단위를 계산하여 동일 행정동 내 유사 건물 100개소의 평균값과 정밀 비교.

### [난제 3] 비공개 단열재 두께 및 창호 스펙 ➔ 허가연도별 역추정 룰베이스
- **문제점**:
  - 도면이 없는 노후 건물은 벽체 내부에 어떤 단열재가 들어갔는지 알 수 없음.
- **해결안 (건축법 개정 이력 기반 열관류율(U-value) 역추정 매트릭스)**:
  - 건축물대장의 '허가일자'를 기준으로 당시 적용되던 국토교통부 '건축물의 에너지절약설계기준' 법정 기준을 자동 매핑:
    - **1979년 이전**: 외벽 단열 기준 전무 (열관류율 $1.5\sim2.0\,\text{W}/\text{m}^2\text{K}$, 단열 등급 F)
    - **1987년~2000년**: 단열재 50mm 의무화 (열관류율 $0.58\,\text{W}/\text{m}^2\text{K}$, 단열 등급 D)
    - **2001년~2012년**: 단열재 80~100mm (열관류율 $0.36\,\text{W}/\text{m}^2\text{K}$, 단열 등급 C)
    - **2018년 이후(최신)**: 고단열 150mm 이상 (열관류율 $0.17\,\text{W}/\text{m}^2\text{K}$, 단열 등급 A)
  - 이를 통해 비파괴 실측 없이도 외벽과 창호의 예상 열손실량을 이론적으로 역추정.

### [난제 4] 지자체 BRP 및 국토부 지원 조건의 수시 변동성 대응
- **문제점**:
  - 서울시 BRP(무이자 융자)는 매년 1월 또는 2월에 사업 공고가 발표되며, 이자율, 융자 한도, 상환 기간이 변경될 수 있음.
- **해결안 (지원 조건 스키마 기반 룰 엔진 모듈화)**:
  - 지원 규정을 하드코딩하지 않고, `지원한도`, `금리(0%)`, `상환기간(8년)`, `최소 에너지 절감률(20% 이상)` 등의 파라미터를 JSON 설정 파일로 분리하여 지자체 고시 개정 시 실시간 업데이트 반영.

- **Backend / API**: Python 3.11, FastAPI, Pydantic v2
- **Agent Orchestration**: LangGraph, LangChain
- **Energy & Statistics**: Pandas, Numpy, Scipy (Degree-Days 날씨 정규화 및 회귀분석)
- **Data & Cache**: PostgreSQL (건축물 제원 캐시), Redis (PNU 매핑 및 API 응답 캐시)
- **LLM**: Claude 3.5 Sonnet / GPT-4o (비정형 진단 요약 및 시방 체크리스트 합성)
- **Document Rendering**: WeasyPrint / ReportLab (BRP 신청용 친환경 진단서 PDF 자동 발행)
