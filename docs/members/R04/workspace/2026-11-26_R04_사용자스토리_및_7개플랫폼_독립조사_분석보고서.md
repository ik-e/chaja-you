## 5. 승인 맥락과 결정 요청

이전 Orca 세션의 제한된 터미널 캡처에는 사용자가 안 A 방향(연락처/가격 규격 분리와 강사 선택 대안 검토)을 승인한 맥락이 있다. 원본 세션 transcript와 저장소의 불변 사람 응답 경로는 확보되지 않았다. independent-result.json의 approval_context에 출처 유형과 한계를 기록했다. 이 승인 맥락을 새로운 R01 응답 문서로 만들거나 구체 DB·변환 알고리즘의 최종 채택으로 해석하지 않는다.

현재 추가 지시는 사용자 스토리 통합 및 서비스 범위 확정 이후 R01이 최종 설계 기준을 결정하도록 명시한다. 따라서 플랫폼별 연락처 노출·자동 마스킹·자동 환산·가격 재설정·감사 로그 보존기간은 제안 또는 결정 요청으로 유지한다. “커뮤니티 연락처 필수”, “마켓형 전체 외부 링크 차단”, “탈잉은 60/120분만 가능”, “감사 로그 법정 5년”은 확인된 조사 결론이 아니다.

## 6. 참고 설계 제안 (미채택)

기존 LessonContactChannel·PlatformPayloadTemplate·external_objects 등의 엔터티 목록과 BLOCKED_AWAITING_CHOICE, 비례 환산 알고리즘은 R04의 참고 설계 아이디어다. 현재 TASK-056 산출물에서 확정 설계 기준으로 사용하지 않는다.

공개용 문의 채널을 원본 정보와 구별해 관리할지, 플랫폼별 출력 허용 여부를 어떻게 검증할지, 시간/가격 충돌 시 어떤 실제 제공 조건을 강사에게 재확인할지는 R01 통합 검토 질문으로 반환한다. 비례 환산·전용 가격 입력·플랫폼 제외는 대안 후보이며, 시간 변경이 수업 가치를 보존하거나 실제 제공 가능한지는 별도 확인해야 한다.

후속 순서는 사용자 행동 통합·서비스 범위 결정 → 필요한 데이터 의미/소유권/상태 검토 → R01 DB/알고리즘 결정이다. 현재 DB/API/모의 구현은 이번 보완으로 변경하지 않는다.
