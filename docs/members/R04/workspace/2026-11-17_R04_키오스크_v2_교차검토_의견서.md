## 1. 종합 총평 및 v1 ➔ v2 피벗 성과 분석

### 1.1 총평
- **평가 요약**: 기존 '가전제품 사양 비교' 안에서 완전히 피벗하여 일상에서 누구나 겪는 구체적 결핍인 **"키오스크 메뉴 선택 장애와 뒷사람 눈치"**를 타깃한 결정은 매우 탁월합니다.
- **피드백 수용도**: v1에 대해 팀원들이 제기했던 핵심 비판(체크박스 필터와의 차별성 부재, 알레르기 의료/법적 리스크, POS/하드웨어 연동 부담)을 정면으로 수용하여 **P0 3자 비교실험(A/B/C)**과 **웹 프로토타입 기반의 스코프 다이어트**를 단행한 점이 매우 돋보입니다.
- **방향성 적합도**: 3~5분 발표용으로 청중(멘토 및 평가위원)이 일상 경험에서 즉각 공감할 수 있는 직관성을 갖추었습니다.

### 1.2 v1 대비 뚜렷한 3대 개선점
1. **문제 정의의 실체화**: '노약자·장애인 디지털 소외'라는 거대 담론 대신, "메뉴가 20개 이상일 때 결정을 내리지 못해 대기 줄 압박을 받는 20~40대 손님"으로 타깃을 명확히 좁힘.
2. **비교 우위 중심의 P0 실험 설계**: '무조건 생성형 AI가 좋다'는 주장을 버리고, `A(기본 키오스크) vs B(다속성 필터) vs C(LLM 추천)` 3개 군의 대조 실험을 통해 AI의 증분 가치(선택 소요 시간 단축 여부)를 직접 입증하겠다는 태도가 매우 설득력 있음.
3. **8주 실현 가능성 확보**: 키오스크 하드웨어, 매장 POS API, 음성 인식, 결제 연동 등 외부 제어 불가능한 의존성을 배제하고, 웹 브라우저 기반의 컴팩트한 프로토타입으로 축소함.

## 3. 핵심 5대 논리적 맹점 및 구조적 취약점 (Critical Deep-Dive)

제3자 검토자로서 멘토진이 가장 날카롭게 파고들 수 있는 5가지 구조적 취약점입니다.

### 맹점 1. [UX 모순] 대기 압박(뒷사람 눈치) 상황에서 대화형 인터랙션의 역효과
- **데이터 사실**: 한국소비자원 조사에서 키오스크 불편 1위는 **"뒷사람 눈치(44.9%)"**입니다.
- **구조적 충돌**: 뒤에 사람이 줄을 서 있는 피크타임에 손님이 키오스크 화면 앞에서 가상 키보드로 타이핑을 하거나 챗봇과 여러 번 대화를 주고받으면 주문 소요 시간이 오히려 늘어납니다. 이는 사용자가 가장 두려워하는 "뒷사람 눈치"를 극대화하는 역효과를 낳습니다.
- **공격 포인트**: *"손님이 뒤에 사람 서 있는데 거기서 챗봇이랑 대화하고 있겠어요? 그냥 아무거나 누르고 말죠."*

### 맹점 2. [비AI 대비 우위] 단순 필터(다속성 검색) 대비 AI의 승리 조건이 너무 협소함
- **대안의 강력함**: "맵지 않고, 1만 원 이하, 면류" 같은 정형화된 조건은 키오스크 상단에 체크박스 3개(라디오 버튼)를 누르면 0.5초 만에 필터링됩니다. DB 쿼리 하나면 끝나는 작업에 토큰 비용과 1~2초의 API 지연시간을 투입할 이유가 없습니다.
- **위험 요소**: P0 실험에서 만약 'B군(다속성 필터)'이 'C군(LLM 추천)'보다 선택 시간도 짧고 만족도도 비슷하게 나온다면, 프로젝트의 핵심 존재 이유가 부정당할 수 있습니다.
- **공격 포인트**: *"이거 상단 필터 3개 누르면 1초 만에 나오는 건데, 굳이 생성형 AI를 왜 써야 하죠?"*

### 맹점 3. [점주 온보딩] 영세 점주가 메뉴 메타데이터를 구축·유지보수할 수 있는가?
- **현실적 한계**: R05 추천 로직이 정확히 동작하려면 매장 메뉴별로 맵기 단계, 알레르기 22종 유발 여부, 탄단지 비율, 조리 방식 등이 사전에 정밀하게 태깅되어 있어야 합니다.
- **병목 지점**: 분식점, 패스트푸드점 영세 점주는 포스기에 신규 메뉴 이름과 가격을 등록하는 것조차 버거워합니다. 점주에게 복잡한 메타데이터 입력을 요구한다면 이 솔루션은 매장 도입이 원천적으로 불가능합니다.
- **공격 포인트**: *"점주가 바빠 죽겠는데 메뉴마다 알레르기 태그 달고 칼로리 입력하고 있겠습니까?"*

### 맹점 4. [법적/안전성] 알레르기 오추천 시 법적 책임 및 무인 매장 현실
- **컴플라이언스 리스크**: 기획안에 "알레르기 표시는 식약처 지정 22종 기반 태그 매칭으로 한정"하고 "직원에게 확인하세요"를 병기한다고 적혀 있습니다.
- **현실의 맹점**: 키오스크가 도입되는 대다수 매장은 '직원이 없거나 조리만 하느라 대화가 불가능한 무인/초소형 매장'입니다. 만약 AI가 안전하다고 추천한 메뉴에 미표기된 알레르기 성분이 있거나 교차 오염이 발생할 경우, 면책 문구 하나로 법적 분쟁을 피하기 어렵습니다.
- **공격 포인트**: *"무인 매장인데 직원한테 확인하라니요? AI 믿고 먹었다가 아나필락시스 쇼크 오면 누가 책임지나요?"*

### 맹점 5. [실험 설계의 함정] 가상 분식점 6개 메뉴의 변별력 상실
- **인지공학적 한계**: 기획안에 제시된 6개 메뉴(신라면, 너구리, 순한라면, 참치김밥, 치즈김밥, 야채김밥)는 인간의 시각적 스캔(Visual Scanning)으로 1~2초면 전부 파악됩니다.
- **실험 왜곡**: 선택지가 6개뿐이면 사용자는 필터나 AI를 켜는 시간(3~5초)보다 눈으로 보고 바로 누르는 것이 훨씬 빠릅니다. 따라서 가상 분식점 6개 메뉴셋으로는 탐색 피로도(Choice Overload)가 전혀 발생하지 않아 실험 결과가 왜곡될 위험이 큽니다.
- **공격 포인트**: *"메뉴가 6개밖에 안 되는데 추천 도우미가 왜 필요합니까? 눈으로 보는 게 더 빠른데요?"*

## 4. 구체적 기술 및 UX 보완 해결안 (Actionable Solutions)

위 5대 맹점을 극복하고 멘토링에서 압도적인 방어력을 갖추기 위한 구체적 솔루션입니다.

### Solution 1. [프론트엔드 UX] '2-Step Quick-Tap' 및 '대기 줄 모바일 QR 프리오더'

```
[대기 줄 모바일 프리오더 흐름]
매장 대기 줄 (배너 QR 촬영) ➔ 모바일 웹에서 10초 추천 ➔ '추천 바코드' 획득 ➔ 키오스크에 바코드 스캔 ➔ 즉시 결제 (5초 컷!)

[키오스크 현장 2-Step Quick-Tap UI 흐름]
+-----------------------------------------------------------+
|  [결정하기 어려우신가요? 10초 맞춤 추천받기] (화면 상단 배너) |
+-----------------------------------------------------------+
| Step 1. 지금 어떤 상황이신가요? (버튼 1개 터치)               |
|  [ 속 편한 해장 ]   [ 든든한 단백질 ]   [ 가벼운 다이어트 ]   |
|  [ 매콤 스트레스 해소 ]   [ 시간 없을 때 초스피드 ]            |
+-----------------------------------------------------------+
| Step 2. 원하는 스타일은? (버튼 1개 터치)                     |
|  [ 따뜻한 국물 ]   [ 깔끔한 밥류 ]   [ 바삭한 튀김류 ]        |
+-----------------------------------------------------------+
| ➔ AI 결과: "속 쓰릴 땐 자극 없는 [순한 계란라면 + 야채김밥]"  |
|    [ 이 조합으로 바로 주문 ]  /  [ 다른 조합 보기 ]         |
+-----------------------------------------------------------+
```
- **효과**: 텍스트 입력과 복잡한 대화를 완전히 제거하여 **2번의 터치(Quick-Tap)**로 3초 만에 추천 완료.
- **모바일 연계**: 대기 줄이 길 때는 매장 입구 QR로 모바일에서 미리 추천받아 바코드만 키오스크에 찍는 UX를 제시하여 **'뒷사람 눈치' 문제를 완벽히 해결**.

### Solution 2. [비AI 필터 차별화] '비정형 감성·상황 맥락' 중심 질의 시나리오
- 체크박스로 가능한 정형 조건(가격, 맵기)을 버리고, **오직 LLM만이 풀 수 있는 비정형 상황 프롬프트**에 집중합니다.
  - *비AI 필터 영역*: "가격 7천원 이하 AND 맵기 1단계" (체크박스 승)
  - *LLM 에이전트 영역*: *"어제 야근하고 과음해서 속은 더부룩한데 첫 끼라 너무 기름진 건 부담스러운 메뉴"* (LLM 압승)
- **발표 강조점**: "단순 스펙 검색은 기존 필터에 맡기고, 저희 에이전트는 **손님의 감성과 신체 상황을 메뉴의 식감·온도·영양과 결합하는 큐레이터**입니다."

### Solution 3. [점주 온보딩] '메뉴판 사진 1장 자동 구조화 에이전트'
- 점주에게 데이터를 수기 입력하라고 하지 않습니다.
- **경량 온보딩 파이프라인**: 점주가 스마트폰으로 메뉴판 사진 1장을 찍어 올리거나 배달의민족 메뉴 텍스트를 복사해 붙이면, 백그라운드 멀티에이전트(OCR + LLM 태깅 에이전트)가 자동으로 메뉴명, 가격, 예상 식자재, 맵기, 알레르기 태그를 JSON으로 구조화합니다.
- 점주는 생성된 JSON 카드에서 틀린 부분만 터치로 검수(Human-in-the-loop)합니다.

### Solution 4. [알레르기 가드레일] 3단계 컴플라이언스 안전 팝업 프로토콜
1. **식약처 22종 태그 매칭**: 알레르기 필터링은 LLM의 환각(Hallucination)에 맡기지 않고, DB에 사전 등록된 정형 태그 매칭(Deterministic Logic)으로 강제 격리.
2. **고위험군 주문 차단**: 심각한 알레르기(땅콩, 갑각류 등) 체크 시 해당 메뉴는 추천 목록에서 원천 배제.
3. **UI 면책 배너**:
   > *"본 추천은 일반 식자재 정보 기반이며, 조리 과정에서의 교차 오염을 100% 방지할 수 없습니다. 중증 알레르기 환자는 주문 전 반드시 매장 관리자에게 확인해 주시기 바랍니다."*

### Solution 5. [PoC 실험설계] 25종 복합 메뉴셋 및 3대 정량 관측 지표
- **메뉴셋 확장**: 6개가 아닌 **25개 메뉴(메인 12개, 사이드/토핑 8개, 음료/세트 5개)**로 가상 매장 DB 구축 (Choice Overload 유발).
- **3대 정량 관측 지표 정의**:
  1. **주문 결정 소요 시간 (초)**: 첫 화면 진입부터 최종 장바구니 담기까지의 시간 (A군 45초 ➔ C군 15초 단축 목표).
  2. **화면 탐색 이탈 횟수 (회)**: 카테고리 탭 전환 및 취소/뒤로가기 클릭 횟수 (탐색 피로도 지표, 50% 이상 감소 목표).
  3. **추천 수용률 (%)**: AI가 제안한 2개 메뉴 중 하나를 실제로 선택한 비율 (목표치 60% 이상).

## 5. 멘토링 킬러 질문(Killer Questions) & 디펜스 스크립트

오늘 저녁 20:00 멘토링에서 예상되는 공격 질문과 100점짜리 답변 스크립트입니다.

### Q1. "상단에 체크박스 필터(안 매운 것, 1만원 이하) 두면 끝인데 왜 LLM이어야 하죠?"
> **[답변 스크립트]**
> "정확한 지적이십니다. 정형화된 스펙 필터링은 체크박스가 훨씬 빠르고 비용도 안 듭니다. 그래서 저희는 **P0에서 A(기본) vs B(필터) vs C(LLM) 3자 비교실험을 정면으로 배치**했습니다. 
> 저희가 해결하려는 진짜 문제는 스펙이 아니라 **'어제 과음해서 속 쓰린데 든든한 것', '다이어트 중인데 씹는 맛이 있는 것' 같은 비정형 상황과 감성 맥락**입니다. 단순 필터는 이런 복합 맥락을 처리하지 못합니다. 만약 3자 실험에서 LLM이 필터 대비 의미 있는 시간 단축과 만족도를 증명하지 못한다면, AI 도입을 고집하지 않고 필터 중심 경량화로 전환한다는 명확한 반증 기준을 세워두었습니다."

### Q2. "뒤에 줄 서서 눈치 보이는데 키오스크에서 챗봇이랑 대화할 여유가 있나요?"
> **[답변 스크립트]**
> "키오스크 앞에서의 대화는 오히려 독이 될 수 있습니다. 그래서 저희는 **'2-Step Quick-Tap'** 방식을 취합니다. 텍스트 타이핑 없이 '상황 버튼 1번, 스타일 버튼 1번' 단 2번의 터치로 3초 만에 2개 메뉴를 요약 추천합니다.
> 나아가 대기 줄이 긴 피크타임에는 **매장 밖 줄 서 있는 동안 입구 QR 코드로 모바일에서 미리 10초 추천을 받고, 키오스크에서는 생성된 바코드만 찍고 5초 만에 결제하는 '모바일 프리오더 연계 UX'**로 뒷사람 눈치 문제를 원천 차단하도록 설계했습니다."

### Q3. "8주 동안 실제 키오스크 기기나 매장 POS에 연동하는 게 가능한가요?"
> **[답변 스크립트]**
> "첫 8주 MVP에서는 복잡한 키오스크 하드웨어나 POS API 연동을 과감히 스코프 아웃했습니다. 상용 하드웨어 연동은 8주 안에 검증하기 힘든 외부 의존성이기 때문입니다.
> 대신 **태블릿 및 웹 브라우저 환경에서 실제 키오스크 UI/UX를 1:1로 모사한 반응형 웹 프로토타입**을 구축하고, 실제 사용자 30명을 대상으로 A/B/C 통제 실험을 진행하여 핵심 가설인 '메뉴 선택 시간 단축'을 완벽하게 검증해 낼 것입니다."

### Q4. "알레르기 안내를 AI가 했다가 환각(Hallucination)으로 사고가 나면 어떡합니까?"
> **[답변 스크립트]**
> "알레르기와 안전 영역은 절대 LLM의 생성에 맡기지 않습니다. 식약처 지정 22종 알레르기 성분은 **DB에 사전 구축된 정형 데이터로만 결정론적(Deterministic) 매칭**을 수행합니다. 
> 또한 중증 알레르기 체크 시 해당 메뉴는 추천 풀에서 원천 차단하며, UI 화면에 교차 오염 가능성에 대한 법적 면책 배너를 강제 노출하여 안전 가드레일을 3중으로 구축했습니다."

## 6. 3~5분 멘토링 피칭 추천 구조 (Pitching Flow)

1. **오프닝 & 문제 공감 (1분)**:
   - "키오스크 앞에 섰는데 뒤에 줄은 점점 길어지고, 메뉴는 수십 개라 뇌정지 온 경험 다들 있으실 겁니다. 키오스크 이용자 불편 1위가 바로 '뒷사람 눈치(44.9%)'입니다."
2. **핵심 솔루션 (1분)**:
   - "결정장애 손님을 위한 10초 메뉴 큐레이터입니다. 긴 텍스트 대화 대신, '상황과 기분'을 딱 2번 터치하면 20가지 메뉴 중 내게 맞는 최적의 2가지를 즉시 압축 추천합니다."
3. **왜 AI인가 & 비교실험 설계 (1.5분 - 승부처)**:
   - "단순 필터는 '안 매운 것'만 찾지만, LLM은 '속 쓰린데 든든한 것'을 이해합니다."
   - "저희는 무조건 AI가 우월하다고 주장하지 않습니다. `기존 화면 vs 필터 vs LLM`의 3자 대조 실험(P0)을 통해 AI가 진짜 결정 시간을 줄이는지 데이터로 검증하겠습니다."
4. **8주 계획 & 방어선 (0.5분)**:
   - "하드웨어 연동 없이 웹 기반 가상 키오스크로 2주 안에 PoC를 끝내고, 사용자 30명 실험을 통해 실측 지표를 확보하겠습니다."
