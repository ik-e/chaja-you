# [기획 제안] 공공데이터를 활용한 리서치 멀티에이전트 서비스 구축 아이디어 10선

- **작성일자**: 2026-11-18
- **작성자**: R04 (원민 - 프론트엔드 / 사용자 흐름 담당)
- **작성 목적**: 주요 공공·빅데이터 플랫폼(문화빅데이터플랫폼, KBDS, 데이터원윈도우, 공공데이터포털, 서울 열린데이터광장)의 오픈 API 및 파일 데이터를 연계하여, 단순 스크래핑/대시보드를 넘어 **수집·가공·교차검증·평가·리포팅**을 자율 수행하는 리서치 멀티에이전트 서비스 기획 후보군을 체계적으로 도출함.

---

## 1. 개요 및 플랫폼 분석

### 1.1 대상 데이터 플랫폼 및 성격
1. **문화빅데이터플랫폼 (`bigdata-culture.kr`)**: 문화, 예술, 관광, 체육, 콘텐츠 소비 트렌드, 지역 축제, 도서관 대출, 영화 예매/관람 데이터
2. **국가바이오데이터스테이션 KBDS (`kbds.re.kr`)**: 범부처 바이오 연구 데이터(유전체, 단백체, 대사체, 화합물, 임상/전임상 데이터맵)
3. **데이터원윈도우 (`data1window.kr`)**: NIA 빅데이터 플랫폼 통합 검색(제조, 소비, 유통, 통신 등 산업 데이터)
4. **공공데이터포털 (`data.go.kr`)**: 대한민국 정부 표준 오픈 API 및 공공 데이터셋(부동산, 교통, 복지, 보건의료, 기상, 특허 등)
5. **서울 열린데이터광장 (`data.seoul.go.kr`)**: 서울시 실시간 도시데이터(인구·혼잡도·상권), 대기오염, 지하철/버스, 상권분석(우리마을가게)

### 1.2 왜 '리서치 멀티에이전트'인가? (기존 대안과의 차별점)
- **단순 API 결합(대시보드)의 한계**: 단순히 A 차트와 B 차트를 나란히 배치하는 것만으로는 이기종 데이터 간의 인과관계나 상충 관계(Trade-off)를 해석할 수 없음.
- **단일 LLM(챗봇)의 한계**: 수천 건의 공공데이터 테이블과 법정 규제 텍스트를 한 번에 프롬프트로 처리할 경우 환각(Hallucination) 및 수치 왜곡 발생.
- **멀티에이전트의 강점**: **[데이터 수집/정규화 에이전트] ➔ [규제·법률/특허 팩트체커] ➔ [상충 조건 교차검증기] ➔ [의사결정 보고서 합성기]**로 책임을 분리하여 높은 신뢰도와 설명 가능한(Explainable) 추론을 보장함.

### [아이디어 1] 바이오·제약 R&D 타깃-특허-임상 선행연구 교차검증 에이전트
> **"신약 후보물질의 바이오 오믹스 데이터와 특허·임상 현황을 자동 교차분석하여 R&D 실패율을 줄이는 연구 비서"**

- **주요 활용 데이터**:
  - **KBDS (국가바이오데이터스테이션)**: 유전체, 단백체, 화합물 데이터맵 및 연계 데이터
  - **공공데이터포털 (data.go.kr)**: KIPRIS 특허 정보 API, 식품의약품안전처 임상시험 승인 현황 API
- **타깃 사용자 & Pain Point**:
  - 바이오 스타트업 연구원, 신약 개발 기획자.
  - 논문, 유전체 데이터, 특허 공보, 임상 사이트(식약처/ClinicalTrials)를 각자 검색하느라 수개월이 소요되며, 이미 특허가 출원되었거나 임상에서 독성으로 실패한 타깃을 뒤늦게 발견하는 막대한 손실 발생.
- **멀티에이전트 역할 분담**:
  1. *오믹스 탐색 에이전트*: KBDS 데이터맵에서 질환 관련 타깃 유전자/단백질 상호작용 네트워크 수집
  2. *선행특허 스크리너*: 타깃 물질의 물질특허/용도특허 청구항 침해 여부 검색
  3. *임상 이력 크로스체커*: 식약처 임상 데이터에서 해당 타깃의 기진행 임상 단계 및 중단 사유(부작용 등) 검증
  4. *R&D 타당성 브리퍼*: 타깃 유효성, 특허 공백(FTO), 임상 성공 가능성을 3축으로 종합 평가한 실사(Due Diligence) 리포트 발행
- **8주 MVP 검증 포인트**: 특정 1개 희귀 질환(예: 알츠하이머 타깃 단백질군)으로 범위를 한정하여 Mock 오믹스 ➔ 특허 ➔ 임상 1건 파이프라인 실증.

### [아이디어 2] 지역 축제·문화행사 흥행 예측 및 프로그램 최적화 에이전트
> **"문화 소비 성향과 실시간 도시 유동인구를 결합하여 지자체 축제의 흥행성을 사전 시뮬레이션하는 기획 에이전트"**

- **주요 활용 데이터**:
  - **문화빅데이터플랫폼**: 지역별 문화소비 성향, 공연/축제 관람객 데이터, 도서/콘텐츠 선호도
  - **서울 열린데이터광장**: 서울 실시간 도시데이터(인구·혼잡도·상권), 지하철/버스 승하차
  - **공공데이터포털**: 기상청 과거 기상관측 데이터 및 계절별 강수/기온 예보
- **타깃 사용자 & Pain Point**:
  - 지자체 문화재단 축제 기획자, 이벤트 대행사.
  - 수억 원의 예산을 투입하면서도 기획자의 감에 의존해 일정을 잡고 부스를 배치하다가, 인근 상권 유동층의 연령대 불일치나 기상 악화로 행사 참패 및 예산 낭비.
- **멀티에이전트 역할 분담**:
  1. *문화소비 프로파일러*: 타깃 지역민의 최근 3개년 공연·축제·예술 선호 카테고리 추출
  2. *도시공간 매퍼*: 행사 예정지 반경 1km의 시간대별·연령별 유동인구 밀집 패턴 분석
  3. *위험요소 검증기*: 동시기에 열리는 인근 유사 행사 스케줄 및 기상 악천후 리스크 교차 대조
  4. *프로그램 편성기*: 시간대별 최적 무대 프로그램, 식음료(F&B) 부스 구성, 예상 관람객 수를 도출한 기획안 생성

> **"소비 트렌드 빅데이터로 신제품 컨셉을 잡고, 공공 안전·KC 인증 규제를 사전 필터링하는 상품기획 에이전트"**

- **주요 활용 데이터**:
  - **데이터원윈도우 (data1window.kr)**: 제조·소비 데이터, 유통/판매 트렌드 데이터
  - **공공데이터포털**: 국가기술표준원 KC인증 정보, 식약처 품목제조보고 데이터, 한국소비자원 위해정보

  3. *인증·규제 감사관*: 원재료/구성품 기준 필수 법정 인증 항목 및 제출서류 자동 도출
  4. *출시 로드맵 설계자*: 원가·트렌드 점수와 인증 소요 기간을 고려한 출시 체크리스트 발행

  - **서울 열린데이터광장**: 서울시 우리마을가게 상권분석서비스 API(개·폐업률, 분기별 매출, 임대료)
  - **공공데이터포털**: 소상공인시장진흥공단 상가(상권)정보, 행안부 인구통계
- **타깃 사용자 & Pain Point**:
  - 소자본 외식업 예비 창업자, 소상공인 폐업 위기 점주.
  - 포털 상권분석은 "유동인구 많음"만 보여줄 뿐, 실제 프랜차이즈가 밀고 들어와 개인 매장이 1년 내 폐업하는 '상권 침체/임대료 폭등 징후'를 경고해 주지 못함.
- **멀티에이전트 역할 분담**:
  1. *상권 역학 추적기*: 반경 500m 내 개인 매장 대비 프랜차이즈 점유율 변화 추세 계산
  2. *매출·수익성 시뮬레이터*: 요일/시간대별 실측 매출과 추정 임대료·원가를 차감한 순이익 추정
  3. *폐업 패턴 매칭기*: 과거 5개년 해당 필지/건물의 평균 영업 유지 기간 및 폐업 업종 이력 추적
  4. *창업 안전진단관*: "이 자리에서 김밥집 창업 시 2년 내 생존 확률 42%" 등 냉정한 반대 근거 중심 진단서 출력

> **"복잡한 법령 기준과 자격 조건을 다각도로 대조하여 숨은 공공 혜택을 찾아주는 복지 코파일럿"**

- **주요 활용 데이터**:
  - **공공데이터포털**: 보건복지부 복지로 복지서비스 목록 및 상세 조건 API
  - **서울 열린데이터광장**: 자치구별 취약계층 현황, 1인 가구 지원 조례 데이터, 청년수당/주거지원 기준
- **타깃 사용자 & Pain Point**:
  - 복지 상담 공무원, 사회복지사, 복지 취약계층(청년 독립가구, 한부모, 고령자).
  - 복지 제도가 중앙부처, 지자체, 교육청 등으로 쪼개져 있어, 내가 받을 수 있는 혜택이 무엇인지 알지 못해 신청주의 복지의 사각지대에 방치됨.
- **멀티에이전트 역할 분담**:
  1. *가구 프로파일 파서*: 사용자의 나이, 소득구간, 주거형태, 가구원 구성을 비정형 인터뷰로 추출
  2. *복지 DB 매칭 에이전트*: 중앙부처 복지서비스 조건과 지자체별 특화 조례 지원책 1차 필터링
  3. *자격 결격사유 검증기*: 중복 수혜 금지 조항(예: 국민취업지원제도 ↔ 청년수당) 자동 판별
  4. *신청 동선 가이드*: 구비 서류 목록과 관할 주민센터/온라인 신청 링크를 타임라인으로 제공

### [아이디어 6] 노후 건축물 에너지 소비 이상 진단 및 그린리모델링 보조금 매칭 에이전트
> **"건물별 전기·가스 실측 데이터를 동종 건물과 비교 진단하고, 지자체 친환경 지원사업을 매칭하는 ESG 에이전트"**

- **주요 활용 데이터**:
  - **공공데이터포털**: 국토교통부 건축물대장 API, 건물에너지 소비량(전기/수도/가스) 데이터 API
  - **서울 열린데이터광장**: 서울시 에코마일리지 현황, 그린리모델링 보조금 지원사업 공고
- **타깃 사용자 & Pain Point**:
  - 중소형 빌딩 건물주, 자산관리회사(PM), 친환경 건축 시공사.
  - 내 건물이 에너지를 과소비하고 있는지 객관적 비교 기준이 없으며, 정부와 지자체의 막대한 친환경 리모델링 지원금(이자 지원, 보조금) 정책이 매년 바뀌어 혜택을 놓침.
- **멀티에이전트 역할 분담**:
  1. *건물 스펙 추출기*: 건축물대장에서 준공년도, 구조, 연면적, 단열기준 적용 연도 자동 파싱

## 3. 서비스 기획 시 멀티에이전트 성공을 위한 4대 검증 프레임워크

1. **단순 API 결합 vs 멀티에이전트 판단**:
   - `단순 API`: A값과 B값을 단순히 한 화면에 나란히 보여주는 대시보드 (에이전트 불필요)
   - `멀티에이전트`: A(문화 소비)와 B(유동인구)와 C(날씨)를 결합하여 **"서로 충돌하는 조건 속에서 최적의 의사결정을 추론하고 반대 근거를 제시"**하는 구조여야 함.
2. **신뢰성(Fact-checking) 분리**:
   - 데이터 추출과 추론을 단일 LLM에 맡기면 환각(Hallucination)이 발생함.
   - 반드시 **"공공 API 정량 데이터만 추출하는 에이전트"**와 **"이를 검증하는 룰 기반 에이전트"**, **"최종 리포트를 작성하는 생성 에이전트"**를 분리해야 실서비스가 가능함.
3. **8주 MVP 데이터 접근성 확인**:
   - 승인 절차(인증키 발급)가 1~2일 내에 즉시 완료되는 오픈 API를 1차 코어로 삼고, 심사 기간이 길거나 이용약관상 크롤링이 제한된 사이트는 모의 샘플(Mock Data)로 실험을 격리하는 전략을 권장함.
4. **결정권자와 비용 주체 분리 인식**:
   - 서비스를 이용하는 실무자(연구원, 기획자, 시민)와 도입을 결정/결제하는 주체(지자체, 연구소, 기업)의 니즈를 분리하여 ROI를 제시해야 함.
