## 1. 시스템 아키텍처 및 데이터 흐름도

WelfareNavigator는 **"자연어 상담 텍스트 비식별화 및 슬롯 필링 ➔ 보건복지부 소득인정액 룰 계산 ➔ 중앙/지자체 복지 매칭 ➔ 중복수혜 배타적 엣지 그래프 ILP 최적화 ➔ 신청 로드맵 합성"** 파이프라인으로 구성됩니다.

```mermaid
graph TD
    User["사용자 (취약계층 당사자 / 사회복지사)"] -->|대화형 상담 입력 (나이/주거/소득/취약상황)| API["FastAPI Gateway / Orchestrator"]

    subgraph Privacy_Parser["개인정보 비식별화 및 슬롯 필러"]
        Masker["PII 마스커 (이름/주민번호 제거)"] --> SlotFiller["복지 자격 슬롯 필러 (Pydantic v2)"]
    end

    subgraph Orchestration["멀티에이전트 오케스트레이션 레이어 (LangGraph)"]
        direction TB
        AG1["에이전트 1: 가구 프로파일러<br/>(소득인정액 & 기준중위소득% 계산)"]
        AG2["에이전트 2: 복지 DB 매칭기<br/>(중앙부처 400개 + 자치구 조례 결합)"]
        AG3["에이전트 3: 중복수혜 배제 최적화기<br/>(배타적 엣지 탐색 & ILP 수혜액 극대화)"]
        
        AG1 --> AG2 --> AG3 --> Synthesizer["에이전트 4: 원스톱 신청 동선 가이드"]
    end

    subgraph Knowledge_Data["복지 지식베이스 및 룰 엔진"]
        direction TB
        DB1[("복지로 중앙부처 DB<br/>(자격 기준/급여 방식)")]

    end

    API --> Masker
    SlotFiller --> AG1
    AG1 <--> RuleEngine
    AG2 <--> DB1 & DB2
    AG3 <--> GraphModel
    Synthesizer --> Output["WelfareNavigator 복지 설계서 (JSON / PDF / 웹 대시보드)"]
```

## 2. 핵심 기술 난제 및 세부 엔지니어링 해결안

### [난제 1] 복잡다단한 '소득인정액(소득평가액 + 재산의 소득환산액)' 산정의 수학적 복잡성
- **문제점**:
  - 한국 복지 기준은 단순 월급이 아니라, `소득평가액(실제소득 - 근로소득공제) + 재산의 소득환산액{(일반재산 + 주거용재산 - 기본재산공제) × 환산율 + 금융재산 × 6.26%}`이라는 고도의 법정 산식으로 결정됨.
  - LLM에게 프롬프트로 이 수식을 계산하게 하면 100% 수치 환각(Hallucination) 및 오차가 발생함.
- **해결안 (보건복지부 공식 고시 100% 결정론적 Python 룰 엔진)**:
  1. **결정론적 계산 모듈 (`welfare_math.py`) 구축**:
     - 2026년 대도시 기준 기본재산공제액(6,900만 원), 주거용 재산 한도액(1억 2,000만 원), 월 환산율(주거용 1.04%, 일반 4.17%, 금융 6.26%)을 상수 파라미터로 고정.
  2. **가구원 수별 기준중위소득 구간 자동 판정**:
     - 1인가구(약 239만 원), 2인가구(약 393만 원) 등 가구원 수별 30%(생계), 40%(의료), 48%(주거), 50%(교육), 100%(청년) 구간을 정확히 부동소수점 오차 없이 판별.

### [난제 2] 중앙부처 ↔ 지자체 조례 간 '중복 수혜 금지' 관계의 그래프 모델링 및 수혜액 극대화
- **문제점**:
  - 예를 들어 자립준비청년이 신청 가능한 복지가 7개일 때, 어떤 제도는 동시 수급 가능하지만, 어떤 제도는 상호 배타적(Mutual Exclusive)이며, 어떤 제도는 타 제도 수령 시 차액만 지급함.
  - 모든 조합($2^7 = 128$가지) 중 합법적이면서 총 수령액이 가장 큰 최적 조합을 일선 사회복지사가 수작업으로 계산하는 것은 불가능.
- **해결안 (이분 그래프 배타적 엣지 & 정수 계획법 ILP 최적화)**:
  1. **충돌 그래프(Conflict Graph) 모델링**:
     - 노드(Node): 각 복지 제도 $B_i$, 가중치 $W_i$: 월 수혜 환산액(현금 + 바우처).
     - 엣지(Edge): 중복 수혜가 법적으로 금지된 두 제도 사이에 배타적 엣지 $(B_i, B_j) \in E$ 연결.
  2. **정수 계획법(Integer Linear Programming, ILP) 수식화**:
     $$\max \sum_{i} W_i \cdot x_i \quad \text{s.t.} \quad x_i + x_j \le 1 \quad (\forall (B_i, B_j) \in E), \quad x_i \in \{0, 1\}$$
     - Python `scipy.optimize` 또는 `PuLP` 솔버를 적용해 50ms 이내에 '수혜액 극대화 최적 독립 집합(Maximum Weight Independent Set)'을 완벽히 계산.

### [난제 3] 비정형 일상 대화 ➔ 복지 수혜 자격 온톨로지 매핑 및 개인정보 보호 (PII Masking)
- **문제점**:
  - 취약계층은 "기준중위소득 50% 이하", "주거급여 수급권자" 같은 전문 용어를 알지 못하며, "원룸 월세 살고 알바비 120 받아요"처럼 일상어로 진술함. 또한 주민등록번호나 실명 등 민감 개인정보 노출 위험.
- **해결안 (정규식 기반 PII 마스커 & 다단계 Pydantic 슬롯 필링)**:
  1. **개인정보 완전 제거 파이프라인**:
     - LLM 전달 전 주민번호, 전화번호, 이름 등 식별자를 정규식으로 `[MASKED_PII]` 처리.
  2. **Pydantic v2 기반 스키마 강제 추출**:
     - `연령`, `거주 자치구`, `주거형태(자가/전세/월세)`, `보증금/월세`, `월평균 근로소득`, `특수자격(자립준비/한부모/장애/우울증 등)` 슬롯을 계층형으로 파싱.

### [난제 4] 지자체별 특화 조례 및 지원사업 공고 마감일 변동성 동기화
- **문제점**:
  - 자치구 조례 지원사업은 3월에 개시되어 예산 소진 시 5월에 조기 마감되는 등 유동성이 큼.
- **해결안 (매일 자정 서울시 공공서비스예약 및 구청 고시공고 크롤러 & 상태 캐싱)**:
  - 서울시 열린데이터광장 공공서비스예약 API 및 자치구 고시공고 RSS를 크롤링하여 `[접수중 / 마감임박 / 마감 / 예정]` 상태 플래그를 Redis에 실시간 동기화.

### 기술 스택 (Tech Stack)
- **Backend / API**: Python 3.11, FastAPI, Pydantic v2
- **Agent Orchestration**: LangGraph, LangChain
- **Graph & Optimization**: NetworkX, PuLP / Scipy (ILP 정수 계획법 솔버)
- **Data & Cache**: PostgreSQL (복지 서비스 DB), Redis (조례 공고 상태 캐시)
- **LLM**: Claude 3.5 Sonnet / GPT-4o (비정형 대화 슬롯 필링 및 신청 가이드 합성)
- **Document Rendering**: WeasyPrint / ReportLab (주민센터 제출용 복지 설계서 PDF 생성)
