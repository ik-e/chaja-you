## 1. 조사 결과 핵심 결론

이 프로젝트는 충분히 추진할 만하지만, 단순히 'AI가 대신 조사해 주는 사이트'를 만드는 것만으로는 차별화가 어렵습니다.

이미 ChatGPT Deep Research, Perplexity, Elicit 등은 여러 자료를 검색하고 종합해 출처가 포함된 보고서를 제공합니다. Claude Research 역시 상위 에이전트가 전문 하위 에이전트들에게 조사 업무를 나누는 멀티 에이전트 구조를 실제로 활용하고 있습니다.&#x20;

[image](https://www.google.com/s2/favicons?domain=https://help-lb.openai.com\&sz=32)

OpenAI Help Center+3



따라서 우리 팀의 개발 방향은 다음과 같이 잡는 것을 추천합니다.

> 사용자의 조사 목적에 맞춰 AI 전문가 팀을 동적으로 구성하고, 전문가별 조사 과정과 근거를 확인할 수 있으며, 검증된 자료를 바탕으로 비교·분석 보고서를 제공하는 웹 서비스

여기에서 중요한 가치는 네 가지입니다.

- 자동 팀 구성: 조사 주제에 따라 필요한 에이전트의 역할과 작업을 다르게 생성
- 조사 과정의 투명성: 어떤 에이전트가 무엇을 조사하고 있는지 시각화
- 근거 검증: 출처가 실제 주장을 뒷받침하는지 확인하고 불확실성을 표시
- 실용적인 결과물: 단순 요약보다 비교표, 핵심 차이, 판단 근거가 명확한 보고서 제공

기술적으로는 AG2 1.x의 동적 하위 에이전트 생성 기능이 프로젝트 목표와 잘 맞습니다. 다만 기존 CaptainAgent는 AG2 Classic 계열이므로, 최신 AG2의 API와 혼용하지 않고 별도의 참고 구현으로 다뤄야 합니다.&#x20;

## 3. 시스템이 실제로 리서치하는 방법

우리 시스템에는 다음과 같은 조사 절차를 제안합니다.

1. 사용자 요청 분석: 조사 목적, 범위, 기간, 비교 항목을 식별합니다.
2. 조사 계획 생성: 필요한 정보를 세부 작업으로 나누고 우선할 출처를 결정합니다.
3. AI 팀 자동 구성: 작업에 맞는 전문가의 역할·목표·사용 도구를 결정합니다.
4. 자료 검색 및 수집: 검색 API나 공식 데이터 API로 원문 링크와 내용을 수집합니다.
5. 비교 및 교차 검증: 정보의 중복, 불일치, 날짜, 근거의 정확성을 점검합니다.
6. 최종 보고서: 결론, 비교표, 출처, 확인하지 못한 사항을 명시합니다.

중요한 점은 웹 검색과 RAG가 동일하지 않다는 것입니다. 외부의 최신 정보를 찾는 서비스에는 검색 API가 우선이고, 내부 문서나 업로드 파일을 검색해야 할 때 RAG가 유용합니다. 초기 MVP에서는 벡터 DB를 반드시 도입할 필요는 없습니다.

## 5. 구현 기술 및 시스템 구성

| 영역     | 추천 기술                 | 선택 이유                         |
| ------ | --------------------- | ----------------------------- |
| 프론트엔드  | React 또는 초기 Streamlit | 입력·팀 구성·진행 현황·보고서 표시          |
| 백엔드    | FastAPI               | 조사 작업 생성 및 API 연동             |
| 에이전트   | AG2 1.x               | `dynamic_agent()`를 이용한 전문가 생성 |
| 검색     | Tavily + 공식 API       | 검색 결과 및 원문 근거 수집              |
| 데이터베이스 | PostgreSQL            | 작업, 전문가, 근거, 결과 저장            |
| 실시간 상태 | SSE 또는 WebSocket      | 전문가별 진행 현황 전달                 |
| 배포     | Docker 기반 클라우드        | 통합 배포·운영                      |

AG2의 `dynamic_agent()`는 요청에 따라 전문가의 이름, 지시문, 허용된 도구를 결정하도록 지원합니다. 다만 역할 생성 뒤의 검증·보고서·작업 상태 관리까지 모두 자동으로 만들어 주는 것은 아닙니다.&#x20;

## 6. 핵심 기능 및 요구사항

이번 주 기획서의 핵심 기능 5개는 다음과 같이 정의하는 것을 추천합니다.

| 핵심 기능         | 대표 세부 요구사항                 |
| ------------- | -------------------------- |
| ① 조사 요청 분석    | 자연어 입력, 목표 분석, 범위·조건 설정    |
| ② AI 전문가 팀 생성 | 난이도 판단, 역할 자동 생성, 작업 분배    |
| ③ 자료 조사       | 외부 검색 API 연동, 원문 수집, 중복 제거 |
| ④ 결과 검증       | 출처 확인, 근거 일치 검증, 충돌·누락 표시  |
| ⑤ 시각화 및 보고서   | 에이전트 상태 확인, 비교표, 인용 보고서    |

이렇게 하면 기획서의 핵심 기능은 5개로 단순하게 설명하면서, 실제 요구사항 명세서에서는 기능별로 2\~4개씩 세분화할 수 있습니다.

비기능 요구사항에는 정확도, 응답시간, API 비용 상한, 장애 대응, 보안, 사용성을 포함해야 합니다. 특히 원문에 근거하지 않은 주장을 확인된 사실처럼 보여 주지 않는 것이 중요합니다. 2025년 발표된 출처 검증 연구에서도 LLM이 제시한 인용이 해당 주장을 충분히 뒷받침하지 않는 문제가 관찰되었습니다.&#x20;

## 7. MVP에서 개발할 기능 범위

| 구분     | 기능 범위                                             |
| ------ | ------------------------------------------------- |
| Must   | 조사 입력, 계획 생성, 동적 팀 구성, 검색, 근거 검증, 보고서, 진행 상태      |
