# TASK-031 | 음악 레슨 등록 지원 서비스 — 기능·검증 통합 요약

**담당:** R03 · **작성일:** 2026-11-23 · **상태:** 기획 요구사항·검증 기준 초안(실행 테스트 전, R02 사실 확인 전)

**입력 근거:** [R02 음악 레슨 등록 1차 기획안](../../R02/workspace/2026-11-18_음악_레슨_등록_지원_1차_기획안.md)의 1·7·8·12·13절과 부록 A·B, [TASK-031 작업 계약](../../../artifacts/tasks/TASK-031.json). R02 기획안의 실제 경험·회상 추정·제품 가설을 아래에서 구분한다. 플랫폼의 현재 화면·약관이나 자동 제출 권한을 이 문서 작성 중 새로 검증하지 않았다.

## 1. 목표 및 범위

기존 모집 글·사진을 보유한 음악 강사가 **당근 모임과 크몽에 첫 레슨 공고를 등록**할 때 반복 입력과 확인 부담을 줄이는 서비스다. **F1 정보 추출·변환 → F2 등록 실행 지원 → F3 상태 확인·실패 처리**로 연결한다. 공고 갱신·후기 재게시·문의 응대·수강생 지도는 이번 범위에서 제외한다.

## 2. F1~F3 기능 요구사항

| 항목 | F1 · 정보 추출·플랫폼별 변환 | F2 · 등록 실행 지원 | F3 · 상태 확인·실패 처리 |
|---|---|---|---|
| **트리거** | 기존 공고·자료 제공 및 플랫폼 선택 | F1 검증 완료 후 실행 범위 승인 | F2 실행 결과·중단·오류 발생 |
| **입력** | 원본 글·사진, 분야·가격·횟수·시간·지역, 게시처 | 검증된 등록 데이터·이미지, 승인 조건, 로그인 상태 | 플랫폼별 실행 기록·마지막 단계·오류·증빙 |
| **처리** | 핵심 정보 추출 → 누락·충돌 점검 → 당근/크몽 양식 변환·검증 | 강사가 공식 화면에 직접 로그인 → 허용이 확인된 범위에서 입력·첨부·제출. 허용 전에는 모의 양식에서만 시험 | 게시/접수 결과 검증 → 상태·오류 분류 → 중복 제출 차단·재개 지점 판단 |
| **출력** | 플랫폼별 등록 초안·사진 목록·추가 확인 질문 | 실행 결과·제출 시도 내역·증빙 또는 중단 사유 | 완료/부분 성공/실패/미확인 상태, 근거, 후속 조치 |
| **예외** | 수업료·시간 누락, 상충 정보, 과거 수업 지역, 사진 부족 | 인증 만료, 필수 항목·업로드 오류, 권한·정책 제한 | 제출 직후 통신 장애, 실제 게시 여부 불명확, 한쪽만 성공 |
| **완료 조건** | 필수 조건을 강사가 확인하고 변환 결과가 원본과 일치 | 승인 범위의 실행을 끝내거나 중단 사유·진행 정보를 F3에 전달 | 플랫폼별 실제 결과를 확인하거나 미확인 사유와 사용자 조치를 기록 |
| **사용자 책임** | 원본·사진 제공, 현재 지역·가격 등 사실과 공개 권한 확인 | 게시처·범위 승인, 로그인/본인인증, 추가 조건 결정 | 추가 인증·수정, 필요 시 게시 확인 및 재개 승인 |
| **서비스 책임** | 추출·변환·오류 탐지·확인 요청·검증 | 허용이 확인된 경우에만 입력·첨부·제출 시도; 그 전에는 모의 실행과 중단·이력 전달 | 증빙 검증, 상태 관리, 중복 방지 및 결과 안내 |

**성공 판정:** 당근은 **모임 개설 + 첫 레슨 글 게시**까지, 크몽은 **상품 심사 접수**까지 확인해야 한다. 단순한 버튼 클릭은 성공이 아니며, 크몽 *심사 접수*와 *심사 승인·공개*는 구분한다.

### 시나리오별 사용자·서비스 단계와 관찰 가능한 판정

아래 단계는 **시험할 요구사항**이다. 실제 플랫폼에서 동작했다는 기록이 아니다. `제출 시도`와 `완료 확인`을 별도 사건으로 기록한다. 한 플랫폼의 성공은 다른 플랫폼의 성공으로 간주하지 않는다.

| ID | 사용자와 서비스의 순서 | 종료 상태와 필요한 관찰 근거 |
|---|---|---|
| **S-01 정상** | ① 강사가 원본 글·사진·월 30만 원/4회/90분 및 현재 공개할 지역을 제공하고 두 게시처를 선택한다. ② 서비스가 당근 모임·첫 글, 크몽 4회 정기 상품의 초안을 만들고 빠진 항목을 질문한다. ③ 강사가 사실·사진·가격과 실행 범위를 확인하고 공식 화면에 직접 로그인한다. ④ **허용된 실행 경로가 확보된 경우에만** 서비스가 게시처별 입력·첨부·제출을 시도한다. ⑤ 서비스가 결과를 각각 조회·기록하고 강사에게 알린다. | 당근 **모임 개설과 첫 글 게시** 증빙, 크몽 **상품 심사 접수** 증빙이 각각 있을 때 2건 완료. 크몽 심사 승인·공개는 별개 상태다. 모의 양식이면 `모의 완료 2건`으로만 기록한다. |
| **S-02 정보 누락** | ① 서비스가 원본의 지역이 과거 정보일 수 있음을 표시한다. ② 강사에게 현재 공개할 지역을 묻고, 답을 받기 전 F2를 중단한다. ③ 강사가 지역을 확정하면 초안을 다시 보여 주고 승인을 받는다. 답이 없으면 재개하지 않는다. | 지역 확인 전에는 `입력 확인 대기`; 제출 시도 0건. 확정값과 강사 확인 기록을 남긴 뒤에만 F2로 넘어간다. 확인 없이 과거 지역을 넣었다면 실패다. |
| **S-03 인증 만료** | ① 크몽 입력 중 인증 만료가 감지되면 서비스가 즉시 중단하고 **마지막으로 확인된 단계와 저장 여부**를 기록한다. ② 강사가 공식 화면에서 직접 재로그인한다. ③ 서비스와 강사가 기존 초안·실제 제출/접수 상태를 먼저 확인한다. ④ 접수되지 않았고 복구 가능한 입력 단계가 확인된 경우에만 강사의 재개 승인 후 진행한다. 단계나 접수 여부가 불분명하면 자동 재시도하지 않는다. | 재로그인 자체는 완료가 아니다. 재개 후 크몽 심사 접수 증빙이 있으면 `완료`, 없으면 `중단/미확인`과 마지막 확인 단계·필요한 사용자 조치를 기록한다. |
| **S-04 결과 미확인** | ① 당근 첫 글 제출 직후 통신 장애가 나면 서비스가 제출 시도 시각·대상·내용 식별 정보를 남기고 재제출을 막는다. ② 강사가 공식 화면의 해당 모임·게시글 목록을 확인한다. ③ **동일한 글이 게시된 근거가 있으면** 완료로 전환한다. 찾지 못했거나 확인할 수 없다면 `미확인`으로 알리고 중복 가능성을 설명한다. ④ 재제출은 미게시가 확인되고 강사가 승인한 뒤에만 검토한다. | 게시 사실을 확인한 화면/상태 기록이 있으면 `완료`. 오류 메시지나 버튼 클릭 기록만 있으면 `미확인`; **미확인을 실패로 단정하거나 자동 재제출하지 않는다.** |

**플랫폼별 상태:** `준비 중 → 입력 확인 대기/실행 중 → 제출 시도 → 완료/실패/미확인/중단`. 당근은 모임 개설만 된 경우 `부분 성공`이며 첫 글 게시 전까지 완료 건수는 0건이다. 당근 완료·크몽 미확인이면 전체 상태는 `부분 성공 + 미확인`이고 정확한 완료 건수는 1건이다. 중복 방지에 필요한 조회 가능 여부와 증빙 형식은 기술·권한 검토 전이므로 구현 확정 계약으로 취급하지 않는다.

## 4. 비교 검증 설계

**비교 대상:** ① 강사 직접 등록(동일 원본·템플릿) ② 범용 AI Codex(동일 원본·재사용 지시문) ③ 전용 서비스.

- **동일 입력:** 랩 레슨 원본, 동일 사진, 월 **30만 원·4회·회당 90분**, 강사가 확인한 최신 지역, 동일한 등록 규칙·승인 가격 옵션. 없는 체험가·할인율은 추정하지 않는다.
- **동일 시작:** 각 방식에서 로그인 전 상태, 미등록 시험 공고, 동일 자료·계정 자격·모의 등록 화면; 최초 작업 행동부터 시간 측정. 설치·초기 설정 시간은 별도 기록한다.
- **동일 종료:** 당근 첫 글 게시와 크몽 심사 접수의 **정확한 완료 건수(0~2건)** 및 각 플랫폼의 최종 상태로 판정. 실제 게시와 모의 성공은 별도 표기한다.
- **측정값:** **사용자 직접 작업 시간(분·초), 추가 개입 횟수(회), 정확한 완료 여부/건수**, 입력 오류·재시도, 전체 경과 시간, 구속 대기 시간, 초기 설정 시간. 직접 등록은 수정 행동을 별도 집계해 AI의 개입 횟수와 무리하게 단순 비교하지 않는다.
- **판단:** 정확성이 확보된 상태에서 전용 서비스가 직접 등록·Codex보다 강사의 시간/개입을 줄이는지 평가한다. 결과와 비용을 제시한 뒤 사용 의향도 확인한다.

**측정 규칙 초안:** 동일한 원본·사진·승인된 가격 조건과 동일한 모의 양식을 세 방식에 제공한다. 사용자 직접 시간은 자료 준비, 최초 지시·입력, 질문 응답, 로그인, 수정, 결과 확인에 실제로 손을 쓴 시간의 합으로 기록한다. 대기 시간과 설치·설정 시간은 별도 항목이다. AI 두 방식의 추가 개입은 **첫 지시 이후** 사용자가 새로 제공한 설명·수정·재개 승인 건수로 센다. 직접 등록은 동일 행동을 `직접 입력/수정 건수`로 별도 기록한다. 각 플랫폼에서 요구된 가격·횟수·시간·지역·사진이 맞고 위 완료 증빙이 있는 경우에만 정확한 완료 1건을 센다. 모의 성공과 실제 게시/접수는 별도 표로 비교하며, 실제 제출 권한이 확인되지 않으면 모의 결과만 보고한다. 시험 화면·시나리오·참가자·횟수와 성공/보류 기준은 실험 전에 확정한다.

## 5. 확인 사항과 다음 검토

**확인된 기획 근거:** 최초 등록 우선, 당근·크몽을 첫 대상 선정. R02의 기존 등록 소요시간(당근 약 15분·크몽 약 20분)은 **회상에 따른 추정치**로 실측값이 아니다.

**미확인/제약:** 두 플랫폼에서 외부 AI의 최종 자동 제출이 허용되는 경로, 최신 입력 양식·이미지 제한, 실제 완료 증빙 확보 방식, Codex/전용 서비스의 실행 성능. **허용 근거가 확보되기 전 실제 자동 제출은 실행하지 않고 모의 환경에서 검증**한다. 외부 계정 비밀번호·인증번호는 서비스에 수집·저장하지 않는다.

**현재 산출물:** F1~F3 요구사항, 정상 1건+예외/미확인 3건, 세 방식의 공통 입력·시작·종료·측정 기준 **초안 작성**. **다음:** R02 사실 확인, R01 검토 및 실제 실험 계획 확정. *(실험 수행·효과 검증 완료 아님)*
