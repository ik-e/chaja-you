# TASK-031 | 음악 레슨 등록 지원 서비스 — 크몽·탈잉 기능 요구사항 및 비교 검증 범위 변경안

**담당:** R03  
**작성·변경일:** 2026-11-23  
**상태:** 플랫폼 비교 대상 변경에 따른 작업용 보완 초안 · R01 범위 결정 및 R02/R05 확인 전  
**기반:** 기존 TASK-031 F1~F3 통합 보완본과 R02의 2026-11-18 1차 기획안. 기존의 공통 요구사항·사용자 개입·예외 처리·측정 원칙은 유지한다.

## 1. 변경 결정과 범위

- **이번 R03 상세 비교 대상:** **크몽 + 탈잉**. 종전 **당근 모임 + 크몽**에서 변경한다.
- **당근을 이번 비교에서 제외하는 이유:** 사용자 확인에 따르면 현재 고려 중인 **PC에서 로그인해 등록을 맡기는 실행 흐름**으로는 당근 모임 글 등록을 진행할 수 없다. 이는 **이번 PC 기반 검증 대상 제외 사유**이며, 당근의 모든 기기·서비스에서 등록 자체가 불가능하다는 일반 판정은 아니다.
- **탈잉을 추가하는 근거:** 탈잉 공식 가이드에 PC '탈잉 스튜디오 → + 클래스 만들기' 등록 절차가 안내되어 있다. 크몽은 공식 안내에 PC 서비스 등록이 제공된다.
- **최초 등록은 우선 검증 시나리오**이며 **최종 MVP 플랫폼·기능 범위는 R01 결정 전**이다. 숨고는 R05의 별도 기술 조사 대상이며 이번 R03 상세 등록 시나리오에 포함하지 않는다.
- **범위 제외:** 와이어프레임, DB/API 상세 설계, 코드 작성, 실제 계정 로그인, 무단 자동 게시, 보안 우회, 실서비스 PoC.
- **정보 표시:** `[확인]` 공식 가이드·R02 자료에 근거 · `[설계]` R03가 제안한 기능/판정 · `[미확인]` 실제 화면 또는 실행 허용 근거가 부족함.

### 탈잉 수업 시간 충돌은 필수 검증 사례

- **원본 수업:** R02 자료에 있는 **월 300,000원 / 4회 / 회당 90분**.
- **공식 가이드:** 탈잉 수강료 설정에서 **회당 시간 1시간 단위** 입력.
- **설계 판정:** AI가 원본을 60분 또는 120분으로 변경해 등록하면 **승인 조건 불일치**다. 플랫폼 상세 설명란에 90분을 써도 가격/시간 정식 입력칸과 충돌할 수 있으므로 **등록 가능 여부를 확인하기 전 제출 보류**.
- **질문:** '탈잉은 회당 시간 입력이 1시간 단위입니다. 현재 제공하는 90분 수업을 그대로 등록할 수 있는 허용 방식이 확인되지 않았습니다. 실제 운영 가능한 다른 수업 구성이 있나요, 아니면 탈잉 등록을 보류할까요?'
- **재개:** 실제로 제공할 수 있는 변경 조건을 강사가 명시적으로 승인하고, 플랫폼 입력 규칙·가격·전체 제공 서비스를 다시 검증한 경우에만 재개. 이용자에게 오인시키는 편법 입력은 금지.

## 5. F3 상태·실패·부분 완료·미확인 처리

| 플랫폼 | 중간 상태 | 1차 목표 완료 증거 | 일부 성공/불명확 시 기록 | 사용자에게 안내할 조치 |
|---|---|---|---|---|
| 크몽 | 전문가 준비됨 → 상품 작성/임시저장 → 심사 접수 시도 | **심사 접수 확인** 화면/상태 등 확보 | 최종 입력 필드, 마지막 확인 단계, 승인값 대조, 접수 시각, 응답/오류, 증빙 유무 | 작성만 됐으면 심사 접수 재개 결정. 접수 여부 불명확하면 **기존 접수 내역 먼저 확인** |
| 탈잉 | 튜터 준비됨 → 클래스 작성 → 심사 접수 시도 | **클래스 심사 접수 확인** | 시간·가격 필드 충돌, 마지막 저장 단계, 정산/정책 동의 여부, 접수 시각, 확인 증빙 | 90분 조건 충돌 시 조건 재승인 또는 보류. 제출 불명확 시 **기존 접수 내역 먼저 확인** |

공통 상태: `대기` / `초안 준비` / `추가 확인 필요` / `입력·작성 중` / `작성·임시저장 완료` / `제출 결과 확인 중` / `접수 완료` / `심사 중` / `반려·수정 요청` / `실패` / `결과 미확인` / `실행 제한`.

**[설계] 실패·미확인 기록 최소 항목:** 플랫폼·등록 대상·승인한 조건(또는 비교 가능한 버전)·최종 성공 단계·제출 시도 여부/시각·발견된 오류·증빙 확보 여부·사용자 재인증/수정 요구·다음 확인 주체. 개인 인증정보/세션 토큰은 기록하지 않는다.

**공통 원칙:** 작성 완료 ≠ 심사 접수 완료 ≠ 심사 승인·실제 모집 가능. 크몽·탈잉 모두 제출 응답을 못 받았다면 **자동 재제출 금지**. 탈잉의 실제 수강 신청 가능 여부는 승인 이후 일정 등록 상태를 별도로 확인한다.

## 6. 비교 검증 기준 — 플랫폼 2개 × 사용 방식 3개

**플랫폼:** 크몽 / 탈잉. **방식:** A 강사 직접 등록(같은 원본·복사 템플릿) / B 범용 AI(Codex, 재사용 지시문) / C 전용 서비스. 실제 구현·실험은 별도 작업이며 지금은 측정 기준만 정의한다.

| 구분 | 공통 설정·평가 방법 |
|---|---|
| 동일 입력 | 공고·사진·현재 지역·가격·횟수·시간·추가 비용·일정 변경·제공 서비스 및 각 플랫폼의 확인된 양식 규칙을 동일하게 사용 |
| 동일 시작 | 동일 플랫폼별 시험 등록 초기 상태(미등록, 필요한 자격 준비, 로그인 전), 같은 모의 환경/조건. 기본 로그인·자료 전달·승인 시간 포함. 설치·초기 설정은 별도 측정 |
| 동일 종료 | 크몽 심사 접수 / 탈잉 심사 접수의 **정확한 완료 건수 0~2건**, 각 플랫폼 상태 확인. 반려·심사 진행은 접수와 구분 |
| 사용자 직접 시간 | 작성·자료 제공·로그인·추가 질문 응답·수정·승인·결과 확인에 소요된 능동 작업 시간(분·초) |
| 사용자 개입 횟수 | 실행 시작 이후 예기치 않은 추가 질의·수정·인증·승인 요청 응답 횟수(회). 직접 등록의 수동 수정은 별도 계수 |
| 오류·정확도 | 필수 정보 누락, 승인 조건 불일치(가격·시간·횟수·추가비용·일정·제공서비스), 이미지 오류, 중복 제출 여부(건) |
| 결과/대기 | 정확한 완료 여부(건), 결과 미확인·실패(건), 전체 경과 시간, 구속 대기 시간. 모의 결과/실제 결과 분리 |

**공정성 유의:** R02의 **90분 수업을 탈잉의 1시간 단위 시간 입력에 맞추려고 임의 수정하면 안 된다.** 이 원본 시나리오에서는 세 방식 모두 '승인 조건 불일치 탐지·추가 확인·안전 보류'가 올바른 결과일 수 있다. 양 플랫폼에서 실제 제출 성공률을 비교하려면 **R02가 실재하는 별도 수업 조건을 승인하고, 탈잉에서 입력 가능한 것으로 확인된 공통 시험 자료**를 별도로 마련해야 한다. 시험마다 같은 자료/시작 상태/종료 조건을 유지한다.
