## 1. 책임과 이번 초안의 범위

| R03이 정할 의미·기본 동작 | R05 초안에 연결할 것 | R01·R04에 연결할 것 |
|---|---|---|
| 앱 조건의 의미·필수/선호·판정 범위 | 조건·판정 식별자 저장·전달 방식 | 사용자에게 문서/기기 확인 범위 표시 |
| 같은 논리 작업·재시도·보완 작업의 구분 | ID 발급·고유 범위·시도 이력 필드 | 자동 재시도를 필수 범위로 늘리지 않음 |
| APP-C의 실행·생략·보류·최종 미실행 판단과 사유 | 상태·결정 ID 연결과 실제 실행·저장 | 부분 결과 최종 수용 기준·확인 한도 정책 |

R05가 백엔드 ID 발급·고유 범위·전달 필드의 초안을 주도한다. R03은 ID가 가리키는 작업·판정·결정의 의미를 정의한다. 시도 ID의 구체적인 이름·자료형·발급 주체를 이번 문서에서 선결정하지 않는다.

아래 조건명·상태명·사유 이름은 R03 초안의 표시값이다. 의미를 유지하는 내부 표현은 담당자가 조정하고, 상대 TASK의 실행·판단에 영향을 주는 연결만 확인한다. 이 문서를 TASK-006의 합의된 최종 계약으로 취급하지 않는다.

## 2. 앱 조건의 의미와 적용 범위

| 조건 후보 | R03 의미 정의 | APP 적용 | 판정에서 구분할 것 |
|---|---|---|---|
| `offline_timer` | 요청한 플랫폼에서 네트워크 연결 없이 타이머를 시작하고 시간을 진행·종료할 수 있음 | APP-C 필수 | 동기화·통계·클라우드 기능까지 오프라인이라는 뜻이 아님 |
| `offline_pomodoro` | 오프라인 상태에서 앱의 뽀모도로 집중·휴식 기능을 사용할 수 있음. 일반 타이머만 있다는 근거로 충족시키지 않음 | APP-A 필수 | 요청에 없는 특정 분 길이·자동 반복 횟수·백그라운드 알림까지 임의로 필수화하지 않음 |
| `accountless` | 해당 핵심 타이머 기능을 사용하기 위해 회원가입·로그인이 필수는 아님 | APP-A 선호 | 계정 없이 동기화·모든 부가 기능을 쓸 수 있다는 뜻이 아님 |

`offline_pomodoro`와 `offline_timer`는 동일 조건으로 자동 매핑하지 않는다. 오프라인 뽀모도로의 직접 근거가 일반 타이머 조건도 뒷받침하는지는 대상 기능·플랫폼·적용 범위가 일치하는지 보고 별도로 판단한다. 일반 타이머 근거만으로 뽀모도로 조건을 충족으로 올리지 않는다.

R05 예시의 `no_account`는 위 accountless 의미와 같으면 이름 매핑이 가능하다. 로그인 없이 최초 진입이 되는지, 계정 생성 후 오프라인 사용이 되는지를 서로 바꾸지 않는다. 최종 조건 ID 문자열은 R05 저장 초안에 맞춰 매핑할 수 있다.

플랫폼·앱 버전·요금제·지역·확인 시점과 확인 방법을 함께 보존한다. 이미 설치된 앱의 오프라인 실행과 최초 설치/첫 실행/로그인 조합을 구분한다. 최초 실행·설치 자체까지 오프라인이어야 한다는 조건은 요청에 없으면 임의로 추가하지 않되, 해당 제한이 실제 사용 판단에 영향을 주면 별도 미확인·제약으로 표시한다.

## 3. 조건별 판정 기준

| 판정 | 기준 | 허용하지 않을 추론 |
|---|---|---|
| 충족 | 해당 대상·조건·플랫폼·확인 범위를 직접 지지하는 근거가 있음 | 검색 요약·앱 이름·일반적인 제품 설명만으로 세부 기능 충족 단정 |
| 미충족 | 해당 조건을 사용할 수 없거나 필수 제한 때문에 요청을 만족하지 못한다는 직접 근거가 있음 | 검색에서 못 찾음·조회 실패·문서 누락을 미지원으로 간주 |
| 미확인 | 필요한 근거가 없거나, 범위가 다르거나, 근거가 충돌해 해소되지 않음 | 미확인을 미충족으로 바꾸거나 근거를 만들어 채움 |

판정은 대상×조건별로 남긴다. 근거가 없는 미확인은 빈 evidence 참조와 사유를 보존하고, 판정을 만든 작업 ID로 추적한다. 근거가 있는 미확인·충돌은 관련 자료를 참조하되 충족/미충족을 임의로 선택하지 않는다.

**문서 확인과 기기 확인의 범위는 다르다.** 문서가 오프라인 사용을 명시하면 ‘문서상 충족’으로 표시할 수 있으나 실제 Android 실행·알림·첫 실행까지 시험한 것으로 표현하지 않는다. 실제 기기 동작이 필요한 판단은 기기 확인 미실시와 조건의 적용 한계를 함께 남긴다. 근거를 확인한 시각과 기기 시험 시각도 같은 값으로 만들지 않는다.

필수 조건의 미확인은 사용 가능 확정 추천으로 처리하지 않는다. 선호 조건의 미충족·미확인만으로 필수 조건을 만족한 후보를 자동 탈락시키지 않는다. APP-C에는 APP-A의 계정 선호를 전이하지 않는다.

출처는 R02의 접근·이용 조건 확인 범위를 따른다. 공개 열람, 원문 확인, 자동 수집·저장·재사용 허용을 별도로 다룬다. 미허가 자동 수집을 보완 작업이나 재시도라는 이름으로 실행하지 않는다. 이 초안은 실제 앱 기능을 새로 판정하거나 외부 페이지를 수집한 결과가 아니다.

## 4. 같은 작업·재시도·새 작업의 구분

논리 작업은 요청 문맥, 조사 대상, 목표·조건, 완료 기준으로 구분한다. 도구 호출 한 번이나 URL 한 개를 무조건 별도 작업·재시도로 세지 않는다.

| 상황 | R03 분류 | 식별·이력 처리 의미 |
|---|---|---|
| 진행 중인 자료 조사 작업이 원래 허용 범위 안의 다른 자료도 확인 | 같은 작업의 정상 진행 가능 | 각 도구 수행·자료 확인 이력 보존. 모든 호출을 새 실행 시도로 만들지 않음 |
| 통신 오류 등으로 실패한 작업을 동일한 목표·범위·완료 기준으로 다시 수행 | 재시도 | 기존 task_id 유지. 새 실행 시도 ID·상태·실패 이유를 별도로 기록 |
| 판정이 미확인으로 완료된 뒤, 부족한 조건을 확인하기 위한 별도 보완 목표를 구성 | 새 보완 작업 | 새 task_id. 어떤 기존 작업·판정의 부족을 보완하는지 연결 |
| 조사 대상·필수 조건·완료 목표가 변경됨 | 새 작업 | 기존 작업을 덮어쓰지 않고 새 작업과 변경 이유를 연결 |
| 두 후보 모두 미충족으로 확인되어 대안 발굴이 필요해짐 | 조건부 후속 작업 | 대안 발굴 작업과 선행 판정·실행 조건·생성/실행 이유 연결 |

재시도인지 새 작업인지 애매하면 ‘기존 작업의 목표·완료 기준으로 끝낼 수 있는가’를 먼저 본다. 같은 완료 기준 안의 진행을 불필요하게 쪼개지 않고, 완료된 판정의 의미·대상·범위를 바꾸는 후속 작업은 별도로 남긴다.

재시도 시 이전 실패를 덮어쓰지 않는 원칙은 이미 R05와 확인했다. 자동 재시도 여부·횟수·시간 상한은 아직 정하지 않았으며 이 표가 자동 재시도 구현을 추가하는 것은 아니다.

## 5. 실패 기록을 입력받는 판정 작업

1. 자료 조사 작업은 성공·실패 결과와 접근 상태·사유를 남긴다.
2. 판정 작업은 명시된 실행 조건이 허용할 때 그 종료 기록을 입력으로 받는다. ‘선행 성공’과 ‘선행 종료 기록 확보’를 구분한다.
3. 자료 접근에 실패해 지지 근거가 없으면 해당 조건을 미확인으로 남긴다. 자료 조사 작업의 실패 상태는 유지한다.
4. 미확인 판정 처리를 끝냈다면 판정 작업 자체는 완료할 수 있다. 이것이 원래 조사 성공이나 기능 충족을 뜻하지 않는다.
5. 다른 작업에서 확보한 유효한 확인 내용은 보존하고 실패·미확인 사유와 함께 결과 구성에 전달한다.

현재 합성 원형의 `all_tasks_terminal`은 이 의미를 표현하는 예시다. 모든 실패 뒤에 모든 후속 작업을 실행해도 된다는 일반 규칙이 아니며, 실제 실행기가 이해할 조건 표현은 R05 초안에 연결한다.

## 6. APP-C 후속 발굴 판단

발굴 실행 조건은 **현재 요청의 두 지정 후보가 필수 오프라인 타이머 조건에서 모두 미충족으로 확인됨**이다. 판정 근거·적용 범위·충돌 상태가 유효한 결과를 입력으로 받는다. 자료 조사 작업의 실패 두 건으로 이 조건을 충족시킬 수 없다.

| 현재 결과 | 실행 조건 의미 | R03 결정 | 결과에 남길 것 |
|---|---|---|---|
| 두 후보 모두 미충족으로 확인, 필요한 선행 판정 준비 | 참 | 대안 발굴 실행 요청 | 두 판정 참조·실행 이유·후속 작업 연결 |
| 한 후보 이상 충족 | 거짓 | 대안 발굴 생략 | 충족 판정 참조·불필요 발굴 생략 이유. 지정 후보 비교는 유지 |
| 충족 없음·일부 미확인 또는 판정 진행 중, 확인 진행 가능 | 아직 판단 불가 | 보류 | 부족한 판정·사유·현재 상태. 한도 안의 확인 여부를 실행 정책과 연결 |
| 위 상태에서 확인 한도 도달, 계속 미확인 | 아직 판단 불가 | 최종 미실행 | 한도 종료·발굴 조건 미확인 사유, 확인 내용과 남은 미확인·실패 |

보류는 최종 상태가 아니다. 한도 종료 뒤에도 보류로 무한 대기시키지 않는다. 최종 미실행은 조건이 거짓으로 입증됐다는 뜻이 아니므로 ‘충족 후보가 있어서 생략’과 이유를 구분한다.

현재 R02의 문서 조사처럼 한 후보의 문서상 충족 근거를 적용할 수 있다면, 같은 문서 확인 범위에서 ‘두 후보 모두 미충족’ 발굴 조건은 성립하지 않는다. 이를 실제 기기 동작이나 실제 시스템 분기 실행의 검증으로 바꾸지 않는다. APP-C3 합성 입력도 실제 판정값으로 덮어쓰지 않는다.

## 7. D1 작업과 결정 기록

**R03 초안 선택:** 현재 요청 안에서 D1이라는 동일한 논리 발굴 작업을 유지하고, 보류와 최종 미실행 등 판단이 바뀔 때마다 별도 결정 기록을 추가한다. 실제 DB에 D1을 언제 생성할지는 R05 구현 선택이며, 실행되지 않은 후속 작업도 이력에서 식별할 수 있어야 한다.

각 결정에는 다음 의미가 있어야 한다. 아래는 필요한 정보이며 최종 필드명·자료형을 정한 목록은 아니다.

- 어느 요청·D1 작업에 관한 결정인지.
- 어떤 실행 조건과 어떤 판정 ID·그 시점의 상태를 사용했는지.
- 실행·생략·보류·최종 미실행 중 어떤 판단을 했고 이유가 무엇인지.
- 이전 결정과의 순서, 한도 도달 등 판단 변경을 일으킨 사건.

보류 DEC1과 최종 미실행 DEC2는 D1을 공통으로 참조한다. DEC1을 DEC2로 덮어쓰지 않으며, D1의 현재 상태와 판단 이력을 구분한다. 실제 결정 ID 발급·저장 필드는 R05 초안에 맞춘다. 종료 뒤 새 정보가 생겨 재개하는 정책은 이번에 추가하지 않는다.

R03은 조건 판정에 따른 다음 행동·사유를 제공하고, R05는 실행·저장·상태 전달에 연결하는 안을 제안한다. 조건 평가를 어느 프로세스에서 수행하고 누가 최종 실행을 시작하는지는 실제 연결에 영향을 주므로 R05와 맞출 항목이다.

## 8. 결과 상태와 사용자 출력

R03이 넘길 기본 내용은 대상·조건, 판정과 근거·출처 참조, 확인 범위·시점, 미확인·충돌·실패, 후속 결정과 사유다. 비교·보고서 작성은 그 상태에서 필요한 내용을 보여주는 단계로 둔다.

확인 내용이 남아 있으면 이를 보존해 부분 결과 후보를 구성한다. 사용자에게는 핵심 비교와 미확인을 먼저 보여주고 필요한 근거를 연결한다. 부분 결과의 최종 수용 기준, 확인 내용이 전혀 없는 경우의 표시, 실제 확인 한도는 R04 전달 형태와 함께 R01 판단에 연결한다. 이번 문서로 확정하지 않는다.

질문별 프로젝션·장기 저장·증분 재조사 전체를 새 기능으로 구현하지 않고, 현재 판정·근거가 보고서 문자열 하나로만 사라지지 않게 하는 경계만 유지한다.

## 9. R05와 연결할 최소 항목

| R03 초안에서 제시할 것 | R05 초안에서 확인할 것 |
|---|---|
| 조건의 의미·필수/선호·근거 적용 범위 | 저장할 조건 ID 매핑과 판정 참조 |
| 같은 작업·재시도·보완 작업 분류 | 기존 task_id·새 시도 ID·새 task_id의 발급·이력 전달 |
| APP-C의 조건 평가 결과·행동·사유 | 실제 실행 시작·보류·종료 상태와 누가 평가·실행하는지 |
| D1 동일 작업과 추가되는 결정 이력 | 작업·판정·결정 ID 참조, 결정 순서와 저장 표현 |

R05는 이 의미를 전제로 백엔드 초안을 작성하고, R03 내부 함수명·문서 표현까지 승인할 필요는 없다. 범위·필수 요구사항·완료 기준을 바꾸는 차이가 생길 때만 R01에게 정리해 전달한다.

## 10. 이번 작성 결과와 미수행

- 수행: R03 주도 의미·기본 동작 초안 작성, 기존 명세·공동 확인 기록과 대조.
- 미수행: 원형 코드·결과 변경, 재시도 구현, 신규 검사, 실제 자료 수집·API/화면 연동.
- 미수행: R05 최종 연결 동의, TASK-005·006 정본 갱신, 공용 명세·기획서·WBS 수정, 커밋·푸시·메시지 전송.

기존 합성 검사의 통과를 이 새 초안 전체의 구현 검증으로 사용하지 않는다. 현재 TASK-005의 진행 중 상태와 실제 연동 검증 전이라는 구분을 유지한다.
