# 기존 대안 반증 점검 결과

R03 두나 · 2026-11-16 · TASK-018 진행 기록

## 1. 현재 결론

**가상 사건 1건의 2턴 실행에서 충분한 지시를 준 LLM은 원문 연결·금액 충돌·정정 이력·배송 미확인을 처리했다. 이 사례로 우리 서비스가 더 낫다고 설명할 근거는 없다.** 폴봇은 현재 공개 진입 표시와 과거 자동 작성 발표를 확인했지만 실제 대화·수정 동작은 미시험이다.

## 2. 폴봇·ECRM 확인

- [현재 공개 메인](https://ecrm.police.go.kr/minwon/main)에서 폴봇 진입 표시·안내 메뉴·진술서 작성 항목·예시를 확인했다.
- [2022-11-30 경찰청 발표](https://m.korea.kr/news/policyNewsView.do?newsId=148908906)는 질문·답변으로 맞춤형 진술서를 생성하는 기능을 설명한다. 과거 발표이며 현재 전체 동작을 입증하지 않는다.
- 실제 브라우저 진입을 시도했으나 도구가 `The browser access host is unavailable`을 반환했다. 화면 조작·대화·수정·신고 제출은 실행하지 못했다.
- 공개 메인에 직접 연결된 스크립트 1개를 최소 조회해 진술서 작성 화면 연결 코드가 있음을 확인했다. 정적 코드 열람은 현재 채팅이 작동한다는 시험이나 로그인 이후 이용 검증이 아니다.
- 따라서 ‘폴봇이 현재 작동하지 않는다/수정을 못한다/우리보다 부족하다’고 판단하지 않는다. 실제 출력 비교가 필요한 상태다.

## 3. LLM 실행 조건

- 가상 자료: 사용자 설명 S1, 판매 글 S2, 판매자 메시지 S3, 이체 내역 S4, 미수령 진술 S5. 최초 진술 10만 원과 내역 12만 원이 다르고 배송 시점·약속일은 없다.
- 2턴 사용자 정정: 12만 원으로 정정하고 S4가 해당 거래임을 확인. 발송 여부·배송 약속일은 계속 모름.
- 원문 ID 연결·주장/추측/미확인/충돌 보존·정정 반영을 명시적으로 요청했다. 응답 형식을 맞추기 위한 JSON 요구 외 제품 코드를 제공하지 않았다.
- Codex CLI 0.167.2, 사용자 설정 제외, 임시 빈 작업폴더, 읽기 전용·ephemeral, 외부 도구 금지 요청. 응답 이벤트에 도구 실행 항목은 없었다. 정확한 백엔드 모델은 수집 이벤트에 노출되지 않아 미확인이다.
- CLI harness를 통한 LLM 점검이며 독립적인 ChatGPT 제품 시험이나 모델 간 벤치마크가 아니다. 기존 대화·저장소를 입력으로 전달하지 않았으나 프롬프트 작성자와 평가자는 동일한 작성 에이전트다.

## 4. 관찰 결과

| 항목 | 결과 |
|---|---|
| 원문 연결 | 두 응답의 요약 문장에 유효 원문 ID가 연결됨. 의미 일치까지 자동 점수화한 것은 아님 |
| 금액 충돌 | 1턴에서 10만/12만 원을 충돌로 보존하고 사용자 확인 질문 생성 |
| 주장·추측 | ‘배송했다’는 판매자 주장, 사기 의도는 사용자 추측으로 구분 |
| 사용자 정정 | 2턴 12만 원 반영, 원문 S1·정정 S6 이력 보존, 이미 답한 금액 질문·미해결 금액 항목 제거 |
| 미확인 | 실제 발송 여부·배송 약속일·메시지 시점 등을 미확인으로 유지 |
| 부분 갱신 효율 | 전체 JSON 응답을 다시 생성하므로 내부의 부분 갱신 구현·효율은 입증되지 않음 |
| 추가 질문 | 최종 합의 가격·운송장 수령 여부 질문이 남음. 필요한 질문인지 사용자 부담인지 실제 사용자 평가는 없음 |

구조 점검 5개는 통과했다. 이는 위 제한된 자동 조건의 결과이며 정확성 전반의 합격률이 아니다. 수동 대조는 [review.json](2026-11-16_가상사례_LLM_점검/review.json)에 항목별 기록했다.

실행 합계: 108.247초, 입력 토큰 37868, 출력 토큰 4896. 사용자 자료 준비·읽기·수정 시간과 비용 금액은 미측정이다. 도구 harness의 기본 입력 오버헤드가 포함돼 서비스 운영 비용으로 일반화하지 않는다.

## 5. 다음 결정

추가 개발을 당연한 다음 단계로 두지 않는다. 현재는 폴봇의 실제 공개 기능 접근과 비AI 체크리스트·LLM 대비 수정 부담의 차이를 확인하는 저비용 점검을 먼저 수행한다. 충분한 지시의 LLM이 이미 수행한 기능은 우리만의 차별점으로 주장하지 않는다. 추가 가치가 확인되지 않으면 기능 축소·제안 재검토로 연결한다.
