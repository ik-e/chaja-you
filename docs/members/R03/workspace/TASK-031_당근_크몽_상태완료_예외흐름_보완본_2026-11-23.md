# TASK-031 | 음악 레슨 등록 지원 서비스 — 기능·검증 통합 요약

**담당:** R03 · **작성일:** 2026-11-23 · **상태:** R01 피드백 1·2·4 반영 보완 초안(실행 테스트 전)

## 1. 목표 및 범위

기존 모집 글·사진을 보유한 음악 강사가 **당근 모임과 크몽에 첫 레슨 공고를 등록**할 때 반복 입력과 확인 부담을 줄이는 서비스다. **F1 정보 추출·변환 → F2 등록 실행 지원 → F3 상태 확인·실패 처리**로 연결한다. 공고 갱신·후기 재게시·문의 응대·수강생 지도는 이번 범위에서 제외한다.

## 2. F1~F3 기능 요구사항

| 항목 | F1 · 정보 추출·플랫폼별 변환 | F2 · 등록 실행 지원 | F3 · 상태 확인·실패 처리 |
|---|---|---|---|
| **트리거** | 기존 공고·자료 제공 및 플랫폼 선택 | F1 검증 완료 후 실행 범위 승인 | F2 실행 결과·중단·오류 발생 |
| **입력** | 원본 글·사진, 분야·가격·횟수·시간·지역, 게시처 | 검증된 등록 데이터·이미지, 승인 조건, 로그인 상태 | 플랫폼별 실행 기록·마지막 단계·오류·증빙 |
| **처리** | 핵심 정보 추출 → 누락·충돌 점검 → 당근/크몽 양식 변환·검증 | 강사가 공식 화면에 직접 로그인 → 허용된 범위에서 입력·첨부·제출 | 게시/접수 결과 검증 → 상태·오류 분류 → 중복 제출 차단·재개 지점 판단 |
| **출력** | 플랫폼별 등록 초안·사진 목록·추가 확인 질문 | 실행 결과·제출 시도 내역·증빙 또는 중단 사유 | 완료/부분 성공/실패/미확인 상태, 근거, 후속 조치 |
| **예외** | 수업료·시간 누락, 상충 정보, 과거 수업 지역, 사진 부족 | 인증 만료, 필수 항목·업로드 오류, 권한·정책 제한 | 제출 직후 통신 장애, 실제 게시 여부 불명확, 한쪽만 성공 |
| **완료 조건** | 필수 조건을 강사가 확인하고 변환 결과가 원본과 일치 | 승인 범위의 실행을 끝내거나 중단 사유·진행 정보를 F3에 전달 | 플랫폼별 실제 결과를 확인하거나 미확인 사유와 사용자 조치를 기록 |
| **사용자 책임** | 원본·사진 제공, 현재 지역·가격 등 사실과 공개 권한 확인 | 게시처·범위 승인, 로그인/본인인증, 추가 조건 결정 | 추가 인증·수정, 필요 시 게시 확인 및 재개 승인 |
| **서비스 책임** | 추출·변환·오류 탐지·확인 요청·검증 | 허용 범위 내 입력·첨부·제출 시도, 중단·이력 전달 | 증빙 검증, 상태 관리, 중복 방지 및 결과 안내 |

**성공 판정:** 당근은 **모임 개설 + 첫 레슨 글 게시**까지, 크몽은 **상품 심사 접수**까지 확인해야 한다. 단순한 버튼 클릭은 성공이 아니며, 크몽 *심사 접수*와 *심사 승인·공개*는 구분한다.

## 3. 사용자 시나리오(설계·테스트용)

| ID | 상황 | 기대 결과 |
|---|---|---|
| **S-01 정상** | 기존 공고·사진을 당근과 크몽 양식으로 변환해 등록 | 올바른 조건으로 당근 첫 글 게시 및 크몽 심사 접수 확인 |
| **S-02 정보 누락** | 기존 공고의 지역이 현재도 유효한지 불명확 | 강사에게 현재 공개할 지역 확인; 확인 전 F2 진행 금지 |
| **S-03 인증 만료** | 크몽 등록 도중 로그인 만료 | 작업 중단 → 강사 재로그인 → 기존 단계 확인 후 안전하게 재개 |
| **S-04 결과 미확인** | 당근 제출 직후 네트워크 오류 | 성공 단정·자동 재제출 금지 → 기존 게시 여부 확인 또는 미확인 안내 |

## 4. 비교 검증 설계

**비교 대상:** ① 강사 직접 등록(동일 원본·템플릿) ② 범용 AI Codex(동일 원본·재사용 지시문) ③ 전용 서비스.

- **동일 입력:** 랩 레슨 원본, 동일 사진, 월 **30만 원·4회·회당 90분**, 강사가 확인한 최신 지역, 동일한 등록 규칙·승인 가격 옵션. 없는 체험가·할인율은 추정하지 않는다.
- **동일 시작:** 각 방식에서 로그인 전 상태, 미등록 시험 공고, 동일 자료·계정 자격·모의 등록 화면; 최초 작업 행동부터 시간 측정. 설치·초기 설정 시간은 별도 기록한다.
- **동일 종료:** 당근 첫 글 게시와 크몽 심사 접수의 **정확한 완료 건수(0~2건)** 및 각 플랫폼의 최종 상태로 판정. 실제 게시와 모의 성공은 별도 표기한다.
- **측정값:** **사용자 직접 작업 시간(분·초), 추가 개입 횟수(회), 정확한 완료 여부/건수**, 입력 오류·재시도, 전체 경과 시간, 구속 대기 시간, 초기 설정 시간. 직접 등록은 수정 행동을 별도 집계해 AI의 개입 횟수와 무리하게 단순 비교하지 않는다.
- **판단:** 정확성이 확보된 상태에서 전용 서비스가 직접 등록·Codex보다 강사의 시간/개입을 줄이는지 평가한다. 결과와 비용을 제시한 뒤 사용 의향도 확인한다.

## 5. 확인 사항과 다음 검토

**확인된 기획 근거:** 최초 등록 우선, 당근·크몽을 첫 대상 선정. R02의 기존 등록 소요시간(당근 약 15분·크몽 약 20분)은 **회상에 따른 추정치**로 실측값이 아니다.

**미확인/제약:** 두 플랫폼에서 외부 AI의 최종 자동 제출이 허용되는 경로, 최신 입력 양식·이미지 제한, 실제 완료 증빙 확보 방식, Codex/전용 서비스의 실행 성능. **허용 근거가 확보되기 전 실제 자동 제출은 실행하지 않고 모의 환경에서 검증**한다. 외부 계정 비밀번호·인증번호는 서비스에 수집·저장하지 않는다.

**현재 산출물:** F1~F3 요구사항, 정상 1건+예외/미확인 3건, 세 방식의 공통 입력·시작·종료·측정 기준 **초안 작성**. **다음:** R02 사실 확인, R01 검토 및 실제 실험 계획 확정. *(실험 수행·효과 검증 완료 아님)*

## 6. 보완 전제 및 근거 표시

- **문서 목적:** R01 피드백에 따라 기존 F1~F3 요구사항을 **당근 모임**과 **크몽 레슨 상품**의 실제 최초 등록 흐름에 연결한다. 최초 등록은 **우선 검증 시나리오**이며 **최종 MVP 확정 범위가 아니다.**
- **표시 체계:** **[R02 확인]** R02가 조사하거나 실제 경험·화면으로 기록한 정보(모든 계정에서 같음을 보장하지 않음) · **[설계 조건]** R03가 검증을 위해 제안한 동작 · **[미확인]** 화면·필수 여부·실제 허용 권한 등에 관한 확인이 필요한 정보.
- **검증 전제:** 외부 AI의 실서비스 최종 제출 허용 경로가 당근·크몽 모두 **미확인**이므로, 다음의 '실행'은 **모의 환경 또는 R05가 허용 근거를 확인한 실제 경로**에서만 수행한다. 강사 본인의 공식 로그인·본인인증을 전제로 하며, 당사 서버는 비밀번호·인증코드·세션 정보를 수집하지 않는다.
- **공통 실험 자료:** R02의 정정 포스터 기준 **월 300,000원 / 4회 / 회당 90분**; **현재 공개할 지역은 강사 확인 전**; **유료 1회 체험의 실제 판매가는 미제공**. 무료 상담·테스트 녹음과 유료 체험 수업은 혼동하지 않는다.

- **R01 피드백 2 반영:** 아래 §7-1·§8-1·§10-1은 **R02가 확보한 실제 경험·화면 기반 입력 필드**를 단계별로 연결한 추적표다. 기존 D-01~05/K-01~06의 기능 정의를 대체하지 않고, 각 단계에서 **무엇을 입력·확인·처리하고 무엇을 증거로 남길지** 보완한다. 공개된 화면에서 확인되지 않은 상세 경로·필수 여부·성공 증빙은 **[미확인]**으로 둔다.
- **R01 피드백 4 반영:** §9는 당근 `모임 생성/첫 글 게시`와 크몽 `상품 입력/심사 접수`를 분리하여 **단계 상태·부분 완료·결과 미확인·기록 항목·사용자 후속 조치**를 구체화한다. 구현 전 검증용 요구사항이며 실제 플랫폼의 완료 화면을 확인했다는 뜻은 아니다.

## 7. 당근 모임 — F1 → F2 → F3 상세 흐름

**목표:** 모임 **생성**과 그 모임 안의 **첫 레슨 글 게시**를 **별도의 완료 단계**로 확인한다. 당근 모임·카페·레슨/과외·비즈프로필은 서로 다른 게시처로 취급하며, 이번 흐름은 **모임**만 다룬다.

### D-01 · F1 / 원본 공고 분석 및 유효 정보 확인

| 항목 | 구체 요구사항 |
|---|---|
| **트리거** | 강사가 '당근 모임'을 선택하고 기존 레슨 글, 정정 포스터, 사진 후보를 제공함. |
| **입력** | 원본 모집 글·포스터, 수업 분야, 월 수업료·횟수·회당 시간, 공개 예정 지역, 사진 후보. |
| **처리** | **[설계 조건]** 핵심 수업 조건을 추출해 원문과 비교하고, 과거 작업실 주소·상충 가격·누락 정보를 분리한다. |
| **출력** | 확인된 수업 조건 목록과 강사에게 확인할 항목(특히 **현재 공개 지역**). |
| **예외** | 기존 공고에 이전 위치가 있거나 사진 권한·가격이 불명확하면 그 항목을 '확인 필요'로 표시한다. |
| **완료 조건** | 사용자가 최신 공개 지역·기본 수업 조건과 사용 가능한 사진을 확인한다. 미확인 항목이 필수라면 D-02를 확정하지 않는다. |
| **사용자 책임** | 현재 수업 지역·수업료·횟수·시간 확인; 사용 가능한 사진 제공. |
| **서비스 책임** | 추출·충돌 탐지·확인 질문 및 입력 데이터 정리. |

### D-02 · F1 / 모임 생성 정보와 첫 글 초안을 각각 준비

| 항목 | 구체 요구사항 |
|---|---|
| **트리거** | D-01의 필수 정보가 확인됨. |
| **입력** | **[R02 확인]** 모임명·카테고리·활동 지역과 범위·모임 소개; 모임 개설 후 게시할 레슨 글·강사/작업실 사진 후보. |
| **처리** | **[R02 확인]** 모임명 **24자 이내**, 소개 **500자 이내**로 변환. **[설계 조건]** `모임 생성용 정보`와 `첫 레슨 글·사진`을 **별도 입력 묶음**으로 만든다. 카테고리·활동 범위는 강사에게 선택받고, 기존 내용의 가격·시간을 사실대로 유지한다. |
| **출력** | A. 모임명·카테고리·활동 지역/범위·소개 초안 / B. 첫 글 본문·첨부 사진 목록 / C. 강사 승인 필요 항목. |
| **예외** | 글자 수 초과는 사실을 유지하여 재작성; 카테고리 선택지·첫 글의 정확한 필수 칸·사진 제한은 **[미확인]** 표시. 레슨 홍보가 허용되지 않는 모임 유형이면 실행 대상에서 제외. |
| **완료 조건** | 강사가 A·B와 공개 범위를 확인·승인함. 단, 필수 항목 중 미확인된 양식 조건은 실서비스 실행 전에 확인해야 함. |
| **사용자 책임** | 모임 목적·카테고리·활동 지역과 범위·사진 선택·홍보 내용 승인. |
| **서비스 책임** | 양식별 변환, 글자 수 검사, 승인 대상과 미확인 필드 분리. |

### D-03 · F2 / 사용자 로그인·실행 승인 및 모임 개설

| 항목 | 구체 요구사항 |
|---|---|
| **트리거** | D-02 승인 완료, 허용된 실행 경로 확보, 강사가 '모임 생성부터 첫 글 게시까지' 범위를 지정함. |
| **입력** | 모임 생성 정보 A, 강사 계정의 공식 로그인 상태, 실행 승인 범위. |
| **처리** | 강사가 직접 로그인·인증. **[설계 조건]** 등록 화면의 필드를 확인하여 A를 입력하고 **허용된 경로에서만** 모임 생성을 실행한다. 이미 생성된 모임이 있다면 중복 생성을 막는다. |
| **출력** | 모임 생성 실행 기록(시점·진행 단계), 확인 가능한 모임 표시명·링크/식별정보·결과 화면(**제공되는 경우**). |
| **예외** | 로그인 만료, 모임 생성 권한/모임 유형 제한, 잘못된 입력, 제출 직후 응답 끊김, **정책상 자동화 불허**. 결과 불명확 시 **같은 모임 자동 재생성 금지**. |
| **완료 조건** | 생성된 모임의 존재와 해당 계정의 접근 가능 여부가 확인됨. **버튼 클릭만으로 성공 판정 불가.** 결과 미확인 상태라면 D-04로 넘어가지 않는다. |
| **사용자 책임** | 직접 로그인/인증, 정확한 모임 유형·지역 승인, 제한 발생 시 직접 확인. |
| **서비스 책임** | 허용 범위 내 입력·실행, 화면 차이·오류 기록, 생성 여부 확인 요청. |

### D-04 · F2 / 생성된 모임에 첫 레슨 글 게시

| 항목 | 구체 요구사항 |
|---|---|
| **트리거** | D-03에서 모임 생성이 확인됨. |
| **입력** | 모임 확인 정보, B(첫 글 본문·승인 사진), 강사의 게시 승인 범위. |
| **처리** | **[설계 조건]** 해당 모임의 게시글 작성 화면에서 본문과 승인된 사진을 입력·첨부하고 내용 일치를 확인한 뒤, **허용되는 경우에만** 게시를 실행한다. |
| **출력** | 첫 글 제출 시도 정보와 게시 결과 화면/URL/식별정보(**제공되는 경우**). |
| **예외** | 사진 업로드 실패, 본문·사진 제한, 권한 문제, 레슨 홍보 제한, 제출 직후 결과 미확인. 게시 결과가 불명확하면 자동 재게시 금지. |
| **완료 조건** | **모임 내부에 승인된 내용·사진의 첫 글이 실제 표시되는지 확인됨.** |
| **사용자 책임** | 사진·본문의 게시 권한 확인, 추가 정보 결정, 필요 시 게시 여부 확인. |
| **서비스 책임** | 입력·첨부·제출 실행 조건 점검, 게시 증빙 확인을 위한 F3 인계. |

### D-05 · F3 / 당근 단계별 성공·실패·미확인 확정

| 항목 | 구체 요구사항 |
|---|---|
| **트리거** | D-03 또는 D-04가 완료·중단·응답 미확인 상태가 됨. |
| **입력** | 모임 생성 시도 기록, 게시 시도 기록, 확인 가능한 모임·글 화면/링크, 오류 메시지. |
| **처리** | 모임 생성 결과와 첫 글 게시 결과를 **독립적으로 확인**하고 중간 상태를 기록. 기존 모임/게시글 존재를 먼저 확인한 후에만 재개 판단. |
| **출력** | `모임 생성 상태`, `첫 글 상태`, 전체 판정(성공·부분 완료·실패·결과 미확인·실행 제한), 증빙·후속 조치. |
| **예외** | 모임만 생성·첫 글 실패, 모임 결과 불명확, 글 제출 직후 응답 끊김, 내용 불일치. |
| **완료 조건** | 각 단계 결과 또는 미확인 사유·다음 조치가 기록됨. 전체 등록 성공은 **모임과 첫 글 모두 실제 확인 시에만** 판정. |
| **사용자 책임** | 결과 불명확 시 기존 모임/글 직접 확인, 필요 시 수정·재개 승인. |
| **서비스 책임** | 증빙 검증, 중복 차단, 오류·단계별 결과 표시. |

### 7-1. 당근 모임 — 실제 입력 필드 ↔ F1·F2·F3 연결 (R01 피드백 2)

**읽는 방법:** **[R02 확인]**은 R02가 실제 등록 경험·제공 화면·기획안에 기록한 범위다. **[설계]**는 그 사실을 바탕으로 R03이 제안한 처리 규칙이며 실제 당근 UI가 이 순서로 구성되어 있다는 뜻은 아니다. **[미확인]**은 존재·필수 여부·화면·제출 허용 여부가 아직 확정되지 않은 사항이다. 아래 '완료 증거'는 **필요한 확인 결과**이지 현재 확보된 실제 제출 증빙이 아니다.

| 입력·단계 / 기존 요구사항 | R02 자료에서 확인된 입력 정보·절차 | 강사 확인 사항 | F1·F2 서비스 처리 범위(설계) | F3에서 필요한 완료 증거 | 확인 상태와 경계 |
|---|---|---|---|---|---|
| **기본 수업 정보** / D-01 | **[R02 확인]** 정정 포스터: 1:1 랩 레슨, **월 300,000원·월 4회·회당 90분**. 이전 작업실 위치가 남은 공고 존재 | 현재 수업 조건·공개할 최신 지역을 명시적으로 확인 | **F1:** 조건 추출·원문과 대조. 과거 위치는 최신 지역으로 대체하기 전까지 등록 자료에서 제외 | **F1 증거:** 강사가 확인한 값·확인일. 실제 게시 성공 증거는 아님 | 당근의 가격·횟수·시간 **전용 입력칸 존재/필수 여부 [미확인]**. 확인되지 않은 필드에 값을 자동 배치하지 않음 |
| **모임명** / D-02→03 | **[R02 화면]** 모임 이름 입력; **24자 이내** | 모임명과 홍보 목적 승인 | **F1:** 24자 제한 검사·문구 제안. **F2:** 허용된 방식에서 모임명 입력·반영 확인 | 생성된 모임에서 **승인된 모임명** 확인(보이는 경우) | 화면 제한은 R02 제공 자료 기준. 최신 변경 여부 [미확인] |
| **모임 카테고리** / D-02→03 | **[R02 경험]** 개설 시 카테고리를 정함 | 실제 활동·유료 레슨 홍보 목적에 맞는 유형 선택 | **F1:** 사용자 결정 항목으로 표시. **F2:** 강사가 승인한 유형만 입력 | 생성된 모임의 유형 표시(확인 가능할 때) | **선택지 전체·필수 여부·유료 홍보 허용 범위 [미확인]**. 자동 결정 금지 |
| **활동 지역·범위** / D-01~03 | **[R02 경험]** 지역과 활동 범위를 정해 개설함 | **현재 공개할 지역·활동 범위** 직접 확인; 이전 위치 재사용 금지 | **F1:** 원본 지역과 현재 확인값 분리. **F2:** 승인한 지역·범위만 반영 | 생성된 모임에서 지역·활동 범위 일치 확인(표시되는 경우) | 정확한 선택 단위·화면 값·필수 여부 [미확인]; 미확인 지역은 제출 차단 |
| **모임 소개** / D-02→03 | **[R02 화면]** 모임 소개 입력; **500자 이내**. 기존 뮬 글을 줄여 사용한 경험 | 소개 내용이 실제 수업·모임 취지와 일치하는지 승인 | **F1:** 기존 문구 축약·500자 제한 및 사실 보존 검사. **F2:** 승인한 소개 입력 | 생성된 모임의 소개 내용 일치 확인(보이는 경우) | R02가 확인한 제한. 추가 금지어·홍보 규정 자동 판단 불가 |
| **첫 레슨 글 본문** / D-02→04 | **[R02 경험]** 모임 개설 **이후 첫 글을 별도로 게시**. 기존 수업 소개와 수업 조건 사용 | 공개할 문구, 가격·횟수·시간 포함 범위 확인 | **F1:** 모임 소개와 분리된 첫 글 초안 마련. **F2:** 확인된 글쓰기 화면에서 승인 본문 입력 | 모임 안에 **승인된 내용의 첫 글이 실제 존재**하는지 확인 | **첫 글 제목칸·본문칸·필수 항목·글자 제한 [미확인]**. 임의의 '제목 필수' 주장 금지 |
| **첫 글 사진** / D-02→04 | **[R02 경험]** 작업실·강사 사진을 골라 첫 글에 올림 | 사진별 게시 선택·사용권한·현재 위치와의 부합 여부 확인 | **F1:** 승인 사진 후보 구분. **F2:** 허용된 방식에서 첨부·업로드 반영 확인 | 실제 글에 **승인된 사진**이 표시되는지 확인 | **사진 수·형식·용량·화면상 첨부 순서 [미확인]**. 업로드 완료 전 제출 중단 |
| **로그인·모임 생성 실행** / D-03 | **[R02 기획]** 강사가 공식 화면에 직접 로그인 후 맡기길 원함 | 본인 로그인·본인인증, 생성·게시 위임 범위 승인 | **F2:** 로그인 정보 수집 없이 화면 상태 확인; **허용된 경로에서만** 생성 실행 | 해당 계정에서 **생성된 모임의 존재** 확인(화면·링크 등 제공 시) | **정확한 화면 진입 경로·외부 AI 생성 허용 여부 [미확인]** |
| **첫 글 게시 실행** / D-04 | **[R02 경험]** 모임 개설 후 첫 글 게시가 별도 작업 | 글·사진 최종 승인 범위 및 필요시 직접 확인 | **F2:** 모임을 확인한 뒤 허용되는 방식에서 첫 글 제출 시도 | 게시된 **첫 글의 존재·내용·사진 일치** 확인(화면·링크 등 제공 시) | **정확한 게시 버튼·결과 안내 형태·AI 게시 허용 여부 [미확인]** |

**당근 단계별 절차·증빙(일부 성공 포함)**

| 순서 | 실제 절차에서 확인된 사실 | F1/F2 실행 전 확인 | F3 확인 및 상태 기록 | 예외 시 사용자 다음 행동 |
|---|---|---|---|---|
| **D-A. 모임 등록 정보 준비** | **모임명·카테고리·활동 지역/범위·소개**를 정함 | 강사가 이름·카테고리·현재 지역·소개를 승인; 길이 점검 | 준비값·승인 여부 기록 (**게시 증거 아님**) | 누락·충돌 정보 답변; 정책상 홍보 목적 적합 여부 확인 요청 |
| **D-B. 모임 생성** | 모임 개설을 먼저 수행 | 로그인/인증·허용 경로·실행 범위 확인 | **모임 생성 확인 / 실패 확인 / 결과 미확인**을 별도 기록; 확인 가능한 모임 정보·시각 | 생성 결과 미확인 시 모임 목록 등에서 기존 모임 직접 확인, 자동 재생성 금지 |
| **D-C. 첫 글 준비·게시** | 모임 생성 후 첫 레슨 글과 사진 게시 | 확인된 모임을 대상으로 승인 글·사진 사용 | **첫 글 게시 확인 / 실패 확인 / 결과 미확인**을 별도 기록; 글 내용·사진·시각 | 모임만 생성됐다면 첫 글만 후속 처리; 게시 결과 미확인 시 기존 글 확인 전 재게시 금지 |
| **D-D. 전체 종료** | 모임 생성 + 첫 글 게시가 목표 | 승인한 조건과 게시 결과 비교 | **두 단계 모두 확인될 때만 전체 성공**. 한 단계만 확인된 상태는 부분 완료/미확인 | 남은 단계에 대해서만 수정·확인·재개 승인 |

**해석 주의:** `24자/500자`는 **모임명/모임 소개**에 대한 R02 화면 자료다. 이를 **첫 레슨 글의 길이 제한**으로 옮겨 적지 않는다. '모임 생성 확인'은 **첫 글 게시 확인**을 의미하지 않는다.

## 8. 크몽 — F1 → F2 → F3 상세 흐름

**목표:** **상품 초안 작성**과 **상품 심사 접수**를 **별도 단계**로 확인한다. **심사 접수=상품 공개**가 아니다.

### K-01 · F1 / 원본에서 크몽 필드 추출·변환

| 항목 | 구체 요구사항 |
|---|---|

## 9. 단계별 완료 상태·예외 흐름·사용자 조치 (R01 피드백 4)

> **구분:** **[R02 확인]** 당근은 모임 생성 후 첫 글을 별도로 게시하고, 크몽은 상품을 작성한 뒤 심사를 접수한다. **[설계 조건]** 아래 상태·예외 판정과 기록 방법은 R03 제안이며, 실제 UI의 상태 문구나 접근 경로를 확인했다는 뜻이 아니다. **[미확인]** 플랫폼에서 제공하는 완료 화면·내역·식별정보와 AI 확인 권한은 R02·R05 확인 후 확정한다.

### 9-1. 단계별 판정 단위와 공통 규칙

| 플랫폼 | 독립적으로 기록할 작업 단위 | 단계 성공의 조건 | 이번 검증의 **최종 성공** 조건 |
|---|---|---|---|
| **당근** | **D-03 모임 생성** / **D-04 첫 레슨 글 게시** | ① 모임이 실제 생성되었음 ② 그 모임 안에 승인된 첫 글·사진이 실제 게시되었음(각각 별도 확인) | ①과 ② **둘 다 확인**하고 승인한 수업 조건과 일치함 |
| **크몽** | **K-04 상품 정보 작성** / **K-05 심사 접수** | ① 상품 정보·사진 입력이 승인값과 일치함(화면 입력 확인) ② 심사 접수 결과가 플랫폼에서 확인됨 | ② **심사 접수 확인** 및 승인 조건 일치. 심사 **승인·공개는 별개** |

- **공통 단계 상태:** `미시작` / `진행 중` / `입력 확인(미제출)` / `성공 확인` / `실패 확인` / `결과 미확인` / `사용자 확인 필요` / `실행 제한`. `입력 확인(미제출)`은 크몽처럼 제출 전에 입력 완료를 구분할 때 사용하며, 플랫폼에서 **임시저장이 실제 유지되는지는 별도 확인**한다.
- **[설계 조건] 성공 판정:** 버튼 클릭·텍스트 입력·업로드 시도만으로 `성공 확인` 처리하지 않는다. 플랫폼이 제공하는 경우 **실제 생성된 모임/첫 글, 실제 심사 접수 결과**를 확인하고, 승인한 가격·횟수·시간·지역·사진과 일치해야 한다. 해당 확인 경로가 없으면 `결과 미확인`으로 남긴다.
- **[설계 조건] 실패와 미확인 구분:** 제출 **전** 확인된 오류(예: 필수값 거절·이미지 업로드 실패) 또는 플랫폼에서 명확히 거절된 작업은 `실패 확인`으로 분류한다. 제출 **후** 네트워크 단절·화면 응답 누락으로 실제 반영 여부를 알 수 없으면 `결과 미확인`으로 분류하고 동일 단계 자동 재시도를 막는다.
- **부분 완료의 의미:** 앞 단계만 확인된 경우(예: `모임 생성 성공/첫 글 실패`, `상품 입력 확인/심사 접수 미실행`)를 말한다. **최종 성공 건수에는 포함하지 않는다.** 후속 단계가 `결과 미확인`이면 최종 상태를 `결과 미확인(앞 단계 확인)`으로 표시해 불명확성을 숨기지 않는다.
- **실행 제한은 실패와 별개:** AI 제출 권한이 확인되지 않거나 플랫폼 정책상 실행이 허용되지 않으면 실제 실행을 시작하지 않고 `실행 제한`으로 기록한다. 모의 환경 결과는 `모의`로 별도 표기하며 실제 완료로 집계하지 않는다.
- **후속 심사 상태:** 크몽에서 `심사 접수 확인` 후 `심사 진행/승인·공개/반려`는 **접수 이력과 별도**로 기록한다. 반려가 발생해도 과거 접수 사실 자체를 없애지 않는다. 다만 잘못된 조건으로 접수되었다면 `정확한 완료`로 집계하지 않고 정정 필요로 표시한다.

### 9-2. 당근 — 모임 생성과 첫 글 게시를 분리한 상태 전이

**순서:** `D-01/02(F1 자료 승인)` → `D-03(F2 모임 생성)` → **모임 생성 성공 확인** → `D-04(F2 첫 글 게시)` → `D-05(F3 두 결과 검증)`. 모임 생성 여부가 불명확하면 첫 글 단계로 진행하지 않는다.

| 발생 상황·단계 | 단계별 기록 상태 → 전체 판정 | 반드시 기록할 정보·증거 | 사용자에게 요청할 다음 행동 | 서비스 처리 책임 |
|---|---|---|---|---|
| **D-A. 모임 생성 전 입력 누락**(모임명·지역·카테고리 등) | `생성 미시작 / 첫 글 미시작` → **사용자 확인 필요** | 누락 항목, 사용자가 마지막 확인한 값, 미승인 이유 | 실제 모임 목적·카테고리·현재 공개 지역을 확인·승인 | F1 보완 질문, 확정 전 생성 실행 차단 |
| **D-B. 모임 생성 성공, 첫 글 미시작** | `모임 성공 확인 / 첫 글 미시작` → **부분 완료** | 생성 확인 시각, 모임명·활동 지역·범위와 승인값 일치, 모임 링크/화면(제공 시) | 모임 정보를 확인하고 첫 글 진행에 필요한 승인·사진 점검 | 모임 재생성 금지, 생성된 **같은 모임**에만 글 작성 준비 |
| **D-C. 모임 생성은 확인, 첫 글의 사진 업로드 실패(제출 전)** | `모임 성공 확인 / 첫 글 실패 확인` → **부분 완료** | 업로드 실패 시점·파일명/형식·오류 문구(민감정보 제외), 제출 전 실패 여부 | 올바른 사진으로 교체하거나 업로드 조건 확인 후 **첫 글 단계만** 재개 승인 | 모임 상태 보존, 원인 안내, 승인된 사진만 재첨부; 글 제출은 보류 |
| **D-D. 모임 생성은 확인, 첫 글 게시가 명시적으로 실패** | `모임 성공 확인 / 첫 글 실패 확인` → **부분 완료** | 게시 실패 표시·마지막 실행 단계·본문/사진 검증 결과 | 글 내용·권한·실패 조건을 수정하고 **첫 글만** 다시 시도할지 승인 | 기존 글 존재 여부 확인 후 허용된 경로에서 해당 단계만 재개 |
| **D-E. 모임 생성 버튼 이후 응답 단절** | `모임 결과 미확인 / 첫 글 미시작` → **결과 미확인** | 생성 시도 시각, 마지막 확인 화면, 오류, 재생성 차단 여부 | 본인 계정에서 모임이 존재하는지 확인하고 확인 결과 전달 | 동일 모임 자동 재생성 금지, 증거가 확보될 때까지 첫 글 단계 진입 금지 |
| **D-F. 첫 글 게시 요청 직후 응답 단절** | `모임 성공 확인 / 첫 글 결과 미확인` → **결과 미확인(모임 확인)** | 첫 글 제출 시도 시각, 모임 식별 단서, 승인 본문·사진 요약, 마지막 화면·오류 | 해당 모임에서 **이미 게시된 글이 있는지** 직접 확인; 게시/미게시 여부 회신 | 자동 재게시 금지, 기존 게시 여부 확인 뒤에만 재개 판단 |
| **D-G. 모임 생성·첫 글 게시가 모두 확인됨** | `모임 성공 확인 / 첫 글 성공 확인` → **최종 성공** | 모임·첫 글 확인 근거, 확인 시각, 게시 내용·사진·지역의 승인값 일치 | 게시 결과 확인만 수행(추가 입력 불필요) | 증거 연결, 1건 성공 집계, 중복 제출 차단 |
| **D-H. 첫 글은 게시됐지만 가격/지역/사진이 승인값과 다름** | `모임 성공 확인 / 첫 글 게시 사실 확인·내용 불일치` → **정정 필요(정확한 완료 0건)** | 실제 표시 내용과 승인값의 차이, 게시 확인 시각·근거 | 게시글 수정·삭제 등 플랫폼이 **허용하는 조치**를 직접 판단·승인 | 불일치 알림; 임의로 수정·삭제·재게시하지 않음 |
| **D-I. 생성 또는 게시 방식이 허용되지 않음/미확인** | 영향받는 단계 `실행 제한` → **실제 실행 미실시** | 제한 대상 단계, 확인한 근거·확인일, 확인 필요 담당자 | 허용 경로 안내를 받을 때까지 대기하거나 모의 검증 선택 | 실제 자동 실행 중단; 미승인 우회 금지 |

**당근 중간 완료 안내 예시(설계 문구):** `모임은 생성된 것으로 확인했습니다. 첫 레슨 글은 사진 첨부 오류로 게시되지 않았습니다. 기존 모임은 유지하며 사진을 확인한 뒤 첫 글 등록만 다시 진행할지 선택해 주세요.`

### 9-3. 크몽 — 상품 작성과 심사 접수를 분리한 상태 전이

**순서:** `K-01/02(F1 원본·옵션 확인)` → `K-03(직접 로그인/전문가 인증)` → `K-04(상품 필드·이미지 입력)` → **작성 내용 확인** → `K-05(심사 접수 실행)` → `K-06(F3 접수 사실 검증)`. `상품 정보 작성`과 `심사 접수`는 다른 단계다. **[미확인] 상품 임시저장 버튼·자동 저장·영속 저장의 제공 여부**는 강사 경험/화면 확인 전 단정하지 않는다.

| 발생 상황·단계 | 단계별 기록 상태 → 전체 판정 | 반드시 기록할 정보·증거 | 사용자에게 요청할 다음 행동 | 서비스 처리 책임 |
|---|---|---|---|---|
| **K-A. 전문가 인증·로그인 미완료** | `상품 작성 미시작 / 심사 접수 미시작` → **사용자 확인 필요** | 필요한 인증 유형(화면에 표시된 경우), 마지막 화면, 실행 중단 시점 | 공식 화면에서 직접 로그인·인증 완료 | 비밀번호·인증번호 취급 금지, 자격 확인 후 재개 가능 여부 점검 |
| **K-B. 상품 필드 입력·사진 첨부가 완료됐지만 아직 심사 접수 전** | `상품 입력 확인(미제출) / 접수 미시작` → **부분 완료(작성 단계)** | 확인한 필드·이미지·가격과 승인값의 일치, 작성 확인 시각, **임시저장 여부 미확인 표시** | 패키지·최종 내용 확인, 접수 진행 승인 | 실제 저장 여부를 추정하지 않으며, 허용된 경우에만 접수 준비 |
| **K-C. 상품 작성 중 이미지 업로드 실패(제출 전)** | `상품 작성 실패 확인 / 접수 미시작` → **실패 확인(작성 단계)** | 어떤 이미지·필드가 실패했는지, 플랫폼 오류·시각, 제출 전 단계 | 적합한 이미지를 선택하거나 사진 권한·규격 확인 | 문제 필드만 보완, 심사 접수 실행 차단 |
| **K-D. 상품 입력은 확인됐지만 패키지 금액·회당 시간이 승인값과 불일치** | `상품 사용자 확인 필요 / 접수 미시작` → **정정 필요** | 승인 값과 화면값의 차이, 확인 시점 | 금액·횟수·시간을 확정하여 수정 승인 | 임의 가격 보정·1회 체험가 추정 금지, 수정 전 제출 금지 |
| **K-E. 상품 입력 확인 후 심사 접수가 명시적으로 거절·실패** | `상품 입력 확인 / 심사 접수 실패 확인` → **부분 완료(접수 미완료)** | 접수 실패 화면·메시지(제공 시), 수정 필요 항목, 마지막 단계 | 실제 필수값·인증·권한 문제를 해결하고 재접수 승인 | **상품 전체를 다시 작성하지 않고** 안전한 재개 지점 판단; 단, 작성 정보가 유지됐는지는 확인 필요 |
| **K-F. 심사 접수 요청 직후 응답 단절** | `상품 입력 확인 / 심사 접수 결과 미확인` → **결과 미확인** | 시도 시각, 승인 판매 조건, 마지막 화면·오류, 접수 재시도 차단 여부 | 자신의 상품/심사 진행 내역에서 **이미 접수된 기록이 있는지** 직접 확인 | 자동 재접수 금지, 허용된 확인 경로에서 기존 접수 존재 확인 후 판단 |
| **K-G. 심사 접수 사실 확인, 심사 결과는 아직 없음** | `상품 입력 확인 / 접수 성공 확인 / 심사 대기` → **최종 성공(접수 목표)** | 심사 접수 상태를 보여 주는 증빙·시각·식별정보(제공 시), 상품 조건 일치 | 별도 진행이 필요한 경우 심사 결과 확인 | 목표 성공 1건 집계, 심사 승인·상품 공개로 오표기 금지 |
| **K-H. 심사 접수 후 반려 또는 수정 요청** | `접수 성공 확인(이력) / 현재 심사 반려·수정 요청` → **접수 이력 유지, 후속 수정 필요** | 반려 사유·확인일·해당 상품 식별 단서, 당초 접수 증거 | 반려 사유 검토, 수업·가격·자료 수정 및 재접수 여부 결정 | 접수 이력을 지우지 않음; 승인 없는 변경·재제출 금지 |
| **K-I. AI 상품 작성·심사 접수 허용 근거 없음** | 영향받는 단계 `실행 제한` → **실제 실행 미실시** | 정책/권한 미확인 단계, 조사 근거·확인일 | 사용 가능한 공식 경로 확인 또는 모의 실험 참여 | 실제 자동 입력·접수 중단, 불허된 계정 공유·우회 금지 |

**크몽 중간 완료 안내 예시(설계 문구):** `레슨 상품의 필수 입력 항목과 이미지는 승인한 내용으로 채웠습니다. 심사 접수는 인증 요청으로 진행하지 못했습니다. 상품이 임시저장되었는지는 확인되지 않았으므로 다시 로그인한 후 작성 내용이 남아 있는지부터 확인해 주세요.`

### 9-4. 결과 미확인 시 F3의 안전한 후속 판단 절차

1. **현재 단계 정지:** 오류 직전의 `제출 전/제출 시도 후`를 구분하고, 결과가 미확인이면 동일한 모임 생성·글 게시·심사 접수 **자동 재시도를 즉시 차단**한다.
2. **기존 결과 확인:** R05가 허용 범위를 확인한 공식 화면·등록 내역 등으로 해당 결과가 존재하는지 조회한다. **[미확인]** 당근/크몽의 정확한 메뉴명·API/식별정보 제공 여부는 가정하지 않는다.
3. **증빙 확보:** `기존 결과 있음`이면 승인 내용과 대조한 뒤 성공 또는 정정 필요로 판정한다. `없음`도 실제 **미제출이 확인된 경우에만** 실패로 판정한다. 조회 불가·결과 불충분이면 미확인을 유지한다.
4. **후속 책임 안내:** **사용자**는 공식 계정에서 기존 모임·글·상품/심사 내역을 직접 확인하거나 수정·재개를 승인한다. **서비스**는 필요한 확인 대상과 이미 성공한 단계·위험한 재시도 범위를 명확히 안내한다.
5. **안전한 재개:** 미제출이 확실하고 입력·권한·승인 조건이 충족되는 경우에만, R05가 허용한 방식으로 **실패한 해당 단계만** 재개한다. 확인되지 않은 중복 가능성을 사용자 동의만으로 제거했다고 가정하지 않는다.

### 9-5. 오류·부분 완료·결과 미확인 시 기록할 최소 항목

아래는 **요구사항 수준의 기록 항목**이며 DB 테이블·API·로그 형식 설계가 아니다.

| 기록 항목 | 왜 필요한가 / 예시 |
|---|---|
| **실험 구분·대상** | `모의/실제`, `당근/크몽`, 1개의 등록 요청, 해당 공고/상품 구분 단서 |
| **단계 식별·상태** | `D-03 모임 생성`, `D-04 첫 글 게시`, `K-04 상품 입력`, `K-05 심사 접수` 및 각 상태 |
| **원본·승인 조건** | 강사가 승인한 제목/내용/지역, **월 30만 원·4회·90분**, 사진 후보·확인일; 필요한 범위만 |
| **실행 이력** | 해당 단계의 시작·마지막 실행·제출 시도 시각, `제출 전/제출 시도 후` 구분 |
| **완료·오류 근거** | 성공/실패/미확인 판단에 사용한 플랫폼 상태·오류 내용·확인 시각, 제공되는 경우 링크/식별정보/민감정보를 가린 화면 |
| **앞 단계 보존** | 이미 생성된 모임·게시된 글·작성 확인 상품·심사 접수 이력과 해당 확인 수준 |
| **중복 방지·재개 판단** | 재시도 차단 여부, 기존 결과 존재 확인 여부, 재개 가능한 단계/그 근거 |
| **사용자 후속 조치** | 사용자에게 요청한 확인·수정·재인증·승인과 담당자, 응답 여부, 현재 미결정 사항 |

**기록 금지:** 비밀번호·인증번호·세션 정보, 승인 범위 밖의 사적 메시지·정산 화면, 불필요한 개인정보. 증빙 보관 범위·기간은 별도 결정하며, **스크린샷·URL·접수번호가 플랫폼에서 반드시 제공된다고 단정하지 않는다.**

### 9-6. 두 플랫폼을 동시에 요청했을 때 전체 결과

| 당근(D-03 + D-04) | 크몽(K-04 + K-05) | 사용자에게 보여 줄 전체 결과 | 정확 완료 건수(0~2) |
|---|---|---|---|
| 모임 생성·첫 글 게시 **모두 확인** | 상품 작성·심사 접수 **모두 확인** | **전체 성공** | **2건** |
| 모임 생성만 확인, 첫 글 **실패 확인** | 심사 접수 **확인** | **1건 성공 + 당근 부분 완료**; 당근 첫 글만 보완 | **1건** |
| 모임·첫 글 **모두 확인** | 상품 작성 확인, 심사 접수 **결과 미확인** | **1건 성공 + 크몽 결과 미확인**; 중복 재접수 금지 | **1건** |
| 모임 생성 **결과 미확인**, 첫 글 미시작 | 상품 작성 입력 확인, 심사 접수 **미시작** | **양쪽 목표 미달성·당근 생성 미확인**; 각각 후속 확인 | **0건** |
| 실제 AI 실행 **제한** | 실제 AI 실행 **제한** | **실제 실행 미실시**, 별도 모의 실험만 가능 | **0건(실제)** |

**원칙:** 하나의 전체 상태 명칭만 보여 주지 말고 **플랫폼별·단계별 상태, 미확인 여부, 정확 완료 건수, 사용자 다음 행동**을 함께 보여 준다. 검증하지 않은 성공은 완료 건수에 더하지 않는다.

### 9-7. 관련 검토 요청과 미확인 경계

- **R02 확인:** 당근 모임을 만든 뒤 실제 **어떤 상태/화면에서 생성 사실을 확인했는지**, 첫 글 게시 후 어떤 방법으로 표시를 확인했는지, 크몽 상품 내용을 **임시저장할 수 있었는지와 입력 내용이 다시 열렸는지**, 심사 접수 성공·반려를 실제 어떤 화면에서 확인했는지. **당시 경험과 현재 화면 확인을 구분**한다.
- **R05 확인:** 각 단계(모임 생성/첫 글 게시/상품 입력/심사 접수)의 **AI 입력·제출 허용 범위**, 로그인 만료 뒤 확인 가능한 공식 경로, 제출 직후 결과가 불명확할 때 허용되는 중복 확인 방법. **허용 경로 확보 전 실서비스 AI 실행 금지.**
- **[미확인] 유지:** 구체적인 완료 화면 명칭·식별번호 제공 여부·임시저장 동작·재개 가능한 경로와 정책상 자동화 허용은 확인 전 임의 지정하지 않는다.

**R05 질문 전달 시 요청 형식:** `(1) 대상 플랫폼/단계 (2) 직접 로그인한 설치형 AI vs 원격 대행 (3) 입력·이미지 첨부·최종 제출 각각 허용 범위 (4) 공식적인 성공 확인 수단 (5) 미확인/불허 시 중단 지점`을 분리해 기록한다. 운영사 승인 또는 공식 허용 근거를 확보하지 못하면 **모의 화면에서만** 비교 실험을 수행한다.

**개발 인계용 판정:** `F1 입력자료 완비`는 실제 게시·접수 성공이 아니다. `F2 입력 완료`도 성공이 아니다. **F3에서** 당근은 **모임 생성과 첫 글 게시**, 크몽은 **심사 접수**가 **각각 증거로 확인될 때만** 목표 달성으로 판정한다. 실제 성공 증빙 경로가 미확인인 단계는 성공 처리 로직을 가정하지 않고 확인 요청으로 남긴다.
