# 공개 안내·체크리스트·LLM 준비 결과 비교

**현재 개발·검증 상태:** 현재 기획안을 구체화하는 단계로, 공개 안내·체크리스트·LLM을 동일 조건에서 비교할 테스트와 시제품은 아직 구현하지 않았다. 작성한 비교 자료는 설명용 모의 예시와 기존 LLM 실행 기록의 대조이며, 실제 수행 시간·누락 건수·화면 이동 횟수를 측정한 비교 실험 결과가 아니다.

R03 두나 · 2026-11-17 · 같은 가상 사건을 이용한 설명용 대조

**결론: 공개 안내를 읽고 직접 작성하거나 체크리스트를 써도 준비 결과를 만들 수 있고, 기존 LLM도 주요 정리·정정 동작을 수행했다. 현재 자료로 어느 방법이 실제로 더 쉽거나 빠른지, 재인증을 줄이는지는 판단하지 않는다.**

## 1. 비교 조건과 한계

| 방식 | 이번 자료의 성격 |
|---|---|
| A. ECRM 공개 안내 참고 작성 | 작성 AI가 안내를 읽고 직접 작성한 모의 예시. 사람의 실제 수행 결과나 ECRM 자동 출력이 아님 |
| B. 안내+체크리스트 | 같은 AI가 자체 체크리스트에 맞춰 작성한 모의 예시. 실제 사용자 실험 아님 |
| LLM. 충분한 지시 | 11/16 가상 1건·2턴 CLI의 실제 원응답을 재사용. 이번에 재실행하지 않음 |

A/B 작성자가 LLM 결과를 알고 있어 독립·맹검 비교가 아니다. 기존 LLM의 프롬프트·실행 조건은 현재 A/B와 완전히 같지 않다. 원래 실행 전 기준과 이번 추가 관찰을 구분하며 점수·우열을 산출하지 않는다. [구조화 결과·원응답·실행 조건](2026-11-17_공개안내_체크리스트_LLM_준비결과_비교.json)

## 2. 모두에게 사용할 가상 자료

- S1: 사용자는 키보드 거래에 10만 원을 보냈고 미수령이라고 설명. 정확한 송금일·약속일을 모름. 사기였던 것 같다는 추측.
- S2: 가상 판매 글의 키보드 가격 12만 원.
- S3: 판매자의 발송 주장과 운송장 추후 전달 문구. 메시지 작성일 없음.
- S4: 가상 이체 문구에 11/10 18:30·12만 원 기재. 실제 파일·식별정보 없음.
- S5: 11/16 현재 미수령, 마지막 연락일 모름.
- 2차 입력 S6: 사용자가 12만 원으로 정정하고 S4를 해당 거래로 연결 확인. 발송 여부·약속일은 계속 모름.

기존 자료의 종류와 표현을 보존한 가상 시험이다. S4 문구를 실제 송금 증빙의 진위 확인으로 해석하지 않는다. 현재 시제품은 사용자가 자료 내용을 설명한 경우 그 설명으로 표시해야 한다.

## 3. A — 공개 안내를 보고 작성한 예시

[공식 공개 메인](https://ecrm.police.go.kr/minwon/main)은 증빙 예시와 피해 경위 작성 요소를 안내한다(11/17 확인). 이를 참고해 같은 가상 자료에서 아래 준비문을 작성했다. 실제 입력 화면 전체를 복제한 양식이나 공식 완성 진술서가 아니다.

> 키보드 거래 후 물품을 받지 못했다고 설명합니다. 판매 글의 가격은 12만 원입니다. 송금액은 최초 설명 10만 원과 제공된 가상 이체 문구 12만 원이 달라 확인이 필요합니다. 판매자는 발송했다고 주장했으나 메시지 일시와 실제 발송 여부는 모릅니다. 거래 플랫폼·상대방 특정정보·배송 약속일·마지막 연락일·신고 시 원하는 조치는 추가 확인 대상입니다.

**준비 목록:** 판매 글·대화·이체에 해당하는 문구는 제공됨. 실제 원본과 신분증의 보유 여부는 별도 확인. 자료 내용의 진위나 실제 제출 가능성은 판정하지 않음.

**정정 뒤:** 현재 송금액을 12만 원으로, 가상 이체 일시를 11/10 18:30으로 반영한다. 과거 10만 원 진술은 이력에 두고 발송·약속일은 미확인으로 유지한다.

## 4. B — 안내에 체크리스트를 추가한 예시

| 확인 항목 | 첫 결과 | 정정 뒤 |
|---|---|---|
| 물품·게시 가격 | 키보드·12만 원. 최종 합의 가격은 모름 | 동일 |
| 송금액·일시·거래 연결 | 10만/12만 원 불일치, S4 거래 연결 미확인 | 사용자 정정12만 원·S4 연결 반영, 이전 진술 보존 |
| 판매자 발언 | 배송 주장, 실제 발송·메시지 일시 미확인 | 동일 |
| 피해 상황 | 사용자 기준 11/16 미수령 | 동일 |
| 원본 증빙·신분증 | 가상 문구 외 실제 보유 미확인 | 동일 |
| 플랫폼·상대방·원하는 조치 | 추가 확인 | 동일 |

**사용 체크리스트:** 물품 / 플랫폼·상대방 / 송금액·일시·거래 연결 / 약속·현재 상황 / 자료 보유 상태 / 신고 이유·원하는 조치 / 미확인·충돌. 이는 비교용 자체 양식이며 ECRM 공식 필수 항목 전체를 확인했다는 뜻은 아니다.

## 5. LLM — 기존 실제 출력 관찰

- 1차: 요약 항목마다 원문 ID 연결, 금액 불일치·거래 연결 질문, 판매자 주장과 사용자 추측 구분, 발송·날짜 미확인 보존.
- 2차: 12만 원과 S4 연결 반영, 과거 진술·정정 이력 보존, 답변한 금액 질문 제거, 배송 미확인 유지.
- 남은 질문: 최종 합의 가격·운송장 수령 여부. 사용자에게 필요한 질문인지 부담인지 측정하지 않음.
- 기존 질문·미확인 목록에 플랫폼·신고 의사를 묻는 항목은 명시되지 않았다. 기존 지시에서 해당 목록을 고정하지 않았으므로 이 관찰을 공식 오류율로 쓰지 않는다. 다음 통제 비교의 점검 항목으로 삼는다.
- 원문 ID가 붙었다는 사실과 문장 의미가 정확하다는 판정은 별개다.

## 6. 나란히 본 결과

| 비교 항목 | A 공개 안내 | B 체크리스트 | 기존 LLM |
|---|---|---|---|
| 경위 초안 | 작성 예시 있음 | 항목별 작성 예시 있음 | 실제 생성 기록 있음 |
| 자료·미확인 목록 | 작성자가 직접 정리 | 체크 항목에 맞춰 직접 정리 | 실제 생성·미확인 보존 관찰 |
| 금액 정정·주장 구분 | 예시에 반영 | 예시에 반영 | 기존 2턴에서 관찰 |
| 준비 항목의 빠짐 점검 | 작성자가 안내와 대조 | 고정 목록을 따라 대조 | 프롬프트의 항목 범위와 출력 확인 필요 |
| 사용자 전체 수고·인증 횟수 | 미측정 | 미측정 | 미측정 |

A/B의 좋은 예시를 실제 사용자의 성공률로, LLM의 생성 시간을 사용자의 전체 준비 시간으로 바꾸지 않는다. 기존 LLM 2턴 합계108.247초는 CLI 실행 시간이며 사용자 시간·다른 방식 대비 우위를 뜻하지 않는다.
