# 중고거래 상담·신고 준비 기획의 근거 검토

- 담당: R03 두나 · 확인일: 2026-11-16
- 관련 작업: [TASK-018](../../../artifacts/tasks/TASK-018.json)
- 대상: [기획안](2026-11-16_생활법률_고소준비_지원_서비스_기획_초안.md) · [1페이지 요약](2026-11-16_중고거래_상담신고_준비_멘토링_1페이지_요약.md)
- 범위: 공식 공개 자료의 최소 개별 조회와 사용자 제공 화면 관찰. 신고 제출·실제 사용자 제품 비교는 수행하지 않음. 가상 LLM 실행은 별도 반증 점검 기록 참조

## 1. 결론

**신고 준비에 사건 설명·증빙자료가 필요하고, 작성 편의성 문제가 제기됐다는 공식 근거는 있다. 그러나 이 기획의 핵심인 자료 재탐색·반복 정리·수정 부담이 현재 중고거래 피해자에게 얼마나 남는지 직접 입증한 근거는 아직 없다.**

또한 경찰청은 이미 질문·답변 기반 맞춤형 진술서 자동 작성을 지원하는 폴봇을 발표했다. 따라서 단순 요약·질문·작성 도움의 부재를 기획의 근거로 삼지 않고, 기존 지원 이후에도 원문 추적·수정 일관성에서 추가 가치가 있는지 비교한다.

## 2. 근거별 확인 사실과 적용 한계

### E01. ECRM의 사건 설명·증빙자료 요구

- 출처: [경찰청 ECRM 공식 공개 안내](https://ecrm.police.go.kr/minwon/main)
- 확인: 피해 내용에 상대방 정보·일시·장소·내역·과정·신고 이유를 기술하도록 안내하고 육하원칙·예시를 제공한다. 신분증·이체내역서·대화내역 등 준비·첨부와 접수 후 방문 절차를 설명한다.
- 기획에 연결: 사용자 입력을 사건 경위와 자료 목록으로 연결할 과제가 실제 신고 준비 과정에 존재한다.
- 한계: 필요한 과제가 있다는 근거이지, 사용자가 수행하기 어렵거나 우리 서비스가 더 낫다는 근거는 아니다. 현재 메인 화면에는 폴봇 진입 표시도 있지만 실제 대화·진술서 생성은 시험하지 않았다.

### E02. 폴봇 도입 배경과 기존 자동 작성 지원 — 중요한 반대 근거

- 출처: [경찰청·정책브리핑 「사이버범죄 신고 챗봇으로 쉽게…경찰청 ‘폴봇’ 개시」](https://m.korea.kr/news/policyNewsView.do?newsId=148908906)
- 발표일: **2022-11-30**. 현재 확인일과 구분한다.
- 확인: 당시 모바일 신고에서 긴 문장 작성과 오탈자 불편, 낯선 범죄유형 명칭 선택 문제를 설명했다. 질문에 답하면 맞춤형 진술서를 작성하고 버튼·음성 입력으로 작성 편의를 돕는 기능을 발표했다.
- 기획에 연결: 작성 수고·용어 이해를 고려한 지원 수요가 당시 정책 설계에 반영됐다는 근거다.
- 반대 근거: 질문을 통한 진술서 생성은 이미 발표된 기능이므로, ‘ECRM은 정해진 양식만 제공한다’거나 ‘자동 구조화를 하지 않는다’고 단정할 수 없다.
- 한계: 2022년 발표로 현재 세부 동작·가용 범위·개선 효과를 확정하지 않는다. 중고거래 물품 미수령 집단의 반복 정리 부담, 원문 ID 연결·부분 수정·충돌 보존의 제공 여부도 이 자료만으로 판단하지 않는다.

### E03. 신고 절차의 번거로움에 대한 공식 교육자료

- 출처: [한국소비자원·서민금융진흥원 「온라인 중고거래 사기탈출 넘버원」](https://www.kca.go.kr/smartconsumer/sub.do?menukey=7101&mode=view&no=1003195530)
- 등록일: **2021-10-08**. 게시된 자막을 확인했다.
- 확인: 소액 피해에서는 절차가 번거로워 신고하지 않는 경우가 있다는 설명과, 온라인 대화 증거·신분증·이체 자료 준비 안내가 있다.
- 기획에 연결: 절차 부담을 살펴볼 이유를 보조한다.
- 한계: 교육용 재연이며 실제 경험자 인터뷰나 표본조사 결과로 취급하지 않는다. 반복 정리 횟수·소요 시간·현재 빈도를 제공하지 않는다. 당시 보상 조건·옛 URL 등 부수 안내를 최신 정보로 재사용하지 않는다.

### E04. 사용자가 제공한 ECRM 진행 표시 화면

- 출처: 2026-11-16 대화에서 제공한 이미지. [화면 관찰 기록](2026-11-16_중고거래_기획_피드백_반영_및_ECRM_확인.md)
- 관찰: 범죄유형 선택 → 증거자료 첨부 → 인적사항 입력 → 내용입력 → 완료. 증거자료 첨부 단계가 강조됨.
- 기획에 연결: 자료 준비가 내용 작성 이전 단계에도 필요하다는 흐름 안내.
- 한계: 진행 표시 한 장으로 전체 기능, 필수값, 저장·수정 흐름이나 사용자의 어려움을 입증하지 않는다. 원본 이미지는 공개 저장소에 복사하지 않는다.

### E05. 더치트 특정 API의 역할

- 출처: [더치트 피해사례 검색 API 공식 안내](https://apidocs.thecheat.co.kr/docs/api-usage/api-search-plain/)
- 확인: 등록 피해사례의 연락처·계좌번호 조회 기능을 설명한다.
- 기획에 연결: 피해 조회와 사건 설명 준비는 구분해 비교할 역할이다.
- 한계: 특정 API 문서로 더치트 서비스 전체에 사건 정리 기능이 없다고 판단하지 않는다. 실제 이용·연동은 미실시다.

## 3. 주장과 근거의 연결

| 기획 주장 | 근거 수준 | 결론 |
|---|---|---|
| 신고 준비에 경위 설명·자료 정리가 필요함 | E01·E04 | 과제 존재 확인 |
| 신고 작성의 편의성 문제를 기관도 고려함 | E02 | 과거 도입 배경 확인. 현재 핵심 pain 전체 증명 아님 |
| 절차 부담 때문에 신고를 주저할 수 있음 | E03 | 공식 교육의 보조 설명. 빈도·인과·실제 사례 검증 아님 |
| 자료 재탐색·반복 정리·수정 부담이 현재 크게 남음 | 직접 근거 없음 | 핵심 사용자 pain 가설 유지 |
| ECRM에 질문 기반 자동 작성 지원이 전혀 없음 | E02와 충돌 | 전제로 사용하지 않음 |
| 우리 원문 연결·수정 반영이 폴봇·범용 LLM보다 유용함 | 가상 1건 LLM 2턴 실행, 폴봇 미시험·서비스 미구현 | 이 사례에서 LLM도 수행. 추가 가치 미확인 |
| 멀티에이전트가 더 정확하고 효율적임 | 비교 실행 없음 | 구현 후보·기술 검증 질문 유지 |

## 4. 다음 확인과 기록 원칙

1. 허용된 공개 자료에서 실제 경험자의 자료 재탐색·반복 작성·수정 행동이 드러나는 사례와 어렵지 않았던 반대 사례를 확인한다. 이번 조회에서는 직접 입증하는 실제 경험 자료를 확보하지 못했다. 피해 발생 사례 자체를 정리 부담의 근거로 바꾸지 않는다.
2. ECRM 비교 범위에 폴봇을 포함한다. 공개 안내·화면에서 확인되는 기능, 인증 이후 미확인 기능, 과거 발표를 구분한다. 실제 신고를 시험용으로 제출하지 않는다.
3. 같은 가상 자료·충분한 LLM 지시로 원문 추적·금액 정정·충돌 보존·불필요한 재실행을 비교한다. 폴봇 출력을 얻지 못했다면 ‘공개 안내 기반 직접 작성’ 결과를 폴봇 성능으로 부르지 않는다.
4. 가상 점검은 주어진 과제의 성능만 설명한다. 실제 수요·현재 문제 빈도·현실 준비 부담 감소로 확대하지 않는다.

경찰청의 과거 홍보 페이지는 검색에서 발견했으나 원문 조회가 리다이렉트 오류로 실패했다. 그 검색 문구는 확인된 근거로 채택하지 않았다. 외부 원문을 대량 복사하지 않고 필요한 요약과 링크만 기록했다.

## 5. 후속 반증 점검

[가상 LLM 1건·2턴 실행과 폴봇 접근 제약](2026-11-16_기존대안_반증점검_결과.md)을 기록했다. 충분한 지시의 LLM이 원문 연결·미확인·정정 이력을 처리했으므로 기능 부재나 서비스 우위를 주장하지 않는다. 실제 핵심 pain과 서비스 대비 수고 감소는 여전히 미확인이다.
