# 중고거래 ECRM 접수 전 준비 지원 — 기획 요약

R03 두나 · 2026-11-17 · 개인 제안 / 기획 구체화 단계

**처음 중고거래 피해 신고를 준비하는 사람이 ECRM에 들어가기 전에 자료와 사건 경위를 정리하고, 검토한 내용을 직접 접수에 활용하도록 돕습니다.**

## 1. 타겟·문제·해결 가설

**타겟:** 입금 후 물품을 받지 못해 처음 ECRM 신고를 준비하는 사람.

**핵심 pain:** 접수 중 시간이 만료되면 다시 본인인증하고 작성 내용을 처음부터 입력하는 번거로움입니다. 두나님 이용 경로 1건의 보고이며 다른 복원 경로와 발생 빈도는 미확인입니다. 대화를 반복 수정하는 부담은 핵심 pain에서 제외하고 용어 설명은 보조 기능으로 둡니다.

**해결 가설:** 자료와 경위를 미리 준비하면 인증 후 확인·입력·첨부 시간을 **10~20분 줄일 수 있다**는 예상입니다. 미측정 가설이며 최소 보장·실측·합격선이 아닙니다. 사전 준비를 포함한 총시간과 실제 재인증·재입력 감소는 따로 확인합니다.

## 2. 근거와 강한 기존 대안

- **직접 이용:** 두나님은 남은 시간 만료→로그아웃→재인증→처음부터 재입력을 경험했고, 이용 화면에 임시저장 기능이 없었다고 보고했습니다. 연장 안내는 보지 못한 것으로 기억합니다. 시간이 부족했던 원인과 정확한 소요 시간은 미확인입니다. [이용 기록](2026-11-17_ECRM_준비항목_확인과_재인증_불편.md)
- **안내 탐색:** 비로그인 홈페이지에서 준비 안내를 찾지 못해 외부 검색이 필요했다고 보고했습니다. 페이지 데이터에는 안내 문구가 있으나 실제 인증 전 표시 경로는 확인되지 않았습니다. 폴봇 이용 경로에서도 자료 설명 없이 신고 종류 질문이 반복됐다고 보고했으며 전체 기능 부재로 일반화하지 않습니다. [접근성 비교](2026-11-17_ECRM_안내접근성_인증전후_비교.md) · [폴봇 기록](2026-11-17_폴봇_직접이용_보고.md)
- **반대 근거:** [공개 경험담](2026-11-17_중고거래_공개경험담_근거_01.md)은 상세 사전 작성 후 경찰서 처리가 수월했다고 설명합니다. 체크리스트·충분한 지시의 LLM도 준비를 도울 수 있고, 기존 가상 1건·2턴 LLM이 원문 연결·정정을 수행했습니다. 별도 서비스의 추가 가치는 아직 미검증입니다. [기존 실행](https://github.com/ik-e/chaja-you/blob/main/docs/members/R03/workspace/2026-11-16_기존대안_반증점검_결과.md)

## 3. 핵심 피처·대표 시나리오

| 피처 | 제공할 결과 |
|---|---|
| 준비자료·사건 경위 정리 | 출처·확인일이 있는 준비 목록, 보유/미보유/모름, 입력 원문 연결 초안 |
| 누락 확인·검토 결과 제공 | 발언자·주장·추측·미확인·충돌 구분, 정정 반영, 검토한 요약·자료 목록 |

**가상 서비스 흐름:** ① 준비 목록 확인 ② 대화·이체 자료는 직접 찾아두고 비식별 설명·필요 문구 입력 ③ 사건 초안과 누락·충돌 검토 ④ 미확인을 보존한 요약·자료 목록 복사 ⑤ ECRM에서 직접 인증·입력·첨부합니다.

가상 예시에서 사용자가 ‘이체 내역에 12만 원이라고 적혀 있다’고 입력하면 사용자 설명으로 기록합니다. 판매자의 ‘배송했다’는 말도 실제 발송 확인으로 바꾸지 않습니다. 모르는 내용은 남긴 채 진행할 수 있습니다. 실제 접수에 추가 항목이 있거나 시간이 다시 만료되면 이를 기록하며 한 번에 접수된다고 가정하지 않습니다.

**제외:** 자동 수집·실제 파일 판독·신분증 업로드·인증 대행·세션 연장·자동 입력/접수·법적 판단. 신분증 첨부는 ECRM에서 사용자가 직접 수행할 절차입니다. 우리 결과는 신고 완료나 증거 충분성 판정이 아닙니다.

## 4. 구현·비교·중단 기준

**기획 구체화 중이며 동일 조건 비교 테스트·시제품은 아직 구현하지 않았습니다.** 현재 비교 자료는 AI 모의 예시와 이전 LLM 기록의 대조이고 실측 실험이 아닙니다. [비교 자료](2026-11-17_공개안내_체크리스트_LLM_준비결과_비교.md)

안내만 / 안내+체크리스트 / 충분한 지시의 LLM / 준비 후 시제품을 같은 가상 과제로 비교할 계획입니다. 누락·왜곡·미확인 보존을 먼저 보고 **자료 찾기→사전 정리·검토→최초 인증→인증 후 직접 입력·첨부→재인증·재입력**을 나눠 기록합니다. 실제 ECRM 미시험 구간은 미측정으로 두며 가상 준비 속도를 실제 재인증 감소로 해석하지 않습니다.

기존 대안이 같은 정확성으로 같거나 적은 수고를 요구하면 축소·보류를 제안합니다. 정확성 악화를 속도로 상쇄하지 않습니다. 실제 수요·일반성·효과와 개인정보·법률 경계 검토는 남아 있습니다. 기술 구성은 상세안의 검증 후보로 유지하며 새 기능은 추가하지 않습니다.

## 5. 멘토 질문

1. 재인증·재입력 경험에서 접수 전 준비 지원으로 해결할 부분을 어떻게 좁히면 좋을까요?
2. 체크리스트·충분한 지시의 LLM 대비 추가 가치를 판단할 가장 작은 과제는 무엇일까요?
3. 사전 준비까지 포함한 전체 수고가 줄지 않으면 어떤 기능을 축소하거나 기획을 보류할까요?
