# 중고거래 ECRM 접수 전 준비 지원 — 멘토용 요약

R03 두나 · 2026-11-17 · 개인 제안 / 기획 구체화, 테스트·시제품 미구현

**신고 전에 준비자료와 사건 경위를 정리하고, 사용자가 검토한 내용을 ECRM 직접 접수에 활용하도록 돕습니다.**

## 1. 타깃과 pain

입금 후 물품을 받지 못해 처음 ECRM 신고를 준비하는 사람을 대상으로 합니다. 핵심 pain은 **시간 만료 후 재인증하고 작성 내용을 처음부터 재입력하는 번거로움**입니다. 보조 pain은 작성 항목·용어 이해입니다.

| 근거 | 확인 범위·수준 |
|---|---|
| 두나님의 ECRM 이용 | 남은 시간 만료·로그아웃·재인증·재입력, 이용 화면의 임시저장 부재를 보고. 경로 1건의 자기보고이며 원인·시간·다른 복원 경로·빈도 미확인. [기록](2026-11-17_ECRM_준비항목_확인과_재인증_불편.md) |
| 준비 안내·폴봇 이용 | 비로그인 안내 미발견과 폴봇의 신고 종류 질문 반복을 보고. 사이트 전체 안내 부재로 확정하지 않음. [비교](2026-11-17_ECRM_안내접근성_인증전후_비교.md) |
| 반대 근거 | 공개 경험담은 사전 작성의 효용을 설명하고 기존 LLM도 가상 1건·2턴의 원문 연결·정정을 수행. 서비스 추가 가치 미검증. [기록](https://github.com/ik-e/chaja-you/blob/main/docs/members/R03/workspace/2026-11-16_기존대안_반증점검_결과.md) |

## 2. 기존 대안과 남는 문제

| 대안 | 이미 가능한 것 | 남을 수 있는 문제 — 가설 |
|---|---|---|
| 메모장 미리 작성 | 내용 보관·재입력 참고 | 무엇을 준비·작성할지 스스로 선정 |
| 체크리스트+메모장 | 항목 확인·직접 경위 작성 | 대화에서 경위를 만들고 값 차이를 대조하는 수고 |
| 충분한 지시의 LLM | 요약·질문·원문 연결·정정 | 지시 작성·추가 질문·결과 점검 수고 |

**차별화 가설:** 준비 항목과 사건 정리를 한 흐름으로 제공하면, 직접 지시하고 결과를 점검하는 수고를 더 줄일 수 있는가? 이미 있는 대안으로 충분할 가능성을 함께 검토합니다.

## 3. 핵심 피처 2개와 이용 흐름

| 피처 | 결과 |
|---|---|
| 준비자료·사건 경위 정리 | 출처 있는 준비 목록, 자료 보유/미보유/모름, 입력 원문 연결 초안 |
| 누락 확인·검토 결과 제공 | 발언자·주장·추측·충돌·미확인 구분, 정정 반영, 검토한 요약·자료 목록 |

**목록 확인 → 자료 직접 준비·자유 설명 → 초안·누락 검토 → 복사 → ECRM 직접 인증·입력·첨부.** 판매자의 배송 주장은 실제 발송과 구분하며, 사용자의 이체 자료 설명을 실제 파일 확인으로 표현하지 않습니다.

실제 파일 판독·자동 수집·신분증 업로드·인증/세션 대행·자동 접수·법적 판단은 제외합니다. 신분증 등 공식 증빙은 ECRM에서 본인이 직접 첨부합니다.

## 4. 다음 검증 2개

1. **가상 준비 결과 비교:** 같은 자료·항목·목표로 안내를 보고 메모장 작성 / 체크리스트+메모장 / 충분한 지시의 LLM / 시제품 준비 후 제안 방식을 비교합니다. 누락·왜곡·미확인 보존과 사전 준비·입력·검토 수고를 기록합니다. 현재 비교 자료는 모의 예시와 이전 실행의 대조이며 실측 결과가 아닙니다.
2. **실제 접수 경로·효과 확인:** 비로그인 안내 경로·인증 후 추가 항목·만료/복원 동작을 확인하고 인증 후 직접 입력·첨부 시간과 재인증·재입력을 따로 기록합니다. 준비 과제 속도를 실제 재인증 감소로 바꾸어 해석하지 않습니다.

시간 단축은 측정할 가설이며 사전 준비를 합친 총시간도 평가합니다. 기존 대안이 같은 정확성으로 같거나 적은 수고를 제공하면 축소·보류합니다. 새 참여자 모집·실제 신고 제출·효과 검증을 완료한 상태가 아니며, 실제 자료·외부 제공 전 개인정보·법률 검토가 필요합니다.
