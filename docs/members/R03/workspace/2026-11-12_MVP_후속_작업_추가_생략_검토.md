## 1. 목적과 현재 결론

조사 중간 결과를 보고 사용자 요청에 답하기 위해 어떤 일이 더 필요한지 판단하는 기준을 정리한다.

MVP에서는 사용자 요청에 명시된 조건과 조사 중 발견된 근거 부족·충돌·접근 실패를 기준으로 후속 작업을 추가하거나 생략하는 방안을 제안한다. 추가 작업은 원래 요청의 범위와 실행 상한 안에서 구성하고, 변경 이유와 최종 결과에 미친 영향을 기록한다.

이 문서는 사용자가 개인 폴더에 작성을 요청한 논의 메모다. TASK-005 전체 결과나 확정 설계를 대체하지 않는다. 아래 내용은 제안과 평가 계획이며, 실제 구현·시험은 수행하지 않았다.

## 2. 후속 작업을 추가하는 두 가지 이유

| 구분 | 의미 | 예시 |
|---|---|---|
| 요청에 명시된 후속 작업 | 사용자가 특정 결과일 때 추가 행동을 요구 | “두 앱 모두 조건에 맞지 않으면 대안을 찾아줘.” |
| 요청 완수를 위한 보완 작업 | 필수 조건을 판단할 근거가 부족하거나 충돌 | 무료 제공 범위가 불명확해 공식 요금제 페이지 추가 확인 |

명시된 후속 행동은 사용자가 정한 조건을 따른다. 보완 작업은 원래 요청에 답하는 데 필요한 범위 안에서 수행한다. 무료 타이머를 비교하다가 커뮤니티 기능을 발견했다고 관련 없는 커뮤니티 비교를 추가하지 않는다.

## 3. 중간 결과별 처리

| 중간 결과 | 다음 행동 제안 |
|---|---|
| 필수 조건의 근거가 충분함 | 같은 조건의 추가 조사 생략 |
| 필수 조건의 근거가 부족함 | 해당 조건을 확인할 출처 추가 조사 |
| 출처 간 내용 충돌 | 플랫폼·버전·요금제·확인 시점 대조 |
| 페이지 조회 실패 | 허용된 대체 출처 조회 |
| 명시된 대안 탐색 조건 충족 | 후보 발굴과 새 후보 검증 추가 |
| 추가 조사 한도 도달 | 조사 종료 후 미확인과 제한 사항 안내 |

근거 부족만으로 항상 새 작업을 만들지는 않는다. 같은 확인을 이미 시도했는지, 대체 출처로 확인할 가능성이 있는지, 실행 예산이 남았는지 함께 확인한다. 대체 출처로도 판단할 수 없으면 미확인으로 남긴다.

## 4. 미충족과 미확인 구분

예시 요청: “A와 B가 모두 오프라인 타이머를 지원하지 않으면 대안을 찾아줘.”

| A 판정 | B 판정 | 대안 발굴 처리 |
|---|---|---|
| 미충족 | 미충족 | 추가 |
| 충족 | 미충족 | 생략 |
| 충족 | 미확인 | 생략 — 두 앱 모두 미충족이라는 조건은 성립하지 않음 |
| 미충족 | 미확인 | 실행하지 않음 — 실행 조건 확인 불가 |
| 미확인 | 미확인 | 실행하지 않음 — 필요한 확인 정보 안내 |

미확인 조건을 더 조사하는 작업은 별도로 검토할 수 있다. 자료를 찾지 못했다는 이유로 기능이 없다고 판단하지 않는다. 한 후보가 충족하더라도 다른 후보의 미확인 사실은 비교 결과에 그대로 표시한다.

사용자가 “확인할 수 없으면 대안도 찾아줘”라고 요청했다면 실행 조건은 달라진다. 앱 이름이 아니라 사용자가 명시한 조건에 따라 분기한다.

## 5. 추가 작업의 구체화와 중복 방지

| 기록 항목 | 예시 |
|---|---|
| 추가 이유 | A의 예약 차단이 무료판에 포함되는지 불명확 |
| 추가 작업 | 공식 요금제·도움말에서 무료 예약 차단 범위 확인 |
| 담당 역할 | 자료 조사 |
| 선행 입력 | 기존 조사 결과와 미확인 조건 |
| 완료 기준 | 무료 지원 여부를 근거와 함께 판정하거나 미확인 사유 기록 |
| 후속 영향 | A 조건 판정, 비교 결과와 보고서 갱신 |

같은 목적의 작업이 이미 존재하면 새로 생성할지, 기존 작업의 결과를 재사용하거나 작업을 보완할지 검토한다. 기존 근거를 재사용할 때에도 대상·플랫폼·버전·시점 등 적용 조건이 맞는지 확인한다. 동일한 목적의 조회와 모델 호출을 반복하지 않도록 생성·실행 이력을 남긴다.

## 6. 생략·보류·실패·취소의 차이

| 상태 | 의미 |
|---|---|
| 생략 | 실행할 필요가 없거나 실행 조건이 성립하지 않아 수행하지 않음 |
| 보류 | 필요한 판정·입력이 아직 없어 기다리는 중 |
| 실패 | 실행했으나 조회 오류 등으로 작업을 끝내지 못함 |
| 취소 | 실행 중이거나 예정된 작업이 더 이상 필요하지 않아 중단 |

위 상태는 의미 구분을 위한 제안이며 구현 상태 코드 확정안은 아니다. A 판정만 끝나고 B가 진행 중이면 조건부 발굴은 보류한다. 두 판정이 끝나고 한 후보가 충족하면 발굴을 생략한다.

최종적으로 조건을 확인할 수 없으면 보류를 무기한 유지하지 않고, 실행하지 않은 이유와 미확인 사항을 기록해 결과를 제출한다. 실패·취소를 조건 미충족 판정으로 바꾸지 않는다.

## 7. MVP에서 허용할 경계

- 원래 요청의 필수 조건 확인과 명시된 후속 행동에 한해 추가한다.
- 사전에 정의한 역할·작업 유형 안에서 구성한다.
- 추가 조사·재시도·시간·호출 예산 상한을 적용한다.
- 같은 미확인 조건에 동일 조사를 반복하지 않도록 기록한다.
- 예산이 끝나면 확인된 결과와 남은 불확실성을 전달한다.

필수 조건을 조용히 완화하지 않는다. 무료 앱을 찾지 못했다고 유료 앱을 조건 충족 후보로 추천하지 않는다. 조건 변경이 필요하면 사용자 확인이나 조건이 다른 대안이라는 명확한 안내가 필요하다.

## 8. 고정할 부분과 동적으로 바꿀 부분

| 고정할 부분 제안 | 동적으로 바꿀 부분 제안 |
|---|---|
| 허용된 역할·작업 유형 | 실제 추가할 작업의 대상·조건·담당 역할 |
| 실행 조건의 평가와 상태 기록 규칙 | 요청에서 추출한 조건과 중간 결과에 따른 실행 여부 |
| 추가 조사·재시도 상한 적용 규칙 | 추가·생략·보류·취소할 작업 |
| 근거 부족·충돌·실패 처리 방식 | 새 결과로 갱신해야 할 판정·비교·보고서 |

## 9. 평가 계획

동일한 요청에 서로 다른 중간 결과를 넣어 다음을 시험한다.

- 추가해야 할 상황에서 필요한 작업을 추가했는가?
- 생략해야 할 상황에서 불필요한 작업을 실행하지 않았는가?
- 미확인을 미충족으로 오해하지 않았는가?
- 추가 작업이 원래 요청 범위를 벗어나지 않았는가?
- 같은 작업을 중복 생성하거나 무한 반복하지 않았는가?
- 새 근거가 조건 판정·비교·최종 결과에 반영됐는가?
- 추가·생략 이유와 시간·호출 수·비용을 기록했는가?

APP-C의 모두 미충족·하나 이상 충족·충족 없이 일부 미확인 분기와, “미확인이면 대안 탐색”으로 조건을 바꾼 요청을 시험한다. 모의 판정값을 사용한 분기 시험과 실제 앱 기능 확인을 구분한다.

고정 워크플로에도 같은 조건부 처리 능력과 도구·예산을 적용해 비교한다. 단순히 APP-C를 처리했다는 사실만으로 동적 구성의 우수성을 주장하지 않는다. 필요한 작업의 누락·불필요한 실행·근거 품질·시간·호출 수·비용을 함께 비교한다. 실제 비교 결과와 성능 개선은 미확인이다.

## 10. 미확인 사항과 결정 요청

- 추가 조사·재시도·시간·호출 상한의 구체적인 값은 미정이다.
- 보류·생략·실패·취소의 구현 상태와 전이는 R05의 상태 관리 구조와 맞춰야 한다.
- 충분한 근거와 추가 조사 필요성을 판단할 세부 기준은 시험이 필요하다.
- 대체 출처 접근·이용 조건은 R02 결과를 반영해야 한다.
- 이 후속 작업 조정 범위를 TASK-005의 MVP 제안에 포함할지 팀 확인이 필요하다.
