## 1. 서비스와 목표

**중고거래 피해 신고를 처음 준비하는 사람이 필요한 자료와 피해 경위를 미리 정리해, ECRM 작성부터 경찰서 방문 시 설명·작성까지 준비된 상태로 진행하도록 돕는다.**

사용자가 자신이 겪은 일을 편하게 설명하면 필요한 자료를 안내하고, 확인 가능한 일시를 기준으로 피해 경위를 시간순으로 정리한다. 일시가 불명확하면 순서를 추측하지 않고 미확인으로 남긴다. 사용자는 누락·오류를 확인한 뒤 정리된 내용을 ECRM 작성과 경찰서 진술 시 참고할 초안으로 활용한다. 첫 시제품의 설명 입력은 텍스트이며 음성 녹음·인식 기능을 추가하는 의미는 아니다.

결과물은 **① 공식 안내에 근거한 준비자료 목록과 보유 상태 ② 입력 원문과 연결된, 사용자가 확인한 피해 경위 초안 ③ 추가로 확인할 사항**이다. 사용자가 이를 검토·복사한 뒤 ECRM에서 직접 인증·입력·첨부하고, 방문이 필요한 경우 안내받은 절차에 따라 초안을 설명·작성·보완에 참고한다.

목표는 접수 전 자료 준비로 전체 준비·접수 시간을 줄이고, 낯선 경찰서 환경에서 피해 경위를 떠올려 설명·작성하는 부담도 줄일 수 있는지 확인하는 것이다. 시간 만료 후 재인증·재입력은 준비 과정에서 발생할 수 있는 추가 손실로 다룬다. 서비스가 ECRM의 인증이나 세션을 변경하지는 않는다.

**해결 가설 — 예상 단축 10~20분:** 자료·대화·이체 내역과 사건 경위를 미리 준비하면 인증 후 확인·입력·첨부 시간을 10~20분 줄일 수 있다고 예상한다. 이 수치는 미측정 가설이며 최소 보장 시간이나 합격 기준이 아니다. 시간 만료·재인증·재입력 감소는 별도 결과로 확인한다.

사전 준비에 드는 시간과 최초 인증 시간도 따로 기록해 전체 준비·접수 시간까지 줄었는지 평가한다. 인증 후 시간만 줄고 전체 수고는 늘 수 있으므로 두 지표를 혼동하지 않는다.

**해결 가설 — 방문 시 설명·작성 부담 감소:** 처음 경찰서를 방문하는 사람이 낯선 환경에서 긴장해 내용을 빠뜨리거나 글쓰기를 시작하기 어려울 수 있다. 미리 검토한 초안이 이를 줄이는 데 도움이 되는지 확인한다. 이는 제안자가 제시한 사용자 가설이며, 실제 방문자의 발생 빈도·부담 감소 효과는 아직 측정하지 않았다.

## 2. 타겟·핵심 pain·문제 정의

| 항목 | 내용 |
|---|---|
| 타겟 | 온라인 중고거래에서 입금 후 물품을 받지 못해 처음 ECRM 신고를 준비하는 사람 |
| 사용 시점 | ECRM 접수 전 자료·피해 경위를 준비하고, 이후 필요한 경찰서 방문에 대비하는 때 |
| 준비 단계의 pain | 필요한 자료를 파악하고, 흩어진 거래 경위를 신고에 활용할 수 있는 글로 정리하기 어려울 수 있음 |
| 방문 단계의 pain | 처음 방문한 경찰서의 낯선 환경과 긴장으로 내용을 떠올리고 순서대로 설명·작성하기 어려울 수 있음 |

**문제 정의:** 중고거래 피해로 처음 신고를 준비하는 사람은 필요한 자료를 파악하고, 자신이 겪은 일을 신고에 활용할 수 있는 글로 정리하는 데 어려움을 겪을 수 있다. 경찰서 방문 시에는 낯선 환경과 긴장으로 피해 경위를 떠올리고 순서대로 설명·작성하는 부담이 더해질 수 있다.

핵심 과제는 **피해 경험을 신고와 진술에 활용할 수 있도록 미리 정리하는 것**이다. 준비 단계와 방문 단계의 어려움은 연결된 가설로 다루되 각각 확인한다. 사용자 정정은 결과 정확성을 위한 기능이다. 재인증 경험만으로 준비 부족이 시간 만료의 원인이라고 판단하거나, 모든 초보 방문자가 위축된다고 일반화하지 않는다.

## 5. 사용자 흐름과 출처 구분

| 단계 | 사용자 행동 | 화면 결과·다음 이동 |
|---|---|---|
| 준비 목록 확인 | 공식 안내에 근거한 자료·작성 항목 열람 | 출처·확인일·적용 범위 표시 |
| 기억나는 내용 입력 | 자유 설명, 가져온 문구, 자료 상태 선택 | 미리 완성된 진술서를 요구하지 않고 초안 생성 |
| 초안·누락 확인 | 발언자·금액·경위 검토, 필요한 질문에 답변 | 모르는 항목은 미확인으로 두고 진행 |
| 검토 후 복사 | 필요한 부분 수정·확인 | 원문 연결·주장·미확인을 보존한 요약과 자료 목록 |
| ECRM 직접 접수 | 공식 사이트에서 인증·작성·첨부 | 우리 서비스에서는 신고 완료로 표시하지 않음 |
| 방문 안내 확인 | 접수 후 안내받은 방문 필요 여부·기한·준비물을 확인 | 공식 안내와 담당 수사관 안내를 따름 |
| 방문 시 초안 참고 | 방문이 필요하면 검토한 초안을 참고해 피해 경위를 설명하고 필요한 내용을 작성·보완 | 모든 사람이 진술서를 처음부터 다시 작성한다고 가정하지 않음 |

자료 상태와 자유 설명 입력 순서는 강제하지 않는다. 상세 근거는 펼쳐보기로 제공하며 ‘자료가 있다’는 응답을 내용 확인으로 처리하지 않는다.

| 입력 예시 | 정리 결과 | 확인하지 않은 것 |
|---|---|---|
| 사용자: 12만 원을 보냈어요 | 사용자는 12만 원 송금을 설명함 | 실제 송금 진위 |
| 사용자: 이체 내역에 12만 원이라고 적혀 있어요 | 사용자가 자료 기재를 그렇게 설명함 | 실제 파일 미열람 |
| 사용자가 옮긴 판매자 발언: 어제 배송했어요 | 제공 문구에서 판매자가 발송을 주장함 | 실제 발송, 원본 대화 진위, 일시 없는 ‘어제’의 날짜 |

각 항목은 내용·발언자·입력 원문 ID를 연결한다. 경험 진술/상대방 주장/추측, 확인 범위, 충돌 여부, 사용자 검토 상태는 별도 속성으로 기록한다. 판매자 주장에 원문이 있어도 실제 발송은 미확인일 수 있다. 발언자가 불분명하면 임의 지정하지 않는다.

금액이 10만 원과 12만 원으로 다르면 양쪽 입력을 남기고 확인한다. 사용자가 정정하면 현재 요약·질문을 갱신하고 과거 입력을 이력으로 보존한다. 수정된 부분은 재검토 대상으로 표시한다. 입력·자료에 없는 날짜·동기·법적 결론을 생성하지 않는다.

### 대표 시나리오 — 온라인 접수와 경찰서 방문을 위한 사전 준비

이 시나리오는 **문제의 출발점인 실제 이용 보고**, **서비스가 제공할 준비 과정**, **실제 접수에서 확인할 결과**를 연결한다. 아래 물품·금액·대화는 동작을 설명하기 위한 가상 사례로, 실제 이용 보고의 사건 내용과 구분한다. 새로운 기능을 추가하는 것이 아니라 앞서 정한 텍스트·준비 목록·초안 검토·복사 기능을 구체화한 설계다.

#### 1) 실제 이용 경험과 문제의 출발점

직접 이용 보고에 따르면, ECRM 화면에 남은 시간이 표시됐고 만료 후 자동 로그아웃됐다. 재인증 후에는 작성 내용을 이어 쓰지 못해 처음부터 입력했다. 이용 화면에는 임시저장 기능이 없었으며, 별도 연장 안내는 보지 못한 것으로 기억한다. [직접 이용 보고](2026-11-17_ECRM_준비항목_확인과_재인증_불편.md)

이 경험에서 확인한 불편은 **다시 인증하는 절차와 이미 작성했던 내용을 다시 입력하는 작업**이다. 반면 자료를 찾느라 시간이 부족했는지, 입력량이나 다른 이유 때문이었는지, 정확히 몇 분이 소요됐는지는 확인하지 않았다. 특정 이용 경로의 자기보고를 모든 사용자·화면의 일반적인 동작으로 확정하지 않는다.

제안 서비스는 시간 제한을 없애거나 ECRM의 세션을 유지하는 방식이 아니라, **사용자가 실제 접수에 들어가기 전에 자료와 사건 설명을 검토할 수 있도록 하는 방식**으로 이 문제에 접근한다.

#### 2) 가상 사용자와 시작 상황

사용자는 중고거래로 키보드를 구매하고 12만 원을 송금했다고 설명하지만 아직 물품을 받지 못한 상태다. 판매자가 배송했다고 말한 대화는 있으나 실제 발송 여부는 확인하지 못했다. 사용자는 처음 신고를 준비하므로 어떤 자료를 준비하고 경위를 어떤 순서로 적을지 파악하려 한다.

판매 글·대화·이체 내역은 사용자가 직접 찾아야 한다. 우리 서비스는 거래 플랫폼이나 은행 계정에 연결하지 않고, 해당 자료를 자동 수집하거나 실제 파일을 읽지 않는다. 신고 대상 범죄인지도 판단하지 않는다. 이 상황을 ‘사기가 확정된 사용자’가 아니라 ‘미수령 상황을 설명하며 신고를 준비하는 사용자’로 다룬다.

#### 3) 단계별 서비스 이용

**단계 A. 접수 전에 준비 목록을 확인한다.**

- 사용자 행동: 서비스를 열고 중고거래 미수령 상황의 준비 목록을 읽는다.
- 서비스 처리: 확인한 공식 안내의 범위에서 거래·송금·대화·상대방·경위 등 준비 항목을 제시하고 출처와 확인일을 연결한다. ECRM 필수 항목 전체를 검증한 목록처럼 표시하지 않는다.
- 화면 결과: 각 자료를 ‘보유’·‘미보유’·‘모름’으로 확인할 수 있다. 신분증은 ECRM에서 필요한 자료로 안내하되 우리 서비스에 업로드하지 않도록 구분한다.
- 다음 이동: 사용자가 모든 자료를 갖추지 않아도 설명 입력으로 진행한다. 확인하지 않은 공식 규격이나 첨부 조건은 임의로 채우지 않는다.

**단계 B. 자료는 직접 준비하고 기억나는 경위를 입력한다.**

- 사용자 행동: 대화·이체 내역을 직접 찾아보고, 이름·계좌번호·전화번호 등 식별정보를 제외한 설명이나 필요한 문구를 입력한다.
- 입력 예시: ‘키보드를 사려고 12만 원을 보냈어요. 판매자는 어제 배송했다고 했는데 아직 받지 못했어요. 이체 내역에는 11월 10일 18시 30분이라고 적혀 있어요. 배송 약속일은 기억나지 않아요.’
- 서비스 처리: 사용자가 직접 말한 경험, 사용자가 전달한 자료 기재, 판매자의 발언을 나누어 원문 ID에 연결한다. 문장이 시간순이 아니어도 확인된 범위만 정리한다.
- 다음 이동: 필요한 입력을 받으면 초안을 만든다. 완성된 진술서·신분증·원본 증빙 제출을 먼저 요구하지 않는다.

**단계 C. 사건 초안과 자료 상태를 확인한다.**

| 초안 항목 | 표시 예시 | 처리 원칙 |
|---|---|---|
| 거래 대상 | 사용자는 키보드 구매 상황을 설명함 | 사용자 입력과 연결 |
| 송금액 | 사용자는 12만 원을 송금했다고 설명함 | 실제 이체 파일을 검증한 값으로 표현하지 않음 |
| 송금일시 | 사용자는 이체 내역에 11월 10일 18시 30분이 기재됐다고 설명함 | 연도가 입력되지 않았다면 임의로 추가하지 않음 |
| 배송 관련 발언 | 사용자가 전달한 대화에서 판매자가 ‘어제 배송’했다고 주장함 | 메시지 작성일이 없으므로 발송일로 환산하지 않음 |
| 현재 상황 | 사용자는 물품을 받지 못했다고 설명함 | 미수령만으로 사기·고의를 확정하지 않음 |
| 배송 약속·실제 발송 | 약속일과 실제 발송 여부 미확인 | 모르는 정보를 사실로 채우지 않음 |
| 자료 보유 | 사용자가 선택한 판매 글·대화·이체 내역의 준비 상태 | 자료 보유와 내용 검증을 구분 |

화면에서는 짧은 경위를 먼저 보여주고 해당 항목을 열면 연결된 입력을 확인할 수 있도록 한다. 사용자는 원문과 다른 부분을 그 자리에서 고친다.

**단계 D. 필요한 누락을 확인하고 초안을 검토한다.**

- 서비스 처리: 현재 준비 과제에 필요한 항목이 빠졌는지 확인한다. 이미 모른다고 한 날짜를 반복 질문하거나 모든 빈칸을 반드시 채우게 하지 않는다.
- 질문 예시: 입력에 거래 플랫폼이 없고 준비 항목상 확인이 필요하면 ‘어느 플랫폼에서 거래했나요?’라고 묻는다. 알 수 없으면 미확인으로 남긴다.
- 충돌 예외: 설명에 10만 원과 12만 원이 섞여 있다면 어느 쪽도 자동 선택하지 않고 양쪽 입력을 보여준다. 사용자가 정정하면 현재 요약·관련 질문을 갱신하되 과거 입력은 이력으로 보존한다.
- 사용자 행동: 잘못 정리된 내용과 자료 상태를 확인하고, 모르는 내용은 미확인으로 둔 채 결과로 이동한다.
- 완료 조건: ‘내용을 검토했다’는 상태와 남은 미확인을 표시한다. 검토가 끝났다는 것을 증거 충분성·법률 검토·신고 요건 충족으로 표시하지 않는다.

정정은 정확성을 위한 보완 동작이며 ‘대화를 계속 수정해야 하는 부담’을 새로운 핵심 pain으로 설정하지 않는다.

**단계 E. 검토한 준비 결과를 복사한다.**

사용자는 다음 내용을 검토하고 복사한다.

1. 사용자 설명과 상대방 주장이 구분된 사건 요약
2. 준비한 자료와 추가로 확인할 자료 목록
3. 아직 모르는 항목·해결되지 않은 충돌·남은 확인 질문

복사한 결과에도 미확인과 주장 표시를 유지한다. 실제 ECRM 입력 칸과 완전히 같은 양식이거나 그대로 제출하면 접수가 완료되는 문서라고 소개하지 않는다. 우리 서비스의 장기 저장·다운로드·자동 복원 기능은 이 시나리오에서 새로 약속하지 않는다.

**단계 F. ECRM에서 직접 인증·입력·첨부한다.**

사용자는 공식 ECRM으로 이동해 본인인증하고, 검토한 요약을 참고해 실제 화면에 직접 입력한다. 대화·이체 내역과 신분증 등 실제 자료도 ECRM의 안내에 맞춰 본인이 첨부한다. 실제 화면에서 추가로 요구되는 항목이 있으면 직접 확인·작성한다.

이 단계에서 우리 서비스는 인증정보를 받거나 화면을 조작하지 않는다. ‘우리 서비스에서 준비함’은 ‘공식 신고 완료’를 뜻하지 않는다. 이후 방문·진술 등 절차도 공식 안내와 담당 수사관의 안내를 따른다.

**단계 G. 방문 안내를 확인하고 검토한 초안을 설명·작성에 참고한다.**

- 사용자 행동: 접수 후 안내받은 방문 필요 여부·기한·준비물을 확인한다. 방문이 필요하면 검토한 피해 경위 초안을 참고할 수 있도록 준비한다.
- 가상 상황: 처음 경찰서를 방문한 사용자가 긴장해 어디서부터 설명할지 막히면, 미리 확인한 거래·송금·연락 경위를 참고해 설명한다. 필요한 경우 담당 수사관의 안내에 따라 작성 내용을 보완한다.
- 서비스의 역할: 사용자가 확인한 피해 경위와 남은 미확인을 사전에 정리해 제공한다. 현장 답변을 대신하거나 기억나지 않는 사실을 만들어 주지 않는다.
- 확인할 효과: 초안이 설명 시작과 중요한 내용의 회상에 도움이 되는지, 작성·보완 시간과 누락·오류 및 사용자가 느낀 부담을 확인한다. 실제 방문에서의 효과는 미검증이며 모의 과제 결과와 구분한다.

ECRM 자체가 방문 전 민원서류 작성을 지원하므로, 경찰서에서 모두 진술서를 처음부터 다시 작성하는 흐름을 전제하지 않는다. 초안의 실제 활용 방식은 해당 접수·방문 절차에 따라 확인한다.

#### 4) 시간 만료나 정보 부족이 발생할 때

| 상황 | 시나리오의 처리 | 결과 해석 |
|---|---|---|
| 접수 중 시간이 다시 만료됨 | ECRM 안내에 따라 사용자가 재인증하고 필요하면 다시 입력함. 발생 여부와 소요 시간을 기록 | 사전 준비로 만료가 없어졌다고 가정하지 않음 |
| 실제 입력 항목이 준비 목록에 없었음 | 사용자가 확인·작성한 추가 항목과 필요한 자료를 기록 | 준비 목록이 충분했는지 평가할 근거 |
| 자료를 찾지 못했거나 일시가 기억나지 않음 | 준비 결과에는 미보유·모름·미확인을 유지. ECRM에서 허용되는 진행 여부는 실제 안내를 따름 | 빈칸을 추측으로 채워 완료 처리하지 않음 |
| 초안이 발언자나 금액을 잘못 정리함 | 해당 입력과 대조해 수정하고 오류·검토 수고 기록 | 시간 절감이 있어도 정확성 문제를 별도로 남김 |
| 체크리스트만으로 같은 준비가 가능했음 | 같은 정확성·전체 수고인지 비교 | AI 서비스의 추가 가치가 없을 수 있음을 인정 |

재인증 뒤 복사한 요약이 다시 입력할 때 참고가 될 수는 있으나 자동 입력·ECRM 복원 기능을 제공하는 것은 아니다. 결과 보관 여부도 실제 사용자가 취한 행동을 기록하며 임의로 가정하지 않는다.

#### 5) 시나리오에서 확인할 결과와 가설

| 구간 | 비교할 내용 |
|---|---|
| 자료 찾기 | 최초 자료 탐색 시간. 서비스가 자동으로 줄인 시간으로 계산하지 않음 |
| 접수 전 준비 | 목록 확인·입력·질문 응답·초안 검토·복사에 든 시간 |
| 최초 인증 | 인증 자체에 든 시간. 서비스의 자동화 효과로 계산하지 않음 |
| 인증 후 작업 | 자료 확인·ECRM 직접 입력·추가 작성·첨부에 든 시간 |
| 만료 이후 | 재인증·재입력의 발생 여부, 횟수와 시간 |
| 준비 결과 품질 | 중요 사실 누락·왜곡·없는 사실 추가, 주장/미확인·자료 상태의 정확성 |
| 방문 시 설명·작성 | 초안 활용 여부, 설명 시작의 어려움, 중요 내용 누락·오류, 작성·보완 시간과 주관적 부담. 실제 방문과 모의 과제를 구분 |

**검증 가설:** 미리 준비하면 인증 후 자료 확인·직접 입력·첨부 시간을 10~20분 줄일 수 있다는 예상이다. 이는 미측정 예상 범위이며 최소 절감 보장이나 합격 기준이 아니다. 사전 준비 시간을 합친 총시간, 실제 재인증·재입력 감소, 기존 체크리스트·충분한 지시의 LLM 대비 추가 가치는 각각 확인한다.

**현재 상태:** 위 서비스 이용 부분은 미실행 가상 시나리오다. 실제 보고의 시간 만료 원인을 자료 준비 부족으로 확정하거나, 시제품이 이미 동작해 개선됐다고 표현하지 않는다. 현재는 기획 구체화 단계이며 비교 테스트·시제품은 아직 구현하지 않았다.

## 6. 기존 대안 이후 남는 문제 — 검증 가설

| 대안 | 이미 해결할 수 있는 것 | 처음 신고하는 사람이 막힐 수 있는 지점 — 미검증 가설 |
|---|---|---|
| 메모장에 미리 작성 | 작성 내용을 접수 전에 보관하고 재입력 때 참고·붙여넣기 가능. 실제 접수 칸과의 호환은 미시험 | 어떤 자료·항목을 적어야 하는지 스스로 정해야 할 수 있음 |
| 안내+체크리스트 | 필요한 항목을 보고 준비 여부를 수작업으로 점검 | 항목은 알아도 여러 대화에서 사건 경위를 작성하거나 서로 다른 값을 대조하는 데 수고가 남을 수 있음 |
| 충분한 지시의 LLM 직접 사용 | 기존 가상 1건에서 원문 연결·충돌·정정 처리 | 처음 사용자가 필요한 지시·추가 질문을 만들고 결과를 확인하는 수고가 남을 수 있음. 충분한 지시의 성공 결과를 숨기지 않음 |
| [ECRM·폴봇](https://ecrm.police.go.kr/minwon/main) | ECRM 자체가 방문 전 민원서류 작성을 지원하며 공개 메인에 피해 내용 작성 안내·예시가 있음(11/20 확인). 폴봇의 질문 기반 작성 지원은 과거 발표 기록 | 초보 사용자가 안내와 작성 기능만으로 준비를 마칠 수 있는지 비교 필요. 폴봇은 이용 경로에서 자료 설명에 도달하지 못했다는 단일 사용자 보고가 있으며 현재 전체 동작은 미확인 |

**차별화 가설:** 신고 준비 항목과 사건 정리를 한 흐름으로 제공해, 사용자가 직접 지시문을 만들고 결과를 점검하는 수고를 줄일 수 있는지 검증한다. ‘대화만 하면 없는 사실을 만들지 않는다’는 보장이나 원문 연결의 독점성을 주장하지 않는다.

방문 전에 글을 준비할 수 있다는 사실만으로 추가 가치를 주장하지 않는다. ECRM에서 미리 작성한 내용, 메모장·체크리스트, 충분히 지시한 LLM 결과와 비교해 자유 설명을 검토 가능한 초안으로 만드는 수고와 이후 설명·작성 부담이 실제로 줄어드는지 확인한다.

위의 막힘은 실제 관찰 결과가 아니다. 메모장·체크리스트·LLM으로 충분히 준비할 수 있다면 남는 문제가 없거나 작다고 판단해야 한다. 특히 **메모장+체크리스트**를 강한 비AI 대조군으로 두고 같은 준비 항목·자료·목표를 제공한다.

더치트의 특정 피해 조회 기능과 플랫폼 신고는 인접 대안으로 남기되, 해당 서비스의 상세 준비 지원 범위는 추가 조사하지 않았다. 경찰민원24는 사용자 판단에 따라 이번 비교 대상에 추가하지 않는다.

## 7. ECRM 접수·경찰서 방문 안내와 운영 경계

사용자가 제공한 진행 표시는 범죄유형 선택 → 증거자료 첨부 → 인적사항 입력 → 내용입력 → 완료다. 전체 접수 흐름을 AI가 실행했다는 근거는 아니다.

공식 안내에 따라 본인 신분증·이체/결제·대화 등 거래 자료를 준비하도록 연결하되, 우리 서비스에는 실제 식별정보·신분증을 입력·업로드하게 하지 않는다. 첨부 형식·용량·세부 필수값은 실제 ECRM 안내를 따른다.

> 신고 자료와 피해 경위를 미리 정리하도록 돕습니다. 검토한 초안은 ECRM 작성과 경찰서 방문 시 설명·작성·보완에 참고할 수 있습니다. 접수 후 안내받은 방문 필요 여부·기한·준비물과 후속 절차를 확인하세요. 일부 사건의 출석 예외와 실제 절차는 ECRM 및 담당 수사관의 안내를 따릅니다.

**공식 안내 확인(2026-11-20):** ECRM 공개 메인은 방문 전 민원서류 작성 지원, 경찰서 출석·진술 필요와 일부 다수 피해 사건의 출석 예외를 안내한다. 이번 공개 안내 확인에서는 ‘2주 이내 방문’이라는 일률적 기한을 확인하지 못했으므로 고정 기한으로 표시하지 않는다. 이는 기한이 없다는 뜻이 아니며, 실제 접수 후 안내받은 기한을 확인하도록 한다. [ECRM 공식 안내](https://ecrm.police.go.kr/minwon/main)

온라인 작성 완료를 전체 절차 종료로 소개하지 않는다. 버튼은 ‘검토한 요약 복사하기’·‘ECRM 안내 보기’다. [공식 절차](https://ecrm.police.go.kr/minwon/main) (공개 안내 확인: 2026-11-17)

운영 후보는 팀 비용의 무료 웹 시제품이다. 실제 배포·기관 연계·예산·법률 적합성 승인은 별도이며 현재 결정하지 않았다.

## 8. 비교·구현 상태·중단 기준

### 현재 완료한 것과 미구현

- 기획·작업 범위·공개 경험 근거와 직접 이용 보고를 정리했다.
- [준비 결과 비교 자료](2026-11-17_공개안내_체크리스트_LLM_준비결과_비교.md)는 A/B 모의 작성 예시와 기존 LLM 원응답의 대조다. 실제 사람 수행 실험이나 동일 조건 성능 비교가 아니다.
- 기획 구체화 단계로 **비교 테스트와 시제품은 아직 구현하지 않았다.** 수행 시간·누락 건수·화면 이동·인증 횟수의 통제 측정은 없다. 이전 LLM 점검은 별도 실제 실행 기록이다.

### 안내 접근성 선행 확인

[안내 접근성·인증 전후 항목 비교](2026-11-17_ECRM_안내접근성_인증전후_비교.md)에 현재 관찰과 미확인을 정리했다. 인증 후 신분증 안내 일부는 확인했으나, 비로그인 준비 안내는 사용자 탐색에서 미발견으로 보고됐으며, AI가 경로를 재현하거나 사이트 전체 부재를 검증한 것은 아니다. 인증 전후 차이 전체는 미확인이다.

① 처음 사용자가 어디를 눌러 준비 안내를 볼 수 있는지 ② 인증 전 실제로 확인 가능한 준비 항목은 무엇인지 ③ 인증 후 추가되는 항목은 무엇인지 먼저 기록한다. 실제 안내 접근 경로와 필요한 클릭·인증 여부를 고정한 뒤 안내만/체크리스트 비교를 설계한다. 페이지 데이터에 포함된 문구를 그대로 읽게 한 과제는 ‘안내문 텍스트 제공’ 조건이며 실제 사이트 탐색과 구분한다.

준비 결과 정확성·입력/검토 시간 비교와 실제 접수의 시간 만료·재인증/복원·재입력 확인은 별도 검증이다. 가상 결과의 속도로 실제 재인증 감소를 주장하지 않는다.

### 구현 후 비교할 방법

A. ECRM 안내를 참고해 메모장에 직접 작성 / B. 같은 안내+체크리스트를 보며 메모장에 작성 / L. 충분한 지시의 LLM / C. 제안 시제품을 같은 가상 사건·준비 목표로 비교한다. 시제품이 없으면 C는 미실행이며 수동 시연은 구분한다. 모델·설정·도구·예산·도움 범위·방법 순서·학습 효과를 기록한다. 기존 CLI 모델명은 미확인이므로 동등 모델 성능 비교값으로 재사용하지 않는다.

| 구간 | 직접 지원 | 기록할 값 |
|---|---|---|
| 최초 자료 찾기 | 자동 수집 없음 | 사용자가 직접 찾는 시간 별도 |
| 준비 항목 확인 | 준비 목록·자료 상태 | 화면 이동·인증 재진입 횟수와 시간 |
| 사전 입력·정리 | 원문 연결 초안 | ECRM 인증 전 정리 시간·중요 내용 누락·왜곡·없는 내용 추가 |
| 대조·검토·정정 | 미확인·충돌·정정 반영 | 시간·원문 확인 횟수·정정 후 불일치 |
| 결과 활용 | 검토한 요약 복사 | 복사·검토 시간, 실제 항목에 맞춰 추가 작성할 내용 |
| 인증 후 직접 입력·첨부 | 자동 입력·첨부 없음. 사용자가 ECRM에서 수행 | 최초 인증 소요 시간은 따로 기록하고 인증 완료→직접 입력·첨부 구간의 시간·누락·중단 기록 |
| 재인증·재입력 | 세션 제어 없음 | 발생 여부·횟수, 재인증 시간, 다시 입력·첨부한 시간. 발생하지 않음과 미시험을 구분 |
| 방문 시 설명·작성 준비 | 검토한 피해 경위 초안 참고 | 설명 시작에 걸리는 시간, 중요 내용 누락·오류, 작성·보완 시간, 주관적 부담. 실제 방문 효과는 별도 확인 |

전체 시간과 구간별 시간을 함께 기록하고, 사전 정리에 쓴 시간이 인증 후 절감분보다 커지는지도 확인한다. 가상 준비 과제의 시간에 실제 접수 시간을 섞지 않으며 실제 경로를 시험하지 않으면 인증 후 구간은 미측정으로 둔다. 사건 요약·자료 목록·미확인·남은 확인 질문을 검토하고 설명하는 것을 공통 종료 과제로 둔다. 종료 선언과 정확성은 별도 평가한다. 정정 과제는 품질 시험이며 재인증 감소의 실증과 구분한다. 실제 신고를 허위 제출하지 않는다. 모의 시간 만료는 모의 조건으로 표시한다.

방문 준비 비교는 같은 가상 사건을 준비한 뒤 그 내용을 설명·작성하는 과제로 확인할 수 있다. 시간과 사실 정확성, 사용자가 느낀 부담을 각각 기록하며, 모의 과제만으로 실제 경찰서의 긴장이나 부담이 감소했다고 결론짓지 않는다. 실제 방문에서 초안을 사용하는 방식과 효과는 미확인으로 남긴다.

### 임시 중단·축소 기준

- 기존 대안이 같은 수준의 사실 보존과 같거나 적은 수고를 제공하면 추가 가치 미확인으로 판단하고 기능 축소·기획 보류를 제안한다.
- 공개 안내·연장·저장·다른 복원 경로로 핵심 불편이 충분히 해소된다면 현재 문제 정의를 재검토한다. 확인하지 않은 기능을 없다고 단정하지 않는다.
- 없는 사실·발송 단정·충돌 소실은 출력 품질 실패다. 시간 단축으로 상쇄하지 않으며 수정·재시험한다. 오류 한 번을 기획 전체 중단으로 처리하지 않는다.
- 시제품·측정이 없거나 결과가 부족하면 실패 대신 미확인으로 기록한다. 법률·개인정보 조건이 미충족이면 실제 자료·공개 운영으로 확대하지 않는다.

3~5명에게 메모장+체크리스트와 LLM을 비교하게 하는 의견은 향후 가능한 검증안이다. 참여자·일정·동의 조건을 확보하지 않았으므로 이번 확정 업무나 완료 결과로 추가하지 않는다.

### 조건부 일정

전체 프로젝트 11/10~1/4 중 11/17은 2주차다. 2주차 기획·대안/재인증 근거·가상 과제 정리 → 채택 시 3~4주차 텍스트 준비 지원 시제품 → 5~6주차 비교 → 7~8주차 분석·시연을 제안한다. 팀 일정 확정이 아니며 미완료를 완료로 소급하지 않는다.

가상 12건(4유형×3건)은 후속 계획이고 현재 자료·LLM 점검은 1건이다. 나머지 11건은 미작성이다. 자발적 성인 5~8명 가상 과제 관찰은 동의·기록 조건과 참여자가 확보될 때의 후보이며 모집·일정 미정이다. 경험자 인터뷰를 후속 의무로 약속하지 않는다. 단일 사례·내부 모의 과제로 실제 수요나 통계적 우위를 주장하지 않는다.

## 9. 기술 비교 계획

멀티에이전트는 사용자 가치를 구현할 후보로 둔다. 단일 에이전트·고정 흐름·동적 멀티에이전트를 비교해 사실 보존·수정 반영의 정확성과 실행 효율을 확인한 뒤 구현 방식을 선택한다. 역할을 나누는 것 자체를 제품 가치나 채택 이유로 삼지 않는다.

| 구성 | 실행 방식 | 확인할 효과 |
|---|---|---|
| 단일 에이전트 | 같은 도구로 정리·안내 확인·자체 대조 | 한 에이전트로 충분한가 |
| 고정 멀티에이전트 | 모든 사례에 사전 정의한 역할·의존 관계 적용. 독립 작업은 사전 정의대로 병렬 실행 | 역할 분담이 사실 보존·근거 연결을 개선하는가 |
| 동적 멀티에이전트 | 같은 역할 후보에서 요청·중간 결과로 작업 선택·변경 | 품질을 유지하며 불필요한 작업을 줄이는가 |

- 같은 모델·버전·생성 설정·사건 자료·도구 접근·출력 항목을 사용한다. 역할 지시 차이는 보존하고 고정 계획은 실행 전에 정한다.
- 전체 토큰·호출·시간·비용 상한과 재시도·수정 한도를 맞춘다. 계획·조정·대조·수정 비용도 합산하며 같은 예산을 반드시 소진하지 않는다.
- 10절의 네 대표 사례(① 경위 정리만 요청 ② 경위 정리+상담 준비 ③ 금액·날짜 충돌과 사용자 정정 ④ 공식 자료 확인 실패)를 점검한다. 사례별 기준 사실·기대 분기·실행 순서·반복 횟수·재시도 상한을 실행 전에 정하며 같은 기준일의 이용 허용 자료·실패 조건을 사용한다.
- 고정·동적 구성 모두 동일한 독립 작업 병렬 허용 기준을 쓴다. 직렬 대비 병렬 자체의 속도 효과와 동적 작업 선택·생략 효과를 섞지 않는다.
- 사실 누락·왜곡·추정 추가, 근거 연결, 분기 정확성, 불필요한 작업, 시스템 시간·답변 대기, 모델/도구 호출·토큰·실행 당시 단가와 비용·예산 소진을 기록한다.
- 단일 대 고정은 역할 분담 효과, 고정 대 동적은 구성 변경 효과를 본다. 모의 기록 점검과 실제 LLM·웹 실행 성능, 사용자 수요 검증을 구분한다.

## 10. 멀티에이전트 책임과 실행 분기

| 역할 | 입력 | 맡을 일·다음 역할에 전달할 출력 |
|---|---|---|
| 계획·조정 | 사용자 요청 유형·입력 원문·이전 결과 상태·남은 실행 예산 | 실행 역할·하위 작업 지정, 순차/병렬 의존 관계·실행 조건·변경 이유·상태 기록, 최종 결과 조립 |
| 사건 정리 | 원문 ID가 있는 설명·자료 문구·자료 보유 목록·추가 답변 | 항목 ID·원문 ID가 연결된 경위 초안, 미확인·충돌 목록, 추가 확인 질문. 필요 안내 결과를 받아 상담 질문 작성 |
| 공식 안내 조사 | 사용자 막힘 항목·조회 질문/키워드·허용 출처 | 출처명·URL·확인일·적용 범위를 갖춘 설명 또는 ‘미확인’과 조회 실패 사유 |
| 결과 대조 | 조립된 초안·연결된 입력 원문·안내 결과·이전 대조 기록 | 원문/출처 미연결 문장·왜곡/임의 추정·미확인 누락 점검, 점검 범위·문제 항목·수정 요청 또는 ‘점검 범위 내 문제 미발견’ |

자동 대조의 문제 미발견은 법률 전문가 승인이나 진위 확인을 뜻하지 않는다. 입력 원문이 없는 공식 설명은 공식 출처에 연결한다.

| 대표 사례 | 실행 흐름 | 계획 변경·종료 |
|---|---|---|
| 경위 정리만 요청 | 계획 → 사건 정리 → 결과 조립 → 대조 | 공식 안내 조사 생략 |
| 경위 정리+상담 준비 | 사건 정리 ∥ 일반 공식 안내 → 상담 질문 작성 → 조립·대조 | 독립적인 일반 안내만 병렬. 사건 세부 조건이 필요한 안내는 정리 후 실행 |
| 금액·날짜 충돌과 사용자 정정 | 충돌 확인 → 답변 대기 → 관련 부분 수정 → 재대조. 별도 정정 단계: 초기 결과 → 사용자 금액 정정 → 연결 요약·질문 갱신 → 기존 대조 결과의 적용 범위 재확인 | 미해결 충돌은 보존. 정정 후 이전 값 잔존·원문 연결·재검토 상태·무관한 조사 재실행 건수를 비교 기록 |
| 공식 자료 확인 실패 | 원인 기록 → 예산 내 대체 출처 검토 → 부분 결과 조립·대조 | 안내 미확인 표시, 확인한 경위는 보존 |

계획·작업·시도별 목적·입출력 참조·선행 관계·실행 조건·상태·추가/생략/보류 이유를 남긴다. 수정은 관련 작업만 다시 실행하고 이전 실패·계획을 덮어쓰지 않는다. 답변 대기·미실행·실패·부분 결과를 구분한다. 수정·조회 한도 후에는 남은 문제를 명시해 부분 결과로 종료한다.

요청·작업·근거·상태 연결은 공통 구조이고, 거래 자료 항목·용어·공식 출처·사실 보존 기준은 도메인 특화다. 역할 분리가 효과적이라는 결론은 9절 비교 후 판단한다.

## 11. 전제·위험과 변경 배경

- 개인 제안이다. 팀 제품·앱 MVP·공식 제출 기획서·WBS·TASK 완료를 자동 변경하지 않는다. 실제 수요·빈도·준비 수고 감소·멀티에이전트 효과는 미검증이다.
- 자동 대조·사용자 검토는 자료 진위·증거 충분성·법률 검토 완료가 아니다. 전문 검토 담당과 범위는 미정이다.
- 피해자와 판매자 등 제3자의 이름·계좌·전화번호·대화가 포함될 수 있다. 가상·비식별 자료만 사용하며 실제 자료 취급 전 저장·보관·삭제·접근·외부 모델 전송 조건을 정한다.
- 공식 API·승인 데이터·필요한 최소 개별 문서를 사용하고 열람과 자동 수집·저장·재사용 권한을 구분한다.
- 법률상담·문서 작성과의 경계는 실제 출력, 무료/유료·수익/소개 대가·제공 범위를 기준으로 전문 검토한다. 명칭·면책만으로 적법성을 확정하지 않는다. [관련 조문 확인 기록](https://www.law.go.kr/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900175916) (기존 확인 2026-11-16)
- 11/17에는 문제를 재인증·재입력으로 좁혔다. 11/20 제안자 설명과 수정 요청에 따라 필요한 자료와 피해 경위를 미리 정리하는 어려움, 방문 시 설명·작성 부담으로 문제 정의를 구체화했다. 재인증·재입력은 추가 손실로 유지한다. 방문 시 긴장과 초안의 도움은 사용자 가설이며 실제 관찰·검증 결과로 승격하지 않는다.
- 부동산의 실제 상태는 현장 확인이 중요해 온라인 정리로 해결할 범위가 불확실하다고 판단하고, 접수 전 준비 지원으로 주제를 변경했다. 이는 제안자의 판단이며 멘토의 전환 지시와 구분한다.
