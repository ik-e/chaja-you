## 1. 서비스 개요

온라인 중고거래 피해를 의심하는 사람이 흩어진 거래 경위와 자료를 정리하고, 빠진 내용을 확인해 처음 상담·신고를 준비하도록 돕는 서비스다.

사용자 흐름은 **상황·보유 자료 입력 → 사건 경위·자료 정리 → 누락·모순 확인 → 사용자 검토·수정 → 상담·신고 준비 결과와 공식 경로 안내**로 제안한다. 용어·작성 항목의 설명은 작성 중 막힐 때 제공하며 이미 이해하는 용어까지 순서대로 설명하도록 강제하지 않는다.

핵심 결과는 사용자가 검토·수정한 사건 요약, 보유 자료 목록, 미확인 항목과 상담 질문이다. 목표는 재확인·반복 정리·수정의 부담을 줄이는 것이며, 용어 설명은 작성 중 필요한 보조 기능이다. 정돈된 요약의 품질과 실제 준비 부담의 감소는 별도로 검증한다.

[멘토링용 1페이지 요약](2026-11-16_중고거래_상담신고_준비_멘토링_1페이지_요약.md)은 Target → Pain 가설 → 기존 대안 → Remaining Pain → 제안 기능 → 미확인 순서로 정리했다.

### 주제 변경 이유

부동산 구상에서는 사진·설명만으로 실제 건물 상태를 판단하기 어렵고 현장 확인이 중요하다고 두나가 판단했다.
온라인 자료 정리로 해결할 범위가 불확실해, 보유 거래 자료와 사건 경위를 정리하는 중고거래 피해 상담·신고 준비로 주제를 변경했다.
이는 두나의 판단이며 멘토가 직접 주제 전환을 지시한 것으로 기록하지 않는다.
현재는 가상 사례로 정리 품질과 비교 절차를 점검하고, 실제 문제와 사용자 가치는 후속 사용자 검증으로 확인한다.

## 2. 타겟 사용자

### 사용자와 정한 첫 검증 대상

> 온라인 중고거래에서 돈을 보냈지만 물품을 받지 못해, 처음 상담·신고를 알아보면서 거래 경위와 자료를 어떻게 정리할지 막힌 사람.

이 타겟 선정은 두나와의 대화에서 정했다. 서비스 이용 시점은 피해를 의심해 처음 준비하는 단계다.

첫 실험은 중고거래의 물품 미수령 상황과 최초 상담·신고 준비에 집중한다. 투자사기·피싱 등 다른 유형이나 이미 수사 중인 사건의 진행 관리는 초기 검증 범위에 포함하지 않는다. 변호사 비용 부담은 타겟의 필수 조건으로 두지 않고 실제 행동에 영향을 주는지 별도 조사한다.

## 3. 페인 포인트 — 검증할 가설

**핵심 pain:** 흩어진 거래 자료를 다시 찾고 사건 경위를 반복 정리하면서, 누락·잘못된 설명을 걱정해 재확인·수정하는 부담.

**보조 pain:** 정리·작성 중 어려운 법률·절차 용어와 작성 항목 때문에 막히는 문제.

아래 P1~P5는 핵심 부담의 세부 양상과 점검할 오류이며, P6은 보조 문제다.

| ID | 사용자 불편 가설 | 현재 행동·확인할 사례 |
|---|---|---|
| P1 | 판매 게시글·대화·입금 내역이 여러 곳에 흩어져 있어 정리하기 어려움 | 거래 앱·메신저·은행 앱을 오가며 어떤 자료를 다시 찾았는지 |
| P2 | 거래와 연락 경위를 시간순으로 설명하기 어려움 | 배송 약속 변경과 반복 연락의 날짜·순서를 혼동한 사례 |
| P3 | 무엇을 설명하고 어떤 정보를 추가 확인해야 할지 모름 | 상대방 정보가 없거나 게시글이 삭제됐을 때 작성이 막힌 부분 |
| P4 | 직접 확인한 사실·상대방의 설명·자신의 추측이 섞임 | ‘연락이 안 됨’에서 상대방의 의도를 단정하는 등 서술이 달라진 부분 |
| P5 | 중요한 내용을 빠뜨리거나 잘못 설명했을까 불안해 반복 확인함 | 반복 수정·재검색한 내용과 실제로 남았던 누락 |
| P6 | 법률·절차 용어와 작성 항목의 의미를 이해하기 어려움 | 고소·진정·피해 진술 등에서 이해하지 못한 표현과 그로 인해 막힌 행동 |

P1~P3의 자료 찾기·경위 정리·누락 확인과 P5의 재확인·수정 부담을 중심으로 경험을 확인한다. P4는 정리 과정의 오류를 점검하는 기준으로도 사용한다. P6 설명은 필요한 순간에 보조하며, 실제 사용자 경험이 다르면 우선순위를 재검토한다. 최신성·적용 범위는 제품 품질 기준으로 관리한다.

## 4. 문제 정의

> 온라인 중고거래에서 돈을 보냈지만 물품을 받지 못해 처음 상담·신고를 준비하는 사람은, 흩어진 거래 자료를 다시 찾고 사건 경위를 반복 정리하면서 누락이나 잘못된 설명을 우려해 재확인·수정을 반복하는 부담을 겪는다.

이 부담이 실제로 반복되는지, 기존 안내·범용 LLM을 사용한 뒤에도 남는지 확인한다. 용어 이해는 보조 문제로 살피되 문제의 원인을 미리 확정하지 않는다.

사용자가 자신의 상황을 설명하고 필요한 준비·상담으로 이어가도록 돕는다.

## 5. 핵심 피처

### 피처 1. 사건 경위·보유 자료 구조화

- 사용자가 입력한 내용을 시간순으로 정리하고, 날짜·금액·행동·자료 연결을 사용자가 수정할 수 있게 한다.
- 각 항목에 **내용 / 누가 말했는지 / 연결된 입력·자료 / 추가 확인할 점**을 함께 표시한다. 직접 경험인지 상대방 설명인지, 추정인지와 확인 여부도 필요에 따라 기록한다. 이 속성들은 겹칠 수 있으므로 진술·자료·추측·미확인을 서로 배타적인 한 가지 분류로만 처리하지 않는다.
- 사용자 진술에도 추측이 포함될 수 있고 자료에도 상대방의 주장이 담길 수 있다. ‘판매자가 배송했다고 말했다’와 ‘실제로 배송됐다’를 구분한다. 자료 기재나 사용자 검토를 내용의 진위 검증으로 표시하지 않는다.
- 판매 글·대화·입금 내역의 목록을 사건 경위와 연결하고 원래 입력으로 돌아가 확인할 수 있게 한다. 없는 사건·대화·증거를 만들어 넣지 않는다.
- 첫 실험은 비식별 텍스트 입력으로 시작하는 방안을 제안한다. 실제 파일 업로드·자동 판독은 개인정보 처리와 필요성을 확인한 뒤 검토한다.
- 대응 문제: P1의 수집 후 정리 부담·P2·P4. 텍스트 입력만으로 여러 앱에서 자료를 찾고 옮기는 부담까지 해결했다고 가정하지 않는다.
- 검증: 원래 진술이 보존되는지, 누락·시간순 혼동을 발견하는지, 추정이 사실로 바뀌지 않는지 확인한다.

### 피처 2. 누락 확인과 상담·신고 준비 결과 제공

- 날짜·금액·약속·연락 경위의 누락이나 서로 다른 기재를 질문한다. 기존 입력에 답이 있으면 반복 질문하지 않고 사용자가 모르는 내용은 미확인으로 남긴다.
- 사용자가 확인·수정한 사건 요약, 보유 자료 목록, 미확인 항목, 상담할 질문을 제공한다. 사용자가 검토했다는 사실을 법률 검토나 증거 충분성 확인으로 표시하지 않는다.
- 현재 목적에 맞는 공식 상담·신고 경로를 연결한다. 준비 결과 생성과 공식 접수 완료를 구분한다.
- 무료 법률상담·법률구조 등의 경로를 제시하되, 상담과 소송 지원을 구분하고 지원 자격·예약·비용 조건은 공식 안내에서 확인하게 한다.
- 대응 문제: P3·P5, P1·P2·P4의 누락·혼동 보완.
- 검증: 누락을 발견하면서 임의로 사실을 채우지 않는지, 불필요한 질문과 사용자 수정 부담이 어느 정도인지, 사용자가 다음에 무엇을 확인할지 설명할 수 있는지 확인한다.

### 피처 3. 어려운 용어·작성 항목 쉽게 설명

- 작성 중 이해하지 못한 법률·절차 용어와 입력 항목을 일상적인 표현과 예시로 설명한다. 어떤 내용을 입력하는 항목인지 이해하도록 돕는다.
- 원래 법률 용어와 쉬운 설명을 함께 표시해 공식 문서를 다시 읽을 수 있도록 한다.
- 각 설명 끝에 출처·확인일, 가능하면 자료 기준일·법령 시행일을 연결한다. 최신 적용 여부를 확인하지 못하면 그 사실을 표시한다.
- 일반적인 설명과 개별 사건에 적용하려면 추가 확인이 필요한 부분을 구분한다.
- 대응 문제: P6·P3.
- 검증: 용어와 안내의 의미를 사용자가 자신의 말로 설명할 수 있는지, 쉬운 설명이 원문의 조건·예외를 왜곡하지 않는지 확인한다.

## 6. 사용자 확인 때 보여줄 네 단계 시안

현재는 아래 시안과 가상·비식별 사건 자료로 시작·수정·미확인 진행·결과 활용 흐름을 점검한다. 시안의 설명 가능성과 실제 사용자 효과는 구분한다. 후속 경험자 인터뷰를 진행하면 실제 준비 경험을 먼저 듣고 시안은 후반에 제시한다.

#### 1단계. 시작 — 받을 결과를 먼저 보여주기

> **중고거래에서 있었던 일을 함께 정리해요.**
>
> 기억나는 내용을 적으면 사건 요약·자료 목록·추가로 확인할 질문을 정리해 드려요.

- 주 버튼: **내 상황 정리하기**
- 보조 선택: **가상 예시 보기**
- 시작 버튼 가까이에 ‘상담·신고 준비를 돕는 도구이며 공식 신고 접수는 아닙니다’라고 짧게 표시한다.

#### 2단계. 입력 — 기억나는 말로 시작하기

> **어떤 일이 있었나요?**
>
> 순서가 뒤섞여도 괜찮아요. 기억나는 만큼 적어주세요.

- 자유 입력과 선택형 **작성 도움 보기** 중 편한 방식으로 시작한다. 도움말: ‘무엇을 거래했고, 돈을 보낸 뒤 어떤 일이 있었는지 적어주세요. 정확한 날짜는 몰라도 괜찮아요.’
- 처음부터 날짜·금액·상대방 정보를 모두 채우게 하지 않는다. 도움말은 원할 때 펼치며 입력 항목을 추가로 강제하지 않는다.
- 입력 예시: ‘중고거래로 10만 원을 보냈는데 물건을 받지 못했고 판매자와 연락이 안 돼요.’ 이는 가상 예시다.
- 입력칸 옆에 ‘이름·계좌번호·전화번호 등 식별정보는 제외해 주세요’라고 안내한다. 대화 원문 전체나 실제 파일 첨부를 시작 조건으로 요구하지 않는다.

#### 3단계. 확인 — 초안을 보며 필요한 것만 보완하기

입력에서 확인되는 경위부터 짧게 정리한다. 순서가 불분명한 부분은 질문하거나 미확인으로 남긴다. 아래 표는 기획 설명용이며 화면에서는 짧은 사건 항목을 먼저 보여준다. 항목을 누르면 원래 입력·누가 말했는지·연결 자료·추가 확인할 점을 펼치는 방식을 우선 시험한다. 내부 정보 구조를 보존하면서 휴대전화에서 한 번에 읽을 양을 줄인다. 위 가상 입력의 정리 예시는 다음과 같다.

| 항목 | 정리 초안 |
|---|---|
| 입금액 | 사용자는 10만 원을 보냈다고 설명함 |
| 배송 약속일 | 아직 미확인 |
| 현재 상황 | 사용자는 물품 미수령·연락 두절이라고 설명함 |

그다음 ‘판매자가 언제 보내겠다고 했나요?’처럼 필요한 항목만 질문하고 **날짜 입력 / 정확히 기억나지 않아요** 선택을 제공한다.

- 이미 말한 내용은 다시 묻지 않는다. 서로 다른 기재가 있으면 차이를 보여주고 확인한다.
- 모르는 정보는 미확인으로 두고 진행할 수 있다. 답을 추정하거나 모든 항목을 채우도록 강제하지 않는다.
- 잘못 정리된 항목은 그 자리에서 수정하고 원래 입력도 확인할 수 있게 한다.
- 용어 설명은 해당 항목 옆에서 필요할 때 열어본다.
- 질문을 계속 이어가는 대화창보다 정리 초안과 필요한 질문을 함께 보는 방식을 우선 시험한다. 남은 질문에 답하지 않고 현재 내용 검토·결과로 이동할 수 있게 한다.

#### 4단계. 결과 — 확인과 다음 행동을 우선하기

| 표시 순서 | 사용자에게 제공할 것 |
|---|---|
| 1 | 사건 요약: 내가 말한 내용이 맞는지 확인·수정 |
| 2 | 추가로 확인할 내용: 아직 모르는 항목과 필요한 질문 |
| 3 | 보유 자료 목록: 어떤 경위와 연결되는지 확인 |
| 4 | 상담할 질문·공식 경로: 다음 행동으로 연결 |

각 항목에서 원래 입력·자료를 확인하고 수정할 수 있게 한다. 검토 후 **요약 복사하기**를 제공하고, 복사 내용에도 출처 구분·미확인 표시를 유지한다. 준비 상태는 ‘준비 완료’라는 단정 대신 ‘사용자가 검토한 요약입니다’와 남은 미확인 항목을 실제 상태에 맞춰 표시한다. 검토하지 않은 상태를 검토 완료로 표시하지 않는다.

복사 기능은 재작성 수고를 줄이기 위한 후보 기능이다. ECRM 등 제출처의 항목에 맞춘 조정이 필요할 수 있으므로 그대로 붙여 넣으면 접수 준비가 모두 끝난다고 약속하지 않는다. 실제 절감과 수정 부담은 실험 B에서 확인한다.

### 이 흐름에서 확인할 사용성

- 진행자의 설명 없이 서비스 목적을 이해하고 입력을 시작하는가?
- 정리 초안의 잘못된 내용을 발견하고 수정할 수 있는가?
- 모르는 항목을 미확인으로 남겨도 계속 진행할 수 있는가?
- 결과를 보고 자신의 상황과 다음에 확인할 행동을 설명할 수 있는가?

가상 사례 점검과 기존 실험 A·B에서 막힘·반복 질문·수정·중단을 기록한다. 내부 점검과 가상 과제 결과로 실제 사용자의 필요성·전체 준비 부담 감소를 확정하지 않는다.

### 출처와 의미를 보존하는 가상 출력 예시

아래 내용·입력·자료 ID는 모두 가상이다. 관련 자료가 없으면 추가 확인할 내용을 미확인으로 남긴다.

| 내용 | 누가 말했는지 | 연결된 입력·자료 | 추가 확인할 점 |
|---|---|---|---|
| 판매자가 “배송했다”고 메시지를 보냄 | 판매자 | 자료 M1: 대화의 해당 메시지 | 발송 주장이다. 실제 발송 여부는 미확인이며 운송장 등 관련 자료 유무 확인 |
| 입금 내역에 송금액 10만 원이 기재됨 | 자료상의 거래 기록 | 자료 M2: 비식별 이체 내역 | 어떤 거래와 연결되는지 사용자 확인. 자료 자체의 진위는 검증하지 않음 |
| 사용자는 아직 물품을 받지 못했다고 설명함 | 사용자 | 입력 U1: 사용자 설명 | 진술 시점과 이후 수령 여부 확인. 독립적으로 확인된 배송 상태로 바꾸지 않음 |
| 사용자는 판매자가 처음부터 속이려 했다고 생각함 | 사용자 | 입력 U2: 사용자 의견 | 의도에 관한 추측임을 표시하고 범죄 확정 문장으로 변환하지 않음 |

요약 문장에서 관련 입력·자료를 다시 확인할 수 있게 한다. 서로 다른 기재가 있으면 한쪽을 임의로 사실로 선택하지 않고 차이와 확인 질문을 남긴다.

## 7. 기존 대안과 차별화 가설

| 대안 | 확인된 내용 또는 비교할 역할 | 남는지 검증할 불편 |
|---|---|---|
| 더치트 | 연락처·계좌번호의 등록 피해사례 조회 | 조회 이후에도 사건 경위·자료 정리에 어려움이 남는가 |
| 거래 플랫폼 자체 신고·분쟁 대응 | 플랫폼 내 신고·대응 기능을 조사할 비교 대상 | 이용한 플랫폼에서 별도로 준비할 내용은 무엇인가 |
| 거래 플랫폼 안전결제 | 거래 과정의 대금 보호·피해 예방 기능을 조사할 비교 대상 | 이미 직접 송금한 사용자가 이용할 수 있는 대응 범위는 어디까지인가 |
| 경찰청 ECRM | 사이버범죄 신고·상담 경로와 피해 내용 작성 항목·육하원칙 예시 제공 | 공식 입력 안내를 보고도 사실을 정리하지 못하는 지점이 남는지 |
| 찾기쉬운 생활법령정보 | 고소 의미·방법 등 공식 생활법령 안내 제공 | 안내를 읽어도 이해·준비에 막힘이 남는지 |
| 대한법률구조공단 | 공식 안내상 무료 법률상담·법률구조 경로 존재 | 상담 전에 상황과 질문을 정리하는 데 추가 도움이 필요한지 |
| 일반 검색·범용 AI | 사용자가 현재 사용하는 해결 방법인지 조사할 비교 대상 | 같은 자료·과제에서 정확성·출처·미확인 구분에 어떤 차이가 있는지 |

더치트 공식 API 안내는 등록 피해사례의 연락처·계좌번호 조회 기능을 설명한다. 비교표는 이 조회 역할을 기준으로 하며, 실제 이용 흐름·효과와 API 연동은 시험하지 않았다. [더치트 공식 안내](https://apidocs.thecheat.co.kr/docs/api-usage/api-search-plain/) (확인일: 2026-11-16)

플랫폼 자체 신고·분쟁 대응과 안전결제는 서비스별 조사 항목이다. 최신 제공 여부·지원 범위·조건은 개별 공식 안내에서 확인한다. 안전결제의 예방 역할과 이미 직접 송금한 사용자의 피해 대응은 구분한다.

ECRM의 제공 범위는 공식 공개 화면에서 확인했다. 신고 과정의 실제 입력·접수·상담 이용은 시험하지 않았다. [경찰청 ECRM](https://ecrm.police.go.kr/minwon/main) (확인일: 2026-11-16; 공개 안내 확인)

생활법령정보와 법률구조 경로의 제공 범위는 문서에 연결한 공식 출처에서 확인했다. 범용 AI의 특정 제품 성능과 각 대안의 사용성은 아직 실험하지 않았다.

찾기쉬운 생활법령정보는 고소 의미·방법을 안내한다. [고소·고발 방법](https://www.easylaw.go.kr/CSP/CSP/OnhunqueansInfoRetrieve.laf?curPage=1&onhunqnaAstSeq=86&onhunqueSeq=1083&pageType=20&sch=) (확인일: 2026-11-16; 해당 페이지 표시 기준일: 2026-09-15)

### 기존 방식의 설계 이유 — 확인과 추정 구분

기능의 제공 여부와 그 설계 이유를 따로 확인한다. 공개 화면에서 찾지 못했다고 자동 구조화 기능이 없다고 단정하지 않는다. ECRM 공개 안내는 방문 전 서류 작성으로 방문 시간을 단축하는 목적을 설명하지만, 자동 구조화의 전체 제공 여부나 미제공 이유까지 설명한 근거는 아니다. 더치트의 특정 조회 API를 서비스 전체의 기능·설계 이유로 확대하지 않는다.

원진술 보존, 잘못된 정리의 책임, 공식 신고 양식의 목적, 플랫폼 간 자료 접근 제약은 가능한 이유를 조사할 가설이다. 공식 정책·기능 문서 또는 담당자 답변에서 직접 확인한 이유만 사실로 기록하고, 나머지는 미확인으로 남긴다. 현재 자동 구조화 설계 이유를 입증한 근거는 없다. 기관의 설계 이유는 공식 자료로, 대안을 이용한 뒤 남는 불편은 사용자 경험으로 확인한다. 같은 제약이 우리 서비스에도 적용되는지 함께 검토한다.

### 범용 LLM 대비 차별화 가설

**사건 문장을 원래 입력·자료에 연결하고, 상대방 주장·사용자 추측·미확인·충돌을 보존하며, 사용자 수정 내용을 연결된 결과에 일관되게 반영해 재확인·반복 정리 부담을 줄인다.**

예를 들어 금액을 수정하면 관련 요약·자료 연결·상담 질문의 불일치 여부를 다시 점검하고, 검토 이후 변경된 항목은 다시 검토할 수 있게 표시한다. 검토된 항목과 남은 미검토·미확인을 구분해 결과를 제공한다. 사실·주장·추측·상태는 서로 겹칠 수 있으며 자료 연결은 진위·범죄 성립의 확정을 뜻하지 않는다.

요약·질문 생성·용어 설명 자체를 범용 LLM과의 차이라고 주장하지 않는다. 비교 대상에도 같은 자료와 출처 연결·미확인 보존·누락 확인·수정 반영을 요구하는 충분한 지시를 제공한다. 그 뒤에도 사실 누락·왜곡, 원문 재확인, 수정 후 불일치, 전체 입력·검토·수정 부담이 줄어드는지 비교한다. 범용 LLM으로 충분하다면 별도 서비스 필요성이 약하다는 반대 근거로 남긴다. 멀티에이전트는 이를 시험하는 내부 구성 방식이며, 우수성 자체는 검증 대상이다.

## 8. 이 제안의 첫 검증 시제품 범위

| 첫 실험에 포함할 것 | 후속 필요성·조건 확인 후 검토할 것 |
|---|---|
| 비식별 텍스트 기반 사건 경위·자료 목록 정리와 원문 연결 | 실제 대화·금융 자료 업로드와 자동 판독 |
| 누락 확인, 사용자 수정 반영, 검토한 요약·자료 목록·질문과 공식 경로 | 개별 사건의 법적 판단을 수행하는 서비스 |
| 작성 중 필요한 용어·항목 설명 | 다양한 사건·진행 단계로 확대 |

비식별 텍스트 입력은 구조화 기능을 시험하기 위한 시작점이다. 사용자가 원래 앱에서 자료를 찾아 옮기는 수고는 남는다. 자동 수집·파일 판독을 전제하지 않고, 입력 준비와 결과 수정이 오히려 ‘두 번 작성하는 부담’을 만드는지도 관찰한다.

## 9. 사용자·정확성 검증 계획

### 현재 우선 작업: 가상·비식별 사례 비교 점검

경험자 인터뷰는 후속 사용자 검증으로 두고, 현재는 가상·비식별 사례를 활용한 비교 점검을 우선한다. 실제 문제의 빈도·심각성과 서비스 수요는 미확인으로 남긴다. 경험자 모집 인원·마감 목표는 현재 일정에서 삭제한다.

1. 물품 미수령 가상 사례와 기준 사실·자료 목록을 작성한다. 금액·날짜 충돌, 상대방 주장, 없는 정보도 구분한다.
2. 동일 자료로 ECRM 공개 안내를 참고한 직접 작성, 충분한 지시를 준 범용 LLM, 제안 방식의 준비 결과를 비교한다. 시제품 미구현 시 제안 방식은 수동 모의 점검으로 표시한다.
3. 중요한 사실 누락·왜곡·임의 추정, 근거 연결·미확인 보존, 입력·질문 응답·검토·수정 수고를 기록한다. 실제 LLM·도구를 실행하지 않았다면 설계 점검과 실행 결과를 구분한다.
4. 결과로 시제품의 우선순위를 조정한다. 자료 찾기부터 비교하는 실험 B도 가상 환경 결과이며 실제 사용자 전체 준비 부담을 입증하지 않는다.

### 후속 사용자 검증

참여자를 확보할 수 있을 때 경험자 인터뷰를 진행한다. 현재의 필수 일정이나 가상 사례 점검의 선행 조건으로 두지 않는다. 실제 준비 순서, 자료를 다시 찾거나 수정한 사례, 기존 안내·범용 LLM으로 해결된 부분과 남은 부담을 확인한다. 어려움이 없었던 반대 사례도 기록한다.

참여 동의와 비식별 기록을 원칙으로 하며 실제 피해 원본의 제출을 요구하지 않는다. 모집·인터뷰는 미진행이다. 가상 사례를 비교했다는 이유로 P1~P3의 실제 반복성이나 서비스 수요가 검증됐다고 표현하지 않는다.

### 진행 순서

**가상 사례·기준 자료 준비 → 동일 출발점에서 비교 점검 → 결과와 한계 기록 → 시제품 우선순위 조정** 순서로 진행한다. 경험자 인터뷰와 실제 사용자 효과 확인은 후속으로 남긴다. 아래 실험 A·B와 기술 비교 계획은 유지한다.

실험에서는 사실 보존·필요한 누락 발견·수정 부담을 대조한다. 사례의 기준 사실과 결과물을 비교하고, 법률 설명·절차 안내의 정확성 검토는 전문 검토 담당과 범위를 정한 뒤 별도로 수행한다.

피해 의심을 범죄 확정으로 바꾸거나, 없는 사실·출처를 생성하거나, 확인하지 않은 적용 조건·기한을 확정하는 출력은 오류로 기록하고 원인을 수정한다.

### 임시 성공 기준

**ECRM 공개 안내를 참고해 사용자가 직접 준비한 경우보다 중요한 사실의 누락을 줄이고, 없는 사실이나 의도를 덧붙이지 않으며, 자료 찾기·입력·검토·수정을 포함한 전체 준비 부담을 줄이는 것을 목표로 한다.**

| 평가 항목 | 개선을 판단할 방향 |
|---|---|
| 정확성 | 기준 사실 대비 중요한 누락·왜곡을 줄이고, 근거 없는 사실·의도 추가를 오류로 기록 |
| 누락 확인 | 필요한 누락을 발견하고 모르는 내용은 미확인으로 보존 |
| 사용자 부담 | 총 준비 시간·중복 입력·재작성·수정 부담을 줄임 |

세 항목은 별도로 보고한다. 정확성만 개선됐다면 ‘정확성 개선, 부담 감소 미확인’으로 남긴다. 새로운 사실 왜곡이 생기면 시간 단축만으로 성공으로 처리하지 않는다. 정량 합격선은 초기 관찰 결과와 사례 난이도를 바탕으로 후속 설정하며, 이는 달성 결과가 아닌 임시 평가 방향이다.

### 공통 완료 과제

참여자는 **사건 요약·자료 목록·미확인 항목·상담 질문을 검토한 뒤, 다른 사람에게 자신의 상황과 남은 확인 사항을 설명한다.** 모든 비교 조건에 같은 완료 과제를 적용한다.

사용자의 완료 선언 시점과 설명 과제 종료 시점을 각각 기록하고, 결과물·설명의 정확성은 별도로 평가한다. 완료 선언이 있어도 중요한 누락이 있으면 품질 문제로 남긴다. 중단·포기 사례는 완료 사례와 구분한다.

### 실험 A. 내용 구조화 품질

- 참여자에게 동일 사건의 같은 비식별 텍스트·자료를 제공한다. ECRM 조건에서는 공개 안내·작성 항목을 참고해 사용자가 준비 결과를 직접 작성한다. 범용 AI·시제품 조건에서는 동일 자료를 입력하고 결과를 검토·수정한다. ECRM이 자동 요약을 생성한다고 가정하지 않는다.
- 제공 문구·날짜·금액·정보 누락은 동일하게 맞추고 우리 서비스에만 정리된 입력이나 추가 단서를 주지 않는다. 각 방식의 작성·검토·수정 시간도 기록한다.
- 자료 준비는 실험자가 공통으로 완료한 상태다. 출력의 사실 보존·자료 연결·누락 질문·임의 추정과 사용자 검토·수정 시간을 비교한다.
- 이 결과는 내용 구조화와 이해 지원의 품질을 보여줄 수 있지만 자료 수집을 포함한 전체 준비 부담 감소의 근거로 사용하지 않는다.

### 실험 B. 전체 준비 부담

- 동일 사건의 판매 글·대화·거래 내역을 구분해 배치한 가상·비식별 자료 묶음에서 시작한다. 각 조건의 접근 가능 자료와 위치·내용은 같게 하고, 각 도구에 입력할 형태는 사용자가 직접 준비한다.
- 자료 찾기·확인 → 복사·비식별 처리·옮기기 → 입력 → 질문 응답 → 결과 검토·수정 → 공통 완료 과제의 설명을 마치는 시점까지 관찰한다. 모든 단계 시간을 포함하고, 중단·오류·포기 사례도 기록한다.
- 총 준비 시간과 단계별 시간, 중복 입력·자료 왕복·수정 횟수, 사실 누락·추정 추가 여부를 함께 비교한다. 결과물이 보기 좋아도 총수고가 늘면 부담이 줄었다고 판정하지 않는다.
- 가상 자료 환경에서 얻은 결과는 실제 앱 간 이동·파일 접근 등 현실의 전체 부담을 입증하지 않는다. 실제 사용자 자료 실험은 동의·비식별·취급 조건을 마련한 뒤 별도로 검토한다.

### 같은 출발점과 관찰 기준

- 각 실험 안에서 목표·사건 자료·자료 접근 조건·진행자의 안내와 도움 범위를 같게 정한다. 추가 도움은 내용과 시간을 기록하고, 조건별 차이가 생기면 결과의 한계로 남긴다.
- ECRM은 공개 안내·작성 항목을 참고한 모의 준비로 비교한다. 실제 접수 절차나 접근하지 못한 화면까지 시험했다고 표현하지 않는다. 각 방법의 입력 방식 차이는 숨기지 않고 수고에 포함한다.
- 범용 AI에도 같은 자료와 충분한 지시(출처 연결·미확인과 충돌 보존·누락 질문·수정 반영)를 제공한다. 단순 요약 요청만을 비교 기준으로 삼지 않는다.
- 범용 AI 모델·버전·요청문·제공 자료와 제안 시제품 조건을 기록한다. 같은 참가자가 반복하면 학습 효과를 고려해 순서를 교차 배치하고 결과 해석의 한계를 남긴다.
- 중요한 사실·필요한 누락의 기준은 사례 원문과 사용자 과제에 맞춰 실험 전에 정한다. 없는 정보를 반드시 채우게 하지 않고, 관련 없는 질문은 별도 기록한다.
- 정리 품질과 법률 설명 정확성은 따로 평가한다. 법률·절차 출력의 검토 담당과 범위가 정해지기 전에는 정확성 검증 완료로 표시하지 않는다.

### 기술 비교 실험 — 사용자 가치 검증과 분리

실험 A·B는 사용자의 정확한 준비와 수고를 평가한다. 아래 비교는 **역할 분담과 동적 작업 구성의 기술적 효과**를 평가하며, 결과를 사용자 수요 검증으로 해석하지 않는다. 처음에는 소수의 가상·비식별 사례로 계획·실행·기록이 설계대로 연결되는지 확인한다.

| 비교 구성 | 실행 방식 | 검증 질문 |
|---|---|---|
| 단일 에이전트 | 하나의 에이전트가 같은 도구로 정리·안내 확인·자체 대조를 수행 | 한 에이전트로도 충분한가? |
| 고정 멀티에이전트 | 사전에 정한 동일 역할·작업 순서를 모든 사례에 적용 | 단일 구성보다 역할 분담으로 사실 보존·근거 연결이 개선되는가? |
| 동적 멀티에이전트 | 동일한 역할 후보에서 요청·중간 결과에 따라 작업 선택·추가·생략·보류와 독립 작업 병렬 실행 | 고정 구성보다 품질을 유지하면서 불필요한 작업을 줄이는가? |

#### 비교 조건과 기록

- 동일한 모델·버전·생성 설정, 사건 원문, 사용자 목적, 도구·자료 접근 권한, 결과 항목, 평가 기준을 사용한다. 역할별 지시와 구성 차이는 별도로 보존한다.
- 사례별 **전체 실행 예산 상한**을 맞춘다. 토큰·도구 호출·시간·비용 상한과 재시도·수정 한도를 실행 전에 정하고, 계획·조정·대조·수정 호출도 모두 합산한다. 같은 예산을 반드시 소진하게 하지 않고 실제 사용량을 비교한다.
- 고정 구성은 실행 전에 정의하고 사례별로 사후 최적화하지 않는다. 동적 구성도 역할 후보와 허용 작업 유형을 고정하고 선택 조건·계획 변경을 기록한다.
- 공식 자료는 우선 같은 기준일의 이용 허용 자료 묶음과 같은 접근 실패 조건으로 맞춘다. 실제 웹 실행은 별도 시험으로 구분하고 자료·조회 시점 차이를 기록한다.
- 사례별 기대 사실·근거 연결과 분기 조건을 사전에 작성한다. 경위 정리만 요청, 상담 준비 병행, 날짜·금액 충돌, 공식 자료 접근 실패 사례를 포함한다. 반복 횟수와 실행 순서도 기록한다.

| 관측값 | 비교할 내용 |
|---|---|
| 사실 보존 | 중요한 사실 누락·왜곡·없는 사실이나 의도 추가 |
| 근거 연결 | 요약의 원래 입력·자료 연결, 안내의 출처·확인일·적용 범위, 미확인 보존 |
| 분기 정확성 | 필요한 작업 선택, 선행 관계 준수, 충돌 확인 추가·답변 대기·실패 후 부분 결과 처리 |
| 불필요한 작업 | 관련 없는 조사·반복 질문·중복 실행·이미 확인된 내용 재조사 |
| 자원과 종료 | 전체 소요 시간, 모델·도구 호출 수, 입력·출력 토큰과 비용, 예산 소진·실패·부분 결과 |

비용은 실행 당시 적용한 단가와 사용량을 함께 남긴다. 미측정 항목은 추정값과 구분한다. 사용자 답변 대기 시간과 시스템 실행 시간도 나눠 기록한다.

단일 대 고정 구성에서는 역할 분담의 효과를, 고정 대 동적 구성에서는 선택·변경의 효과를 각각 판단한다. 품질과 자원 차이를 함께 보고, 사실 왜곡 증가를 시간·비용 감소로 상쇄해 성공 처리하지 않는다. 소수 사례에서 기록이 연결된 결과는 구성 점검이며 일반적인 성능 우위를 입증한 결과가 아니다. 실제 LLM·도구 실행 전에는 성능 검증 완료로 표시하지 않는다.

## 10. 멀티에이전트 구성·실행·검증 계획

**사용자 요청과 중간 결과에 따라 사건 정리·공식 안내 조사·결과 대조 역할의 작업을 선택하고, 선행 관계와 실행 상태를 관리한다. 고정 구성 및 단일 에이전트와 비교해 역할 분담과 동적 구성의 효과를 각각 검증한다.**

### 역할별 책임과 전달 결과

아래는 이 제안의 첫 역할 후보군이다. 역할 수가 매번 같은 수의 모델 호출을 뜻하지는 않으며, 각 실행에서 선택된 작업과 전달 결과를 기록한다.

| 역할 | 입력 | 맡을 일 | 다음 작업에 전달할 출력 |
|---|---|---|---|
| 계획·조정 | 사용자 목적·현재 입력·기존 결과·실행 예산 | 필요한 역할·작업 선택, 의존 관계·병렬 실행 구성, 후속 작업 추가·생략·보류, 결과 조립 | 작업 계획·실행 조건·선행 작업·변경 이유·현재 상태 |
| 사건 정리 | 사용자 설명·이용 가능한 자료와 참조 | 경위 구조화, 누락·서로 다른 기재 발견, 진술과 자료의 의미 보존 | 원래 입력·자료와 연결된 경위, 충돌·미확인, 확인 질문 |
| 공식 안내 조사 | 사용자 질문·계획에서 지정한 확인 항목·허용 출처 | 필요한 공식 안내 확인, 요청한 용어·경로 설명 | 출처·확인일·적용 범위가 연결된 설명, 접근 실패·충돌 기록 |
| 결과 대조 | 결과 초안·원래 입력·자료·공식 안내 결과 | 원문과 요약 대조, 근거 없는 표현·미확인 누락·잘못된 연결 확인 | 문제 항목·연결 근거·수정 요청 또는 대조 결과 |

상담 질문은 사건 정리 작업이 경위와 필요한 공식 안내를 받아 작성하고, 계획·조정 작업이 최종 결과를 조립한다. 결과 대조는 자동 점검이며 법률 전문가의 정확성·적법성 검토와 구분한다.

### 대표 실행과 계획 변경

| 요청·중간 결과 | 작업 흐름·선행 관계 | 추가·생략·보류 이유 |
|---|---|---|
| 경위 정리만 요청 | 계획 → 사건 정리 → 결과 조립 → 결과 대조 | 요청에 없는 공식 안내 조사 생략 |
| 경위 정리와 상담 준비 요청 | 계획 → 사건 정리와 일반 공식 안내 조사 병렬 → 두 결과를 이용한 상담 질문 작성 → 결과 조립·대조 | 사건 세부 정보 없이 확인 가능한 일반 안내만 병렬 실행. 개별 상황에 필요한 안내는 사건 정리 후 실행 |
| 중간에 날짜·금액 충돌 발견 | 기존 계획에 충돌 확인 작업 추가 → 사용자 답변 대기 → 답변이 오면 관련 경위·질문 수정 → 다시 대조 | 충돌을 임의 해소하지 않음. 답을 모르거나 현재 결과를 원하면 미확인으로 남겨 해당 수정 작업 보류 |
| 공식 자료 확인 실패 | 실패 원인 기록 → 한도 내 대체 공식 출처 확인 여부 판단 → 해당 안내 미확인 처리 → 확인된 경위로 부분 결과 조립·대조 | 접근 실패를 안내 확인 성공으로 바꾸지 않음. 사건 정리 결과까지 폐기하지 않음 |

3단계 확인 화면에서 입금액을 이미 말했으면 재질문을 생략하고, 배송 약속일이 빠졌으면 해당 확인 작업만 추가한다. 용어를 이해하지 못한다고 요청한 경우에 해당 용어 안내 작업을 선택하며, 모든 용어 설명을 매번 실행하지 않는다.

### 상태·전달·종료 기록

- 계획 항목에는 목적, 담당 역할, 입력·출력 참조, 선행 작업, 명시적 실행 조건, 예산·재시도 한도, 상태와 변경 이유를 남긴다. 기록 필드명·발급 방식은 구현 계약에서 맞춘다.
- 계획·작업·실행 시도를 구분해 추적하고 이전 실패나 변경 전 계획을 덮어쓰지 않는다. 결과의 각 경위·설명에서 어떤 작업·입력·자료를 사용했는지 연결한다.
- 대조가 수정을 요청하면 해당 작업만 보완하고 변경된 부분을 다시 대조한다. 수정·조회 한도는 실행 전 정하며, 한도 이후에는 남은 문제·미확인을 표시해 부분 결과로 종료한다.
- 사용자 답변 대기·미실행·실패·부분 결과를 구분한다. 준비 결과 생성은 공식 신고 접수나 전문가 검토 완료를 의미하지 않는다.

공통 구조는 요청·계획·작업·근거·상태의 연결이다. 이 도메인에 특화된 부분은 중고거래 경위·자료 항목·법률 용어·공식 출처·사실 보존의 확인 기준이다. 구성 효과는 9절 기술 비교에서 검증하며, 조건부 분기가 있다는 이유만으로 멀티에이전트의 우위를 전제하지 않는다. 개인 제안의 설계 계획으로서 팀의 앱 MVP를 교체하는 결정과 구분한다.

## 11. 전제와 한계

### 제안·검증 상태

- 사용자 요청으로 작성한 개인 제안이다. 팀 제품 방향·요구사항·WBS 변경이나 TASK-013 완료·제출을 의미하지 않는다.
- 타겟 선정과 실제 수요 검증은 다르다. 인터뷰·문제 빈도 조사·실험 A·B·비용 절감 효과·범용 AI 비교·시스템 연동은 미실시이며 수요·차별점은 가설이다.
- 비용 때문에 직접 고소를 준비하는 사람이 많다는 주장과 용어 이해가 정리 어려움의 원인이라는 인과관계는 확인하지 않았다.
- 첫 시제품은 비식별 텍스트 기반이다. 실제 파일 자동 수집·판독·공식 신고 제출을 수행하지 않으며, 자료를 찾고 옮기는 부담은 남는다. 가상 자료 실험으로 실제 앱 이용 전체의 효과를 입증하지 않는다.
- 자동 고소장 완성·제출·대리, 범죄 성립·의도·처벌·피해 회복 확정, 승소 가능성 예측, 수사 상태 실시간 조회는 첫 검증 범위에서 제외한다.
- 동적 멀티에이전트 필요성과 역할 수·프레임워크·API 선택.도 후속 검증 대상이다. 다른 팀원의 독립 제안과 사전 합의한 내용은 아니다.

### 법적 경계·전문 검토

사건 경위와 자료를 정리하는 기능도 제공 방식에 따라 법률상담·법률관계 문서 작성과의 경계 검토가 필요하다. 구현·서비스 제공 전 실제 출력과 운영·수익 구조를 바탕으로 전문적인 법적 검토를 받는다. ‘정리 지원’이라는 명칭이나 면책 문구만으로 적법성을 판단하지 않는다.

변호사법 제109조는 비변호사의 이익 수수·약속과 법률상담·법률관계 문서 작성 등 법률사무 취급을 규정한다. 모든 법률 정보 제공이 곧 위법이라고 단정하거나 이 초안으로 적법성을 판단하지 않는다. [국가법령정보센터 변호사법 제109조](https://www.law.go.kr/lsLawLinkInfo.do?chrClsCd=010202&lsJoLnkSeq=900175916) (확인일: 2026-11-16; 조문 표시 시행일: 2026-10-02)

법률·절차 출력의 정확성을 검토할 담당자와 범위, 서비스 제공의 법적 경계 검토자는 미정이다. 검토자를 확보하고 검토를 수행하기 전 정확성·적법성 검토 완료로 표시하지 않는다.

### 데이터·표시 원칙

- 공개 저장소에는 실제 사건의 이름·연락처·계좌·대화 원문·사건번호 등 식별 자료를 올리지 않는다. 예시는 가상·비식별 자료를 사용한다.
- 저장 범위·보관 기간·삭제·접근 통제·외부 모델 전송 조건은 실제 자료 취급 전에 정한다.
- 외부 자료는 공식 API·승인 데이터 또는 필요한 최소 개별 문서 조회 범위에서 이용한다. 공개 열람과 자동 수집·저장·재사용 권한을 구분한다. API 이용 조건·법령 갱신 관리·플랫폼별 최신 기능은 후속 조사 항목이다.
- 문서 전체의 한계는 이 절에 모으되 가상 사례 표시, 개별 내용의 미확인·추측, 출처·조회일·자료 기준일은 해당 설명 옆에도 유지한다.
