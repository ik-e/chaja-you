# AI 멀티 에이전트 기반 개인 맞춤형 앱 검색 및 추천 시스템

**프로젝트 기획안 v0.1**

- 작성일: 2026년 11월 11일
- 프로젝트 유형: AI 멀티 에이전트 기반 리서치·추천 서비스
- 개발 방식: Bottom-up(바텀업)
- 문서 상태: 팀원 검토 및 기술 검증 전 초안

---

## 1. 프로젝트 개요

### 1.1 프로젝트 소개

본 프로젝트는 사용자의 자연어 요청과 개인 취향을 분석하여 적합한 스마트폰 애플리케이션을 검색하고, 여러 AI 에이전트가 협업하여 개인 맞춤형 추천 보고서를 제공하는 시스템이다.

기존의 인기순위 중심 검색 방식에서 벗어나, 사용자의 취향과 요구사항에 적합한 앱을 탐색하는 것을 목표로 한다.

사용자가 구체적인 조건을 입력하지 않은 경우 AI 에이전트가 선택형 질문을 통해 취향을 파악하며, 필요에 따라 일반 인기순위 기반 추천도 제공한다.

### 1.2 프로젝트 목표

1. 자연어를 이용한 스마트폰 앱 검색 및 추천
2. 사용자 요청의 모호함을 판단하고 선택형 추가 질문 제공
3. RAG를 활용한 앱 정보 검색 및 관련 정보 추출
4. 온톨로지를 활용한 사용자 취향과 앱 특성 간 관계 분석
5. 멀티 에이전트 협업을 통한 검색·분석·추천 자동화
6. 개인 적합도에 따른 앱 순위 산정 및 보고서 생성
7. 인기순위에 노출되지 않는 앱까지 탐색할 수 있는 검색 구조 마련

## 2. 프로젝트 추진 배경 및 필요성

### 2.1 기존 앱 검색 방식의 한계

**① 인기순위 중심의 검색**

일반적인 앱 스토어에서는 인기 차트와 키워드 검색 등을 제공하지만, 인기순위가 높다고 반드시 개인에게 적합한 앱인 것은 아니다.

**② 사용자의 구체적인 검색어 작성 부담**

사용자는 자신이 원하는 앱의 특징을 정확하게 설명하지 못할 수 있다.

예를 들어 "게임 추천해 줘"라는 요청에는 장르, 플레이 방식, 유료 여부 등의 정보가 부족하다.

**③ 낮은 인지도의 앱을 발견하기 어려움**

사용자는 검색 결과에 자주 등장하는 앱 위주로 살펴보게 될 수 있으며, 자신의 조건에 더 적합하지만 잘 알려지지 않은 앱을 발견하지 못할 수 있다.

### 2.2 해결 방향

사용자의 요청을 분석하고 필요한 조건을 대화를 통해 수집한 뒤, 다양한 앱 후보를 탐색하여 개인 적합도 기준으로 재정렬하는 시스템을 구축한다.

## 3. 핵심 서비스 기능

### 3.1 자연어 기반 앱 검색

사용자는 일상적인 언어로 앱을 검색할 수 있다.

**입력 예시**

- "게임 추천해 줘."
- "무료 가계부 앱 찾아줘."
- "광고가 적고 혼자 즐길 수 있는 퍼즐 게임 추천해 줘."
- "운동 기록하기 좋은 앱을 비교해 줘."

시스템은 입력된 문장에서 앱 카테고리, 선호 조건, 제외 조건, 검색 목적 등을 추출한다.

### 3.2 선택형 추가 질문

사용자의 요청에 취향 정보가 부족한 경우 AI가 선택형 질문을 생성한다.

**대화 예시**

사용자: "게임 추천해 줘."

AI: "어떤 장르의 게임을 좋아하시나요?"

선택지:
- RPG
- 퍼즐
- 액션
- 시뮬레이션
- 전략
- 상관없음

AI: "어떤 게임을 원하시나요?"

선택지:
- 무료 게임
- 광고가 적은 게임
- 혼자 하는 게임
- 친구와 함께하는 게임
- 상관없음

사용자의 선택 결과를 검색 조건에 반영한다.

**운영 원칙**
- 추가 질문은 최대 2~3개를 권장한다.
- 조건이 충분한 경우 질문 없이 검색한다.
- 사용자가 질문을 건너뛰거나 인기순위를 요청하면 인기순위 기반 추천을 제공한다.
- 특정 조건에 해당하는 앱을 찾지 못하면 사용자에게 안내한다.

### 3.3 인기순위 및 개인 맞춤형 추천

**A. 인기순위 추천**

사용자가 취향을 지정하지 않거나 인기 앱을 요청한 경우, 수집 가능한 앱 스토어 인기순위 데이터를 기준으로 추천한다.

**B. 개인 맞춤형 추천**

사용자의 선호 장르, 기능, 가격, 광고 여부 등 조건을 반영하여 후보 앱을 탐색하고 적합도를 평가한다.

인기순위가 낮거나 차트에 없는 앱도 검색 후보에 포함할 수 있도록 검색어 확장과 관련 앱 탐색 기능을 설계한다.

단, 실제로 검색 가능한 앱의 범위는 데이터 제공처와 API의 제약에 따라 달라진다.

### 3.4 앱 추천 보고서

최종 결과는 앱별 정보를 가로로 정렬한 목록 또는 비교표 형태로 제공한다.

**기본 출력 항목**

| 순서 | 항목 |
|---|---|
| 1 | 앱 이미지(아이콘) |
| 2 | 앱 이름 |
| 3 | 다운로드 수 |
| 4 | 평점 |
| 5 | 개발자가 제공한 앱 설명 |

**추가 추천 항목**
- 추천 순위
- 사용자 조건과 일치하는 이유
- 일치하지 않는 조건
- 정보 출처 및 확인일
- 앱 스토어 이동 링크

다운로드 수 등 공개되지 않은 정보는 임의로 생성하지 않고 '정보 없음' 또는 '미제공'으로 표시한다.

## 4. 멀티 에이전트 시스템 설계

### 4.1 에이전트 구성

**Agent 1. 요청 분석·대화 에이전트**

- 자연어 요청 분석
- 사용자 취향 및 조건 추출
- 불충분한 정보 판단
- 선택형 추가 질문 생성
- 검색 조건 구조화

**Agent 2. 검색 계획·조정 에이전트(캡틴)**

- 검색 목표 정의
- 하위 조사 작업 생성
- 검색 대상 및 검색어 선정
- 다른 에이전트의 실행 순서 관리
- 검색 실패 및 정보 부족 상황 조정

**Agent 3. 앱 검색 에이전트**

- 앱 스토어 및 허용된 검색 경로에서 데이터 수집
- RAG를 이용한 관련 앱 정보 탐색
- 검색 조건에 맞는 앱 후보 확보
- 앱별 출처 및 메타데이터 저장

**Agent 4. 추천·보고서 에이전트**

- 수집 데이터 검토
- 사용자 취향과 앱 특성 비교
- 적합도 산정 및 순위 결정
- 추천 근거 작성
- 최종 보고서 생성

### 4.2 전체 처리 흐름

사용자 요청 입력

↓  

요청 분석 및 취향 추출

↓

조건 부족 여부 판단

├─ 조건 부족: 선택형 추가 질문

└─ 조건 충분: 검색 진행

↓

검색 계획 및 후보 앱 탐색

↓

온톨로지를 활용한 의미·관계 분석

↓

RAG를 활용한 관련 정보 검색

↓

사용자 적합도 평가 및 순위 결정

↓

출처 검증 및 보고서 생성

↓

사용자에게 추천 결과 제공

※ 실제 실행에서는 온톨로지와 RAG를 순차적으로만 사용하는 것이 아니라 검색 계획과 적합도 평가 단계에서 함께 활용할 수 있다.

## 5. RAG 및 온톨로지 활용 방안

### 5.1 RAG 활용

RAG는 수집·저장된 앱 설명과 관련 문서에서 사용자 요청에 적합한 정보를 검색하는 데 활용한다.

**예시**

사용자 요청: "광고가 적고 오래 즐길 수 있는 게임 추천해 줘."

RAG 검색:
- 앱 설명 중 광고 관련 정보 검색
- 장시간 플레이 관련 기능 검색
- 사용자 조건과 관련된 설명 추출

검색된 자료는 앱 추천 근거를 생성하는 데 활용한다.

RAG 검색 결과만으로 확인할 수 없는 정보는 외부 데이터 확인이 필요하다.

### 5.2 온톨로지 활용

온톨로지는 사용자 취향과 앱의 특징 사이에 존재하는 관계를 구조화하는 데 활용한다.

**관계 예시**

- 게임 → 장르 → 퍼즐
- 퍼즐 → 플레이 특성 → 사고력 중심
- 게임 → 이용 방식 → 싱글 플레이
- 사용자 → 선호 장르 → 퍼즐
- 사용자 → 선호 조건 → 무료
- 앱 → 지원 기능 → 오프라인 플레이

이러한 관계를 기반으로 검색어를 확장하거나 추천 조건을 해석한다.

### 5.3 사용자 취향 기억 관리

사용자가 선택한 선호 조건을 저장하여 이후 추천에 반영하는 기능을 고려한다.

초기 MVP에서는 현재 대화 세션에서 수집한 취향 정보를 유지한다.

장기적인 사용자 프로필 저장, 과거 추천 이력 분석 및 지속적인 선호도 갱신은 후속 기능으로 검토한다.

사용자 정보는 명시적인 동의와 수정·삭제 방안을 고려하여 관리한다.

## 6. 프로젝트 범위

### 6.1 도메인 범위

- 스마트폰 애플리케이션 검색 및 추천
- 특정 산업이나 앱 장르에 제한되지 않는 구조
- 초기 시연은 게임과 가계부 등 대표 카테고리 중심
- Android 또는 iOS 데이터 지원 범위는 수집 가능성 검증 후 결정

### 6.2 검색 범위

**MVP 포함**
- 접근 가능한 앱 스토어 정보
- 앱 이름, 이미지, 평점, 설명 등 기본 메타데이터
- 앱 설명 기반 의미 검색
- 사용자 조건에 따른 검색어 확장
- 출처 URL과 확인 날짜 관리

**후속 확장**
- 다양한 리뷰 플랫폼 및 커뮤니티
- 사용자 후기 분석
- 여러 앱 스토어의 데이터 통합
- 검색 범위 및 후보 수의 고도화

### 6.3 에이전트 사용 범위

- 초기에는 최대 4개 역할로 구성
- 요청에 따라 질문과 조사 작업을 동적으로 생성
- 에이전트 간 작업 결과 전달 및 종합
- 새로운 전문 에이전트를 무제한 생성하는 기능은 제외
- RAG와 온톨로지는 독립 에이전트가 아닌 공통 데이터·지식 기능으로 활용

## 7. 개발 전략: Bottom-up

본 프로젝트는 데이터 및 개별 기능을 먼저 구현하고, 이후 에이전트 협업을 연결하는 바텀업 방식으로 개발한다.

| 단계 | 개발 내용 | 산출물 |
|---|---|---|
| 1 | 앱 데이터 수집 및 저장 | 앱 데이터베이스 |
| 2 | 기본 검색·인기순위 기능 | 앱 검색 API |
| 3 | 앱 정보 의미 검색 | RAG 검색 기능 |
| 4 | 취향·앱 특징 관계 정의 | 온톨로지 초안 |
| 5 | 조건 추출 및 선택형 질문 | 대화형 검색 기능 |
| 6 | 개인 적합도 순위 산정 | 추천 알고리즘 |
| 7 | 에이전트 연결 및 작업 조정 | 멀티 에이전트 실행 흐름 |
| 8 | 최종 보고서 및 화면 구현 | 앱 추천·비교 서비스 |
| 9 | 통합 테스트 및 개선 | 테스트 결과 및 시연 자료 |

## 8. 프로젝트 차별화 전략

### 8.1 대화형 취향 구체화

사용자가 정확한 검색 조건을 모르더라도 AI가 선택형 질문을 통해 요구사항을 구체화한다.

### 8.2 개인 적합도 중심 추천

앱의 인기순위뿐 아니라 사용자 조건과의 적합성을 중심으로 추천 순위를 산정한다.

### 8.3 저인지도 앱 탐색

상위 인기 차트에 없는 앱도 검색할 수 있도록 의미 검색과 검색어 확장을 활용한다.

### 8.4 RAG 및 온톨로지 연계

앱 설명의 실제 근거와 사용자 선호 관계를 함께 활용하여 추천의 설명 가능성을 높인다.

### 8.5 에이전트 협업 기반 리서치

요청 분석, 검색 계획, 데이터 수집, 추천 보고서 생성을 역할별로 분리하여 추후 기능을 확장할 수 있도록 설계한다.

※ 위 항목은 프로젝트가 구현하고자 하는 차별화 후보이며, 기존 서비스와의 비교를 통해 실제 차별성을 검증해야 한다.

## 9. 주요 기술 위험 및 대응 방안

| 위험 | 대응 방향 |
|---|---|
| 앱 정보 수집 제한 | 공식·허용된 데이터 출처부터 검증 |
| 앱별 다운로드 수 미제공 | 미제공 표기 및 플랫폼별 데이터 구분 |
| 인기도 데이터 확보 어려움 | 인기순위 제공처와 기준을 사전 확정 |
| 검색 결과 부족 | 검색어 확장과 추가 검색 적용 |
| LLM의 잘못된 정보 생성 | 수집 데이터와 생성 문장을 분리하여 검증 |
| RAG 검색 정확도 부족 | 검색 결과 평가 및 테스트 데이터 구축 |
| 온톨로지 설계 복잡성 | 핵심 관계만 우선 정의 |
| 에이전트 간 오류 | 입출력 형식 및 완료 조건 명확화 |
| 개발 범위 초과 | 기능별 MVP 우선순위 관리 |

---

## 10. MVP 성공 기준

1. 사용자의 일반적인 앱 추천 요청을 인식한다.
2. 조건이 부족할 경우 선택형 추가 질문을 제공한다.
3. 사용자 응답을 구조화된 검색 조건으로 변환한다.
4. 수집된 앱 데이터에서 관련 앱 후보를 검색한다.
5. 사용자 취향을 반영한 추천 순위를 제공한다.
6. 취향을 지정하지 않은 경우 인기순위 기반 결과를 제공한다.
7. 결과에 앱 아이콘, 이름, 다운로드 정보, 평점, 개발자 설명을 표시한다.
8. 추천 근거와 출처를 확인할 수 있다.
9. 주요 기능이 여러 에이전트의 협업을 통해 실행되는지 검증한다.
10. 최소 2개 앱 카테고리의 시연 시나리오를 실행한다.

---

## 11. 기대 효과

사용자는 복잡한 검색어를 직접 작성하지 않고도 자신의 취향에 맞는 앱을 탐색할 수 있다.

인기순위 중심으로 앱을 검색하는 방식의 한계를 보완하고, 비교적 알려지지 않은 앱도 추천 후보에 포함할 수 있다.

또한 RAG, 온톨로지, 멀티 에이전트 협업 구조를 결합해 설명 가능한 개인 맞춤형 리서치 시스템의 구현 가능성을 검증할 수 있다.

## 12. 향후 확장 방향

- 사용자별 취향 장기 기억
- 추천 이력과 피드백 기반 선호도 업데이트
- 앱 리뷰 및 커뮤니티 정보 활용
- Android·iOS 통합 검색
- 온톨로지 관계 확장
- 사용자 요청에 따른 전문 에이전트 동적 생성
- 다른 디지털 서비스 추천 분야로 확장

## 13. 팀원 협의 및 미확정 사항

기획서 확정 전 다음 사항에 대한 합의가 필요하다.

1. Android와 iOS 중 초기 데이터 수집 플랫폼
2. 앱 인기순위의 기준과 데이터 제공처
3. RAG에 저장할 정보의 범위 및 갱신 주기
4. 온톨로지의 초기 관계 및 데이터 구조
5. 개인 적합도 점수 산정 기준
6. 사용자 취향 저장 기간 및 개인정보 처리 방식
7. 에이전트별 세부 책임과 기술 스택
8. 프로젝트 전체 개발 기간 및 WBS 일정

**최종 목표:** 사용자 요청을 이해하고, 취향을 구체화하며, 관련 앱을 폭넓게 조사하고, 개인에게 적합한 앱을 근거와 함께 추천하는 AI 멀티 에이전트 시스템을 구현한다.
