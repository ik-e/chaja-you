## R01이 중요하게 보는 의도

이번 작업의 목적은 TASK-003~006의 제안을 모두 합쳐 큰 기획안을 만드는 것이 아니다.

**사용자 가치, 실제 데이터·운영 제약, 동적 구성의 필요성, 구현 가능성을 서로 대조해 이번 MVP에서 반드시 할 것과 미룰 것, 아직 판단할 수 없는 것을 결정하는 것**이 목적이다.

제출 일정 때문에 장기 목표를 축소된 MVP와 동일시하지 않으며, 근거가 부족한 선택은 억지로 확정하지 않고 재검토 조건을 남긴다.

추가로 다음 장기 의도를 보존한다.

- 범용 검색·브라우징 루프 자체를 새 핵심 기능으로 다시 만드는 것보다 기존 리서치 실행 능력을 재사용하고, 찾아you는 도메인 특화 조사 구성·상태·근거·판단 연결에 집중한다.
- 조사 산출물은 장기적으로 고정 보고서 하나보다 재사용 가능한 구조화 조사 상태를 지향하고, 사용자 출력은 질문에 필요한 최소 정보의 프로젝션으로 본다.
- 공통 구조는 앱 도메인의 실제 구현에서 반복되는 것을 관찰해 추출하며 첫 도메인만으로 범용 구조를 선결정하지 않는다.
- 외부 데이터는 공개 열람 가능성과 자동 수집·저장·재사용 권한을 구분하며, 비공식 자동 크롤링이나 대량 순회를 MVP의 수집 방식으로 사용하지 않는다.
- 승인 데이터셋·공식 API·사용 조건이 명확한 공개 데이터를 우선하고, 일반 웹은 질문 해결에 필요한 최소 개별 문서 조회와 근거 확인에 한정한다.
- 수집 정책 준수 여부를 정확도·속도보다 앞서는 검증 게이트로 취급한다.

## AI가 실행 기준으로 해석한 내용

TASK-003~006의 결과를 다음 기준으로 비교한다.

- 사실·관찰
- 담당자의 해석·제안
- 서로 충돌하는 제안
- 아직 확인되지 않은 사항
- R01 결정이 필요한 항목

각 항목은 가능하면 다음 중 하나로 분류한다.

- **Must**: 이번 MVP에 반드시 포함
- **Later**: 장기 목표에는 관련되지만 이번 MVP에서는 후순위
- **Unknown**: 근거가 부족해 아직 결정하지 않음

결정할 때는 다음 연결이 끊기지 않는지 확인한다.

`사용자 문제 → 도메인 특화 조사 방식 → 허용된 수집 경로 → 필요한 동적 구성 → 리서치 실행 → 실제 데이터/근거 → 재사용 가능한 조사 상태 → 사용자 프로젝션 → 평가 방법`

수집 경로는 최소한 다음을 구분한다.

- 승인된 데이터셋
- 공식 API·공공데이터
- 사용 조건이 명확한 배포 데이터셋
- 검색으로 발견한 개별 공식/공개 문서의 최소 조회
- 자동 수집 권한 미확인 또는 금지된 경로

마지막 항목에 의존하는 계획은 Must 구현 경로로 채택하지 않는다.

## 과도하게 확장하지 않을 것

- 팀원 제안을 모두 채택해 범위를 키우는 것
- 다수 의견을 근거 없이 합의로 간주
- 제출을 위해 미검증 가설을 확정 사실로 승격
- 프레임워크·RAG·온톨로지 등 후속 후보를 필요성 없이 Must로 포함
- 현재 MVP 범위를 프로젝트의 장기 최종 목표로 재정의
- 검색 공급자 다변화·자체 검색 오케스트레이션을 필요성 검증 없이 Must로 포함
- 질문별 프로젝션·증분 재조사 기능 전체를 이번 제출의 필수 구현으로 승격
- 일반 웹사이트의 비공식 크롤링·페이지네이션 순회·대량 HTML/리뷰/목록 수집을 수집 편의 때문에 도입
- `robots.txt` 허용만으로 자동 수집 권한이 확보됐다고 해석
