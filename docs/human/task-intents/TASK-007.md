## R01이 중요하게 보는 의도

이번 작업의 목적은 TASK-003~006의 제안을 모두 합쳐 큰 기획안을 만드는 것이 아니다.

**사용자 가치, 실제 데이터·운영 제약, 동적 구성의 필요성, 구현 가능성을 서로 대조해 이번 MVP에서 반드시 할 것과 미룰 것, 아직 판단할 수 없는 것을 결정하는 것**이 목적이다.

제출 일정 때문에 장기 목표를 축소된 MVP와 동일시하지 않으며, 근거가 부족한 선택은 억지로 확정하지 않고 재검토 조건을 남긴다.

## AI가 실행 기준으로 해석한 내용

TASK-003~006의 결과를 다음 기준으로 비교한다.

- 사실·관찰
- 담당자의 해석·제안
- 서로 충돌하는 제안
- 아직 확인되지 않은 사항
- R01 결정이 필요한 항목

각 항목은 가능하면 다음 중 하나로 분류한다.

- **Must**: 이번 MVP에 반드시 포함
- **Later**: 장기 목표에는 관련되지만 이번 MVP에서는 후순위
- **Unknown**: 근거가 부족해 아직 결정하지 않음

결정할 때는 다음 연결이 끊기지 않는지 확인한다.

`사용자 문제 → 필요한 동적 구성 → 실제 데이터/근거 → 최소 구현 구조 → 평가 방법`

## 과도하게 확장하지 않을 것

- 팀원 제안을 모두 채택해 범위를 키우는 것
- 다수 의견을 근거 없이 합의로 간주
- 제출을 위해 미검증 가설을 확정 사실로 승격
- 프레임워크·RAG·온톨로지 등 후속 후보를 필요성 없이 Must로 포함
- 현재 MVP 범위를 프로젝트의 장기 최종 목표로 재정의

## R01이 직접 판단할 것

- 첫 MVP의 사용자 문제와 검증 범위
- 필수 요구사항과 후순위 기능
- 동적 구성의 최소 구현 수준
- 데이터와 근거 처리의 최소 기준
- 평가 계획과 아직 정하지 않을 정량 기준
- 중요한 위험과 재검토 조건

## 결과에 반드시 남길 것

- 채택한 것과 이유
- 보류한 것과 이유
- 미확인인 것과 필요한 다음 근거
- 팀원 제안과 R01 결정이 다른 경우 그 차이
- 이후 결정을 다시 열 조건

## 열린 항목

TASK-003~006 결과가 모두 들어오기 전에는 개별 기술·범위 선택을 선결정하지 않는다. 최종 결정은 결과 근거를 검토한 뒤 ADR·state·spec에 별도로 반영한다.
