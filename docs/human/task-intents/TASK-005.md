## R01이 중요하게 보는 의도

이번 작업의 목적은 복잡하거나 범용적인 동적 멀티에이전트 시스템 자체를 만드는 것이 아니다.

**사용자의 요청과 조사 중간 결과가 달라질 때 실제로 필요한 역할·작업·실행 순서가 달라지는 최소 구조를 찾고, 그것이 고정된 조사 흐름보다 가치가 있는지를 검증하는 것**이 중요하다.

동적인 기능을 많이 넣는 것보다 무엇을 동적으로 만들 필요가 있고 무엇은 고정해도 되는지를 구분하는 것이 우선이다.

상위 제품 의도인 `INTENT-PRODUCT-001`에 따라, 동적 구성은 하나의 범용 역할·작업 목록에서만 선택하는 것으로 한정하지 않는다. **선택된 리서치 도메인에 맞게 특화된 역할·작업·출처·검증 기준을 전제로 하고, 그 안에서 사용자 요청과 중간 결과에 따라 필요한 구성을 선택·변경하는 것**으로 해석한다. 현재 역할 후보와 작업 유형은 앱 리서치 도메인의 첫 후보군이며, 모든 도메인에 영구 고정되는 목록으로 보지 않는다.

## AI가 실행 기준으로 해석한 내용

우선 검토할 동적 요소:

- 필요한 역할 선택
- 필요한 작업 선택
- 작업 간 선행 관계
- 병렬 실행 가능 여부
- 중간 결과에 따른 후속 작업 추가·생략

우선 고정 후보로 검토할 요소:

- 역할 후보군
- 작업 유형
- 입출력·결과 형식
- 검증 상태 표현

APP-A, APP-B, APP-C를 이용해 요청과 중간 결과에 따라 실제 구성이 달라지는지 확인한다.

가능하면 동일한 모델·검색 조건의 고정 워크플로를 baseline으로 두고 다음을 비교한다.

- 필요한 작업 누락
- 불필요한 작업 실행
- 실행 순서·조건 분기
- 사용자 조건 누락
- 근거 연결
- 시간·호출 수·비용

## 과도하게 확장하지 않을 것

- 필요성이 검증되지 않은 자유로운 새 역할 생성
- 범용 workflow engine 전체 설계
- 프레임워크를 먼저 정한 뒤 문제를 맞추는 방식
- 실행하지 않은 성능 향상을 달성한 것처럼 표현하는 것

## 담당자가 자율적으로 판단해도 되는 것

- 역할 후보와 작업 유형의 구체적인 초안
- 평가 항목과 비교 방법
- APP-A/B/C를 이용한 실험 설계
- 추가로 필요한 요청 변형

## R01에게 돌려줄 결정

- 실제 MVP에서 어느 수준의 동적 구성을 Must로 둘 것인지
- 자유 역할 생성 등 더 일반적인 기능을 이번 MVP에 포함할 것인지
- 다중 도메인 구현은 후속으로 두되, 도메인별 특화 가능성 자체를 MVP 구조에서 어떤 경계로 보존할 것인지
- baseline 실험 결과를 보고 범위를 확대할 것인지

## 아직 열린 항목

동적 구성의 최종 수준과 정량 합격선은 실제 기준 실행 전에는 확정하지 않는다.
