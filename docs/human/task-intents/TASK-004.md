## R01이 중요하게 보는 의도

이번 작업의 목적은 사용할 수 있는 API나 데이터 출처를 많이 나열하는 것이 아니다.

**앱 리서치 MVP가 실제로 어떤 정보를 확보할 수 있고, 어떤 정보는 확보하기 어렵거나 제약이 있는지를 확인해 이후 제품 범위와 구현 가능성을 판단할 수 있게 하는 것**이 중요하다.

특히 공식 자료에서 확인할 수 있는 사실과 실제 기기·사용 환경에서만 확인 가능한 내용을 구분하고, 확인되지 않은 조건을 사실처럼 확정하지 않는다.

## AI가 실행 기준으로 해석한 내용

R02 결과에서는 가능하면 다음을 구분한다.

- 실제 MVP에서 사용할 수 있는 데이터와 출처
- 자동으로 조회할 수 있는 정보와 수동 확인이 필요한 정보
- 저장·재사용·자동화 과정에서 확인해야 할 이용 조건
- 공식 문서와 실제 기기 동작이 달라질 수 있는 항목
- 현재 확인할 수 없는 정보
- 이러한 제약이 MVP 요구사항에 주는 영향

출처 개수를 늘리는 것보다 **이 정보로 실제 무엇을 할 수 있는가**를 판단할 수 있는 결과를 우선한다.

## 과도하게 확장하지 않을 것

- 모든 앱스토어·데이터 공급자의 전수 조사
- 필요성이 확인되지 않은 데이터 수집 파이프라인 설계
- 특정 인프라·DB·검색 공급자의 조기 확정
- 공개 근거 없이 서비스 정책이나 내부 동작을 추정하는 것

## 담당자가 자율적으로 판단해도 되는 것

- 조사할 공식 출처의 우선순위
- 비교 표와 조사 방법
- 표본 앱이나 데이터의 확인 순서
- 제약을 설명하는 방식

## R01에게 돌려줄 결정

- 자동화하지 못하는 정보가 있을 때 MVP 범위를 조정할 것인지
- 추가 데이터 수집이나 별도 연동에 투자할 필요가 있는지
