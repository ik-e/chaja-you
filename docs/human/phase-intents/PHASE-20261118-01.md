## 지금 이루려는 것

최종프로젝트에서 실제로 만들 **제품의 사용자·페인포인트·문제 정의·핵심 피처**를 근거로 선정하되, 그전까지 기한이 있는 교육기관 제출 요구를 놓치지 않기 위해 **실제 기획 탐색**과 **잠정 제출 대응**을 구분한다.

### 트랙 A · 실제 기획 탐색

- R02~R05는 자신이 생각한 기존안을 구체화하거나 새 문제를 탐색하는 것 중 **한 경로를 자율 선택**한다. 오늘 두 경로 모두 완성할 의무는 없다.
- 어떤 사람이 어떤 순간에 어떤 불편·손실을 겪고, 기존 제품·일반 LLM·수작업이 해결하는 범위 뒤에 무엇이 남는지 검증한다.
- 실제 사례/인터뷰, 공개 근거, 추정·미확인, 반대 증거를 구분한다. 충분한 근거 없이 신규 기능·AI 가치가 있다고 결론짓지 않는다.
- R01은 전체 후보의 근거·반증·일정·협업을 검토하고 2026-11-21 오프라인에서 선택 또는 보류 판단을 이끈다.
- **현재 최종 제품 주제와 구현 범위는 미선정**이다. 이전 찾아you APP-A/C 또는 R03/R05 잠정 우선 후보를 승인된 제품으로 자동 승격하지 않는다.

### 트랙 B · 공식 제출 의무 대응

- 기존 찾아you 기획서·요구사항·WBS·APP-A/C 설계와 그 기반 API/DB 초안은 **과거 작업의 잠정 스냅샷**으로 유지한다.
- **기존 기획안·WBS의 실질적인 구현 및 일정 실행은 보류한다.** 해당 문서들은 공식 양식과 마감에 대응할 때만 **제출용 잠정안**으로 참조한다.
- 현재 제품 결정 전이므로 제출용 내용에 *주제 미확정 / 기존 기획 기준 / 미구현·미검증 / 추후 전면 재검토 가능*을 명시한다.
- 공식 안내 형식은 충족하되 사실을 날조하거나 미확인 기술·성과를 검증 완료로 적지 않는다. 제출 준비·제출·접수는 별도 상태다.
- 기존 WBS상 11/20 API·DB 문서 일정은 현재 공식 마감·방법을 확인하는 대상으로 취급한다. 11/21 실제 기획 결정 뒤 설계·WBS를 재수립한다.
- 기존 WBS의 지난 구현 작업을 별도 승인 없이 자동 재개하지 않는다.
