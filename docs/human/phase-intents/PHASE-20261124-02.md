## 목표

12/8 MVP 설계 판단에 필요한 **실행 가능한 비교 근거**를 확보한다. R03은 플랫폼 중립 공통 테스트 환경 및 플랫폼별 mock 프로필을 만들고, R04와 R05는 **각기 다른 플랫폼에 대해 독립 설계·구현·검증**한다. 같은 제품 구현안을 경쟁시켜 동일 기능 점수만 비교하는 방식이 아니다.

- **R03 (TASK-043):** 테스트 하네스(합성 fixture, 크몽 상품 등록 mock 및 숨고 고수/서비스 등록 mock 후보, 오류/승인/unknown 주입, 양쪽 실행기 연결 방법, 반복 가능한 검증 기록).
- **R04 (TASK-044):** 숨고. 먼저 **실제 등록 객체가 고수 프로필 설정인지, 서비스 등록인지, 다른 단계인지** 공식 출처/접근 가능한 화면으로 규명; 확인된 동작을 최소 구현. 등록 범위가 다르면 모의와 실제 경로를 구분해 입증한다.
- **R05 (TASK-045):** 크몽. 웹 레슨 서비스 상품의 원본 필드 매핑→승인→허용된 모의 입력/이미지 첨부→결과 증빙의 수직 경로를 최소 구현하고 장애/unknown 처리.
- **R01:** 공통 성공/중단 기준, 프로젝트 기능 범위와 11/27 채택·통합 판단. 기존 R02가 보유한 실제 판매 정보는 사용 동의가 확인된 항목만 검토; 신규 민감정보 제출 요구 없음.

## 허용과 제한

- 기존 L0~L7 최소 설계를 각 작업의 **기능·책임·계약·오류·검증 기준**에 적용한다. 설계 없이 개발하지 않고 **최소 설계→작은 코드→실행 증거→설계 갱신**을 반복한다.
- 실제 API·로그인·제출이 아니더라도 **모의 페이지, 테스트 하네스, 독립 제품 구현 PoC**까지 허용한다. 안전하게 되돌릴 수 있는 프레임워크/패키지 선택은 각 담당이 근거와 lock을 자기 작업 브랜치에서 관리하고, 공통 루트 의존성은 공동 합의 전 변경하지 않는다.
- **실서비스 크몽·숨고 로그인, 실제 게시/접수, 무단 자동화, 보안 우회는 이번 단계 불허**. 정책·운영사 허용·본인 동의·필수 인증이 확인되기 전까지 실제 계정/세션/신원자료를 취급하지 않는다.
- 모의 성공을 플랫폼 최종 등록·심사 접수·실사용 가치 입증으로 기록하지 않는다.
- 테스트 환경이 각 구현의 내부 스택을 강제하지 않도록 **공통 입출력과 평가 케이스만 고정**한다.
