# 사람의 의도와 운영 기준

- 소유자: 프로젝트 리더
- 상태: 사람 권위 입력
- 갱신일: 2026-11-12
- 변경 원칙: 사람의 명시적 요청으로만 수정

이 파일은 AI가 추론해 만드는 현재 상태가 아니라, 사람이 장기간 유지하려는 목표와 운영 원칙을 적는 기준입니다. 세부 구현·작업 상태·실험 결과는 AI 원본 공간에서 관리합니다.

## INTENT-PRODUCT-001 · 제품 목표

사용자의 요청과 **리서치 도메인에 맞게** 조사 워크플로와 에이전트 역할·작업을 구성하고, 도메인에 적합한 출처와 검증 기준을 사용해 공개 자료를 조사하여 근거와 출처가 연결된 결과를 제공한다.

공통적인 조사·근거·실행 구조는 재사용하되, 도메인마다 필요한 조사 대상·역할·작업·출처 우선순위·검증 방법은 특화할 수 있어야 한다.

## INTENT-PRODUCT-002 · 리서치 실행 기능과 제품 책임의 경계

찾아you는 검색·브라우징·페이지 탐색처럼 범용 모델·도구가 이미 제공할 수 있는 **일반적인 리서치 실행 기능 자체를 다시 만드는 것을 핵심 가치로 두지 않는다.** 필요한 경우 외부 모델·검색·브라우징 도구의 리서치 실행 능력을 교체 가능한 실행 수단으로 재사용한다.

제품의 핵심 책임은 사용자의 요청과 리서치 도메인에 따라 **무엇을 조사할지, 어떤 역할·작업·출처 우선순위·검증 기준을 적용할지, 중간 결과에 따라 어떤 작업을 추가·생략·보류할지, 확보한 근거가 어떤 판단을 뒷받침하는지**를 구성하고 관리하는 데 둔다.

특정 모델·검색 공급자·API는 장기 제품 의도에 고정하지 않는다. 실행 수단은 바뀔 수 있지만 도메인 특화 구성, 작업 상태, 근거와 판단의 연결은 제품의 지속적인 책임으로 본다.

## INTENT-PRODUCT-003 · 조사 결과 상태와 사용자 프로젝션 분리

조사 결과의 최종 형태를 하나의 고정된 보고서로 한정하지 않는다. 조사가 수행되면 이후 질문과 작업에서 재사용할 수 있도록 **대상, 조건, 주장·판정, 근거·출처, 확인 시점, 조사 범위, 미확인·충돌·실패 상태** 등 확인된 의미와 근거를 구조화된 조사 결과 상태로 보존하는 방향을 지향한다.

사용자에게 보여주는 출력은 조사 결과 전체를 그대로 노출하는 것이 아니라 **현재 사용자의 목적과 질문에 필요한 정보를 우선하여 최소한으로 프로젝션**한다. 보고서는 가능한 프로젝션 중 하나이며, 사용자가 근거·비교 기준·미확인 사항 등을 요구하면 필요한 수준까지 확장해 보여줄 수 있어야 한다.

기존 조사 결과만으로 현재 질문에 충분히 답할 수 있으면 불필요한 재조사를 피한다. 필요한 정보가 없거나 미확인·충돌 상태이거나 최신성 때문에 다시 확인할 필요가 있으면 **그 질문에 필요한 범위만 추가 조사하고 기존 조사 결과에 연결**하는 방향으로 확장한다.

이 기능 전체를 첫 MVP의 필수 범위로 선결정하지 않는다. 다만 현재의 결과 구조가 이후 재사용 가능한 조사 상태와 질문별 프로젝션을 불필요하게 막지 않도록 한다.

## INTENT-PRODUCT-004 · 버텀업 도메인 확장

범용 도메인 프레임워크를 먼저 완성한 뒤 개별 도메인을 끼워 넣는 방식보다, **하나의 실제 도메인에서 충분히 특화된 리서치 흐름을 구현·검증하고 그 과정에서 반복되는 공통 구조를 추출하는 버텀업 접근**을 우선한다.

첫 MVP는 앱 리서치 도메인에서 검증한다. 앱에 필요한 역할·작업·출처 우선순위·검증 기준을 충분히 다루되 이를 영구적인 범용 구조로 일반화하지 않는다. 실제 구현에서 재사용 가치가 확인된 구조만 공통화하고, 일정과 근거가 허용하면 후속 도메인을 추가해 공통 구조와 도메인 특화 경계를 다시 검증한다.

## INTENT-DEV-001 · 구현과 검증 설계의 동시 진행

기능이나 구조를 구현할 때 구현 방법만 먼저 정하지 않고, **그 기능이 어떤 질문을 검증하며 의도대로 동작하는지 어떻게 확인할지도 함께 설계**한다.

구현 범위를 정하거나 작업을 시작할 때 가능한 범위에서 다음을 같이 명시한다.

- 해결하거나 검증하려는 질문
- 기대하는 입력·행동·결과
- 성공, 실패, 미확인, 부분 성공을 구분하는 기준
- 실제 동작을 확인하기 위해 남겨야 할 상태·로그·근거
- 비교가 필요한 경우 사용할 baseline과 동일 조건
- 아직 측정하지 않은 내용과 이후 재검토 조건

검증 설계는 구현을 막기 위한 사전 절차가 아니라, **구현 결과에서 무엇을 배웠는지 판단하고 다음 설계에 되돌리기 위한 장치**로 사용한다. 실제 실행 근거가 없을 때 정량 기준이나 자동 검증을 임의로 확정하지 않고, 가설·임시 기준·미확인을 구분한 뒤 관찰된 결과를 바탕으로 갱신한다.

따라서 개발은 `설계 → 구현 → 검증`을 한 번씩 순서대로 끝내는 과정으로만 보지 않고, **구현 범위와 검증 설계를 함께 세우고 실제 결과를 다음 설계와 범위 결정에 되돌리는 반복 과정**으로 운영한다.

## INTENT-OPS-001 · AI와 사람의 작업 공간

AI는 구조화된 원본 공간에서 입력·출력·상태·근거·검증을 중심으로 작업한다. 사람은 AI 원본을 매번 전부 읽는 대신 생성된 검토 화면과 제출물 프로젝션을 통해 상태와 결과를 확인한다.

## INTENT-OPS-002 · 사람의 의도 되돌려 넣기

사람은 프로젝션을 보고 승인·수정·보류·거절·새 제약을 남길 수 있어야 한다. AI는 그 입력을 임의의 대화 기억으로만 소비하지 않고 필요한 ADR·현재 상태·명세·작업에 연결해 다음 작업의 기준으로 반영한다.

## INTENT-OPS-003 · 사람의 주의 집중

사람에게는 모든 세부 작업보다 중요한 변화, 실패·막힘, 남은 불확실성, 결정 요청을 먼저 보여준다. 필요할 때만 구조화 원본과 상세 근거로 내려간다.

## INTENT-OPS-004 · 사람용 프로젝션의 시간적 의미

사람용 프로젝션은 AI 정본의 실시간 동기화 사본이 아니라, **생성 시점의 상태를 사람이 검토하기 좋게 표현한 스냅샷**으로 취급한다. 프로젝션에는 생성 시각과 가능하면 기준 revision을 표시해 어떤 상태를 표현하는지 알 수 있게 한다. 이후 정본이 변경되었다는 사실만으로 기존 프로젝션을 오류로 간주하지 않는다.

## INTENT-OPS-005 · 검증 규칙의 도입 원칙

운영 규칙이나 자동 검증은 예상 가능한 문제를 모두 선제적으로 막기 위해 추가하지 않는다. **실제 작업에서 반복되거나 사람의 판단·통합·품질에 영향을 주는 실패가 관찰되면 그 근거를 바탕으로 자동화·검증 규칙 도입을 검토한다.** 아직 문제가 관찰되지 않았다면 우선 운영을 통해 필요성을 확인한다.

## INTENT-OPS-006 · GitHub 정본과 Discord 전달 채널

프로젝트의 장기 의도·작업 의도·결정·상태처럼 AI와 팀이 이후 작업에서 다시 참조해야 하는 기준은 **GitHub의 정본 기록에 남긴다.** Discord는 해당 기준을 사람에게 짧고 실행 가능하게 전달하고 질문·협의를 진행하는 커뮤니케이션 채널로 사용한다.

Discord에서 나온 설명이나 실행 조율이 기존 GitHub 기준을 바꾸지 않는다면 별도 정본 기록을 만들 필요가 없다. 반대로 대화 중 프로젝트 의도·범위·완료 기준·중요 결정이 변경되면 그 변경 사항은 GitHub의 관련 Intent·Task Intent·ADR·상태·명세에 다시 반영한다.

## INTENT-GOV-001 · 결정 권한

AI의 추천은 결정이 아니다. 범위·목표·완료 기준·핵심 구조처럼 영향이 큰 선택은 권한 있는 사람이 결정하고, 그 근거와 재검토 조건을 ADR 또는 연결된 상태 기록에 남긴다.
