## 의도 또는 결정

찾아you는 검색·브라우징과 같은 일반적인 리서치 실행 기능 자체를 새로 만드는 것을 핵심 가치로 두지 않는다. 현재 MVP에서는 OpenAI Responses API의 web search 같은 기존 리서치 실행 능력을 우선 재사용 후보로 보고, 찾아you는 도메인 특화 조사 구성, 작업 상태, 근거와 판정의 연결을 직접 책임지는 방향으로 검증한다. 특정 공급자나 API를 장기 제품 의도에 고정하지 않는다.

조사가 끝나면 하나의 고정 보고서만 남기는 대신, 이후 질문과 작업에 재사용할 수 있는 **구조화된 조사 결과 상태**를 만들 수 있는 방향을 유지한다. 사용자에게 보여주는 출력은 전체 조사 결과를 항상 노출하지 않고, 현재 사용자의 질문과 목적에 필요한 정보만 우선 프로젝션한다.

기존 조사 결과만으로 답할 수 있는 질문은 재조사를 피하고, 필요한 정보가 없거나 미확인·충돌·최신성 문제가 있을 때만 필요한 범위를 추가 조사해 기존 결과에 연결하는 방향으로 확장한다.

## 이유

강력한 모델·검색·브라우징 기능이 이미 존재하므로 저수준 탐색 루프를 다시 구현하는 것보다, 어떤 조사를 해야 하는지 도메인에 맞게 구성하고 근거가 어떤 판단을 지지하는지 관리하는 데 프로젝트의 차별점을 두는 편이 현재 목표와 일정에 더 적합하다.

또한 조사 결과와 사용자 출력물을 분리하면 같은 조사 결과를 여러 질문에 재사용할 수 있고, 사용자가 필요로 하지 않는 정보까지 항상 보여주거나 같은 내용을 반복 조사하는 비용을 줄일 수 있다.

## 제약 / 반드시 지킬 것

- 특정 모델·검색 공급자·API를 장기 제품 구조에 고정하지 않는다.
- 검색 공급자 다변화나 자체 검색 오케스트레이션은 실제 필요가 관찰되기 전에는 Must로 두지 않는다.
- 기존 리서치 실행 능력을 사용하더라도 source/evidence/claim·verdict/확인 시점/미확인·실패 상태의 의미 연결은 찾아you가 관리한다.
- 보고서는 최종 상태 그 자체가 아니라 가능한 사용자 프로젝션 중 하나로 본다.
- 질문별 최소 프로젝션과 증분 재조사 전체를 현재 Step 1 MVP의 필수 구현으로 선결정하지 않는다.
- 현재 결과 구조가 향후 재사용 가능한 조사 상태와 질문별 프로젝션을 불필요하게 막지 않도록 한다.
- OpenAI + web search 기본 실행과 찾아you의 도메인 특화·작업 구성·근거 판정 구조를 비교하는 실험은 후보 baseline으로 두되, 실제 비교 전 우월성을 주장하지 않는다.

## 재검토 조건

- 기존 hosted research 기능만으로 도메인 특화 구성과 근거 판정까지 충분히 해결되어 별도 구조의 추가 가치가 나타나지 않는 경우
- 사용자가 반복 질문을 하면서 같은 조사 결과를 재사용해야 할 실제 필요가 확인되는 경우
- 조사 상태를 저장하는 비용·복잡성이 사용자 가치보다 큰 것으로 관찰되는 경우
- 특정 리서치 실행 수단의 제약 때문에 공급자 다변화나 자체 adapter가 필요해지는 경우

## AI에게 요청하는 반영

장기 제품 Intent와 TASK-007에 이 방향을 연결하고, 기획서·WBS에서는 검색 자체 재구현이 아니라 앱 도메인 특화 조사 구성과 근거 기반 결과를 우선 구현하도록 한다. 질문별 프로젝션·증분 재조사는 후속 확장 가능성을 유지하되 이번 핵심 MVP 범위를 과도하게 늘리지 않는다.
