## R01 발화에 따른 결정
- 멘토링 결과 R02의 레슨 강사 업무 불편 해결 방향으로 **기획을 구체화**한다. 이는 기술/수익/MVP가 완전히 검증된 제품 승인이나 개발 착수를 뜻하지 않는다.
- 기획서에는 **서비스 개요·목표 / 타깃·상황 / Pain·근거 / 기존 대안·잔여 Pain / 원인·문제 정의 / 핵심 피처·가치 / 이용 시나리오 / 비즈니스 모델 / 기능 요구사항 / 기술·권한 제약 / MVP / 검증 계획** 12개 항목을 담는다.
- 핵심 인과관계는 **사용자 Pain → 원인 → 핵심 피처 → 실제 개선/가치 → 지불 동기**, 후속 설계에 필요한 입출력·예외·완료 조건이다.
- 기존 R02 조사 자료를 최대한 재사용하고 부족한 근거만 팀원별로 나눠 확인한다. 팀원 역량 및 기존 작업 결과를 고려한다.
- 지금은 기획 단계다. 화면 와이어프레임, 코드 구현, DB/API 설계 및 본격 PoC는 이 배분의 필수 산출물이 아니다.
- 기획 완료 기준과 저장 공간을 사전에 고정한다. TASK에는 누가·무엇을·어디에·어떤 근거로 남길지 명시한다.
