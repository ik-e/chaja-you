## 결정

멘토 피드백과 현재 프로젝트 구조를 바탕으로, GitHub 문서·상태 관리는 유지하되 R01과 main에 작업·검증이 과도하게 집중되지 않도록 운영을 수정한다.

- TASK owner는 합의된 범위 안에서 자기 작업의 구현 방법, 내부 테스트, 검증 근거와 완료 판단을 책임진다.
- 다른 TASK가 의존하는 인터페이스·상태·계약 변경은 관련 owner끼리 확인한다.
- 제품 범위, Must/Done, 공통 구조, 해결되지 않는 cross-task 충돌은 R01 결정으로 올린다.
- R01은 모든 작업을 재검증하는 역할이 아니라 제품 경계·우선순위, cross-task 통합 기준, 핵심 E2E·릴리스 확인을 책임진다.
- main은 병렬 작업 공간보다 통합된 현재 상태로 사용한다. 의미 있는 기능·계약 변경은 기본적으로 TASK 단위 branch와 PR을 거친다.
- 모든 PR에 R01 승인을 강제하지 않는다. TASK 내부 저위험 변경은 owner 검증, 공유 계약 변경은 관련 owner 검토, 제품 범위·공통 계약 변경은 R01 결정이 기본이다.
- 단순 오탈자·생성 프로젝션 갱신처럼 의미가 바뀌지 않는 작은 변경까지 무거운 PR 절차를 강제하지 않는다.
- GitHub에는 다음 작업에서도 재사용할 지속 상태·결정·계약·검증 결과를 남기고, 실행 중 worker/retry/queue 같은 일시적 runtime 상태는 별도 실행 계층에서 관리한다.
- owner는 정상 진행을 자율적으로 이어가고, 막힘·일정 위험·cross-task 영향이 있을 때 관련 owner나 R01에게 올린다.

## 재검토 조건

R01 대기, merge 후 다른 TASK 파손, 공유 계약 충돌, 검증 부족으로 인한 재작업이 반복되면 CAND-014의 AI-native PR / Verification Workflow 또는 CAND-015의 프로젝트 메타구조 개선 일부를 검토한다.
