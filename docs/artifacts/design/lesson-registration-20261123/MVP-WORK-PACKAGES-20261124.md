# MVP 실행 중심 작업 계약 제안 · 2026-11-24

> 상태: R01 검토용 제안. TASK-033~037을 **실제 설계·코드·동작 검증 산출물 중심으로 구체화**한 인계안이다. 이 파일 작성은 업무 정식 배정, 구현 승인, 플랫폼 자동 게시 허용을 의미하지 않는다. 정본은 GitHub main, 작업 초안은 현재 설계 브랜치에 유지한다.
>
> 근거: 기획안 V1.1의 8·9·11·12장 (FR-01~06), 기존 L0~L7 설계 모델, TASK-028~032, 설계 착수 제안 ADR-004. 12/08은 **작동하는 MVP 목표일**, 2027/01/04은 완성품 목표일이다.

## 1. MVP에서 실제로 돌아가야 하는 단일 흐름

**한 명의 강사가 보유한 레슨 원고·사진·확인된 판매 조건을 크몽 상품 한 건으로 변환 → 사람이 내용 및 실행 범위를 승인 → 모의 크몽 양식에 내용/사진 입력 → 모의 결과를 실제 증빙과 함께 확인**한다.

- **Must:** F1 원본 구조화·사실/규칙 검증, 초안·승인 버전 추적, F2 모의 등록 폼 입력·사진 첨부, F3 결과/오류/unknown·증빙, 제출 불명시 재시도 차단.
- **Conditional:** **실제 크몽** 입력·업로드·심사 접수. 운영사 허용·사용자 인증/승인·실행 검증 전에는 불가. 모의 성공을 실제 심사 접수라고 기록하면 안 된다.
- **Out:** 당근 앱 자동화, 타 플랫폼 실등록, 후기·상담·지도, 임의 가격/조건 생성, 비밀번호/인증코드 수집, 정책 우회.
- **우선 판정:** 11/27 첫 모의 E2E 실행을 목표로 하고, 미달 시 실제 막힌 단계와 증거를 남긴다. 완료 여부는 실행 로그로 판단한다.

## 2. 기능별 **유일한 구현 책임자**와 연계

| 부분 | 구현 책임 1명 | 제공하는 결과 | 소비·검증 담당 | 책임에서 제외 |
| --- | --- | --- | --- | --- |
| 레슨 정답 원본·사진 권한·실등록 필드 근거 | R02 | fixtures + source-to-field 사실 매핑 | R03/R05 | AI 변환 코드·브라우저 실행 |
| F1 변환·사실 검증 + F3 상태 규칙 | R03 | 호출 가능한 코드 + 검사/상태 테스트 + 계약 | R05(백엔드), R04(UI) | 웹 UI·크몽 조작·DB/API 배포 |
| 등록 전 검토·명시 승인·진행/결과 UI | R04 | 구동 가능한 화면과 API/mock 연결 | R01(사용자 흐름), R05(연동) | 도메인 상태 의미 변경·브라우저 자동 입력 |
| F2 모의 크몽 어댑터, 백엔드 연결·이벤트 저장 | R05 | 호출 가능한 모의 실행기/API, 사진 업로드, 작업 결과·증거 | R03(계약 검사), R04(UI), R01(E2E) | 가격/횟수 판단 규칙·UI 소유 |
| 제품 범위·MVP Done·최종 E2E 판정 | R01 | 범위 기준선, 승인/보류 기록, 공통 인수 결과 | 팀 전원 | 팀원 개별 세부 구현 대행 |

R03과 R05가 API/데이터 의미를 **공동 협의**하되, 계약의 **업무 의미는 R03**, 구현 가능한 API/저장 구조는 **R05**가 단독 소유한다. R04는 공유된 상태 이름과 의미를 화면에서 임의 변경하지 않는다. 도메인/API/UI 중 한 곳이 바뀌면 영향을 받는 소비자에게 변경 예제와 호환성 확인을 제공한다.

- **입력:** 기획 V1.1 8/9/11/12장, TASK-028~032, ADR-004(제안), 단계 의도 문서.
- **실제 수행:** 첫 1건 시나리오와 Must/Conditional/Out, 사용자 승인/접수 성공의 의미, 11/27·12/8 시연 기준 확정 제안. 현재 PHASE의 **설계·PoC 금지 조건을 해소할 수 있도록** 모의 환경에 한정한 별도 착수 승인/단계 수정 필요성을 기록.
- **반드시 제출:** (1) 1페이지 범위/Done 정의 (2) C01~C07 인수 시험표 (3) 결정/미확인/재검토 조건과 팀원별 구현 책임 확인 기록. 파일은 R01 작업 공간 또는 기존 ADR/TASK 원본에 연결.
- **완료 판정:** 개발자가 추가 설명 없이 '이번에 구현/제외할 동작'과 '성공 관찰 증거'를 구별할 수 있어야 한다. **R01 권한으로 기존 단계 의도/정본을 갱신하기 전까지 모의 PoC도 실제 착수 확정은 아니다.**
- **하지 않을 일:** 플랫폼 운영사 허용으로 미확인을 임의로 승격, 실제 사이트 게시 승인, 팀원 설계 구현 직접 작성.

### TASK-034 · R02 · 실사용 정답 데이터와 크몽 필드 매핑 · 목표 11/25 (오전 부재 반영)

- **입력:** R02 실제 강사 사례·원본, V1.1 8/12장, 공개 가이드 및 본인이 접근 가능한 화면.
- **실제 수행:** 기존 원고·사진의 식별 정보를 가린 테스트 입력 준비; 최신 **월 4회, 90/180/270분, 25/40/50만원** 및 비용·변경/취소·제공내용·사진 사용권의 근거/확인/미확인 표기. 과거 공개 공고(다른 시간·가격)는 **별도 버전**으로 보존. 크몽 필드 이름/필수 여부는 공식 자료·직접 관찰·미확인으로 분리.
- **반드시 제출:** (1) JSON 형태 1건 이상 입력 fixture(민감정보·실제 비밀번호 제외) (2) 기대 구조화/승인값 JSON (3) 크몽 필드 매핑표: 원본 필드, 화면 필드, 형식/제약, 출처·확인일·미확인 (4) 오류 fixture 2건: 누락 조건, 가격/시간 충돌 (5) 사용 가능한 테스트 사진 또는 대체 이미지와 사용권 표기.
- **완료 판정:** R03이 데이터만 받아 값 일치/임의 조건 삽입 테스트를 실행할 수 있고, R05가 정확히 어떤 입력란에 무엇을 넣어야 하는지 구분 가능.
- **하지 않을 일:** 핵심 UI/백엔드 개발, 새로운 판매 조건의 임의 승인, 허용 미확인 사이트 자동 제출.

### TASK-035 · R03 · F1/F3 업무 계약 + **실제 실행 가능한 규칙 코드** · 목표 11/24 계약, 11/26 테스트

- **입력:** V1.1 FR-01~06, R03 기존 보고서, R02 fixture(오전에는 명시적 합성 값으로 시작), R01 범위 기준선.
- **실제 수행:** SourceLesson → RegistrationDraft → Approval → RegistrationEvent/Result의 업무 스키마/필수값/상태 전이·가드 확정안. **F1** 입력을 실제 받아 구조화·크몽 필드 매핑 결과와 누락/충돌을 반환하는 호출 가능한 코드 작성(LLM 추출이 미구현이면 해당 구간은 모의·수동이라고 명시). **F3** 증빙이 없는 성공 판정 차단, 승인 버전 불일치 차단, unknown 재제출 차단 로직과 테스트 작성.
- **반드시 제출:** (1) 버전 붙은 JSON 계약 파일 및 유효/무효 예제 (2) 상태 전이 그래프(11/27 공식 산출물 재사용 가능) (3) 실제 실행 가능한 F1/F3 코드 (4) 정상·조건충돌·버전불일치·unknown을 검증하는 자동 테스트 파일과 실행 명령/결과.
- **완료 판정:** 제공된 명령으로 테스트를 실행하고, 정확한 원본 조건 보존·허락되지 않은 값 생성 차단·unknown 차단이 **PASS/FAIL** 로그로 확인된다. 설계 문서만으로 구현 완료 표시 금지.
- **하지 않을 일:** 브라우저 자동 입력, 파일 업로드/세션 구현, API 서버·화면 구현.
- **특별 주의:** 기존 R03 초안의 '90분 월 30만원'은 예전 값이다. 최신 R02 정답을 반영하고 예전 예제를 최신으로 오인하지 않는다.

### TASK-036 · R04 · **클릭 가능한** 최소 사용자 UI + 화면 동작 확인 · 목표 11/26

- **입력:** R03 스키마/상태, R02 fixture, R05가 약속한 최소 API 또는 동일 형태 mock.
- **실제 수행:** (1) 원본/사진 입력 (2) 변환 결과·출처·충돌 검토 (3) 등록 범위 승인/실행 요청 (4) 진행·결과·미확인/오류 행동의 최소 화면 연결. 초기에는 mock 응답으로 구동, 실제 API 연결 시 교체 가능한 경계 유지.
- **반드시 제출:** (1) 로컬 실행 명령이 있는 UI 코드 (2) 화면별 I/O 매핑표 (3) 정상/누락/unknown 세 흐름의 실제 화면 캡처 또는 짧은 재현 로그 (4) 사용자 개입 시간 측정 시작·종료 이벤트 위치.
- **완료 판정:** R01이 직접 화면을 클릭해 1건의 입력→검토→승인→결과 확인을 따라갈 수 있으며, unknown에서 '등록 완료' 문구가 나타나지 않는다. 로딩/오류 상태도 확인 가능.
- **하지 않을 일:** 사실/가격 검증 로직 재작성, 도메인 상태 정의 변경, 크몽 사이트 실제 조작.

- **하지 않을 일:** 실제 크몽에 무단 자동 게시/접수, 비밀번호·인증코드 수집, 사용자 승인 없는 변경, R03 도메인 규칙 복제.
