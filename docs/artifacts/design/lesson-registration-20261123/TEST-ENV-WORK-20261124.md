## 오늘 목표 및 완료의 의미

합성 레슨 1건과 로컬 모의 폼으로 **입력·검토·mock 제출·오류/unknown**을 재현할 수 있는 환경을 만든다. 별도의 강사 계정·민감한 실제 판매 정보·실서비스 자동 제출은 필요 없다.

오늘의 최소 Done은 (a) Python/uv 잠금 및 테스트 명령 재현 (b) 합성 입력과 계약 (c) 로컬 모의 화면 (d) 정상/누락/unknown 시험의 실제 실행 증거 (e) 기존 문서 관리 도구 회귀 확인이다. 전체 F1→F2→F3 제품 작동은 이번 주 후속 작업이다.

## 이 작업에서 제외하는 기존 미선정 기술

- 현재 MVP 런타임 라이브러리 신규 결정 없음. `pydantic`, `pydantic-settings`, `python-dotenv`, `requests`는 **현재 코드에서 직접 사용되지 않은 것**으로 확인되어 루트 의존성에서 제거; `pytest`·`ruff`만 dev에 유지.
- 오늘은 `core`, `ui`, `adapters/mock-kmong`의 **제품 구조를 확정하지 않는다**. 종전 README 스캐폴드는 제거하고 모의 폼/계약/검증 중심으로 작업한다. R03/R04/R05 담당 역할은 유지되지만 제품 아키텍처 선택으로 확대되지 않는다.
- 로컬 HTML로 검사 가능한 경우 별도 웹서버·브라우저 자동화 패키지를 도입하지 않는다.

## 오전→오후 실행 흐름

1. **오전 시작:** R01이 범위/이번 TASK 제출 경계를 공유. R03이 최소 상태·fixture 계약 초안 제공. R05가 현재 uv 정리와 재현 명령 확인. R04는 독립적인 오프라인 모의 폼 구조를 작성.
2. **오전 후반:** R04 로컬 화면 시연, R03 기대값/상태 결과 대조, R05 CI/pytest 환경의 실제 로그 확보. 외부 패키지 설치가 막히면 재현 명령과 차단 이유를 기록.
3. **오후:** R02가 현실성/권리/민감정보/미확인 조건 점검. R03 계약·시험 수정.
4. **종료:** R01이 각각의 실행 결과 및 실패 원인/미완료를 표에 기록한다. 증거가 없는 작업은 완료가 아니다.
