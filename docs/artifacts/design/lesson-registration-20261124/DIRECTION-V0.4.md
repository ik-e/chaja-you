### 원격 브라우저 구현자 위임

- 사용자 직접 인증, 동일 인증 맥락, 사용자/자동화 제어권 상호배타, 뷰어 종료 후 작업 지속, 승인·계정·대상·권한 결합, 중복/unknown 차단, 인증정보 비저장·최소 처리, 사용자별 격리·폐기, 재현 가능한 증거
- 기술 선택 근거·대안·변경 조건·공통 인터페이스 영향 기록. 공통 의존성/인터페이스 변경은 합의 필요.
- 위임은 구현 기술 선택이지 현재 권한 제한·보안 조건을 완화하는 권한 아님. 최종 운영 격리·보존 정책 및 검증은 별도.

R05의 [원격 브라우저 PoC](https://github.com/ik-e/chaja-you/tree/fc59a4b8f5e8adea3c4dc3b2264df2907131c018/docs/members/R05/workspace/remote-browser-poc)는 구조 채택의 근거이며 CDP/WebSocket/Playwright 등 기술을 강제하지 않는다. R05 보고: 합성 웹 뷰어 원격 로그인·동일 인증 세션 실행·뷰어 종료 후 서버 작업·텍스트/이미지/저장·제어권 반환·논리적 세션 격리/폐기. pytest 10개, 3회 연속 통과 보고. R01 측 독립 재실행 아님. 로컬 합성 환경, Chrome 프로세스 공유 BrowserContext, 실제 플랫폼·Docker/운영 격리·HTTPS/WSS 외부 접속·부하·IME 미검증.

### 최종 목표의 URL 의미 (R01 추가 설명 반영)

URL은 등록 대상 플랫폼 또는 등록 경로의 지정 수단이다. URL 자체가 새로운 범용 웹 에이전트 구축 요구는 아니다. 등록 가능 여부(지원 경로, 필요한 정보, 인증, 사용자 승인, 운영사 허용, 실행/완료 증거)를 확인한다. 플랫폼별 어댑터, 공통 실행기, 동적 분석 등은 구현 선택지이며, 미지원 신규 사이트의 무설정 자동 적응이나 임의 인터넷 URL의 성공은 필수 수용 조건이 아니다. 최종 지원 플랫폼 목록과 확장 방식은 이후 설계에서 구체화한다.

핵심 흐름: 사용자 URL 지정 → 등록 대상 플랫폼/경로 확인 → 필요한 정보 및 인증 충족 → 실행 승인 → 최초 등록 → 결과 확인.
