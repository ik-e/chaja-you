# LR 논리 설계 V3 — 오류 시에만 중단

R01 2026-11-24 피드백: “중단 요청은 없어 중단은 오류 상황에서만 되도록 할거고 멱등성은 키 관리가 기본이고 실제 실행 환경은 세부 사항인데”.

- 최상위 합의와 mock-only 제한 유지. 사용자는 준비·인증·승인·실행 요청·결과 조회를 한다. 작업 수락 후 사용자 중단/취소/변경/재개 기능 없음. 실제 권한·인증 상실을 무시하는 것은 아님: 안전상 시스템 오류로 중단.
- lifecycle: 수락 전 none → active → done, 또는 오류로 active → stopping → stopped. 확정 실패/부분 효과/미확인/목표 관측은 결과 정보. 중단 종료 뒤 신규 mutation 없음. 오류 발생 후 사용자 확인·명시 재개 루프를 기본 범위에서 제외한다. 정상 검증/관측은 active의 일부.
- 멱등성은 동일 요청 키/내용의 결과 재사용, 키 충돌 거부, 안정적인 대상/동작 식별 및 불명 효과의 중복 실행 금지라는 논리 계약으로 충분. 구체적 키/저장/동시성/실제 효과 검증은 하위 설계.
- 실제 원격 브라우저 기술·실행 환경·격리 구현·DB/API/패키지 및 부하 검증은 하위 설계/구현 검증 대상. 권한/격리/사실·승인 범위 보존 제약은 계속 상위 의무.

검증: 전이 31개, 복합 상태 62개, 간선 203개, 선정 불변식 위반 0, 미사용 전이 0, 도달 가능한 결과 경로 없는 상태 0, 결함 주입 6/6. 실제 제품/키 구현/운영 실행은 not_run. 모든 상태에서 반드시 실제로 진행한다는 시간적 보증도 아님.
