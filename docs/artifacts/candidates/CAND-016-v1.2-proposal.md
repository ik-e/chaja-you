# 시험장 부정행위 위험 탐지 및 감독 지원 시스템
## 기획안 V1.2 — 선행 서비스 재검증을 반영한 문제·차별성·실험 게이트 개정

- 개정일: 2026-11-16
- 프로젝트 맥락: 2026-11-10 ~ 2027-01-04, 5인·약 8주
- 문서 상태: **R01 독립 주제 후보 / 멘토 검토안**. 팀의 공식 주제 채택, 기관 승인, 현장 도입, 성능 실증이 아니다.
- **보존:** [V1.0 동결 원문](CAND-016-v1.0-snapshot.md) · [V1.1 원문](CAND-016-v1.1-proposal.md)
- **근거:** [2026-11-16 기존 서비스·잔여 문제 검증 기록](CAND-016-evidence-review-2026-11-16.md)
- 변경 의도: 기존에 구현·운영 중인 기능을 독자적인 신규성으로 주장하지 않고, **대면시험에서 실제로 남는 사용자 손실과 기존 대안 대비 개선 효과**에 집중한다.

## 1. 타깃 사용자는 이미 결정했다

| 역할 | 대상 | 실제 책임 |
|---|---|---|
| **도입·승인 주체** | **대면시험 운영기관** | 시험별 규정, 장비·데이터·설치·인력 배치·예산·기록 정책 승인 |
| **핵심 실사용자** | **현장 시험감독관** | 응시자 관찰, 규정에 따른 확인·보류·전담요원 연락, 사실 기록 |
| 협업 사용자 | 판별 전담요원 / 시험 운영본부 | 근거 검토, 협의·이관, 사후 사실 확인 |
| 보호 대상 | 수험생 | 무고한 응시자 지목·시험 방해·무허가 데이터 수집 방지 |

다른 유형의 사용자로 타깃을 다시 선정하지 않는다. 자동 판정·제재가 아닌 **감독관의 안전한 업무 지원**을 목표로 한다.

## 2. 한 문장 문제 정의와 해결 가설

**문제 정의(검증 중):** 대면시험 감독관은 스마트안경 등 미허가 전자기기가 의심될 때 제한된 관측·시험별 규정·확인 가능 시점 사이에서 적절한 확인·보류·이관을 결정하고 사실관계를 남겨야 한다. **발견 한계는 실제로 관측되지만**, 기존 지침·전담인력·검사·관제·보고 시스템을 사용한 이후에도 **부적절 개입, 정보 누락, 반복 보고/사후 재작성의 추가 부담이 얼마나 남는지는 아직 측정되지 않았다.**

**제품 가설:** 관측 사실·자동 추정·미확인 사항·규정·검토자의 조치 이력을 분리한 사건 처리 흐름이, **같은 정보를 가진 공식 지침+비AI 체크리스트**보다 불필요한 확인과 후속 인계·재구성 부담을 줄이되, 필요한 확인 누락과 총업무시간을 악화시키지 않을 수 있다.

**의도적 제한:** '스마트안경을 검출하면 부정행위를 막는다', '보고서 자동화만으로 차별화된다', '한국 시험장에는 이런 통합 서비스가 없다'는 주장을 하지 않는다.

## 3. 상황 기반 페인포인트: 확인된 것과 가설인 것을 분리

| 상황 ID | 실제 상황 | 관측된 근거 / 이미 있는 대안 | 잔여 부담 가설 | 검증 우선순위 |
|---|---|---|---|---|
| **S1 / P1 발견** | 시험 중 안경 교체·조작이나 무선 경고, 또는 아무 신호가 없는 경우 | 공식 수능·국가자격시험의 장비 대응 및 전담 인력, 스마트안경 검사·BLE·영상 탐지 서비스 존재. RF는 무송신·기종 미지원·소유자 불특정 문제 | 정상 안경에 대한 오인과 실제 금지기기 미발견을 함께 줄일 방법이 부족할 수 있음 | **높음: 실기기/모의 탐지 한계 측정** |
| **S2 / P2 판단** | 의심은 있으나 수험생에게 즉시 개입하기 곤란하거나 사실 확인이 부족 | 교육부는 감독관→전담인력→상황실 판단 흐름과 위반유형 구분 제시. ProctorU도 사람 검토·사건 등급 관리 구현 | 상황별 관측 근거와 규정 버전·확인 시점 연결에서 잘못된 개입·이관이 생길 수 있음 | **높음: 감독관 시나리오 조사** |
| **S3 / P3 인계** | 발견과 적법한 확인 시점 사이에 여러 감독 업무가 병행 | 구두 보고·조서·체크리스트가 존재하고 상용 원격 플랫폼은 시간순 로그 구현 | 관측 사실·추정이 섞이거나 전달 시 재질의가 생길 수 있음 | 중간: 인계 지연·재질의 유무 실측 |
| **S4 / P3 사후** | 의심이 해소되거나 이의제기 때 경위 재구성 | 기존 사건 보고서·영상 연결 솔루션 존재. 일부 대면 지필시험 교실에는 CCTV가 없어 사후 영상 조회 제한이 공식 보고됨 | 영상 없이 기록 가능한 범위에서 사실 누락·재작성 시간이 발생할 수 있음 | 중간: 재구성 정확도·소요시간 측정 |

**근거 추적:** [E01~E13 증거 원장](CAND-016-evidence-review-2026-11-16.md). S1 기술의 존재/한계는 확인, S2~S4의 **개선 가능성은 검증 전 가설**이다. CCTV가 없으면 기존에 촬영되지 않은 사건을 시스템이 영상으로 복구할 수 없다.

## 4. 기존 솔루션이 실제로 커버하는 영역

| 비교군 | 실제 제공·설명된 기능 | 본 기획에서 철회해야 할 주장 | 아직 답이 없는 질문 |
|---|---|---|---|
| **Monito, SmarterProctoring** (온라인) | 스마트안경/웨어러블 확인·탐지, 영상 이상행동 플래그, AI/사람 검토와 리포트 | '안경 탐지+AI 경고는 새롭다' | 종이시험·대규모 교실·현장 규정 적용에서도 동일하게 동작하는가? |
| **ProctorU** (온라인/사건관리) | 사건 유형·시간순 이벤트·감독 조치·채팅·출력 보고서 | '사건 카드/타임라인/PDF가 차별점' | 교실 영상/채팅이 없는 대면시험에서 인수인계 품질을 개선할 수 있는가? |
| **Innovatiview GuardView/CamView** (대면) | 반입 검사, HHMD, 다중 시험장 CCTV, AI 경보·관제·영상 근거 | '대면시험 통합 대안이 없다' | 대상 기관이 설치·예산·정보 수집을 허용하는가? 한국 시험별 판단에 맞는가? |
| **VigIA, Exam-Proctor-System, ExamShield** (공급사 설명/공개 구현) | 의심 행동·센서 관측·영상/스크린샷 저장·보고서 기능 | '카메라+BLE/Wi-Fi+로그 조합은 구현되지 않았다' | 주장된 성능이 어떤 조건에서 독립 검증됐는가? |
| **ExamGuard, ZuckOff** (점검/탐지) | BLE 신호 단서, 광학 실물 검사, 기종 규칙, 로그 내보내기 | '신호 탐지/실물 검사/로그만으로 신규성' | 미탐·오탐·무송신·소유자 귀속 한계를 어떻게 관리하는가? |
| **교육부·한국산업인력공단 현행 운영** | 위반 유형과 담당자 판단 체계·교육·검사·전담 인력 | '기존에 절차나 감독관 지원이 없다' | 실제 현장 오류/이관 지연/사후 업무시간이 남는가? |

**판정:** F1~F3 각각과 결합은 선행 대안이 존재한다. 차별성은 **구현 조합이 아닌, 특정 시험 운영환경에서 검증된 추가 사용자 가치**가 있어야 인정한다. 상용 제품의 기능 소개는 독립 정확도/운영 효과를 입증하지 않는다.

## 5. 제안 솔루션의 차별화 위치

### F1. 위험 징후 발견·선별 — 발견 기능 자체는 선행, 증분 성능은 조건부
- **기본:** 감독관 수동 관측과 승인된 이벤트의 출처·시각·수집 상태 구분, 중복/배경 경고 분류, 보류 가능한 불확실성 표시.
- **금지:** BLE/RSSI만으로 특정 학생·좌석·기종·촬영/부정행위를 확정.
- **추가 센서 채택 조건:** 통제 실험에서 필요한 확인 누락을 늘리지 않으면서 유효 경고와 처리 시간에 개선이 있는 경우만 채택.

### F2. 근거 중심 판단·대응 지원 — 우선 검증 대상
- 관측 사실 / 시스템 추정 / 미확인 / 적용 시험 규정의 버전과 출처 / 담당자 확인·보류·이관을 별도 필드로 관리.
- 감독관에게 시험 도중 금지된 PC/휴대폰 조작을 요구하지 않는 흐름. 상황을 전담요원에게 전달하는 권한·수단은 운영기관 승인 전 **모의 절차**만 사용.
- **비교 기준:** 같은 규정과 관측 자료를 제공하는 비AI 체크리스트. 규정 문구를 AI가 새로 해석해 제재를 자동 결정하지 않음.

### F3. 사건 기록·사후 재구성 — 일반 로그 기능은 선행, 정보 품질 개선은 가설
- 생성/수정/확인/이관/조치 시간, 기록 출처, 미확인 항목을 변형 이력과 함께 보존.
- 영상이 없는 시험실에서도 관측한 사실만 남기며, 사건 발생 시각이나 동작을 AI가 허구로 채우지 않음.
- **비교 기준:** 기존 표준 보고양식, 체크리스트, 상용 시스템의 사건 타임라인 설계. 전체 기록 작성시간과 재질의가 늘면 기능을 축소.

## 6. 대표 시험 운영 흐름(기관 승인 전에는 모의 실행)

1. **시험 전** — 기관이 해당 시험의 공식 규정 버전·장비·관측 허용 범위·확인 시점·담당 권한을 결정한다.
2. **시험 중** — 감독관은 현행 육안 감독을 지속한다. 허가된 데이터만 사전 설정된 방식으로 수집한다.
3. **징후 선별** — 전담요원/운영 담당자가 관측 사실과 배경·중복·불확실한 신호를 구분한다. 외부/복도 신호는 수험생에 귀속하지 않는다.
4. **판단** — 해당 시험 규정에서 허용하는 시점에 확인·보류·이관을 결정한다. 불충분한 근거는 '미확인'으로 유지한다.
5. **인계** — 원본 관측·추정·검토자·규정 및 시각을 분리해 승인된 경로로 전달한다.
6. **시험 종료/사후** — 실물 확인 결과와 후속 조치·담당자를 기록하고 재구성 가능한 범위만 요약한다.

**범위 경계:** 수능 규정의 착용·사용·소지·확인 불응 구분은 수능에만 적용한다. 임의로 모든 대면시험 규정으로 확장하지 않는다.

## 7. 8주 MVP: 가치 입증에 필요한 최소 기능

| 단계 | 필수/조건부 | 기능 | 이유 |
|---|---|---|---|
| **P0** | 필수 | 한 시험 유형에 대한 공식 규정·시나리오, 정답 있는 모의 사건 12~20개, 동일 정보 대조군 | 문제 정의와 기준선부터 검증 |
| **P0** | 필수 | 사건 카드: 출처·시각·관측 사실/추정/미확인·규정 버전 | 기술이 판단을 돕는지 검증 |
| **P0** | 필수 | 확인/보류/이관 상태·담당자, 타임라인, 규정에 맞는 정형 보고 | F2/F3 비교 가능한 구현 |
| **P0** | 필수 | A/B/C 평가, 오류·시간·기록 품질 측정, 실패 사례 기록 | 기능 존재가 아닌 사용자 가치 평가 |
| **P1** | 조건부 | **한 개** 검증된 BLE 또는 Wi-Fi 입력 경로와 C/D 비교 | F1의 추가 관측 가치가 확인될 때만 |
| **P2** | 제외 | 학생/좌석 자동 식별, 모든 스마트안경 탐지 보장, 대규모 CCTV/모든 시험 규정 범용화, SDR/정밀 RF 측위, 실제 시험장 무허가 도입 | 현장 타당성·법규·일정 근거 부족 |

**구현 원칙:** 오픈소스/공개 기술을 참고해 재사용하되 라이선스를 확인한다. 개발의 독자성보다 **기존 기술의 효과 검증 및 사용자 업무 통합**을 우선한다. 특허 검색 결과는 제품 기능의 부재/개발 금지를 뜻하지 않는다.

## 8. 가설 검증: 대조군과 측정

| 실험군 | 제공 자료 | 구분하려는 효과 |
|---|---|---|
| **A** | 해당 시험 공식 지침 + 현행 조서/보고양식 | 현재 절차의 기본 성과 |
| **B** | A + 비용 적은 비AI 체크리스트 | 새 시스템 없이 가능한 개선 |
| **C** | **B와 같은 양과 질의 관측 정보** + 사건 카드/상태 전환/기록 | F2/F3 소프트웨어 자체의 증분 효과 |
| **D** | C + **실측으로 확인된** 단일 센서 이벤트(확보 시) | F1 관측 추가의 증분 효과 |

### 모의 사건 준비
- 정상 안경/일반 조작, 의심 기기 실제 착용, 주변인·복도 신호, 기기 무송신, 승인된 확인 시점 전후, 위반 유형별 규정 차이, 보고 내용 분실/중복, 이의제기 재구성을 포함한다.
- 사건별로 **실제 관측 정답**, **기기/상태 정답(있는 경우)**, **규정상 올바른 조치**, **알 수 없는 항목**을 분리한다.
- 12~20개는 탐색적 PoC용이며 실제 시험장의 오류율·소송 감소·전체 사용자 집단 일반화를 주장하지 않는다. 비교 참여자가 동일 사례를 반복하는 경우 순서·학습 효과를 고려한다.

### 사전등록할 평가 항목
- **안전/정확:** 필요한 확인 누락, 부적절 개입, 올바른 확인·보류·이관, 기록에서 사실과 추정의 혼동 비율.
- **업무:** 최초 조치까지 시간, 입력 시간, 재질의 횟수, 사후 경위 재구성 정확도·시간, **전체 업무시간(관찰 후 처리+입력+이관+사후)**.
- **센서(조건부):** 소유·동의 기기 실측 검출률/미탐, 시험실 시간당 오경보, 실내/복도 구분 실패, 지연/수신 누락.
- 성공 임계값과 평가자·정답 작성자는 **기준선 탐색 후 본 실험 전에 고정**한다. 데이터가 부족하면 '미확인'이지 '효과 입증'이 아니다.

### 중단·피벗 게이트
1. **현장 검증 게이트:** 인터뷰·기관 자료에서 실제 불필요 확인/인계·재구성 손실이 확인되지 않으면 P2/P3 가치 주장 중단.
2. **B→C 게이트:** B 대비 부적절 개입 **또는** 재구성 시간 개선을 보이고, 필요한 확인 누락 및 총업무시간이 악화되지 않아야 확대 논의. 그렇지 않으면 C 축소/대체·주제 재검토.
3. **C→D 게이트:** 추가 센서의 유효 경고/업무 가치가 없거나 권한/실기기 확보가 불가능하면 D 제외.
4. **도입 게이트:** 법규·시험 규정·개인정보·촬영·무선 수집·기관 승인 조건을 충족하지 못하면 실제 시험장 도입 불가.

## 9. 리스크와 비약 방지

- **거짓 양성/수험생 피해:** 모든 경고는 검토 대상이지 부정행위 판정 아님. 검토자/권한과 정확한 관찰 출처를 남긴다.
- **거짓 음성:** 무송신·배터리·개인기기·카메라 사각지대 등 탐지되지 않은 기기가 있을 수 있다. '탐지되지 않음=없음' 금지.
- **과도한 수집:** 실제 시험에서 승인되지 않은 녹화·무선 추적·실명/좌석 연결을 하지 않는다. 모의 사건은 합성 데이터·소유/동의 기기만 활용.
- **규정 혼동:** 국가·시험·연도별 규정을 혼용하지 않는다. 공식 문서 ID/확인 날짜/시행일을 사건별로 명시.
- **기존 솔루션 과소평가:** 상용 제품의 일부 기능이 공개 자료에 없다는 이유로 부재를 주장하지 않는다. 실제 체험/도입 조건 미확인은 그대로 남긴다.
- **개발 과잉:** 규칙·템플릿·체크리스트보다 나은 효과가 없으면 LLM/ML과 추가 하드웨어 채택 금지.

## 11. 멘토 예상 질문과 답변

**Q. 이미 Monito·ProctorU·Innovatiview가 비슷하게 하지 않나요?**
A. 맞다. 온라인 스마트안경 확인·사건 리포트, 대면 반입검사·관제·증거 관리는 이미 제공된다. 따라서 **동일 기능 재구현 자체는 가치가 없다.** 특정 지필 대면시험의 감독관에게 남는 적정 개입·정보 전달 부담이 존재하는지, 비AI 체크리스트보다 유효하게 줄일 수 있는지를 먼저 검증한다.

**Q. 현장에 CCTV가 없으면 어떤 근거를 보관하나요?**
A. 없는 영상을 만들지 않는다. 관찰자·관찰 시점·직접 본 사실·확인되지 않은 사항·조치만을 분리 기록한다. 이것조차 기존 양식과 차이가 없으면 기능을 채택하지 않는다.

**Q. AI가 꼭 필요한가요?**
A. 아직 아니다. 기준선은 규칙과 정형 보고로 만든다. AI/센서는 검증한 증분 효과가 있을 때만 채택한다.

**Q. 하드웨어를 반드시 만들 건가요?**
A. 아니다. 실기기·허가·오경보 검증이 통과하지 않으면 F2/F3 모의 비교만 수행하거나 후보를 중단한다.

**Q. 구체적으로 무엇을 증명하면 기획이 설득되나요?**
A. '기존 안내·체크리스트보다 적절한 조치를 더 많이 선택하고 불필요 개입·기록/인계/사후 시간을 줄였으며, 필요 확인 누락·총업무시간이 악화되지 않았다'는 평가 결과와 실제 운영기관의 승인 가능성이다. 현재 그런 결과는 없다.
