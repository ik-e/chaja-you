# 찾아you — User Story V2.1 (사용자 부담 최소화 후보)

- **정상적인 상황 Golden Path**
- **비정상적인 상황 : <u>에러 → 예외처리</u>** — 정상 흐름 확정 후 각 행동 아래 작성

> 목적: 개인 음악 레슨 강사의 반복 준비(P01)·반복 실행(P02)·분산 상태 확인(P03)을 줄이는 것이 우선이다. V2.0을 보존하고, 서비스가 대신 처리할 수 있는 행동과 사용자가 실제 수행해야 할 행동을 구분해 대안을 제안한다. **V2.1은 R01/팀 검토 후보이지 채택·구현 지시가 아니다.** 버튼·화면 이름은 논리적 조작점이다. 계정 연결·세션 재사용, 통합 검토·일괄 승인 UX, 임시 준비값 보존 방식은 추가 결정 사항이다. 기존 7개 플랫폼·44개 업무·5개 제외·14개 오류 이월 및 개별 범위 미승인 상태를 유지한다. 현재 외부 접근·인증 연결·입력·첨부·제출·읽기·지속 접근은 모두 mock-only. 운영사/정책·법률·기술·사용자 권한 검토 및 해당 단계의 허용 확인 전에 실제 업무를 수행하지 않는다. 개인정보 권리 및 비밀번호·인증코드 미수집/미저장 원칙, 사용자 직접 본인인증·약관 동의·결제/정산, 외부 효과 원복 미보장 유지.
>
> 멘토 참고 자료의 이용 상황 → 번호 페이지 → 행동 → case 구조 사용. `Nxx.yy`·`Pxx-업무.yy` 태그 및 연속 범위(`Nxx.yy~zz`)는 V2.0의 기존 단계 연결이다. 여러 태그는 기존 행동을 한 조작/표시로 통합했거나 서비스 내부 책임으로 유지했다는 뜻이다. 새로운 조작 후보는 '(제안)'으로 표시한다. 기존 ID를 삭제/재발급하지 않는다. ## 가장 자주 이용하는 경로

- **처음:** 본인 식별 → 레슨 자료 제공 → AI 추출·확인/보완·저장 → 플랫폼/업무 선택 → 필요한 계정 연결 → 최종 내용·범위 검토 및 승인 → 실행 요청 → 통합 결과.
- **재사용:** 저장된 레슨 선택 → 플랫폼/업무 선택 → 기존 설정 적용 및 차이·변경 사항 확인 → (유효하고 허용된 연결이 있으면 인증 생략) → 현재 업무 승인·실행 → 통합 결과.
- **수정:** 통합 관리에서 등록물/대상 선택 → 변경할 항목만 편집 → 현재 외부 값과 변경 범위 비교 → 현재 승인·실행 → 결과.
- **상태 확인:** 통합 관리 → 저장된 마지막 상태 확인 → 필요한 대상만 최신 조회 요청 → (필요시 인증) → 최신 관측 및 대응 확인.


## 📌 유저스토리1 : 서비스를 처음 이용하거나 다시 접속하는 경우


1. **모든 페이지 (공통 이용 case)**
   - 강사는 홈 또는 메뉴에서 **레슨 관리·계정 연결·작업 목록·통합 결과** 중 필요한 화면으로 이동한다. (제안: 작업 대상과 저장 상태에 맞는 메뉴 제공.)
   - **case1. 다른 화면으로 이동하거나 다시 접속하는 경우**
     - 강사는 기존 작업 목록에서 자신의 저장된 준비 상태와 진행/보류 중인 업무를 확인한다. 이동만으로 새 외부 효과가 발생하거나 이전 실행이 자동 재개되지 않는다. (화면 이탈과 진행 중 실행의 세부 정책은 결정 필요.) `N02.04~05`
   - **case2. 이용을 종료하는 경우**
     - 강사는 **로그아웃** 동작을 누른다. 진행 업무가 있으면 종료·보류 및 기존 효과에 관한 안내를 확인한다. 새 외부 쓰기를 차단하고 서비스 세션을 종료한다. 업무용 세션과 별도 허용된 장기 연결은 서로 다른 종료 정책을 적용한다. 장기 연결 유지 여부는 미결정이다. `N24.01~04`

2. **메인페이지 및 로그인뷰**
   - 강사는 서비스의 이용 목적, 지원 범위와 개인정보 처리 안내를 확인한다. `N01.01~02`
   - **case1. 처음 이용하는 강사**
     - 강사는 인증 방법을 선택하고 직접 인증한다. 필요한 가입 정보와 안내를 확인하여 등록을 요청한다. 이미 연결된 본인 계정이면 중복 생성하지 않고 로그인하며, 처음이면 검증된 본인 식별 관계를 만든다. 가입 방법과 별도 화면 여부는 미확정이다. `N01.03~06`
     - 강사는 원본 레슨 관리 화면에서 비어 있는 목록과 새 레슨 만들기 동작을 확인한다. `N01.07`
   - **case2. 기존 회원**
     - 강사는 로그인이 필요한 경우 로그인하고, 이미 유효하게 인증된 상태라면 바로 본인 소유 레슨과 연결 업무를 조회한다. `N02.01~03`
   - **case3. 재인증·계정 복구가 필요한 경우 (지원 후보)**
     - 강사는 기존 인증으로 다시 로그인하거나 채택된 인증 제공자의 복구 경로를 이용한다. 동일 본인 확인 이후에만 작업 목록이 제공된다. `N08.01~04`

3. **계정 및 개인정보 안내뷰 (지원 후보)**
   - 강사는 서비스 계정과 외부 연결 계정을 구분해 확인하고, 보관·처리 목적·기간 및 권리 행사 경로를 확인한다. 열람·정정·삭제 등의 요청과 결과 확인은 채택된 운영 절차에 따른다. 독립 계정 삭제 UI는 미채택이다. `N07.01~04`

## 📌 유저스토리2 : 레슨 자료를 처음 제공하거나 저장한 레슨을 이용하는 경우


1. **레슨 목록뷰**
   - 강사는 본인 레슨 목록의 제목, 저장 버전, 연결 상태를 확인한다. 새 원본 만들기 또는 기존 레슨을 선택한다. `N03.01~02`
   - **case1. 저장된 레슨이 있는 경우**
     - 강사는 기존 레슨을 클릭한다. 제목·소개·레슨 종류·대상·제공 방식·장소·시간·회차·가격·첨부·연결 등록물을 한 화면에서 확인할 수 있다. 재사용 시 원본을 다시 입력하지 않는다. `N03.03~07`
     - *그대로 이용하려면 유저스토리4로, 원본 변경·삭제는 아래 원본 관리로 이동한다.*
   - **case2. 새 레슨을 등록하는 경우**
     - 강사는 새 레슨 작성 화면으로 이동한다. 이미 보유한 소개글 등 원문을 제공한다. `N04.01~02`
     - 강사는 필요한 이미지·자료를 선택해 첨부한다. 파일 목록, 규격, 사용 권리와 공개 범위를 확인하며 필요 없는 첨부는 제거한다. 첨부는 선택 사항이다. `N04.11~13`
     - 강사는 제공한 자료로 **정보 준비** 동작을 요청한다. 서비스는 제공된 원문·자료에서 사실을 추출하고 출처·확인 필요 항목을 제시한다. (제안: 사용자에게 모든 구조화 필드를 먼저 직접 입력하게 하지 않는다.) `N04.14`

2. **원본 정보 확인뷰**
   - 강사는 추출 결과를 한 화면에서 확인한다. 제목·소개, 레슨 분류·대상, 방식·장소, 수업시간·회차·가격 및 단위와 원문 근거가 표시된다. 사실이 맞으면 항목별 확인 버튼을 누를 필요는 없다. `N04.15~18`
   - **case1. 추출 결과에 수정·보완이 필요한 경우**
     - 강사는 수정이 필요한 항목을 선택한다. 제목·종류·대상·제공 방식·장소·회당 시간·회차·가격·통화·가격 기준(회당/시간당/총액) 중 부족하거나 잘못된 사실만 입력한다. 사용자가 직접 작성하고 싶은 경우 같은 편집 영역을 이용할 수 있다(선택 방식 후보). `N04.03~10` `N04.19`
   - **case2. 제공 사실과 추출 정보가 일치하는 경우**
     - *추가 입력을 요구하지 않고 원본 저장·작업 준비로 진행한다.*
   - 강사는 **원본 저장 및 계속** 동작을 누른다. 검토한 원본 사실·첨부가 본인 소유 원본 및 버전으로 저장되며, 저장 결과·식별 정보·시각을 확인한다. (제안: 저장과 다음 화면 이동을 통합하되 저장 성공을 확인해야 이동한다.) `N04.20~21`

3. **저장 원본 관리뷰**
   - **case1. 원본 내용을 수정하는 경우**
     - 강사는 수정 동작을 선택하고 변경하려는 사실 및 첨부만 편집한다. 추가 파일의 권리와 제거 결과를 확인한다. `N05.01~05`
     - 강사는 변경 전후와 미실행 작업에 미치는 영향을 확인하고 저장 또는 취소를 선택한다. 저장하면 새 버전이 생성되고 원본과 기존 외부 등록물은 자동으로 동기화되지 않는다. `N05.06~08`
   - **case2. 원본 또는 관리 연결을 삭제하려는 경우**
     - 강사는 내부 원본 삭제 동작을 선택하고 연결 등록물·진행 업무·보존 기록·외부 효과에 미치는 영향을 확인한다. 확인 시 허용된 내부 삭제만 진행하고 취소 시 유지한다. 결과와 남은 원본 목록을 확인한다. `N06.01~04`
     - 강사는 필요할 때 별도로 외부 등록물 관리 연결을 선택하여 해제를 요청하고 결과를 확인한다. 내부 연결만 해제하며 외부 게시물은 삭제하지 않는다. `N06.05~07`

## 📌 유저스토리3 : 외부 플랫폼 계정을 연결하거나 연결된 계정을 재사용하는 경우 (인증 재사용 정책 제안)

인증 유지 승인과 외부 업무 실행 승인은 독립이다. 장기 연결을 기본 정책으로 확정하지 않는다. 공식 OAuth/API가 해당 레슨 업무 권한을 실제 위임할 때 우선 검토하고, 미제공 시 허용된 사용자별 원격 브라우저 로그인 상태 보관/재사용을 검토한다. 크몽·탈잉·숨고 등의 공식 위임 API나 지속 세션 허용은 미확인. OAuth 로그인 자체는 해당 업무 위임을 의미하지 않는다. 비밀번호·인증코드를 수집하거나 복호화해 보관하는 후보는 추가하지 않는다.


1. **계정 연결 관리뷰 (제안: 업무별 인증을 분리)**
   - 강사는 플랫폼별 연결된 본인 계정·확인 시각·인증 유효 상태·허용된 접근 범위·보유 만료 시점 및 연결 해제 동작을 확인한다. 계정 연결은 신규 업무 중 필요할 때도 시작할 수 있다. 표시 정보만으로 실제 인증이 현재 유효하다고 단정하지 않는다. (제안)
   - **case1. 아직 연결되지 않은 계정 또는 새 계정으로 작업하려는 경우**
     - 강사는 외부 인증 요청과 필요한 범위·위험·세션 종료/유지 안내를 확인하고 인증 화면을 연다. 해당 접근 단계의 허용을 먼저 확인한다. `N12.01`
     - 강사는 허용된 인증 화면에서 외부 플랫폼에 직접 로그인하고 필요한 본인인증을 수행한다. 외부 가입·약관 동의·전문가 인증·정산 등은 직접 처리하며 입력한 비밀번호·인증코드는 서비스 데이터나 AI에 전달하지 않는다. `N12.02~03`
     - 강사는 인증 결과 및 실제 연결할 계정을 확인한다. 계정 정보·접근 권한이 검증되어야 선택할 수 있다. `N12.05`
     - 강사는 해당 플랫폼에서 장기 연결이 별도 허용·채택된 경우 인증 상태 유지의 목적·기간·위험·철회 방법을 확인하고 유지 여부를 선택한다. 거절 또는 미확인 시 업무 한정 인증만 사용한다. (제안)
   - **case2. 기존 연결을 사용하는 경우**
     - 강사는 연결된 플랫폼 계정을 선택한다. 별도 채택·허용된 저장 인증 상태가 현재 유효하고 범위가 충분하면 직접 재로그인을 요구하지 않는다. 서비스는 업무에 필요한 단계별 허용·계정 일치·유효 기간·철회·현재 권한을 다시 확인한다. (제안)
   - **case3. 인증 만료·철회·필요 권한 변경이 확인된 경우**
     - 강사는 해당 플랫폼에 대해서만 재인증 동작을 선택하여 직접 인증한다. 이전 계정·대상·승인과의 일치를 다시 검증하며 다른 정상 연결은 다시 로그인하지 않는다. `N12.04`
   - **case4. 연결을 하지 않거나 해제하려는 경우**
     - 강사는 인증 화면의 취소 또는 계정 연결 해제를 선택한다. 인증 연결을 종료하고 해당 인증 상태에 대한 새 접근을 차단·폐기한다. 외부 계정·기존 등록물 및 관련 업무 기록을 자동 삭제하지 않는다. (장기 보관 해제는 제안이며 외부 토큰 철회 가능 여부도 확인해야 한다.) `N19.08~09`

## 📌 유저스토리4 : 저장된 레슨으로 여러 플랫폼의 작업을 한 번에 준비하는 경우

## 📌 유저스토리5 : 준비된 내용을 한 번에 검토하고 승인하여 업무를 실행하는 경우

## 📌 유저스토리6 : 등록 결과와 상태를 통합 확인하고 후속 업무를 선택하는 경우

   - 강사는 상세에서 완료 근거·관측 경로·확인 수준·검증된 외부 링크 또는 업무 이력을 선택하여 확인할 수 있다. 모든 상세를 필수로 열 필요는 없다. `N17.03~05`

   - **case3. 다시 시작하는 경우**
     - 강사는 현재 조건에서 새로운 모니터링 설정과 승인을 요청한다. `N23.10`
