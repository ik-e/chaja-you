## 검토 방법

- 주체(S)는 모두 레슨 강사. 표의 대상(O)·행동(V)은 정본 그대로이며 카테고리와 하위 묶음은 검토 편의상 재배치했다. 목록은 고정된 UI나 실행 순서가 아니다.
- 기본 = 제품 기본 후보, 조건부 = 별도 채택 전 미제공, 제외 = 독립 제품 기능 미채택 추천. 자동 대행 허용을 뜻하지 않는다.
- 팀원은 문서 전체를 확인하고 담당 영역을 중점 검토한다. 의견에는 ID(또는 카테고리/플랫폼 업무 ID), 유형(누락/중복/표현/근거/범위 충돌/추가), 내용, 근거, 변경 제안을 적는다. 여러 사람이 정본을 동시에 수정하지 않는다. R01이 검토 의견을 통합하고 판단한다.

## 정상·오류·정책 검토 기준

- 정상/오류/예외/반복은 [15개 이용 시나리오·전체 분기](USER-STORIES-REVIEW.md)와 [정본](user-stories.json)의 해당 ID 기준으로 함께 확인한다. 28개 기존 오류, 9개 반복, 16개 정책 검증 기대 상황은 별도 원본에 유지한다.
- [정책 위험 검토](POLICY-RISK-REVIEW.md) 및 [위험 정본](policy-risk-register.json): 사용자 승인·플랫폼 허용·법적 적합성·실제 외부 효과를 분리하고 단계별 정책 조건 확인. 사용자 최종 제출은 앞선 자동 접근/입력을 정당화하지 않는다. 현재 외부 접근/실행 차단 유지.
- 등록 효과, 심사 접수/승인, 공개·모집 가능, 독립 관측, 사용자 보고 및 내부 준비 결과는 서로 구분한다. 이미 성공했거나 효과 미확인인 외부 업무는 자동 재실행하지 않는다.

## 검토 완료 기준

- 각 팀원이 중점 담당 영역의 SVO, 지원 범위, 정상/오류·예외 경로 및 근거를 대조한다.
- 누락·중복·충돌 등 의견별 조치 및 판단 근거를 R01이 통합한다.
- 정본과 최신 팀원 조사 간 차이를 반영하거나 보류 근거를 명시한 뒤 R01이 최종 범위를 승인한다. 체크/열람만으로 승인하지 않는다.
