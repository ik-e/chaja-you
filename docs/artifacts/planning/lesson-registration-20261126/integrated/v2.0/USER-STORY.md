# 찾아you — User Story V2.0

- **정상적인 상황 Golden Path**
- **비정상적인 상황 : <u>에러 → 예외처리</u>** (정상 흐름 검토 후 각 행동 바로 아래에 추가)

> [멘토님 참고 User Story](https://app.notion.com/p/42449106016080018a4bdcadc298c2f2)와 같은 이용 상황 → 번호가 붙은 페이지 → 행동 → case 구조. 현재는 정상 흐름만 작성한 팀 검토안이다. **버튼·페이지 명칭은 기능을 설명하는 논리적 이름**이며 레이아웃, 인증 제공자 및 구현 기술은 미확정이다. 기본 후보·후순위·보류·조건부를 구분하며 최종 범위 승인은 아직 없다. 외부 플랫폼 단계는 7개 모두 설계에 포함하되 **현재 mock-only**: 외부 인증 연결·접근·읽기·입력·첨부·제출·지속 접근은 단계별 운영사 허용·정책·권한·승인·실제 효과 검증 전 제공하지 않는다. 사용자 직접 제출만으로 앞선 자동화가 허용되는 것은 아니다. 외부 계정 가입/본인인증/약관 동의/결제·정산 등은 본인이 직접 한다. 오류가 이미 기록된 이후 결과 조회·후속 선택은 정상 이용 기능이고 오류의 발생·복구는 다음 단계에서 추가한다.
>
> 행동 끝의 짧은 태그(`Nxx.yy`, `Pxx-업무.yy`)는 [공통 단계](COMMON-NORMAL-FLOWS.md), [플랫폼 단계](PLATFORM-NORMAL-FLOWS.md), [기존 행동 추적표](README.md)의 기존 ID다. 기존 V1.3과 상세 자료를 변경하지 않고 추적한다. 사용자 스토리를 읽을 때 태그를 해석할 필요는 없다.


## 📌 유저스토리1 : 회원가입을 하게 되는 경우


1. **메인페이지**
   - 강사는 **메인페이지**에 진입한다. 이용 목적, 지원 플랫폼, 로그인 여부 및 개인정보 처리 안내를 확인한다. `N01.01`
   - 강사는 **서비스 이용 안내**를 열어 원본 레슨 보관과 외부 플랫폼 작업의 차이를 확인한다. `N01.02`
   - 강사는 처음 이용하는 경우 회원가입을 선택하여 가입 화면으로 이동한다.

2. **회원가입뷰**
   - 강사는 회원가입에 사용할 **인증 방법**을 선택한다. (구체적인 인증 제공자는 미확정.) `N01.03`
   - 강사는 선택한 방법으로 인증을 진행한다. 인증 결과에 따라 처음 이용하는 강사인지 기존 회원인지 확인된다. `N01.04`
   - 강사는 회원가입에 필요한 최소 정보 및 이용약관·개인정보 처리 안내를 확인한다. 필요한 동의는 직접 선택한다. `N01.05`
   - 강사는 **가입 완료** 동작을 선택한다. 검증된 인증 주체에 본인의 서비스 계정이 연결된다. 이미 등록된 계정이면 유저스토리2의 로그인 경로로 이동한다. `N01.06`
   - **case1. 이미 등록된 인증 주체인 경우**
     - *새 계정을 만들지 않고 유저스토리2의 기존 회원 로그인으로 이동한다.*
   - **case2. 처음 등록하는 경우**
     - 강사는 가입 후 **원본 레슨 관리 화면**으로 이동하여 비어 있는 목록과 새 원본 생성 동작을 확인한다. `N01.07`
     - *원본이 없다면 유저스토리3의 새 원본 작성으로 이동한다.*

## 📌 유저스토리2 : 회원인 경우


1. **메인페이지**
   - **case1. 로그아웃 상태인 경우**
     - 강사는 메인페이지에서 **로그인 버튼**을 클릭하여 로그인 화면으로 이동한다. `N02.01`
     - 강사는 기존 계정의 인증 방법으로 로그인한다. 본인에게 연결된 서비스 계정으로만 접근한다. `N02.02`
   - **case2. 로그인 상태인 경우**
     - 강사는 본인 원본 관리 화면으로 이동한다.

2. **원본 레슨 관리 및 작업 목록**
   - 강사는 **원본 레슨 관리 화면**에 진입하여 본인 소유 원본 목록과 연결 작업 요약을 확인한다. `N02.03`
   - 강사는 작업 목록을 열어 진행 중이거나 보류한 작업, 대상 플랫폼, 마지막 확인 시각을 확인한다. 이전 외부 작업은 자동 재개되지 않는다. `N02.04`
   - 강사는 원본 관리, 작업 준비, 결과 확인 중 원하는 메뉴를 선택하여 해당 페이지로 이동한다. `N02.05`

3. **로그인뷰 — 재접속/계정 복구 (지원 기능 후보)**
   - 강사는 서비스 로그인 화면에서 기존 계정으로 재접속을 선택한다. 서비스는 채택된 인증 방식과 공식 복구 안내를 제공한다. `N08.01`
   - **case1. 기존 인증 수단을 사용할 수 있는 경우**
     - 강사는 기존 인증 주체를 사용할 수 있는 경우 재인증한다. 서비스는 동일 owner를 확인한 후에만 본인 자료를 제공한다. `N08.02`
   - **case2. 기존 인증 수단을 사용할 수 없는 경우**
     - 강사는 복구가 필요한 경우 안내된 복구 경로를 선택한다. 서비스는 확정된 인증 제공자 또는 운영 절차로 연결한다. 비밀번호·복구 수단 구현 여부는 미정이다. `N08.03`
   - 강사는 본인 식별 확인 이후 작업 목록을 다시 연다. 서비스는 본인 작업의 마지막 기록을 제공하고 외부 작업은 현재 조건을 검토하기 전 재개하지 않는다. `N08.04`

## 📌 유저스토리3 : 원본 레슨을 작성하거나 저장된 레슨을 이용하는 경우


1. **원본 레슨 목록**
   - 강사는 **원본 레슨 목록**에 진입한다. 본인이 저장한 원본 이름, 저장 버전, 연결 상태를 확인한다. 비어 있으면 새 원본 등록 동작을 확인한다. `N03.01`
   - 강사는 **새 원본 만들기**를 선택하거나 기존 원본의 이름을 클릭한다. `N03.02`
   - **case1. 새 원본을 생성하는 경우**
     - *아래 원본 작성뷰로 이동한다.*
   - **case2. 기존 원본을 이용하는 경우**
     - 강사는 선택한 원본의 상세 화면으로 이동하여 저장된 정보·첨부·외부 등록 연결을 확인한다. `N03.03`
     - 강사는 원본의 레슨 제목과 소개를 확인한다. 서비스는 저장된 내용을 변환 전 원본과 구별해 제공한다. `N03.04`
     - 강사는 레슨 제공 방식·장소·시간·횟수·가격 정보를 확인한다. 서비스는 원본의 사실과 조건·가격 단위를 표시한다. `N03.05`
     - 강사는 원본의 첨부 자료를 확인한다. 서비스는 해당 원본에 연결된 첨부와 사용 가능 범위를 제공한다. `N03.06`
     - 강사는 원본 수정, 삭제 또는 재사용 동작을 선택한다. 서비스는 N05, N06 또는 N09로 이동한다. `N03.07`
     - *수정은 유저스토리4, 삭제·관리 연결 해제는 유저스토리5, 플랫폼 작업은 유저스토리6으로 이동한다.*

2. **원본 작성뷰**
   - 강사는 **새 원본 작성 화면**에 진입한다. `N04.01`
   - 강사는 레슨 소개 원문을 입력한다. 이미 가지고 있는 소개 문구를 활용할 수 있다. `N04.02`
   - 강사는 원본 레슨을 식별할 제목을 입력한다. `N04.03`
   - 강사는 레슨 종류와 수강 대상·수준을 입력한다. `N04.04`
   - 강사는 실제 레슨 제공 방식을 선택하거나 입력한다. `N04.05`
   - 강사는 실제 레슨 장소와 공개할 수 있는 범위를 입력한다. `N04.06`
   - 강사는 1회 수업시간과 시간 단위를 입력한다. `N04.07`
   - 강사는 레슨 횟수를 입력한다. `N04.08`
   - 강사는 레슨 비용과 통화를 입력한다. `N04.09`
   - 강사는 입력한 비용이 회당·시간당·총액 중 무엇인지 선택한다. `N04.10`
   - **case1. 첨부 자료를 사용하는 경우**
     - 강사는 **파일 첨부** 동작을 눌러 사용할 이미지 또는 자료를 선택한다. 수신된 파일과 형식·크기 검증 결과를 확인한다. `N04.11`
     - 강사는 첨부 자료의 사용 권한과 외부 공개 가능 범위를 확인한다. `N04.12`
     - 강사는 첨부된 파일 목록을 확인한다.
   - **case2. 첨부를 제거하려는 경우**
     - 강사는 불필요한 파일을 선택한 뒤 **첨부 제거** 동작을 누른다. 해당 초안의 첨부 연결이 제거된 것을 확인한다. `N04.13`

3. **원본 정보 분석 및 확인뷰**
   - 강사는 **원본 정보 분석** 동작을 누른다. 서비스는 원문과 첨부에서 레슨 사실을 추출하고 출처와 불확실한 항목을 표시한다. `N04.14`
   - 강사는 추출된 제목과 소개 문구를 원문과 비교한다. `N04.15`
   - 강사는 추출된 레슨 종류 및 대상자를 확인한다. `N04.16`
   - 강사는 추출된 수업시간·회차·가격 및 단위를 확인한다. `N04.17`
   - 강사는 추출된 수업 방식과 장소, 협의 가능 여부를 확인한다. `N04.18`
   - **case1. 추출 내용 정정 또는 추가가 필요한 경우**
     - 강사는 추출 내용 중 정정할 항목을 선택하여 실제 값을 입력한다. 변경된 사실과 근거를 확인한다. `N04.19`
   - **case2. 추출 내용과 제공 사실이 일치하는 경우**
     - 강사는 그대로 저장 단계로 이동한다.

4. **원본 저장**
   - 강사는 **원본 저장** 동작을 누른다. 검토된 사실과 첨부가 본인의 원본 및 저장 버전으로 기록된다. `N04.20`
   - 강사는 저장 완료 표시와 원본 이름·식별 정보·버전·저장 시각을 확인한다. `N04.21`
   - *저장한 원본을 다시 확인하거나 플랫폼 작업을 시작한다.*

## 📌 유저스토리4 : 저장한 원본 레슨을 수정하는 경우


1. **원본 상세뷰**
   - 강사는 기존 원본 상세에서 **수정 버튼**을 누른다. 현재 저장 버전의 수정 화면으로 이동한다. `N05.01`
   - 강사는 수정할 레슨 정보 항목을 선택한다. `N05.02`
   - 강사는 선택한 항목의 값을 입력하거나 변경한다. `N05.03`
   - **case1. 첨부를 추가하는 경우**
     - 강사는 추가할 첨부 파일을 선택하고 파일별 사용 권한을 확인한다. (첨부할 자료가 있는 경우.) `N05.04`
   - **case2. 첨부를 제거하는 경우**
     - 강사는 제거할 첨부 파일을 선택하여 **제거** 동작을 누른다. (제거할 자료가 있는 경우.) `N05.05`

2. **수정 내용 확인 및 저장**
   - 강사는 변경 전후 값과 미실행 작업에 미치는 영향을 확인한다. `N05.06`
   - **case1. 변경을 저장하는 경우**
     - 강사는 **변경 저장** 동작을 누른다. 기존 원본 및 외부 게시물과 구분된 새 버전이 저장된다. `N05.07`
     - 강사는 새 원본 버전과 저장 결과를 확인한다. 영향을 받는 미실행 작업은 다시 검토할 수 있다. `N05.08`
   - **case2. 저장하지 않고 돌아가는 경우**
     - 강사는 저장을 취소하고 이전 원본을 유지한다.

## 📌 유저스토리5 : 원본을 삭제하거나 외부 등록물의 관리 연결을 해제하는 경우


1. **원본 상세뷰**
   - **case1. 서비스 내부 원본을 삭제하는 경우**
     - 강사는 원본 상세에서 **삭제 버튼**을 누른다. `N06.01`
     - 강사는 삭제 대상 원본, 연결된 등록물, 진행 중 작업, 보존 대상 기록 및 외부 게시물이 자동 삭제되지 않는다는 안내를 확인한다. `N06.02`
     - 강사는 삭제를 확인하거나 **취소**를 선택한다. 확인 시 허용된 내부 삭제만 처리되며 취소 시 원본은 유지된다. `N06.03`
     - 강사는 삭제 처리 결과와 남은 원본 목록을 확인한다. `N06.04`
   - **case2. 외부 등록물의 관리 연결만 해제하는 경우**
     - 강사는 기존 외부 등록물의 관리 연결 목록에서 해제할 플랫폼·계정·대상을 선택한다. `N06.05`
     - 강사는 연결 해제 범위와 외부 글이 삭제되지 않는다는 안내를 확인하고 **연결 해제** 동작을 누른다. `N06.06`
     - 강사는 관리 연결 해제 결과 및 남은 연결 목록을 확인한다. `N06.07`
   - *원본 삭제·연결 해제는 외부 플랫폼의 실제 게시물 삭제가 아니다.*

## 📌 유저스토리6 : 원본 레슨을 선택하여 외부 플랫폼 작업을 준비하는 경우


1. **플랫폼 및 업무 선택뷰**
   - 강사는 선택한 원본 상세에서 **작업 시작** 동작을 누른다. 작업에 사용할 원본과 저장 버전을 확인한다. `N09.01`
   - 강사는 크몽·탈잉·숨고·프람피·뮬·힙합플레이야·힙합LE의 플랫폼 목록을 확인한다. `N09.02`
   - 강사는 원하는 플랫폼의 지원 업무 안내를 열어 신규·조회·수정·갱신·상태 확인 등 실제 지원 후보와 제한을 확인한다. `N09.03`

## 📌 유저스토리7 : 외부 플랫폼에 로그인하여 작업 계정과 등록 대상을 확인하는 경우

   - *플랫폼마다 수행 가능한 업무와 실제 완료 기준이 다르므로 유저스토리14~20의 해당 case를 적용한다.*

## 📌 유저스토리9 : 업무 결과와 등록 상태를 확인하거나 보완하는 경우

   - 강사는 조회할 외부 대상을 선택하여 **상태 갱신 요청** 동작을 누른다. 필요한 인증 및 읽기 권한을 확인한다. `N17.06`
   - 서비스는 허용된 경로에서 정확한 대상의 최신 상태를 조회하여 관측 시각과 함께 기록한다. `N17.07`

   - **case1. 외부 정보가 변경된 경우**
     - 강사는 외부에서 변경된 정보가 확인된 경우 새 관측값과 원본·기존 승인본에 미치는 영향을 확인한다. `N17.09`
   - **case2. 심사 승인 후 추가 모집 준비가 필요한 경우**

4. **심사 반려 결과 및 보완뷰**
   - 이미 반려가 확인된 경우에 이용하는 흐름이다. 반려 발생 원인·예외 처리의 상세는 2차 작성 대상이다.
   - 강사는 실제 반려가 확인된 업무 상세를 연다. 서비스는 해당 객체의 반려 상태와 확인 시각을 표시한다. `N18.01`

   - 강사는 보완할 레슨 정보를 선택하여 변경한다. 서비스는 변경값을 새 입력안으로 반영하고 N10에서 재검증한다. `N18.04`

     - *유저스토리10으로 이동한다.*

5. **부분 성공·실패·미확인 결과 확인뷰**
   - 강사는 실패하거나 부분 성공한 업무 결과 화면을 연다. 서비스는 플랫폼별 성공·실패·미실행·효과 미확인을 서로 구분한다. `N20.01`
   - **case1. 일부 플랫폼만 성공한 경우**

   - **case2. 외부 효과가 미확인인 경우**
     - 강사는 확인할 수 없는 외부 효과의 상태와 안내를 확인한다. 서비스는 미확인 사유·마지막 관측·추가 확인 필요를 표시한다. `N20.03`
     - 강사는 이전 외부 효과의 확인을 요청한다. 서비스는 허용된 독립 조회를 수행해 확인된 성공, 실패/미실행 또는 계속 미확인으로 기록한다. 새 쓰기는 하지 않는다. `N20.04`
   - 강사는 가능한 후속 대응을 선택한다. 서비스는 확인, 보류, 별도 재처리 후보를 제공하고 성공·효과 미확인 작업의 재실행을 차단한다. `N20.05`

     - *미확인 상태가 지속되면 재실행하지 않는다.*

## 📌 유저스토리10 : 업무를 제외하거나 승인을 거절·철회·보류하는 경우

아래 case는 독립적인 정상 선택이다. 모든 case를 연속 수행하지 않는다.

   - **case2. 실행 범위 승인을 거절하는 경우**
     - 강사는 실행 범위 승인을 거절한다. 서비스는 실행 범위 미승인 상태를 기록하고 외부 실행을 허용하지 않는다. `N19.05`
   - **case3. 이미 승인한 내용을 철회하는 경우**

   - **case4. 이미 승인한 실행 범위를 철회하는 경우**
     - 강사는 이미 부여한 실행 범위 승인을 철회한다. 서비스는 실행 범위 승인 철회와 그 영향을 기록하고 관련 새 쓰기를 차단한다. 이미 발생한 효과는 원복하지 않는다. `N19.07`

3. **외부 인증 및 접근 관리뷰**
   - **case1. 외부 인증을 취소하는 경우**
     - 강사는 외부 플랫폼 인증의 진행 취소를 선택한다. 서비스는 해당 인증 연결을 종료하고 승인 없는 외부 접근을 차단한다. `N19.08`
   - **case2. 외부 접근 권한을 철회하는 경우**
     - 강사는 외부 접근 권한 철회 동작을 선택한다. 서비스는 해당 업무용 접근을 차단하고 세션을 폐기한다. `N19.09`

4. **작업 관리뷰**
   - **case1. 업무를 보류하는 경우**
     - 강사는 업무 보류를 선택한다. 서비스는 해당 업무의 새 실행을 차단하고 저장된 준비 상태 및 기발생 효과를 보존한다. 자동 재개하지 않는다. `N19.10`

     - 강사는 업무 중단 결과를 확인한다. 서비스는 해당 업무의 처리 상태 및 세션 폐기 여부를 확인 가능한 범위에서 표시한다. `N19.12`
   - **case3. 보류한 업무를 다시 진행하는 경우**
     - 강사는 보류된 업무의 재개를 요청한다. 서비스는 이전 효과·현재 대상·정보·권한·승인 조건을 확인할 새 검토 단계로 연결한다. 자동으로 이전 실행 지점부터 재개하지 않는다. `N19.13`
     - 강사는 변경된 조건을 검토하고 재개 여부를 선택한다. 서비스는 재개 시 N09/N10/N12/N13 중 변경된 조건에 필요한 흐름으로 연결한다. 최종 실행은 새 요청에 따른다. `N19.14`
     - *이전 외부 효과와 현재 조건을 다시 검토한다. 기존 성공 또는 효과 미확인 작업 자동 재실행 없음.*

## 📌 유저스토리11 : 외부 플랫폼에 직접 작성하는 경우

   - **case1. 내부 작성안만 이용하는 경우**

   - **case2. 외부 사이트에서 직접 작업하는 경우**

   - *사용자 직접 수행 및 자료 제출은 서비스 대행 성공이나 독립 확인 성공으로 처리하지 않는다.*

## 📌 유저스토리12 : 계정 및 개인정보 관련 안내를 확인하거나 로그아웃하는 경우

     - 강사는 변경할 항목을 하나씩 선택한다. 서비스는 공유 객체/다른 레슨에 영향을 미치는 항목과 해당 객체에만 적용되는 항목을 구분한다. `P01-UPDATE.02`
     - 강사는 P01-V에서 선택 항목의 변경 예정 값을 확인한다. 서비스는 N13에서 이전 값·변경값·범위를 비교하고 새 승인을 받는다. `P01-UPDATE.03`
     - 강사는 동일 객체에 대한 수정 요청을 누른다. 서비스는 변경 이전 상태, 현재 권한·대상·양 승인·이전 효과를 재검증하고 작업을 기록한다. `P01-UPDATE.04`
     - 서비스는 승인 범위에 포함된 수정 가능한 항목만 변경한다. 같은 객체의 허용된 저장/재심사 효과만 수행한다. 새 게시물 생성은 하지 않는다. `P01-UPDATE.05`
     - 서비스는 동일 대상의 저장값과 필요한 후속 상태를 독립 확인한다. 동일 상품의 승인 변경값 저장 확인 및 필요한 경우 재심사 접수 확인을(를) 기록하고 심사 접수·진행·승인·판매 가능을 분리한다. `P01-UPDATE.06`
     - 강사는 수정 결과를 확인한다. 서비스는 확인된 변경값, 객체 식별, 별도 공개 상태 및 결과 증거를 제공한다. `P01-UPDATE.07`
   - **case4. 공고 갱신을 이용하려는 경우 (지원 보류)**
     - *실제 실행 경로는 제공하지 않고 지원 여부·제한·대안만 확인한다.*
     - 강사는 크몽의 지원 업무 목록을 연다. 서비스는 정확한 관리 대상과 지원 보류 상태를 표시한다. `P01-RENEW.01`

4. **크몽 상태 및 결과 확인뷰**

     - 서비스는 크몽의 정확한 관리 대상 상태를 확인한다. 심사 접수·진행·승인·판매 가능을 분리하고 확인된 관측 시각·근거를 저장한다. `P01-STATUS.03`
     - 강사는 상태 갱신 결과를 확인한다. 서비스는 이전·최신 관측, 상태 변화, 확인 수준, 가능한 후속 조치를 구분해 제공한다. `P01-STATUS.04`
   - **case2. 확인된 반려·제한·오류의 후속 안내를 확인하는 경우 (우선 후보)**
     - 강사는 크몽의 해당 업무 결과 또는 제한 안내를 연다. 서비스는 레슨 서비스 상품과 상품별 가격 옵션에 관련된 실제 관측 결과와 지원 범위를 구분한다. `P01-RESPOND.01`

   - *결과 이력·확인 시각·독립 근거 및 세션 처리 확인은 유저스토리9와 공통 흐름을 따른다.*

## 📌 유저스토리15 : 탈잉에서 레슨을 등록하거나 관리하는 경우

튜터 프로필과 클래스는 별도 관리 관계이다. 클래스 심사 접수, 승인, 최초 모집 일정 및 실제 신청 가능을 분리한다. 현재 모든 외부 실행은 차단된 목표 흐름이며 미관찰 항목은 확정된 외부 UI/필수값이 아니다.

   - 강사는 신규·조회·수정·갱신·상태 확인·대응 중 원하는 업무 및 지원 여부를 확인한다. 유저스토리6의 선택·준비 흐름을 따른다.

     - 강사는 힙합LE의 기존 등록물 조회 동작을 선택한다. 서비스는 공개 레슨 글의 작성자·게시일·확인 가능한 식별 근거를 확인할 수 있는 허용된 읽기 경로를 제공한다. `P07-READ.01`
     - 강사는 조회할 기존 대상의 식별 정보를 선택한다. 서비스는 정확한 계정/소유권·객체/하위 객체 식별 및 최신 관측값을 제공한다. `P07-READ.02`
     - 강사는 선택한 등록물 상세 내용을 확인한다. 서비스는 레슨 장터 개별 게시물의 내용·관계·관측 시각·검증 가능한 링크를 제공한다. `P07-READ.03`
     - 강사는 관리 연결 또는 후속 작업을 선택한다. 서비스는 N12 내부 연결, N15 변경 또는 N17 조회로 연결하며 외부 정보를 자동 수정하지 않는다. `P07-READ.04`
   - **case3. 기존 등록물을 수정하려는 경우 (지원 보류)**
     - *실제 실행 경로는 제공하지 않고 지원 여부·제한·대안만 확인한다.*
     - 강사는 힙합LE의 지원 업무 목록을 연다. 서비스는 정확한 관리 대상과 지원 보류 상태를 표시한다. `P07-UPDATE.01`
     - 강사는 '기존 정보 수정'의 지원 조건을 확인한다. 서비스는 수정 가능 범위·저장 결과 미확인 및 현재 미제공 이유를 구분하여 제공한다. `P07-UPDATE.02`
     - 강사는 해당 업무를 제외하거나 내부 작성 안내를 선택한다. 서비스는 외부 접근·쓰기 요청을 생성하지 않고 N19 또는 해당하는 경우 N21로 연결한다. `P07-UPDATE.03`
   - **case4. 공고 갱신을 이용하려는 경우 (지원 보류)**
     - *실제 실행 경로는 제공하지 않고 지원 여부·제한·대안만 확인한다.*
     - 강사는 힙합LE의 지원 업무 목록을 연다. 서비스는 정확한 관리 대상과 지원 보류 상태를 표시한다. `P07-RENEW.01`
     - 강사는 '동일 공고 갱신'의 지원 조건을 확인한다. 서비스는 갱신 기능·간격 실제 집행 미확인 및 현재 미제공 이유를 구분하여 제공한다. `P07-RENEW.02`
     - 강사는 해당 업무를 제외하거나 내부 작성 안내를 선택한다. 서비스는 외부 접근·쓰기 요청을 생성하지 않고 N19 또는 해당하는 경우 N21로 연결한다. `P07-RENEW.03`

4. **힙합LE 상태 및 결과 확인뷰**
   - **case1. 최신 등록 상태를 확인하는 경우 (후순위 후보)**
     - 강사는 힙합LE 관리 대상의 현재 저장된 상태를 연다. 서비스는 레슨 장터 개별 게시물의 마지막 확인 정보와 시각을 제공한다. `P07-STATUS.01`
     - 강사는 최신 상태 확인 동작을 누른다. 서비스는 해당 객체·허용 읽기 경로·접근 권한을 확인하고 새로운 관측을 요청한다. `P07-STATUS.02`
     - 서비스는 힙합LE의 정확한 관리 대상 상태를 확인한다. 게시/공개 관측·실제 등록 제한을 구분하고 확인된 관측 시각·근거를 저장한다. `P07-STATUS.03`
     - 강사는 상태 갱신 결과를 확인한다. 서비스는 이전·최신 관측, 상태 변화, 확인 수준, 가능한 후속 조치를 구분해 제공한다. `P07-STATUS.04`
   - **case2. 확인된 반려·제한·오류의 후속 안내를 확인하는 경우 (내부 안내)**
     - *서비스 외부 조작 없이 내부 준비·제한 안내만 제공한다.*
     - 강사는 힙합LE의 해당 업무 결과 또는 제한 안내를 연다. 서비스는 레슨 장터 개별 게시물에 관련된 실제 관측 결과와 지원 범위를 구분한다. `P07-RESPOND.01`
     - 강사는 확인된 사유와 근거를 확인한다. 서비스는 확인된 실제 사유와 미확인/내부 준비 제한을 분리해 제공한다. `P07-RESPOND.02`
     - 강사는 지원 가능한 후속 조치를 확인한다. 서비스는 내부 준비 보완·허용된 직접 작성·보류 안내만 제공한다. 외부 반려/제재 복구 기능을 주장하지 않는다. `P07-RESPOND.03`
     - 강사는 보완, 재검토 또는 보류를 선택한다. 서비스는 N18/N19/N20 중 선택된 경로로 이동한다. 실패·효과 미확인·정책 미확인 상태에서 자동 재실행하지 않는다. `P07-RESPOND.04`
   - *결과 이력·확인 시각·독립 근거 및 세션 처리 확인은 유저스토리9와 공통 흐름을 따른다.*

## 📌 유저스토리21 : 기존 게시글을 유지한 채 새 글을 등록하고 싶은 경우 (힙합플레이야·힙합LE, 별도 미결정 후보)

최신 R02-US-036의 추가 조사에 따른 독립 신규 효과 후보이다. 기존 44개 업무의 채택이나 일일 자동 재등록 승인이 아니다.


1. **기존 게시글 상세 및 신규 게시 지원 안내뷰**
   - 강사는 기존 게시글 상세를 연다. 서비스는 기존 객체와 원본을 표시한다. `REPOST.01`
   - 강사는 동일 모집 내용의 새 글 등록 지원 여부를 확인한다. 서비스는 기존 글 수정·동일 객체 갱신과 별도 신규 생성의 차이 및 중복·간격·운영사 허용을 안내한다. `REPOST.02`
   - 강사는 게시판의 현재 규칙과 지원 결정 상태를 확인한다. 서비스는 힙합플레이야의 매일 동일글 재등록 공식 허용 미확인, 힙합LE의 공지 본문 2일/하단 3일 문구 상충 및 실제 집행 미확인을 표시한다. `REPOST.03`
   - **case1. 현재처럼 지원이 미결정이거나 규칙이 미확인인 경우**
     - 강사는 미제공 상태에서 해당 업무를 제외하거나 내부 준비 자료를 확인한다. 서비스는 외부 신규 실행을 차단하고 N19/N21로 연결한다. `REPOST.04`
   - **case2. 별도 제품 채택 및 실제 중복·간격·정책 허용이 확인된 경우 (현재 미제공)**
     - 강사는 별도 채택된 경우에만 신규 글의 대상과 내용을 확인하고 새 범위 승인을 요청한다. 서비스는 기존 글 유지, 동일 원본의 새 객체 생성, 기간·중복 제한, 정책 및 승인 근거를 재검증한다. 현재 비활성 후보 단계이다. `REPOST.05`
     - 강사는 별도 채택·허용 후 신규 등록을 요청하고 결과를 확인한다. 서비스는 P06/P07-CREATE의 허용된 단계 및 독립 확인을 거쳐 기존 글과 다른 신규 객체로 기록한다. 현재 실행 차단, 자동 재등록 없음. `REPOST.06`
