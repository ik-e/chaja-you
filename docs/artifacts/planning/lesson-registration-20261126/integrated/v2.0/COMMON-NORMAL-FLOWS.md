# 사용자 스토리 V2.0 — 정상 흐름 우선 (1차 검토안)

> TASK-058 · R01 · 2026-11-26 · 개별 범위 승인 전. 작성 방식은 [멘토님 참고 User Story](https://app.notion.com/p/42449106016080018a4bdcadc298c2f2)의 Golden Path와 오류를 분리하는 구조를 따른다. 이 문서는 정상 이용 및 정상적인 사용자 선택을 먼저 정의하는 V2.0 후보이다. V1.3 정본·분기·검토 기록은 변경하지 않는다. 오류 및 예외 흐름은 정상 범위 검토 후 별도 2차로 추가한다.

## 1. 목적과 읽는 방법

개인 음악 레슨 강사의 반복 작성·변환(P01), 반복 등록·수정·갱신(P02), 분산 상태 확인·대응(P03)을 줄인다. 서비스 진입부터 종료까지 사용자가 실제 조작하는 수준으로 표현한다. 각 Nxx는 하나의 이용 목적, Nxx.yy는 하나의 확인 가능한 단계이다. 같은 정보의 재사용은 단계 참조로 표현하고 중복 정의하지 않는다. 표기한 화면·버튼은 논리적 조작점이며 실제 UI 배치·인증 기술·API·DB 구현을 확정하지 않는다. 선택 사항은 조건이 맞을 때만 수행하며, 별도 명시가 없으면 다음 번호로 진행한다. 여러 이용 목적 또는 사용자 의사가 묶인 시나리오는 아래 '정상 선택 분기'가 우선하며 모든 번호를 순서대로 수행하지 않는다. '서비스는'으로 시작하는 행동은 사용자가 클릭하지 않는 독립 시스템 처리이다. 승인·거절·보류·제외·취소 등 사용자 의도는 정상 선택으로 다루되, 실제 실패/반려/미확인 발생 원인과 구체 복구·재시도·탈출 전이는 2차 오류 흐름에 둔다. 실패 결과를 이미 관측한 뒤의 사용자 후속 선택은 정상 이용 기능으로 N18/N20에 별도 정의한다.

**범위 원칙:** 7개 플랫폼 모두 설계 대상. 기본/후순위/조건부/제외는 추천이며 업무·행동별 최종 승인 0. 현행 mock-only로 외부 접근·자동 입력·첨부·제출·조회·유지 모두 차단. 사용자 승인·운영사 허용·법률·단계별 실제 효과는 별도 확인; 최종 버튼을 사람이 눌러도 앞선 자동화 허용이 되는 것은 아니다. 정책상 불허/미확인은 실행 경로가 아닌 안내/보류/독립 직접 작성으로 연결한다. 외부 등록 성공, 심사 접수/승인, 공개·모집 가능, 내부 준비, 사용자 보고, 독립 관측은 별도 결과로 표시한다. 권한·소유권·대상·버전·실행 범위·이전 효과의 재검증은 실행의 선행 조건이다.

## 3. 공통 정상 흐름 및 정상 사용자 선택

### N01. 첫 방문 및 사용자 등록

- 범위: 기본 후보
- 시작 조건: 최초 방문, 인증된 기존 owner 없음
- 정상 완료: 검증된 본인 식별 관계 생성·본인 자료 영역 제공
- 다음 흐름: N03
- 정상 선택 분기: 신규 인증 주체이면 등록 안내→등록 요청→초기 자료 영역, 기존 owner이면 새 계정 생성 없이 N02로 연결.

1. **N01.01** 강사는 서비스의 최초 진입 화면을 연다.
   - 서비스 처리·관찰 결과: 서비스는 이용 목적·지원 범위·현재 로그인 여부·개인정보 처리 안내를 표시한다. (V1.3: IS-121)
2. **N01.02** 강사는 서비스 이용 안내를 확인한다.
   - 서비스 처리·관찰 결과: 서비스는 원본 보관 및 외부 플랫폼 업무가 구분됨을 표시한다. (신규 구체화/지원 후보)
3. **N01.03** 강사는 인증 수단을 선택한다.
   - 서비스 처리·관찰 결과: 서비스는 채택된 인증 방식으로 본인 식별을 시작한다. 방식은 별도 결정 사항이다. (V1.3: IS-051)
4. **N01.04** 강사는 서비스 인증 절차를 수행한다.
   - 서비스 처리·관찰 결과: 서비스는 인증 주체를 검증하고 기존 owner 연결 여부를 확인한다. (V1.3: IS-051)
5. **N01.05** 강사는 최초 사용자 등록에 필요한 안내와 정보를 확인한다.
   - 서비스 처리·관찰 결과: 서비스는 필요한 최소 정보, 처리 목적·권리, 등록 조건을 제공한다. 별도 약관 동의가 필요한 경우 사용자 직접 선택을 요구한다. (V1.3: IS-062)
6. **N01.06** 강사는 서비스 계정 등록을 요청한다.
   - 서비스 처리·관찰 결과: 서비스는 검증된 인증 주체와 신규 owner를 중복 없이 연결한다. 같은 주체가 이미 연결되어 있으면 N02로 이동한다. (V1.3: IS-062)
7. **N01.07** 강사는 본인의 서비스 이용 시작 결과를 확인한다.
   - 서비스 처리·관찰 결과: 서비스는 본인 원본이 없는 초기 상태와 원본 생성 동작을 제공한다. (신규 구체화/지원 후보)

### N02. 기존 사용자 로그인 및 재접속

- 범위: 기본 후보
- 시작 조건: 등록된 owner 존재
- 정상 완료: 동일 owner의 접근 가능한 원본·작업 이력 표시
- 다음 흐름: N03 또는 N09 또는 N17
- 정상 선택 분기: 기존 원본 N03, 보류 업무 N19, 결과/이력 N17, 새 원본 N04 중 선택한다.

1. **N02.01** 강사는 서비스 진입 화면에서 로그인 동작을 선택한다.
   - 서비스 처리·관찰 결과: 서비스는 채택된 서비스 인증 절차를 제공한다. (V1.3: IS-121)
2. **N02.02** 강사는 기존 인증 주체로 인증을 수행한다.
   - 서비스 처리·관찰 결과: 서비스는 인증 주체와 기존 owner를 검증하여 동일 사용자 세션을 생성한다. (V1.3: IS-051)
3. **N02.03** 강사는 본인의 원본 관리 화면을 연다.
   - 서비스 처리·관찰 결과: 서비스는 해당 owner의 원본 목록과 연결 업무 요약을 조회한다. (V1.3: IS-066)
4. **N02.04** 강사는 진행하거나 보류했던 작업 목록을 확인한다.
   - 서비스 처리·관찰 결과: 서비스는 저장된 작업 상태·대상·마지막 관측 시각을 표시하고 외부 실행은 자동 재개하지 않는다. (V1.3: IS-080)
5. **N02.05** 강사는 원본 관리, 작업 준비 또는 상태 조회 중 원하는 동작을 선택한다.
   - 서비스 처리·관찰 결과: 서비스는 선택된 이용 흐름으로 이동한다. (신규 구체화/지원 후보)

### N03. 원본 목록·상세 조회 및 빈 목록에서 새 원본 선택

- 범위: 기본 후보
- 시작 조건: 서비스 이용 인증 완료
- 정상 완료: 원본 선택 또는 새 원본 작성 시작
- 다음 흐름: N04 또는 N05 또는 N06 또는 N09
- 정상 선택 분기: 빈 목록 또는 새 원본 선택 시 N04로 즉시 이동. 기존 원본은 상세 조회→수정(N05), 삭제(N06), 재사용(N09) 중 선택.

1. **N03.01** 강사는 원본 레슨 목록을 연다.
   - 서비스 처리·관찰 결과: 서비스는 본인 소유 원본별 식별 가능한 표시 정보, 최신 저장 버전, 연결 상태를 제공한다. 목록이 비어 있으면 새 원본 생성 동작을 제공한다. (V1.3: IS-066)
2. **N03.02** 강사는 새 원본 생성 동작 또는 기존 원본을 선택한다.
   - 서비스 처리·관찰 결과: 서비스는 새 원본 작성은 N04, 기존 원본 선택은 다음 단계로 연결한다. (V1.3: IS-002)
3. **N03.03** 강사는 선택한 원본 상세 정보를 연다.

### N05. 저장 원본 수정 및 새 버전 생성

- 범위: 기본 후보
- 시작 조건: N03에서 본인 원본 선택
- 정상 완료: 새 저장 버전 확인, 기존 외부 등록 및 승인 버전은 자동 변경되지 않음
- 다음 흐름: N03 또는 N09
- 정상 선택 분기: 첨부 추가·제거는 필요한 경우만 독립 조작. 수정 취소 시 저장 전 상태 유지, 저장 시 새 버전 확인.

2. **N05.02** 강사는 수정할 레슨 사실 항목을 선택한다.
   - 서비스 처리·관찰 결과: 서비스는 원문과 기존 확인값을 구분하여 제공한다. (V1.3: IS-004)
3. **N05.03** 강사는 선택한 항목의 값을 변경한다.
   - 서비스 처리·관찰 결과: 서비스는 변경된 값을 편집 초안에 반영한다. (V1.3: IS-004)
4. **N05.04** 강사는 추가할 첨부 파일을 선택한다.
   - 서비스 처리·관찰 결과: 서비스는 N04의 파일별 수신·규격·권리 확인 규칙을 적용한다. 추가할 파일이 있는 경우만 수행한다. (V1.3: IS-064, IS-055)

6. **N05.06** 강사는 변경된 정보를 검토한다.

7. **N05.07** 강사는 원본 변경 저장을 요청한다.
   - 서비스 처리·관찰 결과: 서비스는 최신 기준 버전과 소유권을 확인하고 새 버전을 저장한다. 기존 외부 게시물과 승인된 버전을 자동 변경하지 않는다. (V1.3: IS-005)
8. **N05.08** 강사는 새 원본 버전의 저장 결과를 확인한다.
   - 서비스 처리·관찰 결과: 서비스는 새 버전과 저장 시각을 표시하고 영향을 받는 미실행 준비본은 재검토 대상으로 구분한다. (V1.3: IS-113, IS-019)

### N06. 원본 삭제 및 관리 연결 해제

- 범위: 기본 후보
- 시작 조건: 본인 원본 또는 관리 연결 선택
- 정상 완료: 선택한 내부 객체만 처리되고 외부 게시물 유지
- 다음 흐름: N03 또는 N17
- 정상 선택 분기: 원본 삭제 N06.01~04, 기존 외부 관리 연결 해제 N06.05~07로 독립 진입. 삭제 취소 시 원본 유지 후 N03. 내부 삭제에 외부 연결 해제/외부 삭제가 자동으로 이어지지 않는다.

1. **N06.01** 강사는 선택한 원본의 삭제 동작을 누른다.
   - 서비스 처리·관찰 결과: 서비스는 삭제 대상·연결 등록물·진행 업무·보존해야 하는 기록을 확인할 수 있게 표시한다. (V1.3: IS-034)
2. **N06.02** 강사는 삭제 범위와 외부 게시물에 미치는 영향을 확인한다.
   - 서비스 처리·관찰 결과: 서비스는 내부 삭제와 외부 글 삭제가 다름을 안내한다. 보존 조건 및 처리 가능 범위는 정책 결정에 따른다. (V1.3: IS-034)
3. **N06.03** 강사는 삭제 요청을 확인하거나 삭제를 취소한다.
   - 서비스 처리·관찰 결과: 서비스는 확인 시 허용된 내부 삭제만 처리하고, 취소 시 기존 원본을 유지한다. (V1.3: IS-034)
4. **N06.04** 강사는 삭제 처리 결과와 남은 원본 목록을 확인한다.
   - 서비스 처리·관찰 결과: 서비스는 확인된 내부 처리 결과를 표시한다. 외부 게시물과 다른 연결을 자동 변경하지 않는다. (V1.3: IS-066)
5. **N06.05** 강사는 별도 관리 연결 해제가 필요한 경우 해당 연결을 선택한다.
   - 서비스 처리·관찰 결과: 서비스는 선택된 플랫폼·계정·외부 객체·원본 관계를 표시한다. 삭제와 무관하게 직접 진입할 수 있다. (V1.3: IS-035)
6. **N06.06** 강사는 관리 연결 해제 범위를 확인하고 해제를 요청한다.
   - 서비스 처리·관찰 결과: 서비스는 소유권·진행 작업·보존 조건을 확인하여 내부 관계만 해제한다. (V1.3: IS-035)
7. **N06.07** 강사는 연결 해제 결과를 확인한다.
   - 서비스 처리·관찰 결과: 서비스는 관리 목록에 반영된 결과 및 외부 게시물 유지 여부의 관측 범위를 표시한다. (V1.3: IS-024)

### N07. 서비스 계정 및 개인정보 권리 안내

- 시작 조건: 업무 대행 미허용·미확인 또는 직접 수행 선택
- 정상 완료: 내부 입력안 제공, 외부 직접 수행과 서비스 완료 구분
- 다음 흐름: N17 또는 N19
- 정상 선택 분기: 내부 작성 지원은 N21.01~02로 완료 가능. 외부 직접 수행은 서비스 범위 밖, 보고/자료는 별도 채택 때만 N21.04~05.

1. **N21.01** 강사는 직접 작성 지원 동작을 선택한다.
   - 서비스 처리·관찰 결과: 서비스는 외부 사이트에 접근하지 않고 준비된 내부 입력안 및 사용자가 직접 확인할 대상 항목을 제공한다. (V1.3: IS-059)
2. **N21.02** 강사는 플랫폼별 작성용 텍스트·가격·첨부 정보를 확인한다.
   - 서비스 처리·관찰 결과: 서비스는 허용된 내부 자료와 공개 가능 범위를 표시한다. 자동 외부 복붙·입력·첨부는 지원한다고 가정하지 않는다. (V1.3: IS-059)
3. **N21.03** 강사는 자신의 외부 브라우저에서 필요한 작업을 직접 수행한다.
   - 서비스 처리·관찰 결과: 서비스는 그 외부 작업을 직접 실행하거나 완료로 판정하지 않는다. (V1.3: IS-059)
4. **N21.04** 강사는 별도 채택된 기록 기능이 있는 경우 직접 수행 결과를 입력한다.
   - 서비스 처리·관찰 결과: 서비스는 사용자 보고와 시각·대상·출처를 구분해 기록한다. 이 단계는 조건부이며 미채택 시 제공하지 않는다. (V1.3: IS-144)
5. **N21.05** 강사는 별도 채택된 경우 비민감 확인 자료를 제공한다.
   - 서비스 처리·관찰 결과: 서비스는 사용자 제공 자료의 출처 및 확인 수준을 표시한다. 독립 확인 성공으로 승격하지 않는다. (V1.3: IS-145)
6. **N21.06** 강사는 내부 준비 완료 또는 직접 수행 보고 결과를 확인한다.
   - 서비스 처리·관찰 결과: 서비스는 대행 완료와 구분된 상태를 제공한다. (V1.3: IS-023)

### N22. 자동 상태 모니터링 설정 및 시작

- 범위: 조건부 확장·미채택 시 미제공
- 시작 조건: E01~E05 채택, 플랫폼별 읽기 허용·권한·비용·보안 확인
- 정상 완료: 승인된 대상·주기·기간·방식으로만 모니터링 시작
- 다음 흐름: N23
- 정상 선택 분기: 공개/인증 기반 조회는 각각 허용 확인. 인증 유지 거절 시 해당 인증 기반 조회 시작 안 함. 미지원 대상 제외 후 설정 검토.

1. **N22.01** 강사는 자동 모니터링 설정 화면을 연다.
   - 서비스 처리·관찰 결과: 서비스는 별도 채택·허용된 대상 및 지속 접근의 한계를 표시한다. (V1.3: IS-030)
2. **N22.02** 강사는 모니터링할 플랫폼 및 외부 객체를 선택한다.
   - 서비스 처리·관찰 결과: 서비스는 선택한 관리 객체와 허용된 읽기 범위를 표시한다. (V1.3: IS-030)
3. **N22.03** 강사는 조회할 상태 항목과 조회 범위를 지정한다.
   - 서비스 처리·관찰 결과: 서비스는 지정된 읽기 데이터의 범위를 저장한다. (V1.3: IS-128)
4. **N22.04** 강사는 허용된 공개 조회 또는 인증 기반 조회 방식을 선택한다.
   - 서비스 처리·관찰 결과: 서비스는 방법별 필요 권한·유효 기간을 표시한다. (V1.3: IS-129)
5. **N22.05** 강사는 조회 주기를 설정한다.
   - 서비스 처리·관찰 결과: 서비스는 허용된 빈도 및 비용 조건 내 주기 후보를 제공한다. (V1.3: IS-141)
6. **N22.06** 강사는 모니터링 유지 기간을 설정한다.
   - 서비스 처리·관찰 결과: 서비스는 시작·종료 시각 및 만료 조건을 표시한다. (V1.3: IS-070)
7. **N22.07** 강사는 알림 발생 조건을 선택한다.
   - 서비스 처리·관찰 결과: 서비스는 관측할 상태 변화 및 알림 조건을 저장한다. (V1.3: IS-071)
8. **N22.08** 강사는 알림 수신 채널을 선택한다.
   - 서비스 처리·관찰 결과: 서비스는 채택된 채널 및 사용자 수신 설정을 표시한다. (V1.3: IS-142)
9. **N22.09** 강사는 인증 유지가 필요한 경우 위험 고지를 확인한다.
   - 서비스 처리·관찰 결과: 서비스는 유지할 접근 범위·위험·종료 및 폐기 조건을 안내한다. (V1.3: IS-086)
10. **N22.10** 강사는 지속 조회용 인증 유지 여부를 선택한다.
   - 서비스 처리·관찰 결과: 서비스는 별도 승인 또는 거절을 기록한다. 거절 시 인증 의존 모니터링을 시작하지 않는다. (V1.3: IS-031, IS-061)
11. **N22.11** 강사는 지원하지 않는 대상을 제외한다.
   - 서비스 처리·관찰 결과: 서비스는 허용된 모니터링 대상만 남긴다. (V1.3: IS-133)
12. **N22.12** 강사는 설정 내용을 검토한다.
   - 서비스 처리·관찰 결과: 서비스는 대상·범위·주기·기간·알림 채널·승인 상태를 표시한다. (V1.3: IS-130)
13. **N22.13** 강사는 자동 모니터링 시작을 요청한다.
   - 서비스 처리·관찰 결과: 서비스는 모든 선행 조건을 검증하고 승인된 읽기 전용 작업만 시작한다. 자동 등록·갱신·수정은 하지 않는다. (V1.3: IS-131)

### N23. 자동 모니터링 이용·변경·종료

- 범위: 조건부 확장·미채택 시 미제공
- 시작 조건: N22가 별도 승인되어 시작됨
- 정상 완료: 조회·알림 기록 또는 종료 및 접근 해제 확인
- 다음 흐름: N17 또는 N24
- 정상 선택 분기: 운영 상태·알림·근거 조회는 독립 선택. 변경 N22, 중단/철회는 새 조회 차단→폐기→종료 확인. 재개는 새 설정/승인부터.

1. **N23.01** 서비스는 승인된 주기·기간에 허용된 상태를 조회한다.
   - 서비스 처리·관찰 결과: 서비스는 관측 근거·시각을 기록하며 승인 범위 외 데이터 및 쓰기 작업을 하지 않는다. (V1.3: IS-134)
2. **N23.02** 강사는 모니터링 운영 상태를 조회한다.
   - 서비스 처리·관찰 결과: 서비스는 대상별 마지막 조회와 다음 조회 예정, 종료 조건을 표시한다. (V1.3: IS-134)
3. **N23.03** 강사는 상태 변화 알림을 확인한다.
   - 서비스 처리·관찰 결과: 서비스는 확인된 상태 변화와 대응 안내를 제공한다. (V1.3: IS-032)
4. **N23.04** 강사는 알림의 관측 근거를 연다.
   - 서비스 처리·관찰 결과: 서비스는 관측값·시각·확인 수준을 표시한다. (V1.3: IS-137)
5. **N23.05** 강사는 모니터링 설정 변경을 요청한다.
   - 서비스 처리·관찰 결과: 서비스는 변경된 범위·기간·주기·인증 필요 여부를 N22에서 다시 검토하도록 한다. (V1.3: IS-132)
6. **N23.06** 강사는 모니터링 중단을 요청한다.
   - 서비스 처리·관찰 결과: 서비스는 새 조회를 중지하고 해당 접근의 종료 처리를 시작한다. (V1.3: IS-033)
7. **N23.07** 강사는 지속 조회 권한을 철회한다.
   - 서비스 처리·관찰 결과: 서비스는 권한 철회 대상에 대한 새 접근을 차단한다. (V1.3: IS-072)
8. **N23.08** 강사는 모니터링 세션 파기 결과 확인을 요청한다.
   - 서비스 처리·관찰 결과: 서비스는 관련 세션을 폐기한다. 폐기는 사용자 클릭에 의존하지 않는다. (V1.3: IS-073)
9. **N23.09** 강사는 종료 결과를 확인한다.
   - 서비스 처리·관찰 결과: 서비스는 종료 상태 및 확인된 세션 처리 결과를 제공한다. (V1.3: IS-138, IS-139)
10. **N23.10** 강사는 별도 재개가 필요한 경우 새 모니터링 시작 의사를 표시한다.
   - 서비스 처리·관찰 결과: 서비스는 N22의 현재 조건 및 별도 승인을 다시 요구한다. (V1.3: IS-136)

### N24. 서비스 세션 종료 및 재방문

- 범위: 기본 후보
- 시작 조건: 서비스 이용 종료 의사
- 정상 완료: 서비스 세션 종료, 미실행 외부 업무 자동 재개 없음
- 다음 흐름: N02 (재방문)
- 정상 선택 분기: 진행 중 기본 업무가 있을 때만 보류·중단 및 효과 처리 상태 확인. 이용 종료 후 이전 업무 자동 재개 없이 N02.

1. **N24.01** 강사는 서비스 이용 종료 동작을 선택한다.
   - 서비스 처리·관찰 결과: 서비스는 진행 작업이 있는 경우 해당 작업의 보류·외부 효과 확인 및 종료 경계를 표시한다. (V1.3: IS-053)
2. **N24.02** 강사는 진행 중인 업무의 보류 또는 종료 여부를 확인한다.
   - 서비스 처리·관찰 결과: 서비스는 N19에 따라 새 외부 쓰기 차단과 기존 효과·이력 보존을 처리한다. (V1.3: IS-049, IS-125)
3. **N24.03** 강사는 서비스 로그아웃을 요청한다.
   - 서비스 처리·관찰 결과: 서비스는 서비스 세션을 종료하고 기본 업무용 외부 세션을 별도로 처리한다. 별도 모니터링 채택 시 그 정책 및 종료 상태를 명시한다. (V1.3: IS-053, IS-127)
4. **N24.04** 강사는 서비스 종료 화면을 확인한다.
   - 서비스 처리·관찰 결과: 서비스는 보호된 원본·업무 자료 접근을 차단하고 재방문 시 N02 인증을 요구한다. (V1.3: IS-053)

## 4. 정상 흐름 검토 기준과 다음 단계

- 각 Nxx의 시작·종료 및 다음 Nxx 연결, 각 Nxx.yy의 독립 사용자 조작/서비스 처리/관측 결과를 대조한다. UI 클릭 수를 확정하는 것이 아니라 서비스가 지원해야 할 조작을 빠뜨리지 않기 위해 충분히 세분화한다.
- 플랫폼 장과 함께 7개 플랫폼 업무별 지원 후보·보류·내부 안내·조건부의 정상 경로 및 완료 기준을 검토한다. 실제 미관찰 외부 화면은 확정하지 않는다.
- 신규 구체화·계정 복구/권리 행사 등 지원 제안은 최종 채택 전이며, 기존 V1.3 기본·조건부·제외를 묵시적으로 바꾸지 않는다.
- 다음 단계: 각 정상 단계의 입력/검증/상태/외부 효과를 기준으로 오류 ID를 부여하고, 정상 분기와 구분하여 원인·서비스 처리·사용자 후속 행동·복귀 단계/종료 상태·재실행 금지 조건을 작성한다. V1.3 693개 분기와 대표 30개·정책 기대 사례 16개·기존 오류 28개·반복 9개는 누락 검증 자료로 보존한다. 공식 검증·실제 외부 실행·DB/API 상세 확정은 이번 범위 밖이다.
