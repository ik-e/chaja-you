# R05 키오스크 메뉴 선택 도우미 — 멘토 재검토용 구체화 초안

> 2026-11-16 R01 인수인계용 초안. **R05 작성자 확인 전 / 사용자 효과 검증 전 / 공식 제품·제출안 아님.** 최종 제출 원본은 R05가 확정.
>
> 근거: [11/16 첨부 스냅샷](../inbox/IDEA-20261116-R05-01_키오스크_메뉴_선택_도우미.md) · [공식 선정 양식](../submission-template.md)

## 1. 타깃 사용자

- **첫 타깃:** 음식점·술집에서 키오스크 앞에 섰지만 여러 메뉴 중 **무엇을 주문할지 결정하지 못한 손님**(가설)
- **제외:** 이미 주문 메뉴를 결정한 사람, 키오스크 조작 자체가 어려운 사용자(접근성 문제), 긴 결제/매장 POS 처리
- **상황:** 뒷사람의 대기 압박 속에 사진·짧은 설명을 보고 메뉴를 고르려 함. R05 자신의 반복 경험 외 타인 빈도/시간 손실은 미측정

## 2. 두 가지 Pain 가설을 구분

| 상황/원인 | 현재 대응 | 겪는 고통 가설 | 근거 |
|---|---|---|---|
| **A: 기준 없음** | 메뉴를 훑거나 추천/인기 표시를 따라감 | 취향/조건 우선순위를 정하지 못해 망설임 | R05 개인 경험, 일반화 불가 |
| **B: 정보 부족** | 메뉴판 사진·짧은 설명·직원 질문 | 맛·양·재료·옵션 차이 파악 어려움 | 개인 경험+키오스크 일반 조사 (R05 문서), 직접 수요 미확인 |
| 뒤에 사람이 기다림 | 빨리 선택하거나 주문 포기 | 대화 도우미가 되레 주문 시간을 늘릴 위험 | R05 문서의 압박 관련 조사, 해당 타깃 정량 효과 미확인 |

## 3. 가장 강한 대안과 Remaining Pain

| 대안 | 해결하는 것 | 이후에 남을 수 있는 것 |
|---|---|---|
| 자세한 메뉴판·인기/추천 표시 | 메뉴 기본 정보·일반적 선호 제공 | 나의 우선 기준 정하기/후보 비교가 필요한 경우 |
| **동일 메뉴 정보의 간단한 필터** (맵기·양·예산) | 많은 조건 선택 및 추천을 **AI 없이** 처리 가능 | 기준조차 명확하지 않은 사람에게 질문 정리가 더 유효한지 |
| 직원 추천·테이블오더 추천 | 사람에게 설명을 듣거나 조합 추천 | 이용 가능 여부·대기 부담·개인 선호 반영 |
| [토스플레이스 함께 담기](https://tossplace.com/story/together_menu) 등 | 메뉴 추가 추천 기능 이미 존재 | 메뉴를 결정하지 못한 사람의 기준 설정·비교 지원 여부 미확인 |

**가장 강한 반대 가설:** 메뉴 설명과 필터만 정리해도 AI보다 더 빠르고 정확히 주문한다. 그렇다면 도우미의 AI 부분은 불필요하다.

## 4. 문제 정의 한 문장

> 키오스크로 메뉴를 결정하지 못한 손님은 자신의 선택 기준이 분명하지 않거나 화면의 음식 정보가 부족할 때 후보 사이에서 반복해 망설이며, 뒤에 대기하는 사람이 있을 경우 질문하거나 비교할 시간도 부담스러울 수 있다.

## 5. Painkiller 피처와 측정

| 피처 | 직접 해결하려는 고통 | 사용 흐름 | 비교·성공 지표 |
|---|---|---|---|
| F1 **선택형 짧은 취향 질문·후보 축소** | A 기준을 정하기 어려움 | '고르기 어려워요' 선택→조건 말하기→2~3개 추천/최대 1회 추가 질문 | 같은 정보 필터 대비 선택·주문 총시간, 추천까지 질문 수, 포기 |
| F2 **등록 메뉴의 근거 기반 설명·비교** | B 메뉴 정보 부족 | 가격·맵기·제공량/중량 기준·재료·옵션 차이 제시 | 원자료 불일치·임의 특징 생성, 메뉴 오해, 남은 질문 |
| F3 **주문 확인/즉시 일반 화면 복귀** | 대화 지연·선택 실수 | 옵션/수량/금액 확인→완료 또는 메뉴 화면 복귀 | 잘못된 옵션 선택·최종 소요시간 |

**선택 원칙:** 실제 매장 등록 데이터가 없는 사항은 '미확인'. 알레르기/교차 오염 안전은 등록 정보만으로 확정하지 않고 직원 확인. AI가 등록되지 않은 음식 특징을 만들어서는 안 됨.

## 6. 8주 MVP/대조군/검증

- **MVP 1개 흐름:** 가상 분식점 6개 메뉴(기존 R05 제안)→선택형 추천 시작→짧은 질문(필요 시 1회)→근거 설명·2~3개 비교→메뉴·옵션·수량·금액 최종 확인. 음성·POS·결제·매장 일반화 제외.
- **기준선 3개:** A=정보량이 같은 일반 메뉴판, B=정보량이 같은 **맵기/양/예산 필터**, C=AI 대화 도우미. 동일 메뉴 구성/옵션·조건·정보 접근, 입력/학습 차이 통제.
- **실험 제안:** 정답/선호 조건을 가진 과제(예: '맵지 않고 1만원 이하'), 메뉴선택 기준이 없는 과제(사용자 자발선호), 정보 부족 과제 분리. **주문 전체 시간**·질문 수·옵션 오해·추천 데이터 정합성·포기·주관적 부담을 관찰.
- **사전 검증:** R05 본인 외 3~5명 사용자 시험 **제안**; 실제 확보/측정 전. 시간 목표값을 임의로 '성공 실증'으로 주장하지 않음.
- **도입:** 손님이 직접 선택하지만 도입/메뉴 등록·갱신 결정자는 점주 또는 키오스크 공급사. 이들의 실제 사용·입력 의향 미확인.
- **중단/축소:** (1) B가 C와 같거나 우월하면 AI 대화 축소/제외 (2) 질문 때문에 주문 소요시간/포기가 증가하면 기능 축소 (3) 실제 메뉴 데이터 수집·지속 갱신이 어려우면 가상 시연으로 제한 (4) 안전·알레르기 정보 불충분하면 직원 확인 처리.
- **개발 전제:** 승인된 가상 메뉴 또는 적법히 제공된 매장 데이터만 사용. 무단 수집·결제 연동을 MVP 전제로 두지 않음.

## 7. 근거·반증·미확인

| 주장 | 상태 | 근거 | 반대 근거·미확인 |
|---|---|---|---|
| 메뉴 선택이 R05에게 반복적인 불편 | 개인 경험 관찰 | 2026-11-16 R05 제안서 | 일반 사용자에게 일반화 불가 |
| 키오스크 상세 설명 부족·대기 압박 불편 보고 존재 | 간접 공개 조사 | R05 원문이 인용한 2023 기사, 확인일 2026-11-16 | 대상의 메뉴 미결정 빈도 직접 측정 아님 |
| AI 취향 질문이 필터보다 빠르고 만족스럽게 선택 지원 | **가설** | R05 기획 아이디어 | 실제 동일 정보량 비교 전 |
| 가상 메뉴 6개로 도입성 확인 가능 | **아님** | 시연 가설 | 가상 프로토타입은 실제 점주 도입·메뉴 갱신 효과 입증 불가 |

## 멘토에게 물을 3가지

1. 메뉴 선택 망설임이 실제 제품화할 가치 있는 **사용자 Pain**인지 가장 작은 실험으로 무엇부터 검증할까?
2. 메뉴 정보를 동일하게 준 필터보다 **대화 도우미가 이기는 상황**이 충분히 구체적인가?
3. 실제 점주·키오스크 사업자 데이터/도입 협조가 없다면 8주 프로젝트의 시연 경계를 어디까지로 잡을까?

## 3~5분 발표 골격

1. 30초 타깃: 키오스크 앞에서 메뉴를 못 정하는 손님
2. 60초 두 원인 A/B와 현행 대안·직원/필터가 이미 해결하는 부분
3. 60초 선택형 짧은 취향 질문→후보 좁힘→등록정보 비교
4. 60초 동등 정보량 필터/설명 대조, 선택시간·오류·질문·포기 측정
5. 30초 매장 데이터·도입 위험, 멘토 결정 질문

## 작성자에게 남긴 수정 요청

- [ ] 메뉴 선택이 어렵다는 타인 경험/상황을 직접 확인했는지 표시
- [ ] 개인 경험과 일반 키오스크 조사 수치를 혼합하지 않기
- [ ] 기존 UI + 필터 대조 실험을 **필수 P0**로 끌어올리기
- [ ] 가상 메뉴 6개에서 차이가 너무 쉽게 사라지는 문제에 대한 반증 실험 설계
- [ ] 최종 원본 경로/버전 R05가 확정하고 R02 원 아이디어와 개발 주체 구분
