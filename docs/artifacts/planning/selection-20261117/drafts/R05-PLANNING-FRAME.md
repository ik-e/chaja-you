## 0. 11/17 결과물

**P0:** R05 승인 **키오스크** 기획 1페이지, 3~5분 발표 흐름, 멘토 질문 2~3개, 검증할 사용자 고통과 강한 기존 대안. 18시 전 평가 취합본에 포함.  
**P1:** 사용자 흐름·기능·검증·도입 경로가 들어간 상세 기획/FR/NFR.  
**P2:** 후보 채택 이후 사용할 조건부 WBS 보완.  
**병행 역할:** R05는 임시 취합/진행 담당. R02에게 교육 양식 검토, R04에게 UX·R05 독립 평가를 요청해 **본인 자기평가가 독립 집계에 들어가지 않도록** 한다.

## 1. 정확한 타깃과 한 순간

**초기 원안 타깃:** 식당·술집에서 키오스크로 주문하며 **메뉴를 아직 정하지 못한 손님**. 키오스크를 조작하기 어려운 접근성 문제나 이미 메뉴를 정한 손님은 이번 첫 타깃이 아니다.

- 사용자 목적: [예산·맵기·선호에 맞게 하나의 메뉴를 결정하기]
- 현재 행동: [사진/설명 비교, 인기 배지, 직원 질문, 메뉴 목록 반복 탐색 등]
- 실제 손실: [망설인 시간/질문 수/주문 포기/선택 오류] → **측정 전이면 미확인**
- 경험 범위: R05의 개인 경험은 출발점이나 다른 손님에게 일반화하지 않는다.
- 사용자와 도입자 구분: **손님=사용자**, **점주/키오스크 업체=메뉴 정보 입력·운영·승인 주체 후보**. 도입 의향·비용은 미확인.

## 2. Pain의 두 원인을 섞지 말 것

| 원인 | 기존 원안의 문제 가설 | 현재 대안 | 먼저 검증할 것 |
|---|---|---|---|
| **A. 선택 기준이 없다** | 오늘 무엇을 먹고 싶은지 우선 기준이 정리되지 않음 | 인기/추천 메뉴, 직원 추천, 메뉴 탐색 | 짧은 취향 질문이 간단한 필터보다 도움이 되는가 |
| **B. 메뉴 정보가 부족하다** | 맛·재료·양·옵션 등의 차이를 알기 어려움 | 자세한 설명·등록 메뉴 정보, 직원 질문 | 메뉴판 정보만 충분히 보강해도 해결되는가 |
| 시간 압박 | 뒤에 손님이 있으면 결정이 부담 | 빠른 주문·기본 메뉴 화면 | 질문 UI가 오히려 전체 주문시간을 늘리는가 |

**R05가 명시:** 1순위 Pain=[A/B], 보조 Pain=[ ]. 원안의 2023년 키오스크 이용 관련 공개 조사는 **키오스크 전체 불편에 관한 간접 근거**로, 메뉴 결정 어려움의 발생 빈도를 직접 보여주는 자료가 아니다.

## 3. 가장 강한 현행 대안과 잔여 문제

| 대안 | 이미 해결하는 것 | 남는지 확인할 사용자 행동 |
|---|---|---|
| 정보가 잘 정리된 일반 메뉴판·인기 표시 | 메뉴 특징 확인·빠른 탐색 | 기준을 못 정하는 사람의 망설임 |
| **같은 정보량의 비AI 필터** | 가격·맵기·양 조건으로 후보 빠르게 축소 | 조건 자체를 아직 정하지 못한 손님의 판단 |
| 직원 질문 | 취향·알레르기 등의 질문에 직접 응답 | 매장·상황마다 질문 가능 여부가 다른가 |
| 기존 테이블오더 추천([토스플레이스 참고](https://tossplace.com/story/together_menu)) | 함께 담기 등 메뉴 제안 | 선호 기준 자체를 정하는 작업까지 해결하는지 미확인 |

**강한 반대 가설:** 메뉴 설명 강화나 비AI 필터만으로 AI 도우미와 같은 품질·더 빠른 주문이 가능하다. 따라서 AI의 존재만으로 차별화됐다고 주장하지 않는다.

## 5. 구체적 사용자 흐름과 데모 데이터

**흐름:** 기본 메뉴판(도우미 선택) → '고르기 어려워요' → 짧은 기준 입력(필요 시 최대 1회 추가 질문, **초기 설계 가정**) → 등록 정보에 근거한 후보 2~3개 → 비교/이유 → 메뉴·옵션·수량·총액 확인 또는 기본 메뉴 복귀.

**가상 시나리오:** 손님이 "맵지 않고 1만 원 이하로 든든한 것"을 원한다. 가상의 분식점 메뉴 6종(기본 떡볶이/로제 떡볶이/야채김밥/참치김밥/돈가스/우동)에서 등록된 가격·매운 정도·제공량/표시 기준·재료·옵션만 참조한다. 가상 메뉴 가격/설명은 **실제 매장의 사실이 아님**을 명시한다.

- **예외 1:** 조건에 맞는 메뉴가 없으면 억지 추천 대신 조건 불충족과 조정 가능 항목 표시.
- **예외 2:** 등록되지 않은 음식 맛·중량·알레르기 정보는 만들어내지 않고 **미확인** 표시.
- **예외 3:** 선택 기능을 쓰지 않는 손님은 도우미 없이 바로 주문.
- **예외 4:** 알레르기/교차 오염 여부는 직원 확인을 안내하며 AI만으로 안전하다고 단정하지 않음.

## 6. 핵심 피처 2~3개와 성공·실패 지표

| 기능 | 줄일 Pain | 입력→출력 최소 계약 | 수용 조건/실패 기록 |
|---|---|---|---|
| F1 선택형 짧은 취향 질문 | A 기준 없음 | 자연어/간단 선택→조건 정리→2~3개 후보 | 전체 시간, 질문 수, 중도 포기, 비AI 필터 대비 차이 |
| F2 등록 정보 기반 설명·비교 | B 정보 부족 | 메뉴 원본 필드→차이/추천 이유·미확인 | 임의 특성 생성 0을 목표로 검증; 가격/옵션 오류·오해 별도 기록 |
| F3 주문 확인/즉시 이탈 | 대기·오선택 부담 | 메뉴·옵션·수량·총액/복귀 | 실제 POS·결제 없이 정확한 가상 합계·복귀 |

**중요:** 6개 메뉴만으로 사용성 차이가 드러나지 않을 수 있다. 메뉴 수·옵션·취향 조건의 난이도를 조절하되 **세 비교군에 동일하게** 제공한다.

## 7. 공정한 최소 비교 실험

**세 비교군:** A=상세 메뉴를 같은 데이터로 보여주는 일반 키오스크 화면, B=동일 메뉴 정보를 사용하는 **비AI 필터**, C=AI 도우미. 메뉴/옵션/가격/재료/조리 특성의 정보량은 모두 동일하게 공개한다.

| 과제 유형 | 예제(가상) | 측정 |
|---|---|---|
| 기준이 있음 | 맵지 않은 메뉴, 예산 1만 원 이하 | 최종 결정까지 전체 시간·클릭/질문·조건 충족 |
| 정보 비교가 어려움 | 돈가스와 우동의 양 비교, 중량 기준 차이 표기 | 잘못 이해한 메뉴·남은 질문·설명 정확성 |
| 기준이 없음 | 무엇이 먹고 싶은지 정하지 못함 | 실제 선택 이유·중도 포기·질문 피로·총시간 |

**가장 싼 수요 검증:** R05 본인 이외 사용자 3~5명 행동/사용 경험 확인을 제안한다. 모집·시험 전에 '실증'이라고 쓰지 않는다. 점주/업체의 등록 메뉴 정보 입력·갱신 비용도 별도 확인할 의문이다.

**중단 조건:** (1) B 필터가 C보다 같거나 우수 → AI 축소/제외; (2) C가 질문을 늘려 총 주문시간/포기를 악화 → 흐름 단축; (3) 실제 메뉴 데이터 공급·유지 경로 미확인 → 가상 시연 수준으로 제한.

## 8. 8주 MVP/자료·도입 경계

- **Must:** 가상 메뉴와 가격/옵션 필드, 정보량 동일 비AI 필터, 선택형 짧은 질문, 출처/미확인 비교, 주문 확인·복귀, 평가 기록.
- **Later:** 실제 결제, POS, 음성, 다매장 실시간 연동, 대규모 주문 기록/프로파일, 자동 메뉴 스크래핑.
- **허용 경로:** 가상 메뉴 또는 사용 허가받은 매장 제공 데이터만 사용. 등록 정보로 확인되지 않는 안전/식재료를 사실처럼 추천하지 않음.
- **실제 도입:** 사용자 손님과 도입자 점주/업체를 분리하고 의향·운영비·메뉴 관리 책임을 **미확인**으로 남김.
- **WBS 연결:** [R05 조건부 8주 예비안](WBS-alternatives.md)의 owner·선행·산출물/수용 기준 보완.

## 9. 상세 기획서로 이어질 작성 목차

1. 서비스 개요·손님/점주 역할 구분·첫 사용 순간
2. 선택 기준 부재(A)·메뉴 정보 부족(B)의 실제 Pain/반례
3. 기존 메뉴판·필터·직원·테이블오더의 해결 범위와 잔여 문제
4. 문제 정의 한 문장/사용 흐름/화면 예외 및 복귀
5. F1~F3·FR/NFR·메뉴 데이터 계약·수용 기준
6. 8주 MVP/포함·제외 기능, 접근 권한·안전/미확인 처리
7. 세 비교군(A/B/C) 실험·지표·AI 필요성 및 중단 게이트
8. 점주 도입/데이터 갱신 검증, 위험/의존성 및 WBS
9. 출처 URL·확인일·가설·미확인·멘토 질문

이 목차는 **작성 프레임**이고 교육기관의 공식 필수 목차와 다르다. [OUTPUT-GUIDE 원문 확인 기록](../../../../../../guidelines/2026-11-16_OUTPUT-GUIDE_적용확인.md)을 바탕으로 R02가 실제 제공 목차를 대조한다.
