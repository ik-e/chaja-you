## 1. 타깃 및 상황

- **타깃:** 온라인 중고거래에서 송금했으나 물품을 받지 못해 **처음 상담·신고를 준비**하는 사람
- **목표/현 행동:** 거래 메시지·이체 내역·배송 약속과 관련 날짜를 찾아 사건 경위를 정리하고, ECRM 등 공식 안내에 맞춰 직접 상담·신고 준비
- **빈도/총 부담:** 아직 미측정. 11/20까지 피해 경험자 인터뷰 2~3명 목표(확보 전)

## 2. 검증할 사용자 Pain

| 대표 상황 | 기존 대응 | 고통 가설 | 현재 근거 |
|---|---|---|---|
| 거래 사실과 자료가 대화·이체 기록 등에 흩어짐 | 자료를 찾아 요약·복사하고 사건 경위 재작성 | 자료 찾기·원문 왕복 확인·재기입 시간 | R03 사용 시나리오/가설, 시간 미측정 |
| 신고 내용을 고치거나 누락·충돌 발견 | 원문과 요약·자료 목록을 각각 다시 검토 | 수정 결과 불일치, 부정확한 진술 우려, 반복 수정 | 가상 사례로 실험 가능, 실제 빈도 미확인 |
| 신고·상담 안내의 용어와 필요한 항목 확인 | ECRM 안내·무료 상담·범용 LLM | 질문 찾기/용어 해석의 보조 부담 | 원본에 보조 문제로 구분 |

## 3. 강한 기존 대안과 Remaining Pain

| 대안 | 해결한 부분 | 남는지 검증할 것 |
|---|---|---|
| [경찰 ECRM](https://ecrm.police.go.kr/minwon/main) | 공식 피해 신고/상담 안내와 작성 절차 | 자료·진술의 반복 정리 및 사용자 수정 부담 |
| 충분히 지시한 범용 LLM | 사건 요약, 누락 질문, 문장 정리 가능 | 원문과 주장·추측 구분, 자료 연결, 정정 후 모든 연결 결과 일관성 |
| 수기 메모/표·거래 플랫폼 안내 | 사용자가 직접 자료 순서와 사실관계 조정 가능 | 전체 준비 수고, 실수, 재검토 부담 |

**강한 반대 가설:** ECRM 안내와 충분한 프롬프트를 제공한 범용 LLM만으로 사용자가 같은 품질/더 낮은 전체 노력으로 끝낼 수 있다. **이 경우 별도 제품 가치 미입증.**

## 4. 문제 정의 한 문장

> 중고거래에서 대금을 송금했지만 상품을 받지 못한 사람이 처음 상담·신고를 준비할 때, 거래 경위와 증빙을 여러 곳에서 다시 찾아 연결하고 수정해야 해서 내용을 빠뜨리거나 원문과 다르게 쓰지 않았는지 반복 확인하는 부담이 생길 수 있다.

## 5. 핵심 기능 — Pain과 측정값 연결

| 핵심 기능 | 사용자 동작 | 줄일 Pain | 대조군/관측값 |
|---|---|---|---|
| F1 **사건·자료 구조화** | 자유 입력/비식별 자료 → 날짜·금액·사건 요약·관련 원문 링크 확인 | 재기입·원문 재탐색 | ECRM 안내 수기·LLM / 내용 누락, 원문 찾기 횟수, 총 시간 |
| F2 **누락·충돌·수정 일관성 확인** | 모르는 사항은 미확인, 판매자 주장과 확정 사실 구분; 사용자가 수정하면 연결 요약·질문 재대조 | 반복 수정·사실 왜곡 | 같은 정정 과제/사실 누락·왜곡·임의 추정, 수정 횟수/시간 |
| F3 **상담 준비 결과 검토·용어 안내** | 확인된 사건 요약·보유 자료·미확인 항목·상담 질문을 검토/복사 | 작성 막힘·설명 부담 | 기존 안내와 비교/오류·준비 총시간·이해도 |

## 6. 8주 MVP와 검증 게이트

- **최소 흐름:** 시작 → 기억나는 사실과 가상·비식별 자료 입력 → 사건 초안/원문 연결 확인 → 미확인·충돌 질문 → 사용자 수정 → 요약·자료 목록·상담 질문 검토/복사.
- **입력:** 비식별 텍스트·가상 캡처 사례/이체 기록 설명부터. **실제 신분증·민감 정보는 받지 않음**. 자동 OCR/신고 제출은 필수 제외.
- **대조군:** A=ECRM 공식 안내로 사람 정리, B=같은 자료·예산으로 충분히 지시한 범용 LLM, C=제안 시제품.
- **측정:** 사실 누락/왜곡·임의 추정 및 미확인 보존을 먼저 평가하고, 자료 탐색→입력→검토→수정까지 **전체 준비 시간**·재확인 왕복·사용자 체감 부담을 별도 기록. 같은 사례·동일 정보량으로 순서효과 주의.
- **실제 수요 게이트:** 2~3명 경험자 모집은 목표, 인터뷰 실행 전. 피해 경험자에게 최초 준비 과정 및 ECRM/LLM 이용 경험 질문.
- **중단/축소:** (1) 실제 잔여 부담 없음 또는 B≥C → 구조화 제품 가치 재검토 (2) 사실 왜곡 증가 → 확장 중단, 수동 검증 강화 (3) 개인정보·법률 검토 불가 → 가상 데이터 시연만.
- **AI 필요성:** 기존 템플릿·단일 LLM·고정/동적 작업 구성 비교 후 **실측 효과가 있을 때만** 다중 에이전트 채택.
- **비범위:** 실제 사건 접수, 수사/범죄 판단, 자동 고소장 법률 자문, 신분증 수집, 법률적 효과 보장.
- **도입:** 사용자는 피해자; 비용 지불·유통·신뢰·법률 검토 책임자는 **미확인**.

## 7. 근거·반증·미확인

| 주장 | 상태 | 자료/확인일 | 반대 근거·미확인 |
|---|---|---|---|
| ECRM은 공식 신고/상담 안내를 제공 | 제공 자료에서 확인 범위 명시 | [ECRM](https://ecrm.police.go.kr/minwon/main), R03 2026-11-16 조사 | 사이트 전체의 자동 구조화 부재는 단정 금지 |
| 거래 자료 반복 정리·원문 재확인이 실제 피해자에게 큰 손실 | 가설 | R03 사용자 시나리오, 인터뷰 전 | 충분한 안내/LLM으로 해결될 수 있음 |
| 원문 연결·정정 갱신이 총부담을 줄임 | 가설 | 현재 설계/실험 계획 | 기능 구현 추가 작업으로 총시간 증가 가능 |
| AI 동적 작업 구성이 단일/고정보다 우수 | 가설 | R03 기술 비교 계획 | 동일 모델·예산으로 검증 전 주장 금지 |

## 멘토에게 물을 3가지

1. 피해자에게 기존 안내·범용 LLM 이후 남는 문제를 **인터뷰/가상 사례 과제**로 검증하는 수준이 멘토 재검토에 충분한가?
2. 실제 신고·법률 자문을 하지 않는 범위에서 가장 가치 있는 **최소 결과물**은 무엇인가?
3. 현 시점에서 멀티에이전트보다 **원문 추적·정정 일관성**을 먼저 제품 핵심으로 잡는 것이 적절한가?

## 3~5분 발표 골격

1. 30초 대상: 처음 피해 신고를 준비하는 사람
2. 60초 상황과 강한 기존 대안 인정
3. 60초 남는 고통 **가설**, 보존/정정 기능 2~3개를 구체 사례로 설명
4. 60초 ECRM·충분히 지시한 LLM·시제품의 공정한 비교/중단 조건
5. 30초 권한·개인정보 경계, 멘토 결정 질문

## 작성자에게 남긴 수정 요청

- [ ] 실제 피해자 준비 경험 인터뷰 대상 **확보 여부**와 출처/관찰 범위 갱신
- [ ] R03 상세안의 이미 있는 실험/시나리오 구체값을 이 1페이지에 반영
- [ ] 확정 사용자 문제/효과처럼 표현된 문장 제거, 확인/가설 구분
- [ ] 멘토 최종 1페이지 버전/경로를 확정하고 R05에게 공유
