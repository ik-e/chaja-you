# 음악 레슨 강사 신규 채널 등록 지원 서비스 — 12항목 기획서 V1.0

> **기획 본문 완성 · 2026-11-23 · R01 통합**  
> 팀 조사 기반 기획 기준선 후보. 첫 검증은 크몽 웹 레슨 상품 1건으로 좁히되, 실제 자동 제출/상품 출시/기술 스택 및 과금은 미승인·미검증이다.

## 기획 요약

**타깃:** 기존 공고·사진·수업 조건을 갖고 모집 채널을 추가하려는 개인 음악 강사.

**문제:** 플랫폼마다 등록 양식·가격 조건·이미지·심사 단계가 달라 기존 자료를 다시 가공·검수·입력·제출해야 한다.

**해결:** **F1** 사실 기반 정보 구조화·플랫폼 변환 → **F2** 본인 인증·사전 승인 이후 허용된 입력·첨부·제출 → **F3** 접수·심사·게시 증빙·실패 복구.

**직접 가치 가설:** 강사의 직접 조작·수정·대기·결과 재확인 부담 감소. **사업 모델 가설:** 실제 완결 등록 1건/묶음 단위 과금(가격·원가 미확정).

**첫 검증 범위:** **크몽 웹 상품 등록을 우선 검증**하며, 탈잉은 클래스 비교·확장 후보, 숨고는 현재 등록 객체·허용 경로 선별. 정상·실패·미확인 상태는 분리한다.

**중요한 판단 경계:** 기술적 브라우저 제어 가능성 ≠ 운영사 자동 제출 허용 ≠ 등록·사업 성과 입증. 본 문서의 기획 본문 완성과 실제 실증·제출·구현 승인도 구별한다.

## 12항목 기획 본문

### 1. 서비스 개요와 목표

**서비스 정의.** 기존 소개글·사진·커리큘럼·판매 조건을 보유한 개인 음악 레슨 강사가 새로운 모집 플랫폼에 최초로 등록할 때, 한 번 받은 원본을 플랫폼별 입력 정보로 변환하고 사용자 승인 뒤 허용된 범위에서 등록 실행과 결과 확인을 지원하는 서비스다. **홍보 문구 생성 서비스가 아니라 등록 작업의 완결성을 관리하는 서비스**를 지향한다.

**1차 제품 목표.** 강사가 직접 수행하는 자료 재분할, 가격·시간 검수, 필드 입력, 이미지 첨부, 제출 상태 재확인의 부담을 줄인다. 수강생 유입이나 매출 증가를 이미 달성한 것처럼 주장하지 않는다.

**우선 검증 문제.** 네 업무 중 **새 플랫폼 최초 등록**을 이번 기획의 주된 검증 대상으로 선택한다. R02 경험에서 1~2시간이 걸렸고 등록을 미룬 사례가 있으며, R03의 F1~F3로 완결된 작업을 정의할 수 있기 때문이다. 후기 재게시와 상담은 반복 발생하므로 후속 가치 후보로 기록하되 1차 구현에서 제외한다. 이는 R01의 **기획 범위 선택**이며 시장의 최우선 Pain이 입증됐다는 의미가 아니다.

**대상 구분.** **크몽·탈잉·숨고**는 조사 우선 3곳. **크몽 웹 레슨 상품 등록**은 1차 실행 검증 후보, 탈잉 클래스는 비교·확장 후보, 숨고는 고수 프로필·서비스 등록과 견적 업무의 구분을 먼저 확인할 후보로 둔다. 제품에서 세 플랫폼의 자동 제출을 약속하지 않는다. 당근의 기존 모임 시나리오는 비교 연구로 보존한다.

**산출 수준.** 본 문서는 문제·가치·업무 요구사항·검증·조건부 MVP에 대한 기획 기준선이다. 플랫폼 허용, 기술 스택, 세부 설계, 실제 구현 및 상용 운영 승인은 후속 게이트다.

**후속 검증:** 첫 Pain·첫 1~2개 플랫폼·제품 범위 확정

### 2. 타깃 사용자와 이용 상황

**1차 고객·결제자.** 이미 음악 레슨을 운영하고 한 곳 이상에서 홍보하며, 기존 공고 원문과 사진을 보유했지만 다른 플랫폼을 추가할 시간이 부족한 **개인 음악 강사**다. 악기/보컬/작곡 등 세부 분야로 확장 가능하나 초기 관찰은 R02의 랩·미디 레슨 경험에 한정된다.

**이용 트리거.** 기존 홍보 채널 외에 크몽·탈잉·숨고 등의 모집 채널을 신규 개설하려고 할 때. 강사는 새 플랫폼의 가입·본인인증, 입력 항목, 가격 상품 구성, 사진 조건, 심사 접수 단계를 확인해야 한다.

**고객의 실제 기대.** 원본·사진 제공 → 강사가 직접 로그인·인증 → 가격·횟수·시간·수업 범위·추가 비용·변경 규정 확인 및 실행 승인 → 이후 강사는 계속 화면을 지켜보지 않고 **제출 시도와 결과 안내까지** 맡기고 싶어 한다. 입력 제한·새로운 의사결정이 있으면 중단해 추가 승인을 요청해야 한다.

**조사 근거와 한계.** R02 자신의 직접 경험 1건, R02가 회상한 동료 강사 2명의 발언이 있다. 강사 A는 타 플랫폼 추가 등록의 번거로움을 이야기했고, 강사 B는 크몽·탈잉의 가격 경쟁을 우려했다. **B의 서비스 이용·지불 의향은 미확인**이다. 이 소수 표본을 음악 강사 전체의 특성으로 일반화하지 않는다.

**미대상.** 수강생, 수업 자체를 대신 제공할 사람, 공고·수업 조건이 전혀 없는 신규 강사, 다량 게시·광고 대행사가 1차 고객이 아니다.

[근거: R02-USER]

**기획 상태:** 기획 문서 작성 완료 · 실증/승인 조건 분리

**후속 검증:** 2명 간접 진술 외 추가 인터뷰 및 AI 사용/지불 의향 검증

### 3. 페인포인트와 실제 근거

**R02의 업무 부담 비교 (2026-11-23 회상, 실측 아님).**

| 업무 | 관찰된 상황 | 직접 작업 시간·빈도 | 1차 결정 |
| --- | --- | --- | --- |
| **처음 등록** | 기존 글로 크몽 상품 작성, 임시저장·반려·재제출 | 최초 작성·접수 **1~2시간**, 반려 수정 **5~10분**; 가입/인증/심사 대기 제외 | **우선 검증** |

**Pain P1 — 정보 재구성.** 기존 원고가 있어도 플랫폼의 제목·커리큘럼·패키지·진행 절차·사진 규격 등에 맞추어 내용을 다시 나눠 작성해야 한다.

**Pain P2 — 직접 조작과 대기.** AI가 문구를 다듬어도 별도 화면에서 입력·첨부·접수해야 한다. 정보 누락·반려 시 재방문도 필요하다.

**Pain P3 — 사실 오류와 완료 불명확.** AI가 실제로 존재하지 않는 비용·일정 규정을 생성한 경험이 있으며, 작성/제출/심사/게시 상태를 별도로 확인해야 한다.

**반대 증거.** 최초 등록은 일회성이다. 반복 재게시·문의의 장기 누적 부담이 더 클 수 있다. 강사 B는 가격 경쟁 때문에 입점을 주저했으며 자동화가 이 문제를 해결하지는 않는다. 공고 등록 지연으로 얼마의 매출 손실이 발생했는지는 모른다.

**문제의 크기 가설.** 강사가 자기 자료를 제공·승인한 뒤 작업을 최소한으로 감독하면서 완결할 수 있다면 직접 시간과 주의가 줄어든다. R02의 **3개 플랫폼 합계 직접 20~30분 이내**는 희망 목표이며 성과가 아니다.

### 4. 기존 해결 방식과 한계

**기존 대안의 해결 범위와 남은 문제.** R04가 다섯 범주를 조사했으나 동일 작업을 실제 사용자로 비교한 실험은 아직 없다.

| 대안 | 이미 해결되는 일 | 남는 문제 또는 경쟁력 검증 질문 |
| --- | --- | --- |
| 템플릿·직접 복사 | 원본 보관·문구 재활용 | 플랫폼별 필드/가격/사진 입력·제출 필요 |
| 범용 대화형 AI | 소개글·커리큘럼 초안 작성 | 승인 사실 대조, 플랫폼 입력·상태 확인이 별개로 남을 수 있음 |
| 범용 브라우저 에이전트 | 웹 필드 입력·버튼 조작·일부 파일 첨부 가능 | 사용자가 지시·파일 연결·인증·예외 처리를 얼마만큼 해야 하는가 |
| 플랫폼 자체 등록 도구 | 자사 플랫폼의 등록·심사·견적 템플릿 | 타 플랫폼으로 동일 원본을 변환·상태 통합하는지 불명확 |
| 사람·마케팅 대행 | 원고·등록·운영의 일부 위탁 | 실제 계약·가격·계정 권한·오류 책임과 총 비용을 확인해야 함 |

**가장 강한 경쟁 기준.** (A) 범용 AI + 템플릿 + 강사 직접 제출, (B) 충분히 설명하고 동일한 파일 접근을 제공한 범용 AI 브라우저 에이전트다. 기술적 브라우저 조작 자체를 독점 경쟁력으로 주장하지 않는다.

**잔여 가치 가설.** 전용 서비스는 음악 레슨 조건을 근거에 맞게 보존하고, 플랫폼마다 필드·제약을 사전 검증하며, 진행 상태·오류를 강사가 이해하기 쉽게 안내함으로써 **직접 조작·재확인·사용 준비 비용**을 줄일 수 있다. 이 차별성이 실제로 나타나는지는 시험으로 반증 가능해야 한다.

**가격 자료의 경계.** R04의 대행 건당 3만~10만 원, 전용 서비스 권장 건당 5천~1만 원 등은 **독립 확인 가능한 개별 상품 URL 및 실구매 근거가 부족한 제안·추정**이다. 확정 시세나 BM 결론으로 사용하지 않는다. Browser Use·ChatGPT Work·Codex의 파일 첨부 지원도 **실행 경로별로 다르게** 판단한다.

[근거: R04-ALT, R02-USER, R05-TECH]

**후속 검증:** 대행 가격·실제 사례별 외부 URL 및 브라우저 도구별 지원 기능 검증

### 5. 문제 정의와 발생 원인

**한 문장 문제 정의.** 기존 레슨 모집 원고와 사진을 가진 강사가 새로운 플랫폼에 처음 등록할 때, **플랫폼별 정보 구조와 실행·심사 절차의 차이 때문에** 이미 정해진 수업 조건을 반복 가공·검수·입력·첨부·제출해야 하므로 직접 작업과 판단 부담이 생기고 등록을 미루게 될 수 있다.

| 원인 | 관측 수준 | 발생하는 Pain | 해결할 기능 |
| --- | --- | --- | --- |
| **C1 이질적 등록 양식**: 제목·패키지·커리큘럼·이미지 규칙 차이 | 사용자 크몽 경험+공식 등록 안내 | P1 재가공·재입력 | F1 |
| **C2 생성과 실행의 단절**: AI 초안은 실제 등록 결과가 아님 | R02 실제 AI 사용 사례 | P2 등록 조작·대기 | F2 |
| **C3 원본 사실과 생성 정보 불일치** | R02가 AI 추가비·변경 규정 오류 수정 | P3 검수·반려 위험 | F1·F2 승인 규칙 |
| **C4 등록 결과의 다중 상태·응답 유실** | 플랫폼 심사 흐름+R03 설계상 위험 | 결과 재확인·중복 위험 | F3 |
| **C5 범용 도구의 초기 설정·운영 부담** | R04의 미검증 가설 | 전용 서비스 이용 동기 가능성 | UX 비교 시험 |

**해결하지 못하는 외부 원인.** 채널별 수업료 경쟁, 실제 모집 수요, 강사의 수업 품질·상담 응대 문제는 등록 자동화만으로 해소되지 않는다. 그러므로 등록 완료→신규 수강생 증가→매출 상승의 인과를 주장하지 않는다.

**문제 선정 논리.** R02의 실제 등록 경험과 동료 A의 지연 사유로 최초 등록을 첫 검증에 선택한다. 반복 업무가 더 큰 문제일 수 있다는 반론은 후속 비교 질문으로 보존한다.

[근거: R02-USER, R03-REQ, R04-ALT]

**후속 검증:** 복수 플랫폼 미입점의 경제적 이유/조작 부담 인과 및 C4 사용 장벽 실증

### 6. 핵심 피처와 사용자 가치

**기능이 실제 사용자 일을 줄일 때만 가치가 만들어진다.**

| Pain→원인 | 핵심 피처 | 사용자에게 생기는 직접 가치 가설 | 효과 관측 |
| --- | --- | --- | --- |
| P1/P3→C1·C3 | **F1 원본 추출·검증·플랫폼별 변환** | 가격·시간·횟수·내용을 다시 쪼개 작성하고 사실 오류를 찾는 시간 감소 | 승인 사실 일치율, 누락·환각 건수, 수정 시간 |
| P2→C2 | **F2 사용자 인증·승인 후 허용된 등록 실행** | 강사가 입력·첨부·제출 단계를 계속 조작·감시할 필요 감소 | 사용자의 능동 작업 시간, 예상 밖 개입 횟수, 정확 완료 건수 |
| P3→C4 | **F3 상태·증빙·안전 재개** | 완료 여부 확인과 실패 대응의 재작업·중복 위험 감소 | 상태 판정 오류, 미확인 처리, 중복 접수 수, 복구 시간 |

**가치 전달의 전제.** 강사가 자기 조건·사진에 대한 최종 결정을 내리고 명시적으로 실행 범위를 승인한다. 플랫폼의 권한 조건이 충족되는 경우에만 F2 제출을 실행한다. F1 텍스트 생성 결과를 제공하는 것만으로 '완결 대행'의 가치를 실현했다고 볼 수 없다.

**경쟁 서비스와의 구별.** 범용 브라우저 자동화도 등록 작업을 수행할 수 있으므로, 전용 제품은 도메인 정합성·반복 설정 절감·상태 확인·지원 비용에서 실제 우위가 있어야 한다. 검증 전에 우월하다고 단정하지 않는다.

**미달 조건.** 최종 제출 경로가 불허되고 강사가 직접 제출해야 한다면 원래 희망 서비스와 다른 '등록 준비/검증' 가치가 된다. 이는 독립 고객 수용·지불 의향 검증 없이는 같은 제품으로 대체하지 않는다.

[근거: R02-USER, R03-REQ, R04-ALT]

**기획 상태:** 기획 문서 작성 완료 · 실증/승인 조건 분리

**후속 검증:** 최종 제출 허용과 등록 지원만의 별도 사용자 가치 검증

### 7. 서비스 이용 시나리오

**대표 정상 이용 시나리오 — 첫 검증 후보 크몽 상품 심사 접수.**

1. 강사가 기존 레슨 소개글·사진 및 현재 운영 조건을 제공하고, 크몽 레슨 상품 등록을 선택한다.
2. F1이 가격·횟수·시간·추가비·일정 변경·제공 서비스를 구조화하여 크몽 필드로 매핑한다. 출처와 작성 시점을 확인한다.
3. 강사가 판매 조건·사진·등록할 상품·실행 범위를 확인하여 승인한다. 존재하지 않는 체험가·할인율·변경 규정은 자동 생성하지 않는다.
4. 강사가 크몽의 공식 화면에서 직접 로그인·전문가 인증한다. 외부 플랫폼 비밀번호를 우리 서버에 제출하지 않는다.
5. F2는 플랫폼이 허용하고 승인된 범위에서 입력·사진 첨부·심사 접수를 수행한다. **허용 미확인이라면 모의 페이지에만 적용**한다.
6. F3는 작성 완료·심사 접수 확인·심사 중·반려·공개·결과 미확인 중 근거가 있는 상태를 돌려주며, 다음 조치를 안내한다.

**플랫폼별 완결 단위.**

| 플랫폼 | 현재 조사에서의 작업 객체 | 1차 목표 완료와 그 이후 |
| --- | --- | --- |
| **크몽** | 전문가 레슨 서비스 상품 | **상품 심사 접수 확인**이 1차 완료; 판매 공개는 심사 승인 후 별도 |
| **탈잉** | 튜터 온·오프라인 클래스 | **클래스 심사 접수 확인**이 1차 완료; 승인 후 일정 등록까지 해야 신청 가능 |
| **숨고** | 고수 프로필·서비스/포트폴리오, 별개인 견적 발송 | **어느 객체를 최초 등록이라 부를지 아직 결정 전**. 종료된 정찰제 마켓 상품과 혼동하지 않음 |

**대표 예외.** (E1) 가격/시간 원본 충돌→추가 승인 요구. (E2) 탈잉 1시간 단위 입력과 90분 수업 충돌 가능→임의로 60/120분으로 변경하지 않고 보류. (E3) 인증 만료·업로드 실패→그 플랫폼만 중단. (E4) 제출 직후 통신 장애→결과 미확인, 기존 접수 확인 전 재제출 금지. (E5) 한 플랫폼만 완료→부분 완료와 각 증빙 유지.

**정확한 R02 최신 테스트 원본(2026-11-23).**

| --- | ---: |
| 회당 **90분** | **250,000원** |
| 회당 **180분** | **400,000원** |
| 회당 **270분** | **500,000원** |

수업 중 기본 녹음·믹싱·마스터링 포함. 별도 제작·발매 비용은 상담 후 결정. 일정 변경의 고정 사전 통보 기한 없음. 당일 취소·무단 불참은 해당 회차 사용 처리. 첫 방문 무료 상담·테스트 녹음, 작업실 대면 1:1. **R03/R05 기존 90분 월 30만 원 자료는 지난 값으로, 신규 실험에서는 사용하지 않는다.**

### 8. 비즈니스 모델

**사업 모델 가설: 강사의 직접 업무가 실제로 감소한다면, 그 완결된 등록 결과에 건별 또는 플랫폼 묶음으로 비용을 지불한다.**

| 구성 요소 | 구체적 기획 | 확인 상태 |
| --- | --- | --- |

| 거래 단위 | 한 플랫폼 최초 등록 1건 / 복수 플랫폼 패키지 | **후보**, 아직 확정 가격 없음 |

**조건별 판매 가치.** A. 정식으로 허용된 최종 제출 대행 + 접수 증빙. B. 초안·파일만 준비하는 등록 지원. 두 방식은 **상품 가치와 가격이 다를 수 있다**. B를 A의 대안으로 제안하기 전 별도 선호·지불 의향을 받아야 한다.

**수익성 확인식(설계 관측 항목).** 플랫폼당 받는 실제 금액 − (모델·브라우저 비용 + 사용자 지원 공수 비용 + 평균 실패/재작업 비용 + 플랫폼·운영 부담 배분) = 건당 기여이익. 아직 수치가 없으므로 임의 손익분기점·수익률을 작성하지 않는다.

**최초 등록의 일회성 약점.** 사용자가 모든 플랫폼에 등록하면 재구매가 드물 수 있다. 실제 반복 이용과 신규 유입/추천 여부를 확인하기 전 구독형 매출을 전제하지 않는다.

### 11. MVP와 개발 범위

**MVP 기획 기준선(조건부).**

**1차 완결 단위 선택 — 크몽 웹 레슨 상품 1건의 정보 준비→사용자 승인→(허용될 경우) 입력·사진 첨부→심사 접수 상태 확인.** 현재 확보한 공개 웹 절차와 R02 경험, R03의 상세 요구사항이 가장 구체적인 경로라 **검증 우선순위를 크몽으로 잠정 지정**한다. 이는 상용 자동 제출 허용·기술 스택 채택·제품 출시 승인이 아니다.

| 우선순위 | MVP 범위 | 종료/승격 기준 |
| --- | --- | --- |
| **Must / 모의 검증** | 원본 1건·사진, 최신 수업 조건 검증, 크몽 필드 변환, 사용자 승인, 모의 양식 입력/업로드, 시도·증빙, 오류/미확인·중복 차단 | 동일 입력에서 F1 사실 보존·F2 모의 완료·F3 정확한 상태 분류가 시험에서 확인됨 |
| **Conditional / 실제 경로** | 공식적으로 허용된 크몽 실제 입력·업로드·심사 접수와 결과 확인 | 운영사 권한·계정·개인정보 조건, 사용자 승인 및 실서비스 검증 계획이 충족된 경우만 후속 확대 |
| **Extension 1** | 탈잉 클래스: 심사 접수, 승인 이후 일정 등록 별도 | 시간/가격 표현·자동화 허용·절차 확인 후 선택 |
| **Research only** | 숨고 고수 프로필/서비스 또는 견적 업무 | '최초 등록' 객체·완료·허용 경로부터 선택 |
| **Out** | 세 플랫폼의 무조건적 무인 게시 약속, 계정 비밀번호 서버 보관, 무허용 자동 게시, 앱 전용 당근 자동화, 후기·상담·수강생 지도, 자동 가격 변경 | 별도 문제/가치/권한 확인 전 1차 범위 제외 |

**개발 의존성(후속 WBS 입력).** 등록 객체·허용 조건 확인 → 정확한 원본/필드 맵·승인 계약 → 모의 UI 입력·파일 처리 → 단계 상태/안전 재개 → 동일 조건 사용자 비교. 상용 실행이 막혀도 모의 기획 검증은 가능하나, **모의 등록만으로 원래의 완결 대행 서비스가 시장에서 실현됐다고 주장하지 않는다**.

**범위 재판단 게이트.** (G1) 크몽 실제 등록 대행 불허/공식 경로 없음 → 실제 자동 제출 제거, 가치 제안 재검증. (G2) 탈잉 입력·가격 충돌/제약 → 수정 승인 불가능하면 대상 보류. (G3) 범용 AI가 같은 품질과 더 적은 부담을 제공 → 전용 제품 차별성 재검토. (G4) 8주 내 안전한 실행·상태 증빙/운영 비용이 맞지 않음 → 플랫폼 수·기능 축소.

**현재 착수 판단.** 기획 내용은 모의 실험 설계와 후속 상세화의 입력으로 충분하다. **실서비스 자동 제출 구현·상용 배포·계정 운영을 포함하는 상세 설계는 R05 권한·보안·공수와 R01 선택 전까지 보류한다.**

[근거: R02-USER, R03-REQ, R05-TECH, R01-SCOPE]

**기획 상태:** 기획 문서 작성 완료 · 실증/승인 조건 분리

**후속 검증:** R01 첫 플랫폼·범위 공식 채택 및 착수 게이트 결정

### 12. 검증 계획과 성공 기준

**평가 목표: 승인 사실을 정확히 지키면서 강사의 직접 작업을 실제로 줄이는지 확인.** 실험 수행 전인 지표를 실적으로 쓰지 않는다.

**동일 조건 비교군.** A. 강사 직접 등록·템플릿, B. 재사용 지시문과 파일 접근을 충분히 제공한 범용 AI/브라우저 도구, C. 전용 서비스. 같은 원본·사진·사용자 인증·시작 상태·플랫폼 규칙과 최종 성공 정의를 고정한다.

**최신 시험 사실:** R02 2026-11-23 확인값인 월 4회·회당 90/180/270분, 각각 **25/40/50만 원**, 추가 비용·변경 조건·포함 서비스·이미지 사용 권리를 기준으로 한다. 이전 보고서의 '90분 30만원'을 복사해 쓰지 않는다. 탈잉 1시간 단위 입력 제약에서 90분은 '정확한 등록 성공'이 아니라 **충돌 탐지·중단이 정답일 수 있는 사례**다. 정상 완료 비교에는 실제 제공 가능한 180분 과정 등 **플랫폼에 맞게 승인된 별도 자료**를 사용한다.

## 문서 상태·후속 작업 경계

- 이 문서는 [구조화 원본 V1.0](proposal-v1.0.json)에서 생성한 읽기용 기획서다. V0.1은 팀 조사 통합 이력으로 보존한다.
- 기존 **R02·R03·R04 개인 산출물은 main**, **R05 기존 조사 보고서는 개인 작업 브랜치**에서 읽었으며, 팀원 소유 보고서/TASK는 수정하지 않았다.
- Step1 제출본·Notion 멘토 공유본·WBS/API/DB 문서는 **별도 검증·승격** 대상이다. 이 문서 작성만으로 공식 제출/접수·설계 착수 완료로 간주하지 않는다.
- R01의 첫 검증 우선순위 제안과 상용 제품 범위 최종 확정은 서로 다르다.
