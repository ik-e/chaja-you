## 1. 서비스 개요와 목표

**서비스:** 기존 레슨 공고·사진·수업 조건을 가진 개인 음악 강사가 새 모집 채널에 최초 등록할 때, 공통 정보를 재사용하고 플랫폼별 입력·결과 확인을 지원한다. 최종 등록 대행은 플랫폼의 허용 경로에서만 수행한다.

**1차 목표:** 강사의 직접 등록 시간·추가 개입을 줄이면서 실제 게시·심사 접수 등 완료 상태를 구분한다. 수강생용 근거리 지도는 정보 재게재 권한이 확인되지 않아 확장 가설로 보류한다.

**원안의 검증 범위:** 당근 모임 개설 후 첫 글 게시, 크몽 레슨 상품 등록 후 심사 접수의 **두 개 서로 다른 완료 조건**이다. 첫 단계에서 플랫폼 1곳으로 기술 가능성을 좁혀 시험하는 것은 가능하지만, 그것만으로 ‘여러 게시처 등록’의 제품 가치를 검증했다고 판단하지 않는다. [R02 원안 §1·§8]

**현재 상태:** 초안 · **담당:** R01

**추가 확인:** 첫 Pain(최초 등록 vs 반복 게시)·첫 플랫폼 확정

**완료 기준:** 업무 대상·가치·제외 기능을 명확하게 설명

## 2. 타깃 사용자와 이용 상황

**첫 타깃:** 한 곳 이상에서 개인 음악 레슨을 모집한 경험이 있고, 기존 소개글·사진·가격 조건을 갖고 있으며, 다른 플랫폼으로 모집을 넓히고 싶은 강사.

**이용 순간:** 새 플랫폼을 선택하고 첫 공고를 등록하려는 시점. R02 본인과 동료 강사 1명의 사례가 있으나 표본은 제한적이다. 강사의 범용 AI 숙련도와 사용 장벽은 확인 전이다.

**사용자 구매 조건에 중요한 기존 증거:** 동료 강사 1명은 **글만 준비해 주거나 마지막 등록 버튼을 직접 누르게 하는 방식은 이용하지 않겠다**고 답했다. 자료 제공 후 **최종 제출까지 위임하고, 문제가 있을 때만 직접 수정**하고 싶어 했다. 이는 강사 집단 전체에 대한 일반화가 아닌, 해당 응답자의 구체적 기대 결과다. [R02 원안 부록 A]

**현재 상태:** 기존 근거 보유 · **담당:** R02

**추가 확인:** 다른 강사 인터뷰·기술 사용 방식 확인

**완료 기준:** 첫 타깃·업무 트리거·미대상 사용자를 구별

## 3. 페인포인트와 실제 근거

| 업무 | 기존 근거(실측 아님) | 확인할 손실 |
| --- | --- | --- |
| 최초 등록 | 당근 약 15분, 크몽 약 20분(R02 회상) | 양식·사진·제출 반복, 채널 진입 지연 |
| 게시글 갱신 | 뮬 약 1분/일, 일부 게시판 약 3분/회(회상) | 반복 접속·게시 |
| 후기·영상 재게시 | 주 2~3건, 추가 게시 주 20~60분(회상 추정) | 복수 공간 업로드·대기 |
| 상담·견적 | 하루 약 1시간(회상) | 문의 응대 부담 |

동료 강사는 추가 게시를 미룬 이유로 **등록 불편과 플랫폼의 예상 레슨 가격**을 모두 언급했다. 단일 원인으로 단정하지 않는다.

**추가로 확보된 구체 사례:** R02가 11월 19일 공유한 후기 한 건에서는 첫 게시 후 추가 **4곳에 올리는 데 총 20분**이 들었고, 가장 지연된 과정은 영상 첨부 후 전송 대기였다. 대기 시간만의 별도 측정은 없었다. 최초 등록 15·20분과 재게시 주 20~60분은 같은 단위의 값이 아니므로 누적 부담·신규 채널의 기대효과를 분리해 비교해야 한다. [R02 원안 부록 A]

**현재 상태:** 실측·우선순위 보완 · **담당:** R02

**추가 확인:** 업무별 실측/빈도, 실제 위임 의향, 최우선 Pain 비교

**완료 기준:** 근거·빈도·손실·반대 설명이 함께 기록됨

## 4. 기존 해결 방식과 한계

수동 복사·템플릿, 범용 AI/Codex의 문안/브라우저 작업, Browser Use 같은 도구, 유료 대행·플랫폼 자체 기능을 비교한다. **기술적으로 가능하다는 사실과 강사가 쉽게 사용할 수 있다는 사실을 분리**한다.

대안별로 설정·로그인·자료 준비·가격 입력·사진 첨부·최종 제출·결과 확인·실패 복구에 누가 관여하는지, 서비스 가격은 무엇인지 조사한다.

**이미 조사한 구체적 대안:** R02 자료에는 숨고의 ‘자주 쓰는 견적’, 탈잉의 튜터 등록 가이드, 솜씨당의 자체 AI 클래스 등록 안내가 있다. 모두 동일한 최초 공고 등록 대행을 완전히 해결한다고 확인된 것은 아니지만, 전용 서비스가 이미 존재하는 보조 기능을 새로 만든다고 주장하지 않도록 비교에 포함한다. [R02 원안 부록 A·B]

**가장 강한 반증 대안:** 강사가 본인 계정에 직접 로그인한 뒤 **재사용 가능한 충분한 지시문을 받은 Codex가 사진 첨부·최종 게시·심사 접수까지 처리**하는 방식. 그 결과가 전용 서비스와 같고 사용자 선호·지불 이유도 없으면 제품 가설을 축소·보류한다. [R02 원안 §12·§15]

**현재 상태:** 보완 대기 · **담당:** R04

**추가 확인:** 대표 대안 3~5개와 실제 잔여 불편

**완료 기준:** 기존 서비스의 해결 범위·가격·출처와 남는 사용자 부담이 구분됨

## 5. 문제 정의와 발생 원인

**문제 정의 초안:** 이미 모집 자료가 있는 음악 강사도 새 플랫폼에 처음 등록하려면 플랫폼별 필수 항목·사진·가격 구성·제출 절차를 다시 처리해야 하므로 업무 부담이 생기고, 일부는 경제적 조건과 함께 추가 채널 진출을 미룬다.

**C1** 플랫폼별 입력 구조 차이(기존 사례 확인). **C2** 문안 작성 이후에도 인증·첨부·심사 접수 조작이 남음(기존 사례 확인). **C3** 범용 AI 설정·지시·복구 자체가 강사에게 부담일 수 있음(**미검증**).

**인과관계의 경계:** 등록 절차가 복잡한 것과 강사가 실제로 신규 채널을 포기한 것은 구별해야 한다. 동료 강사는 등록 불편 외에 **크몽·탈잉에서 기대하는 판매가를 받을 수 있는지**를 우려했다. 자동화가 가격/채널 적합성 문제까지 해결한다고 주장하지 않는다. [R02 원안 부록 A]

**현재 상태:** 가설 · **담당:** R01

**추가 확인:** 채널 포기의 경제적 이유 vs 입력 부담 구분, C3 사용자 검증

**완료 기준:** Pain과 원인·근거 수준이 분리됨

| P2/C2 등록 조작 | F2 허용된 경로의 인증 후 등록 실행 지원 | 등록 단계의 직접 조작 감소 | 최종 완료 건수·개입 횟수 |

**현재 상태:** 가치 가설 · **담당:** R01

## 7. 서비스 이용 시나리오

**정상 흐름:** ① 강사가 원본 공고·사진·대상 플랫폼·공개 조건 제공 → ② 서비스가 정보 구조화·필수 조건 점검 → ③ 누락 값은 강사에게 확인 → ④ 허용된 방식으로 강사가 인증하고 승인 범위 안에서 등록 진행 → ⑤ 게시 확인/심사 접수/실패/미확인 결과 제공.

**예시:** 월 4회·회당 90분·월 30만 원의 1:1 랩 레슨. 1회 체험 판매가는 주어지지 않았으므로 임의로 정하지 않는다.

**예외:** 세션 만료·자료 누락·파일 업로드 실패·제출 결과 불명확·취소·중복 위험.

**플랫폼별로 확인된 화면 차이:** 당근 모임은 모임 이름(기록된 화면 기준 24자), 소개(500자), 지역 지정·사진 선택 후 **모임 개설뿐 아니라 첫 레슨 글 게시**가 남는다. 크몽은 설명·진행 절차·준비물·메인 이미지 등 필드를 나눠 입력하고 가격 패키지 조건을 확인한 뒤 **심사 접수**해야 한다. 기록된 크몽 화면 기준 설명 100자 이상, 절차·준비물 50자 이상, 메인 이미지 1장 이상이 언급된다. 실제 서비스 조건은 검증 시 다시 확인한다.

**가격 정확성:** 제시된 정규 과정은 월 300,000원 / 4회 / 회당 90분이다. ‘시간당 50,000원’은 이 수업 조건의 환산액이며, **유료 1회 체험 판매가가 아니다**. 사용자 확인 없이 체험 가격이나 할인율을 만들지 않는다. [R02 원안 §8·§9·부록 B]

**현재 상태:** 대표 사례 기반 · **담당:** R03

**추가 확인:** 각 단계 사용자/서비스 책임과 승인 조건 정리

**완료 기준:** 정상 흐름과 실패 시 종료·복구 상태를 구분

## 8. 비즈니스 모델

**인과 흐름:** 강사의 신규 채널 등록 필요 → F1~F3로 재입력·직접 조작 감소 → 등록 업무 위임의 편의·시간 가치 → 강사의 지불 동기.

| 요소 | 현재 가설/근거 | 확인할 내용 |
| --- | --- | --- |
| 고객·결제자 | 개인 음악 강사 | 고객 규모·구매 조건 |
| 판매 가치 | 등록 준비·실제 제출·완료 상태 확인 | 어느 단계까지 돈을 내는가 |
| 과금 | 건당/플랫폼 수별 묶음 | 가격·구매 실험 |
| 반복 매출 | 공고 갱신·후기 재게시 추가 서비스 | 실제 반복 이용 필요성 |
| 핵심 비용 | AI/API, 서버/브라우저, 플랫폼 변경, 실패 처리·지원, 보안 | 등록 1건당 원가 |
| 유입 채널 | 강사 커뮤니티·소개(가설) | 고객 획득 가능성 |

동료 강사 1명이 **10개 플랫폼 최초 등록 총 5만 원** 지불 의향을 밝혔지만 실제 결제·2곳만의 가격은 미확인이다. 5천 원/플랫폼 가격으로 단순 환산하거나 구독 매출을 전제하지 않는다.

**구매 가능성과 거래 조건의 차이:** 위 50,000원은 동료 강사 1명이 공고 **1건을 10개 플랫폼에 최초 1회씩 실제 등록**해 주는 조건에 대해 밝힌 의향이다. 직접 결제, 2개 플랫폼의 가격, 단순 초안 제공의 지불 의향을 확인한 근거가 아니다. **최종 제출을 포함하는 서비스**와 **문안/등록 준비만 하는 서비스**의 과금 가능성을 별도로 평가한다.

**확장에 관한 기존 연결 가설:** 등록 과정에서 강사가 확인한 지역·가격·횟수·모집 상태를 향후 수강생용 지도에 재사용할 수 있다. 그러나 별도의 **지도 공개 동의·재표시 권한과 동일 생활권의 공고 확보**가 있어야 하므로 현재 BM 수익이나 확정 기능으로 합산하지 않는다. [R02 원안 §14·부록 A]

**현재 상태:** 수익 가설·검증 전 · **담당:** R01

**추가 확인:** 지불 의향·단가·운영비·재이용 빈도 실증

**완료 기준:** 고객→가치→지불→수익·비용 흐름과 리스크 명확

## 10. 기술 실현 가능성과 제약

**대안:** 공식 API/제휴, 강사 기기 로컬 브라우저, 서버 일회성 브라우저, 범용 AI·Browser Use. 기술 성공·플랫폼 허용·안전한 인증은 **별개의 통과 조건**이다.

R02는 10개 플랫폼, 당근의 서로 다른 게시 공간을 포함하면 **13개 게시 경로**를 조사했다. 2026-11-19 당시 공개 근거만으로 **강사 부재 중 외부 AI가 필수 항목·이미지·최종 게시/심사 접수까지 수행할 수 있음을 확인한 경로는 0개**였다. 이는 13개 모두 기술적으로 불가능하거나 위법하다는 판정이 아니다.

일회성 비밀번호를 삭제해도 인증 세션·쿠키가 남을 수 있다. 서버/로컬 결정에는 사용자 편의, 세션 격리·폐기, 구현 비용, 플랫폼 권한을 함께 고려한다.

**조사에서 발견된 제약과 후보:** R02는 탈잉의 계정 공유/미승인 자동 접속 제한과 솜씨당의 자동화 수단 제한을 확인해 이번 방식의 대상에서 제외했다. 당근의 광고 OpenAPI는 유료 광고용으로, 일반 모임 글·선생님 프로필 게시 API가 확인된 것은 아니다. 당근 비즈프로필의 ‘운영자 초대’는 유용한 공식 권한 위임 사례이지만 외부 AI 신규 등록 허용까지 입증하지 않는다. [R02 원안 부록 B·C]

**실행 위치에 관한 판단 이력:** R02의 기존 1차안은 **강사가 직접 로그인한 자기 기기의 설치형 AI를 우선 검증**하고 원격 실행을 비교 대상으로 두었다. 이후 R01과 논의한 **서버 일회성 인증·세션 폐기** 방식은 *추가 검토 후보*이며, 이미 승인된 구조로 바꾸지 않는다. 서버가 비밀번호를 일회성으로 처리하더라도 쿠키·세션·접근권한에 대한 의무는 남는다. 원안에서는 사업자가 사용자 비밀번호를 받아 로그인하는 구조를 1차 구현에서 제외했으므로, 변경하려면 명시적 결정과 근거가 필요하다. [R02 원안 §9·부록 C·D; R01 후속 기술 논의]

**현재 상태:** 제약 조사 완료·실증 대기 · **담당:** R05

**추가 확인:** 플랫폼별 허용 경로, 원격 인증, 작업 종료·세션 폐기

**완료 기준:** 가능/허용/안전/미확인을 분리한 기술 판단표

## 11. MVP와 개발 범위

**첫 검증 범위 구분:** 기술 가능성 확인은 기존 공고 1건 × 대상 플랫폼 **1곳**의 모의 작업부터 시작할 수 있다. 그러나 R02의 원래 **제품 가치 검증은 당근 모임 개설·첫 글 게시와 크몽 심사 접수라는 서로 다른 두 경로**를 비교하는 것이었다. 한 곳의 양식 입력 성공을 여러 플랫폼 등록의 가치 입증으로 승격하지 않는다. 플랫폼 허용 경로가 확보될 때만 실제 제출 실험 범위를 정한다.

**포함 후보:** 원본 정보 재사용·누락 검증·플랫폼별 변환·작업 상태 구분. **조건부:** 외부 플랫폼에 대한 실제 자동 제출(허용 경로·인증 안전성을 확보한 경우). **제외:** 수강생용 지도, 무단 수집/등록, 10개 플랫폼 동시 지원, 반복 업무·상담 자동화의 무조건적 포함.

허용된 자동 게시 경로가 없으면 등록 보조 등 축소형의 사용자 가치·지불 의향을 다시 확인하며, 자동 대행 서비스가 실현됐다고 보고하지 않는다.

**범위 결정의 핵심:** 동료 강사가 원한 결과는 '자료를 넘긴 뒤 강사가 다시 마지막 버튼을 누르지 않는 완결된 등록'이다. 허용된 자동 제출 경로가 없을 때 초안 변환만 제공하는 기능은 **다른 가치 제안**이므로 재인터뷰·지불 의향 검증 후에만 MVP 대체안으로 채택한다. [R02 원안 부록 A·§15]

**현재 상태:** 조건부 제안 · **담당:** R01

**추가 확인:** 첫 Pain·첫 플랫폼·MVP must/conditional/out 결정

**완료 기준:** 8주 안에 검증할 하나의 완결된 시나리오와 제외 범위

## 12. 검증 계획과 성공 기준

**사용자 확인:** 강사의 업무 빈도·실제 손실·기존 도구 활용 장벽·가격/위임 의향을 검증한다.

**대조 설계:** 동일한 원본·사진·조건·초기 상태에서 ① 직접 등록/템플릿 ② 충분한 지시의 범용 AI+브라우저 ③ 전용 서비스 비교. 우선 모의 양식에서 시험한다.

**측정:** 등록 정보 정확도와 최종 완료 건수, 강사 직접 작업 시간, 추가 클릭·지시·수정, 세션 만료·실패 복구, 불명확한 결과의 중복 게시, 비용·선호·지불 의향.

**실제 플랫폼:** 운영상 허용 근거가 확인된 뒤 제한적으로 검증. 측정 전 정량 합격선·AI 우위를 임의로 확정하지 않는다.

**R02가 이미 제시한 정확한 대조:** 당근 모임·크몽을 각각 모의 양식으로 준비하고 ① 직접 복사/템플릿 ② 재사용 가능한 충분한 지시를 받은 Codex ③ 전용 서비스에 **같은 원본·사진·가격·로그인 조건·완료 기준**을 준다. 설정·자료 준비·추가 지시·수정·결과 확인의 **강사 직접 시간**과 도구 대기 시간을 따로 측정한다.

**중단/축소 조건:** 실제 게시처의 허용된 완결 경로를 확보하지 못하면 무인 대행을 보류한다. Codex와 전용 서비스가 동일한 정확도·직접 시간·개입으로 끝나고 사용자가 추가 비용을 낼 이유도 없으면 제품 가설을 축소한다. 단, **범용 AI가 기술적으로 업무를 할 수 있다는 사실 자체**를 가치 부재 근거로 삼지는 않는다. [R02 원안 §12·§13·§15; 리뷰 이슈 #18]

**현재 상태:** 비교 계획·실행 전 · **담당:** R03

**추가 확인:** 케이스별 동일 조건·정량 기준·중단/보류 조건 확정

**완료 기준:** 실행 전 계획과 관측 사실을 분리하고 판단 기준을 남김
