# TASK-014 · 가전제품 구매 추천 서비스 기획안

- 갱신: 2026-11-16
- 상태: 독립 제품 제안 및 검증 가설. 팀의 제품 방향·첫 MVP 채택 결정은 아님.
- 정본: [TASK-014.json](TASK-014.json)

## 1. 제안 요약

사용자가 가전제품을 구매할 때 자신의 사용 목적과 중요 조건을 말하면, 후보 제품의 장단점과 근거를 같은 기준으로 비교하고 **왜 특정 제품을 추천하는지** 설명한다. 이미 생각해 둔 제품이 있으면 그 제품을 비교에 포함한다. 후보가 없으면 사용 목적을 먼저 묻고 조사 가능한 제품 중에서 후보를 제안한다. 결론을 낼 수 없는 조건은 미확인으로 남기며, 가격과 혜택은 공식 판매 페이지에서 확인 가능한 범위로 제시한다.

냉장고는 기존에 공개 자료를 수동 대조한 사례일 뿐, 서비스 품목으로 확정하지 않는다. 첫 실사용 검증 품목도 아직 정하지 않았다. 현재 프로젝트의 앱 리서치 MVP 범위를 이 제안으로 변경하지 않는다.

## 2. 타깃 유저

가전제품 구매나 교체를 **직접 결정하는 일반 소비자**가 서비스 대상 가설이다. 제품을 매일 사는 사람으로 한정하지 않는다. 가전 구매는 드문 일이지만, 한 번 선택하면 오래 사용하므로 자신에게 맞는 제품인지 확인하고 싶은 상황을 대상으로 한다.

- **후보가 있는 사람:** 모델 1~3개를 생각해 두었지만 중요 조건에서 무엇이 더 적합한지 확신하지 못한다.
- **후보가 없는 사람:** 필요한 품목과 사용 목적은 알지만 어떤 모델부터 비교해야 할지 모른다.
- **첫 문제 검증 대상:** 실제 구매 예정자 3~5명 가운데 후보와 중요 조건을 말할 수 있는 사람. 관찰 가능한 과제를 좁히기 위한 표본이며 최종 서비스 타깃의 경계는 아니다.

구매자에게 이런 어려움이 얼마나 자주 발생하는지, 제안 서비스를 별도로 이용할 이유가 있는지는 아직 확인하지 않았다.

## 3. 페인 포인트와 문제 정의

**페인 포인트 가설:** 사용자가 본인에게 중요한 조건으로 여러 가전제품을 비교할 때, 후보별 장단점을 같은 기준으로 파악하고 자료를 얼마나 믿어도 되는지 판단하기 어렵다. 기존 가격비교, 제조사 안내, 매장 상담, 범용 AI를 이용해도 실제 구매자가 어떤 부분에서 멈추는지는 관찰이 필요하다.

**문제 정의:** 가전제품 구매를 직접 결정하는 소비자가 자신의 사용 목적과 중요 조건에 맞는 제품을 고르려 해도, 후보별 장단점과 정보의 신뢰도를 함께 비교하기 어려워 선택에 필요한 근거를 얻지 못할 수 있다.

출처별 표기 차이나 누락은 **자료에서 관찰할 수 있는 현상**이다. 그것 때문에 사용자가 반복 검색하거나 선택을 미루는지는 **아직 검증하지 않은 가설**이다. 설치 공간에 실제로 들어가는지 같은 현장 측정과 설치 적합성의 최종 판단은 이 서비스의 자동 판정 범위로 삼지 않는다.

## 4. 핵심 기능과 사용 흐름

| 기능 | 사용자에게 보이는 결과 | 해결하려는 문제 |
| --- | --- | --- |
| F1. 목적·조건 확인 | 사용 목적, 예산, 중요 조건을 짧게 묻고 필수 조건과 선호 조건을 구분 | 사람마다 다른 구매 기준을 비교의 출발점으로 삼음 |
| F2. 후보별 근거 비교 | 같은 모델·같은 조건에 대해 확인된 정보, 출처, 확인 시점, 충돌·미확인을 표시 | 후보별 장단점과 자료의 적용 범위를 함께 확인 |
| F3. 이유를 설명하는 추천 | 추천 후보와 대안, 추천 이유, 남은 확인 사항, 공식 가격·조건부 혜택을 요약 | 제품을 고를 때 근거 없는 단정 대신 판단에 필요한 차이를 제시 |

### 진입 경로

1. **생각해 둔 제품이 있는 경우:** 해당 모델을 비교 대상에 유지한다. 사용자가 원하거나 필수 조건을 만족하는지 판단하기 어려울 때만 비교 후보를 추가한다. 기존 후보를 설명 없이 추천 목록에서 제외하지 않는다.
2. **생각해 둔 제품이 없는 경우:** 먼저 어떤 목적으로 사용할지, 예산과 필수·선호 조건이 무엇인지 묻는다. 자료와 이용 권한을 확인한 제품 집합에서 후보를 좁힌 뒤 근거와 함께 제시한다. 제품 집합이 충분하지 않으면 발굴 범위를 밝히고 임의의 전 시장 최적 제품처럼 말하지 않는다.
3. **조건 자체가 불명확한 경우:** “어떤 용도로 쓰실 예정인가요?”처럼 목적을 되묻는다. 정보가 없는 제품 사양은 사용자의 답으로 채우지 않고 미확인으로 남긴다.

조건이 확인된 후보 중 필수 조건을 충족하는 제품을 우선 비교한다. 선호 조건과 가격의 중요도는 사용자에게 확인한다. 필수 조건의 근거가 없으면 그 후보를 확정 추천하지 않고 추가 확인 항목을 보여준다. 같은 조건에서 후보별 장단점이 갈리면 하나를 무조건 최고로 선언하지 않고 선택 기준에 따라 추천이 어떻게 바뀌는지 설명한다.

## 5. 자료와 가격 표시 원칙

- **제품 사양:** 제조사의 공식 제품·지원 자료를 우선 확인하고 모델 코드와 확인 날짜를 붙인다. 서로 다른 모델이나 세부형의 정보를 혼용하지 않는다. 독립 비교시험은 해당 시험의 대상 모델과 시점에만 적용한다.
- **자료 수집:** 승인된 데이터셋, 사용 조건을 확인한 공식 API, 허용된 범위의 개별 공식 페이지 확인을 우선한다. 비공식 자동 크롤링과 대량 순회는 사용하지 않는다. 제품 전체 카탈로그의 확보·저장·갱신 권한은 아직 검증 과제다.
- **가격:** 공식 판매 페이지의 표시 가격을 기준으로 확인 시점과 판매처를 함께 적는다. 가격은 바뀔 수 있으며, 장바구니·결제 단계의 최종 금액 확인을 안내한다.
- **혜택:** 회원가입 쿠폰처럼 개인 자격, 적용 품목, 최대 할인액, 중복 적용 여부, 유효기간이 확인된 경우에만 예상 적용가를 계산한다. 확인하지 못한 혜택은 ‘적용 가능성 미확인’으로 표시한다. 적립 포인트는 즉시 결제 할인과 구분한다.
- **최저가 표현:** 확인된 공식 구매 경로 안에서의 예상 가격을 비교한다. 모든 온라인 판매처를 조사하지 않았다면 ‘시장 최저가’라고 말하지 않는다.

## 6. 가상 사용자 시나리오

아래 제품·가격·쿠폰은 **흐름을 설명하기 위한 가상 수치**다. 실제 상품 추천이나 가격 조사 결과가 아니다.

1. 수민은 이불 세탁이 가능한 세탁기를 찾는다. 예산은 120만 원이고 자동 세제 투입은 있으면 좋지만 필수는 아니다. 처음에는 생각해 둔 모델이 없다.
2. 서비스는 이불 세탁을 **필수**, 자동 세제 투입을 **선호**로 확인하고, 조사 가능한 후보 A와 B의 공식 자료를 같은 조건으로 비교한다.
3. 가상의 공식 표시 가격은 A 120만 원, B 105만 원이다. 두 제품 모두 이불 세탁 조건을 충족하고 A에만 자동 세제 투입이 있다. A 공식몰에서 첫 가입 10% 할인, 최대 10만 원 쿠폰의 **적용 자격과 조건이 확인되었다고 가정**하면 A 예상 결제액은 110만 원이다. B에는 확인된 할인 혜택이 없다고 가정한다.
4. 서비스는 “자동 세제 투입에 5만 원을 더 지불할 의향이 있나요?”라고 짧게 묻는다. 그렇다면 A, 아니라면 B를 추천하고 각 선택의 이유를 보여준다.
5. 실제 서비스에서는 A의 쿠폰 적용 자격·대상 제품·중복 할인 여부가 확인되지 않았다면 110만 원을 확정 가격으로 표시하지 않는다. 공식 결제 화면에서 최종 금액을 다시 확인하도록 한다.

이 시나리오는 **사용자의 선호에 따라 추천이 달라지는 방식**을 보여준다. 실제 사용자에게 이 질문이 도움이 되는지, 자동 세제 투입의 가치와 가격 차이를 이렇게 판단하는지는 시험하지 않았다.

## 7. 기존 대안과 첫 검증

가격비교 서비스는 가격과 필터 탐색에 강하고, 제조사 페이지는 자사 모델의 공식 정보를 제공한다. 매장 상담은 사용 목적을 물을 수 있고, 범용 AI도 여러 제품의 비교표를 만들 수 있다. 따라서 비교표나 대화형 추천 자체를 차별점으로 가정하지 않는다. 제안의 추가 가치는 **사용자가 중요하게 여긴 조건별로 근거의 적용 범위·충돌·미확인을 드러내고, 추천 이유와 남은 확인 행동을 연결하는지**에 있다. 그 가치도 아직 검증 전이다.

첫 검증에서는 실제 구매 예정자 3~5명의 후보 비교 과정과 기존 검색·문의 행동을 관찰한다. 같은 품목, 같은 후보, 같은 조건으로 가격비교·제조사 안내·범용 AI를 사용하는 과정과 제안 방식을 비교한다. 다음을 기록한다.

- 사용자가 원하는 후보가 비교에 유지되고, 추천 이유를 이해하는가
- 중요한 조건의 누락·잘못된 확신이 줄어드는가
- 출처 충돌과 미확인을 올바르게 알아차리고 필요한 재확인을 하는가
- 과제 수행 시간과 다시 검색·문의하는 횟수가 어떻게 달라지는가
- 공식 가격과 혜택 자격·상한·최종 결제금액을 혼동하지 않는가

소수의 관찰로 시장 수요나 제품 우월성을 확정하지 않는다. 첫 자료 검증 품목과 확보 가능한 공식 자료 범위, 가전 도메인을 MVP에 채택할지는 R01과 팀의 후속 판단 사항이다.

## 8. 스스로 피드백

**좋아진 점:** 타깃을 냉장고 구매자로 고정하지 않았고, 이미 후보가 있는 경우와 없는 경우를 모두 설명했다. 핵심 가치가 단순 제품 나열이 아니라 조건별 근거와 추천 이유에 연결된다. 공식 가격과 개인별 혜택을 분리하고, 미확인 정보로 확정 추천하지 않는 경계를 정했다.

**부족한 점:** 타깃은 넓지만 실제 첫 사용자는 아직 관찰하지 않았다. 후보가 없는 사람에게 어느 범위의 제품을 안정적으로 발굴할 수 있는지, 공식 자료와 가격을 지속적으로 사용할 권한이 있는지 확인되지 않았다. 쿠폰은 개인 자격과 판매 조건이 자주 달라져 실제 적용가 산출이 특히 어렵다. 사용자에게 추천 이유가 유용한지, 기존 가격비교·상담·AI보다 시간과 재확인 부담을 줄이는지도 측정하지 않았다. 첫 검증은 자료가 확보되는 한 품목과 좁은 과제로 시작하되, 품목을 사전에 냉장고로 확정하지 않는 편이 적절하다.

**다음 판단:** 사용자 관찰과 자료 접근성, 동일 과제 비교 결과를 얻은 뒤에야 문제의 우선순위와 MVP 채택 여부를 논의한다.
