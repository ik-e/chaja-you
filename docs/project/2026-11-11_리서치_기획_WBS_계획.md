## 내일의 목표

기존 AI 리서치·멀티에이전트 시스템을 비교해 우리 시스템의 차별점과 MVP 범위를 좁히고, 11월 13일 제출용 기획서와 WBS 초안을 시작합니다. 하루 전체를 조사에 쓰지 않고 오후에 범위와 작업 항목으로 전환합니다.

## 핵심 주제와 시연 후보 구분

- **프로젝트 주제:** 사용자 요청에 맞춰 리서치 에이전트 팀을 구성하고, 조사를 나누어 수행한 뒤 출처가 있는 결과를 종합하는 상위 에이전트 시스템.
- **시연 후보:** 중고거래 상품 비교는 위 시스템의 동작을 보여주기 위한 후보 사례입니다. 내일은 후보 플랫폼 전체를 비교하지 않고 데이터 접근 가능성과 한 번의 시연 흐름만 확인합니다.

## 역할별 작업

| 담당 | 작업 | 산출물 |
|---|---|---|
| R01 지효 | 사용자 문제·비교 기준을 정리하고 결과를 종합해 차별점, MVP 결정안을 작성 | 사용자와 문제, 우선순위, 미해결 결정 목록 |
| R02 상옥 | 에이전트 시스템의 운영·인프라·배포 요구와 데이터 접근에 관련된 비용·제약 조사 | 실행·배포 선택지와 제약, 확인된 출처 |
| R03 두나 | 기존 AI 리서치·멀티에이전트 시스템의 요청 명확화, 조사 분해, 전문 역할 구성 방식 비교 | 비교표와 우리 시스템에서 검증할 차별점 후보 |
| R04 원민 | 기존 리서치 도구의 요청·결과 경험과 사용 흐름 조사 | 사용자 흐름, 주요 화면 요구, 차별화 기회 |
| R05 다혁 | 조사 작업 오케스트레이션, 데이터 수집·출처 저장·보고서 생성의 백엔드 구현 가능성 검토 | 최소 데이터 흐름, 의존 요소와 기술 위험 |

| 구간 | 진행 내용 | 결과 |
|---|---|---|
| 아침 체크 | Discord 또는 각자 일일 상태 문서에서 목표·담당·막힘을 비동기로 확인 | 조사 범위와 질문 확정 |

| 저녁 체크 | 산출물 상태·미확정 사항·다음 작업을 일일 상태 문서에 남김 | 11월 12일 보완 항목 |

시간은 수업·작업 가능 시간에 맞춰 조정하며, 정기 회의는 추가하지 않습니다. 결정이 막혀 비동기 논의로 풀기 어려울 때 팀장이 필요에 따라 회의를 소집합니다.

## 기존 시스템 비교 기준

비교 대상은 AI 리서치 도구와 멀티에이전트 시스템에서 2~3개 정도를 고릅니다. 다음 기준으로 비교합니다.

- 요청이 모호할 때 추가 질문을 하는가?
- 조사 계획과 하위 과제를 만드는가?
- 전문 에이전트 역할을 고정하거나 요청별로 구성하는가?
- 출처를 확인하고 결과에 연결하는가?
- 여러 조사 결과를 어떤 방식으로 종합하는가?
- 우리 MVP에서 실제로 구현할 수 있는 차별점은 무엇인가?

중고거래 시연 후보는 사용할 수 있는 데이터 출처가 있는지와 시연 흐름을 구성할 수 있는지만 확인합니다. 플랫폼별 시장 비교는 내일의 조사 범위에 넣지 않습니다.

## 종료 시 결정할 항목

1. 핵심 사용자와 해결할 문제
2. 시스템이 요청에서 결과 보고서까지 수행할 최소 흐름
3. 에이전트 역할을 미리 정할지, 요청별로 구성할지에 대한 MVP 수준
4. 중고거래 비교를 시연 후보로 유지할지와 데이터 접근 위험
5. MVP 포함·제외 항목 및 11월 13일까지의 WBS 담당·의존성·완료 기준

## 조사 메모 형식

각 담당자는 `확인 질문 / 핵심 발견 / 출처와 확인일 / 우리 범위에 미치는 영향 / 미확인 사항`만 간단히 적습니다. 회의 아이디어를 검증된 사실로 쓰지 않고, 확인하지 못한 내용은 미확인으로 남깁니다.

- **11월 13일:** 제출물 최종 정리 및 제출 상태 확인
