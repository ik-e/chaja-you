## 읽는 방법

- 정상적인 상황 (Golden Path): 이용 상황 → 번호가 붙은 논리 화면 → 강사가 실제로 하는 행동 → 화면이 제공하는 결과.
- 비정상적인 상황: 해당 행동/화면 아래의 **Case**, **Error**, **예외처리**를 확인한다. 시스템 처리와 화면 표시는 별도의 사용자 클릭이 아니다.
- [FE] 화면·상호작용, [BE] 저장·권한·업무·검증, [D/ML] 자료 추출·변환. 기술 관점의 예시 분류이며 구현 방식이나 담당자 확정이 아니다. 짧은 노드/ER/SC 참조는 정본 추적용이다.
- **대상:** 개인 음악 레슨 강사. 본인 소유의 원본과 본인이 관리 권한을 가진 외부 등록물만 다룬다.
- **실행 경계:** 모든 실제 외부 플랫폼 접근·읽기·쓰기·인증 연결은 현재 차단(mock-only). 아래 등록·조회·인증 경로는 조건을 충족하는 모의 설계 경로이다. 운영사 허용, 권한, 정확 객체, 실제 효과 및 독립 검증 경로 확인 전 실사용하지 않는다. 계정 가입·전문가 인증·약관 동의·결제/정산 등 직접 수행이 필요한 절차는 대행하지 않는다.

## 공통 화면과 이용 원칙

| 화면 | 강사에게 제공되는 내용 |
| --- | --- |
| V0 본인 확인 | 필요한 경우 서비스 인증 또는 공식 복구 |
| H 내 레슨 관리 | 내 원본, 연결된 등록물, 최근 업무 결과, 마지막 관측 시각과 가능한 업무 |
| E 원본 작성·수정 | 원문·자료 입력, 사실과 근거, 필요한 보완 및 저장 |
| W 작업 준비·승인 | 플랫폼별 지원 범위, 대상별 초안, 조건·변경·제한 및 승인 범위 |
| R 진행·결과 | 대상별 진행·종료, 효과 근거, 모집 목표, 후속 조치와 인증 폐기 상태 |
| X 직접 인증·선행 업무 | 필요한 플랫폼의 공식 인증 및 사용자 직접 절차 |
| D 직접 작성안 | 제한된 업무의 충분히 검증된 내부 자료 |
| G 설정·권리 / A 외부 계정 관리 | 권리 요청·로그아웃 / 계정 관리 관계와 권한 상태 |

핵심 화면은 H/E/W/R 네 개이다. X/D/G/A/V0는 조건에 따라 사용한다. 홈에 진입하는 것만으로 외부 조회나 변경이 발생하지 않는다. [FE][BE]

## 📌 유저스토리 1 : 처음 레슨을 등록하는 경우 (UJ-01)

### 1. 본인 확인 및 내 레슨 관리 (V0 → H)
- 강사는 서비스에 접속한다. 인증이 필요한 경우에만 본인 인증 또는 공식 복구를 수행한다. [FE][BE] (AUTH)
  - **Case 1. 이미 유효한 본인 인증이 있는 경우:** 별도 인증 조작 없이 본인 관리 화면으로 이동한다.
  - **Case 2. 인증이 필요한 경우:** 같은 본인인지 확인한 뒤 접근한다. 가입·인증 제공자와 세부 UI는 아직 미정이다.
  - **Error (ER-01, ER-02):** 인증 실패·만료, 가입 결과 불명 또는 소유권 확인 실패.
  - **예외처리:** 본인 확인 전 다른 사람의 정보는 노출하지 않는다. 필요한 공식 복구/재인증 또는 같은 가입 요청 확인만 한다. 불명 상태에서 새 계정을 만들지 않는다.
- 시스템은 본인의 원본·등록물·작업과 최근 상태를 표시한다. 강사는 새 원본 작성(등록 준비)을 선택한다. [FE][BE] (HOME, EDIT)
  - **Error (ER-05):** 원본 목록 조회 실패.
  - **예외처리:** 조회 불가로 표시하고 원본이 없다고 단정하지 않는다. 허용된 본인 범위에서 다시 조회한다.

### 2. 원본 작성 및 수정 (E)
- 강사는 이미 보유한 소개글, 수업 조건, 사용 권한이 있는 사진 등 필요한 자료를 제공한다. [FE][BE][D/ML] (EDIT, FACT)
  - 시스템은 필요한 경우에만 사실을 추출하고 원문 근거와 불확실성을 표시한다. 직접 입력이 충분하면 추출을 생략한다.
  - **Case 1. 정보가 충분한 경우:** 추가 확인 버튼을 요구하지 않는다.
  - **Case 2. 정보가 부족하거나 충돌하는 경우:** 강사는 강조된 항목만 정정하거나 자료를 교체한다. (EDITFIX)
  - **Error (ER-03, ER-04):** 파일 수신/형식/권리 문제, 추출 실패, 사실 충돌.
  - **예외처리:** 정상 입력은 보존하고 문제 항목만 보완한다. 불확실한 추정값을 사실로 확정하지 않는다.
- 강사는 원본 저장 또는 저장 후 등록 준비 의도를 명시한다. [FE][BE] (SAVE, SAVEACK)
  - 시스템은 원본 ID와 버전, 저장 여부를 확인한다. 저장 완료가 확인된 경우만 H 또는 W로 이동한다.
  - **Error (ER-05, ER-06):** 다른 수정과 버전 충돌, 저장 실패 또는 응답 유실.
  - **예외처리:** 최신 버전을 확인해 필요한 변경을 다시 검토한다. 저장 결과가 불명이면 동일 요청 ID로 확인하고 입력을 유지한다. 새 원본/새 저장 요청을 만들지 않으며 안전 이탈은 가능하다. (SAVEUNKNOWN)

### 3. 작업 준비 및 승인 (W)
- 강사는 등록할 플랫폼을 선택하고 준비 범위를 요청한다. 이전 화면에서 정확한 의도를 전달했으면 같은 선택을 반복하지 않는다. [FE][BE][D/ML] (SELECT, PREP)
  - 시스템은 플랫폼별 지원 여부, 변환안, 필수 정보, 정확 계정·신규 등록 대상, 선행 조건, 비용 및 효과를 검증한다. (IDENT)
  - **Case 1. 정보와 조건이 충분한 경우:** 최종 검토안으로 진행한다.
  - **Case 2. 보완이 필요한 경우:** 강사는 필요한 플랫폼 전용 정보/대안만 선택한다. 공통 사실 변경은 유저스토리 7에 따른다.
  - **Case 3. 외부 인증·대상 선택이 필요한 경우:** 유저스토리 7의 X 화면으로 진입한 뒤 같은 준비로 돌아온다.
  - **Case 4. 지원·허용이 불명인 경우:** 유저스토리 9의 보류/제외/내부 작성안으로 분기한다.
  - **Error (ER-07, ER-08, ER-09, ER-14, ER-15):** 변환 실패, 규격 충돌, 대상/중복 여부 불명 또는 지원 제한.
  - **예외처리:** 해당 대상만 보완하거나 보류한다. 조회 불가를 기존 등록 없음으로 처리하지 않는다.
- 강사는 화면에 표시된 현재 최종 내용, 대상 계정·객체/등록 위치, 예정 효과, 비용, 실행 범위 및 검증 조회 범위를 확인하고 승인하여 실행을 요청한다. [FE][BE] (PREVIEW, APPROVE, ACCEPT)
  - 내용 승인과 실행 범위 승인은 논리적으로 분리 기록하되 한 조작으로 처리하는 UX 후보이다. 별도 실행 버튼을 강제하지 않는다. 필수 직접 동의는 분리한다.
  - **Error (ER-10, ER-16, ER-17):** 승인 거절, 조건 변경, 요청 수락 여부 불명.
  - **예외처리:** 수락 전 변경 대상만 재검토한다. 수락이 불명이면 같은 요청을 조회한다. 동일 요청의 수락이 확인되면 기존 업무를 표시한다. 새 승인/중복 실행을 만들지 않는다. (ACCEPTUNKNOWN)

### 4. 진행 및 결과 (R)
- 시스템은 수락된 정확 대상별로 현재 실행 자격·충돌·권한·필수 독립 조회 경로를 확인하고, 승인된 효과만 일회 모의 처리한다. 독립 관측으로 결과를 확인한다. [BE] (START, RESERVE, DISPATCH, VERIFY)
- 강사는 자동으로 표시되는 대상별 처리 결과·근거·후속 조치를 볼 수 있다. 결과 확인 버튼은 완료의 필수 조건이 아니다. [FE][BE] (RESULT)
  - **Error (ER-18, ER-19, ER-21, ER-29, ER-31, ER-32):** 실행 실패, 결과 불명, 부분 성공, 부수 효과·근거 불명.
  - **예외처리:** 영향받은 대상의 새 쓰기를 차단하고 이미 확인된 효과를 보존한다. 유저스토리 8로 연결한다. (FENCE)
- 시스템은 업무 종료 시 업무용 접근을 차단하고 폐기 결과를 별도로 기록한다. (CLEANUP)
  - **Error (ER-23):** 폐기 확인 실패 또는 불명.
  - **예외처리:** 접근 차단을 유지하고 업무 결과와 별개로 폐기 상태를 표시한다. 새 접근을 복원하지 않는다.
- 강사는 필요하면 홈으로 돌아간다. 기존 원본과 결과는 재사용된다.

참조 시나리오: SC-01 (최초 크몽 모의 등록). 접수/심사 진행 확인과 실제 판매 가능 상태는 구분한다.

## 📌 유저스토리 2 : 저장된 레슨을 추가 플랫폼에 등록하는 경우 (UJ-02)

### 1. 내 레슨 관리 (H)
- 강사는 보관된 정확 원본 행에서 추가 등록 업무를 선택한다. 원본을 다시 입력하거나 저장할 필요가 없다. [FE][BE] (HOME, SELECT)
  - **Error (ER-05, ER-02):** 원본 조회 실패 또는 접근 권한 불명.
  - **예외처리:** 본인 소유의 정확 원본과 현재 버전을 확인하기 전 준비하지 않는다.

### 2. 작업 준비 및 승인 (W)
- 강사는 필요한 신규 대상만 선택한다. 시스템은 저장된 원본으로 입력안을 준비하고 기존 등록 여부 및 필요한 조건을 확인한다. [FE][BE][D/ML] (PREP, IDENT)
  - **Case 1. 기존 자료가 충분한 경우:** 재입력 없이 최종 검토.
  - **Case 2. 보완/인증/정확 후보 선택 필요:** 해당 조건만 유저스토리 7로 이동.
  - **Case 3. 이미 등록됨 또는 기존 효과 불명:** 신규 등록으로 대체하지 않고 기존 대상/효과를 확인하거나 보류.
  - **Error (ER-07, ER-08, ER-10, ER-14, ER-15):** 지원 제한, 오래된 준비, 중복 위험.
  - **예외처리:** 해당 대상만 재검토하며 기존 원본과 기존 성공 결과를 유지한다.
- 강사는 이번에 추가할 대상과 현재 최종 내용을 승인한다. [FE][BE] (PREVIEW, APPROVE, ACCEPT)
  - **Error (ER-16, ER-17):** 승인 변경 또는 수락 불명.
  - **예외처리:** 유저스토리 1의 승인/수락 규칙을 적용한다.

### 3. 진행 및 결과 (R)
- 시스템은 신규로 수락된 대상만 모의 처리하고 독립 확인한다. 기존 성공 대상은 실행하지 않는다. 결과는 자동 표시된다. [FE][BE] (START, RESERVE, DISPATCH, VERIFY, RESULT, CLEANUP)
  - **Error (ER-18, ER-19, ER-21):** 신규 대상 일부 실패/불명.
  - **예외처리:** 대상별 결과를 보존하고 유저스토리 8의 정확 잔여 업무만 검토한다.

참조 시나리오: SC-02.

## 📌 유저스토리 3 : 기존 등록물의 정보를 수정하는 경우 (UJ-03)

### 1. 내 레슨 관리 (H)
- 강사는 수정하려는 정확한 등록물과 수정 업무를 선택한다. [FE][BE] (HOME, PREP)
  - **Error (ER-14, ER-15):** 기존 글/상품을 특정할 수 없거나 기존 변경 효과가 불명.
  - **예외처리:** 정확 대상 선택과 허용된 독립 확인 전까지 수정하지 않는다. 새 게시물로 대체하지 않는다.

### 2. 작업 준비 및 승인 (W)
- 강사는 필요한 변경값을 제공한다. 시스템은 같은 계정·같은 기존 객체의 현재 값과 변경안을 비교하고 편집 가능 범위 및 공유 영향(예: 프로필 공통값)을 표시한다. [FE][BE][D/ML] (IDENT, PREP, FIX, PREVIEW)
  - **Case 1. 플랫폼 전용 표현 변경:** 해당 준비만 수정한다.

  - **Error (ER-24):** 작성안 미완료 또는 사용자가 직접 등록했다는 보고만 있음.
  - **예외처리:** 보고를 독립 확인 근거나 대행 완료로 간주하지 않는다. 자동 복붙·제출·직접 결과 보고 기록 기능은 제공하지 않는다.
