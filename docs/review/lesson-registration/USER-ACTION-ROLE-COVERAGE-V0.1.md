## 7. 한계 및 검토 기준

- 직접 해결=기획안 P01/P02/P03의 반복 준비·실행·확인/대응을 줄이는 사용자 의도. 보조 지원=사용·권리·정확한 대행·기록·복구가 성립하게 하는 행동. 실제 직접 작업은 시스템이 대행할 수 있으며 사용자 조작 수와 같지 않다.
- 역할과 기능 영역은 기존 330개에 대한 검토용 분류만. 기존 ID·문장·범위·정본은 수정하지 않는다. 분류는 스토리 그룹화나 화면/DB 설계 승인이 아니다.
- 각 후보에는 하나의 주 영역과 필요한 교차 참조를 둔다. 범위 밖 13개는 보조나 직접 해결로 억지 편입하지 않는다. 별도 검토·조건부 범위는 기존 상태 유지.
- D01의 원본 삭제는 사용자 자산 관리 의도이며 S02/S04에 교차 연결. S04의 이력 열람은 P03에도 연결되지만 기록/추적의 관점에서 보조로 분류. D05는 외부 업무 오류에 관한 가치이고 S05는 서비스 자체의 실패·복구/운영 책임이다.
- 모든 영역에 후보가 존재한다는 것은 기능 설계 완전성 또는 외부 실행 성공을 의미하지 않는다. G01~G10은 추가 검토 제안이며 신규 UA로 확정하지 않음.
- R02 필수·선택 목록 실제 86개와 보고서 96개 차이 미해결. 250개 상세 필드 및 248개 스토리 초기 대응의 의미 검증과 추가 상세 주장 374개 전수 대조는 아직 후속. 이번에는 팀원 126개 업무를 42개 조합으로 직접 대조하여 원문 단계·근거·미확인을 함께 남김.
- 7개 플랫폼 조사는 범위의 근거이지 일괄 실행 허용 아님. R02/R04/R05 지원 보고·관측·문서·unknown을 분리; 관련 화면 관찰만으로 실행 완료 판정하지 않음.
- 원본 전체 버전 이력 저장, 사용자 버전 화면, 운영자 화면, 지속 설정 저장 방식은 결정하지 않는다. 버전 추적 및 실행 당시 승인값/근거를 보존하는 것은 기획 요구.
