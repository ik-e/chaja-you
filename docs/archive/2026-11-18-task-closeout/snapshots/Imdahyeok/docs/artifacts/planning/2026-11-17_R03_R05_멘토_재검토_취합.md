## R03 · 중고거래 ECRM 접수 전 준비 지원

**사용자와 상황.** 송금 후 물품을 받지 못해 처음 ECRM 상담·신고를 준비하는 사람이 거래 대화, 이체 설명, 배송 약속과 사건 경위를 직접 정리한다.

**핵심 고통과 근거 수준.** R03 본인은 접수 중 시간 만료 뒤 재인증하고 처음부터 재입력한 경험을 보고했다. 이는 **이용자 자기보고 1건**이며, 실제 제한 시간·복원 경로·다른 이용자의 빈도와 전체 시간 손실은 미확인이다. 증빙 준비·상세 경위 작성 경험에 관한 공개 사례는 있지만, 제안 서비스의 효과를 입증하지는 않는다.

**강한 기존 대안.** ECRM의 공식 안내, 메모장·체크리스트, 충분히 지시한 범용 LLM이 이미 준비와 요약을 돕는다. 기존 LLM의 가상 1건·2턴 기록에서도 원문 연결·금액 충돌 표시·정정·미확인 처리가 가능했다. 제안의 추가 가치는 같은 일을 **더 적은 전체 수고와 사실 왜곡 없이** 수행하는지에 달려 있다.

**첫 흐름.** 공개 안내에 근거한 준비 목록 확인 → 사용자가 자료의 보유·미보유·모름 상태와 사건 내용을 입력 → 원문에 연결된 초안과 누락·충돌·미확인 검토 → 사용자가 확인한 요약과 목록 복사 → 사용자가 ECRM에서 직접 인증·입력·첨부한다. 실제 파일 판독, 신분증 수집, 인증·세션 대행, 자동 접수와 법적 판단은 포함하지 않는다.

**최소 검증.** 같은 가상 자료·정정 과제로 안내만 사용 / 체크리스트+메모 / 충분히 지시한 LLM / 시제품 준비 후 제안 방식을 비교한다. 누락·왜곡·미확인 보존과 **사전 준비를 포함한 총시간**, 재인증·재입력 횟수와 시간을 분리해 기록한다. 현재 비교표 일부는 모의 예시와 기존 LLM 기록의 대조일 뿐, 신규 동등 조건 실험이나 시제품 구현 결과가 아니다. 기존 방법이 같은 정확성으로 같거나 적은 수고를 제공하면 축소·보류한다.

**멘토에게 확인할 것.** 재인증·재입력 불편을 실제 서비스 동작과 구분해 가장 작게 검증할 방법은 무엇인가? ECRM·체크리스트·범용 LLM 이후에도 남는 수고를 어떤 동일 과제로 판단해야 하는가?

## R05 · 키오스크·테이블오더 메뉴 선택 도우미 v5

**사용자와 상황.** 첫 타깃은 음식점·술집의 **테이블오더**에서 “속 편한 거”, “느끼하지 않은 거”처럼 먹고 싶은 느낌은 있지만 메뉴를 정하지 못한 손님이다. 키오스크는 후속 확장 대상이다. R05의 반복 경험에서 출발했으며 다른 손님의 빈도와 손실은 미확인이다.

**핵심 고통과 근거 수준.** 느낌을 메뉴판의 정형 필터로 옮기기 어려워 메뉴를 계속 훑고, 일행을 기다리게 하는 부담 속에 원하던 것과 다른 메뉴를 고른다는 **가설**이다. 키오스크 일반 조사에서 설명 부족과 대기 압박이 보고됐지만, 첫 타깃인 테이블오더의 메뉴 미결정 빈도나 AI 추천의 효과를 직접 측정한 자료는 아니다.

**강한 기존 대안.** 잘 정리된 메뉴판, 맵기·양·가격 필터, 점주가 확인한 추천 태그, 일행 따라 주문하기와 직원 질문이 이미 선택을 돕는다. 정형 조건은 필터로 처리하고, **필터·추천 태그로 표현하기 어려운 요청**에서만 AI 대화의 추가 가치를 시험한다.

**첫 흐름.** ‘고르기 어려워요’ 선택 → 추천 태그 또는 누르는 동안 말하기·짧은 입력 → 인식된 글자 확인·필요 시 1회 질문 → 점주가 확인한 메뉴 특징으로 후보 2~3개와 이유·미확인 비교 → 주문 내용 확인 또는 일반 화면 복귀. 알레르기를 말하면 AI 추천을 중단하고 메뉴 표시·직원 확인으로 안내한다. 실제 결제·POS·기기 연동은 포함하지 않는다.

**최소 검증.** 가상 메뉴 약 25개로 정보량이 같은 상세 메뉴판(A), 비AI 필터(B), 도우미(C)를 소규모 참가자 3~5명에게 비교한다. 필터·태그 밖의 요청에서 **B와 C의 텍스트 입력을 비교해 AI 효과**, C의 텍스트 입력과 음성을 비교해 음성 효과를 분리한다. 결정·전체 주문 시간, 재탐색, 오해·포기, 추천 후보 선택, 응답 지연과 근거 없는 특징 생성을 기록한다. 참가자와 시제품 실험은 아직 수행하지 않았다. 필터·태그가 같거나 낫다면 AI를 축소하거나 제외한다.

**멘토에게 확인할 것.** 필터·추천 태그로도 표현하기 어려운 메뉴 선택 문제가 제품화할 만큼 반복되는가? 테이블오더를 첫 타깃으로 잡은 판단과 점주·업체 데이터 협조 없이 가능한 8주 시연 범위는 적절한가?
